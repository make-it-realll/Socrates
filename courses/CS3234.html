从进度块恢复

先看三件事。每一件里，写的人都相信自己是对的。

第一件。 一个 function 号称计算加法，跑了四个 unit test：add 0 0 = 0、add 0 5 = 5、add 2 3 = 5、add 7 0 = 7，全部通过。可它的定义是“第一个 argument 不超过 7 时做加法，否则返回 0”，add 8 1 给出 0。四个 test 检查了无穷多个 input 中的四个，剩下的它们什么也没说。

第二件。 “Every student is younger than some instructor” 和 “Some instructor is older than every student” 读起来像同一句话。两个 student、两个 instructor、每个 student 只比自己的那个 instructor 小，第一句为真，第二句为假（第 3 站画出这个 model）。

第三件。 一个 Prolog 程序把“X 是 Y 的 descendant”写成两条在逻辑上完全正确的 rule，问 descend(martha, rose) 时程序不返回，最后报 out of stack。把同样两条 rule 的顺序换一下，立刻得到 yes（第 9 站）。

Truth：用 valuation 定义

Propositional logic 的 formula 由 atom（p,q,r,…p,q,r,\dotsp,q,r,…）、⊤\top⊤、⊥\bot⊥ 和 connective 拼成：

Box：一个假设管到哪里

要证 φ→ψ\varphi\to\psiφ→ψ，自然的做法是“假设 φ\varphiφ，推出 ψ\psiψ”。但假设只是暂时的。如果假设在用完之后还留着，就能证出任何东西。所以每个假设开一个 box：box 外面的行在 box 里都能用；box 里的行，包括那个假设本身，在 box 关上之后都不能再用。Box 关上时只带出一行结论，比如 φ→ψ\varphi\to\psiφ→ψ，它不再依赖那个假设。

例子，p→q⊢¬¬p→qp\to q\vdash\neg\neg p\to qp→q⊢¬¬p→q：

行 Formula 理由
1 p→qp\to qp→q premise
2 ¬¬p\neg\neg p¬¬p assumption（开 box）
3 ppp ¬¬\neg\neg¬¬e 2
4 qqq →\to→e 1, 3（关 box）
5 ¬¬p→q\neg\neg p\to q¬¬p→q →\to→i 2–4

第 4 行用到 box 外的第 1 行，这是允许的。第 5 行的理由写的是一段行号 2–4，表示整个 box。

Soundness 与 completeness

现在有两种“得出”：⊨\models⊨ 看所有 valuation，⊢\vdash⊢ 看有没有 proof。它们由两个 theorem 连起来：

  • Soundness：如果 φ1,…,φn⊢ψ\varphi_1,\dots,\varphi_n\vdash\psiφ1​,…,φn​⊢ψ，那么 φ1,…,φn⊨ψ\varphi_1,\dots,\varphi_n\models\psiφ1​,…,φn​⊨ψ。能证出来的都是真的。
  • Completeness：如果 φ1,…,φn⊨ψ\varphi_1,\dots,\varphi_n\models\psiφ1​,…,φn​⊨ψ，那么 φ1,…,φn⊢ψ\varphi_1,\dots,\varphi_n\vdash\psiφ1​,…,φn​⊢ψ。真的都能证出来。

Soundness 的证明思路是对 proof 的行数做 induction：每条 rule 都保持“在所有使 premise 和当前有效假设为 T 的 valuation 下为 T”。以 →\to→e 为例：若某个 valuation 使 φ\varphiφ 和 φ→ψ\varphi\to\psiφ→ψ 都为 T，由 →\to→ 的 truth table，φ→ψ\varphi\to\psiφ→ψ 为 T 而 φ\varphiφ 为 T，只剩 ψ\psiψ 为 T 一种可能。

Soundness 最直接的用处是证明某个东西证不出来。要说明 p→q⊬q→pp\to q\nvdash q\to pp→q⊬q→p，不必试遍所有可能的 proof，只要找一个 valuation：v(p)=v(p)=v(p)= F，v(q)=v(q)=v(q)= T。这时 p→qp\to qp→q 为 T，q→pq\to pq→p 为 F，所以 p→q⊭q→pp\to q\not\models q\to pp→q⊨q→p。如果有 proof，soundness 就会给出 ⊨\models⊨，矛盾。

边界情况Soundness 这个词在别处也用

Danvy 的讲义第一周把同一对概念用在 program 上：一个判断 prime 的 function，sound 指“它说 true，那个数就是 prime”，complete 指“那个数是 prime，它就说 true”。两个方向和这里的 ⊢⇒⊨\vdash\Rightarrow\models⊢⇒⊨、⊨⇒⊢\models\Rightarrow\vdash⊨⇒⊢ 一一对应。第 5 站用这个说法来谈 unit test。

Validity 变成 satisfiability

φ\varphiφ valid，意思是没有 valuation 使它为 F，也就是没有 valuation 使 ¬φ\neg\varphi¬φ 为 T，也就是 ¬φ\neg\varphi¬φ unsatisfiable。所以只要有一个判断 satisfiable 的程序，validity 和 entailment 都能交给它：φ1,…,φn⊨ψ\varphi_1,\dots,\varphi_n\models\psiφ1​,…,φn​⊨ψ 当且仅当 φ1∧⋯∧φn∧¬ψ\varphi_1\land\dots\land\varphi_n\land\neg\psiφ1​∧⋯∧φn​∧¬ψ unsatisfiable。

判断一个 formula 是否 satisfiable，这个问题叫 SAT。它是第一个被证明 NP-complete 的问题（证明见 CS3231 的最后一站），所以不指望有对所有 input 都快的 algorithm。但实际的 SAT solver 在上百万个 variable 的工业 instance 上常常几秒出结果，靠的是先把 formula 化成统一的形状，再用能大量剪枝的 search。

Conjunctive normal form

SAT solver 只吃一种形状：若干 clause 的 conjunction，每个 clause 是若干 literal 的 disjunction，literal 是 atom 或 atom 的 negation。这叫 CNF。化成 CNF 分四步：

  1. 消去 →\to→：A→BA\to BA→B 换成 ¬A∨B\neg A\lor B¬A∨B。
  2. 把 ¬\neg¬ 往里推到 atom 上：¬¬A≡A\neg\neg A\equiv A¬¬A≡A，¬(A∧B)≡¬A∨¬B\neg(A\land B)\equiv\neg A\lor\neg B¬(A∧B)≡¬A∨¬B，¬(A∨B)≡¬A∧¬B\neg(A\lor B)\equiv\neg A\land\neg B¬(A∨B)≡¬A∧¬B。
  3. 把 ∨\lor∨ 往里推过 ∧\land∧：A∨(B∧C)≡(A∨B)∧(A∨C)A\lor(B\land C)\equiv(A\lor B)\land(A\lor C)A∨(B∧C)≡(A∨B)∧(A∨C)。

DPLL

最笨的 search 是试遍 2n2^n2n 个 valuation。DPLL 在每一步先做不需要猜的事，实在没有了才猜一次：

  1. Unit propagation。 只有一个 literal 的 clause {L}\{L\}{L} 叫 unit clause，它逼着 LLL 为 T。于是删掉所有含 LLL 的 clause（已经满足），并从所有 clause 里删去 ¬L\neg L¬L（它为 F，对 disjunction 没有贡献）。
  2. Pure literal。 如果 ¬L\neg L¬L 不出现在任何 clause 里，就让 LLL 为 T，删掉所有含 LLL 的 clause。这不会伤害任何别的 clause。
  3. 出现 empty clause：这一支 unsatisfiable。所有 clause 都删光了：satisfiable。
  4. 否则 case split：挑一个 literal LLL，分别在 LLL 为 T 和 LLL 为 F 两种情况下递归。两支中有一支 satisfiable，原来的 clause set 就 satisfiable。

先看上面那个不 valid 的例子。要找 P∨Q→Q∨RP\lor Q\to Q\lor RP∨Q→Q∨R 的 counterexample，就是要 satisfy 它的 negation，negation 的 clause 是 {P,Q}\{P,Q\}{P,Q}、{¬Q}\{\neg Q\}{¬Q}、{¬R}\{\neg R\}{¬R}。Unit ¬Q\neg Q¬Q：删掉 {¬Q}\{\neg Q\}{¬Q}，从 {P,Q}\{P,Q\}{P,Q} 里删去 QQQ，剩 {P}\{P\}{P}、{¬R}\{\neg R\}{¬R}。Unit PPP：剩 {¬R}\{\neg R\}{¬R}。Unit ¬R\neg R¬R：全部删光，satisfiable，一路上逼出来的 P=1P=1P=1、Q=0Q=0Q=0、R=0R=0R=0 就是 counterexample，和上一小节的结论一致。

边界情况Case split 的 literal 怎么挑

DPLL 本身不规定挑哪个。挑得好，一边很快出 empty clause；挑得差，search tree 指数级变大。现代 solver（CDCL）在每次冲突时从冲突里学出一个新 clause 加进去，下次不再走进同样的死路，并按最近参与冲突的频率挑 variable。这一部分 Paulson 的讲义没有讲，这里只说明它在 DPLL 的哪一步上改进。

Resolution

DPLL 是 search，找的是 valuation。另一条路是直接从 clause 推出新 clause，直到推出 empty clause。只需要一条 rule：

{B,A1,…,Am}{¬B,C1,…,Cn}{A1,…,Am,C1,…,Cn}\frac{\{B,A_1,\dots,A_m\}\qquad\{\neg B,C_1,\dots,C_n\}}{\{A_1,\dots,A_m,C_1,\dots,C_n\}}{A1​,…,Am​,C1​,…,Cn​}{B,A1​,…,Am​}{¬B,C1​,…,Cn​}​

例子。假设 H→(M∨N)H\to(M\lor N)H→(M∨N)、M→(K∧P)M\to(K\land P)M→(K∧P)、N→(L∧P)N\to(L\land P)N→(L∧P)，要证 H→PH\to PH→P。前三个化成 clause：{¬H,M,N}\{\neg H,M,N\}{¬H,M,N}、{¬M,K}\{\neg M,K\}{¬M,K}、{¬M,P}\{\neg M,P\}{¬M,P}、{¬N,L}\{\neg N,L\}{¬N,L}、{¬N,P}\{\neg N,P\}{¬N,P}。Goal 取 negation，¬(H→P)≡H∧¬P\neg(H\to P)\equiv H\land\neg P¬(H→P)≡H∧¬P，给两个 clause {H}\{H\}{H}、{¬P}\{\neg P\}{¬P}。

{¬M,K}\{\neg M,K\}{¬M,K} 和 {¬N,L}\{\neg N,L\}{¬N,L} 没有用上：KKK 和 LLL 的 negation 从不出现，它们是 pure literal，DPLL 会第一时间删掉这两个 clause。

看起来对，其实不对一次可以同时消掉两对互补的 literal

{P,Q}\{P,Q\}{P,Q} 和 {¬P,¬Q}\{\neg P,\neg Q\}{¬P,¬Q} 似乎可以一步消掉 PPP 和 QQQ，得到 {}\{\}{}，从而说明两者矛盾。可是 P=1,Q=0P=1,Q=0P=1,Q=0 同时满足这两个 clause，它们并不矛盾。正确的做法是一次只消一个 atom：消 PPP 得到 {Q,¬Q}\{Q,\neg Q\}{Q,¬Q}，那是一个恒为 T 的 clause，没有用。

还剩什么性质

Propositional logic 的 soundness 和 completeness 在 predicate logic 里仍然成立（completeness 是 Gödel 1929 年证的）。但 truth table 那样的判定方法没有了：没有 program 能对任意 formula 判定它是否 valid。讲义的证明思路是把 Post Correspondence Problem 编码成一个 formula，PCP 有 solution 当且仅当 formula valid，而 PCP 是 undecidable 的（见 CS3231 的 undecidability 一站）。所以 proof 在这里不只是省时间的办法，而是唯一的办法；能证出来的都可以检查，但没有 algorithm 保证一定找得到 proof。

Kripke model：为什么证不出 p∨¬pp\lor\neg pp∨¬p

Valuation 只有 T 和 F 两种状态，用它没法说明 p∨¬pp\lor\neg pp∨¬p 证不出来，因为在任何 valuation 下它都为 T。需要一个能表达“还不知道”的 semantics。

Kripke model 是一组 world，带一个 partial order w≤w′w\le w'w≤w′，读作“从 www 出发，以后可能到达 w′w'w′”。每个 world 上有一些 atom 成立，而且成立了就不会失效：w≤w′w\le w'w≤w′ 且 ppp 在 www 成立，则 ppp 在 w′w'w′ 也成立。复合 formula 在 world www 成立（记作 w⊩w\Vdashw⊩）的条件是：

  • w⊩A∧Bw\Vdash A\land Bw⊩A∧B：w⊩Aw\Vdash Aw⊩A 且 w⊩Bw\Vdash Bw⊩B。
  • w⊩A∨Bw\Vdash A\lor Bw⊩A∨B：w⊩Aw\Vdash Aw⊩A 或 w⊩Bw\Vdash Bw⊩B。
  • w⊩A→Bw\Vdash A\to Bw⊩A→B：每个 w′≥ww'\ge ww′≥w，只要 w′⊩Aw'\Vdash Aw′⊩A，就 w′⊩Bw'\Vdash Bw′⊩B。
  • w⊩¬Aw\Vdash\neg Aw⊩¬A：没有任何 w′≥ww'\ge ww′≥w 使 w′⊩Aw'\Vdash Aw′⊩A。

Intuitionistic natural deduction 对这个 semantics 是 sound 的：可证的 formula 在每个 Kripke model 的每个 world 上都成立。所以只要找一个 world 让 p∨¬pp\lor\neg pp∨¬p 不成立，它就证不出来。

Gallina：一个不会出错的 programming language

Coq 里写 program 的 language 叫 Gallina。它是 pure 的（没有 side effect：不打印、不改变量、不抛 exception）和 total 的（每个 function 都必须 terminate）。Total 是必需的：按第 4 站的对应，一个 program 就是一个 proof，一个永不返回的“proof”可以有任何 type，会证出任何东西。

Natural number 按 Peano 的方式定义，只有两个 constructor：

Inductive nat : Type :=
  O : nat
| S : nat -> nat.

3 写作 S (S (S O))。Danvy 的讲义第一周就问了这个 representation 的两个性质：用 O 和 S 造出来的每个值都表示一个 natural number（sound），每个 natural number 都能这样造出来（complete）。

Function 按 constructor 分情况写，递归调用只能作用在更小的 argument 上，这样 Coq 能自动确认它 terminate：

Fixpoint add (i j : nat) : nat :=
  match i with
    O => j
  | S i' => S (add i' j)
  end.

Compute (add 2 3). 得到 5。

Unit test 能说明什么

Danvy 的讲义每写一个 function 先写 unit test，而且 test 本身是一个以“候选 function”为参数的 function：

Definition test_add (candidate : nat -> nat -> nat) : bool :=
  (Nat.eqb (candidate 0 0) 0) &&
  (Nat.eqb (candidate 0 5) 5) &&
  (Nat.eqb (candidate 2 3) 5) &&
  (Nat.eqb (candidate 7 0) 7).

Compute (test_add add).

这样同一组 test 可以跑在不同的 implementation 上。可是开头第一件事里那个“第一个 argument 超过 7 就返回 0”的 function 也通过这四个 test。用第 1 站的说法：test 失败一定说明 function 错了（失败是 sound 的），test 通过却不说明 function 对。要说“对所有 input 都对”，需要一个关于所有 input 的 statement，以及它的 proof。

Specification：一个关于 function 的 Prop

“加法应该满足什么”写成一个 proposition，它的参数是一个 function：

Definition recursive_specification_of_addition (add : nat -> nat -> nat) :=
  (forall y : nat, add O y = y)
  /\
  (forall x' y : nat, add (S x') y = S (add x' y)).

Prop 是 Coq 里 proposition 的 type。按 Curry–Howard，证明 recursive_specification_of_addition add 就是造出一个这个 type 的 term。

写了 specification，就有三个要问的问题，每个都对应一个 theorem：

  1. 有没有 function 满足它？ 证明某个 implementation 满足它。没有的话，这个 specification 是 vacuous 的。
  2. 满足它的 function 是不是只有一个？ 证明任意两个满足它的 function 在所有 input 上相等。不是的话，它是 ambiguous 的。
  3. 满足它的 function 对不对？ 这要拿别的已知事实去比。

Tactic：一步一步造 proof term

直接写 proof term 很快就写不动了。Coq 里的 proof 是交互式的：屏幕上显示当前的 goal（横线下面）和可用的 hypothesis（横线上面），每个 tactic 把 goal 变成更简单的 goal，Coq 在背后拼出 proof term。

最常用的几个：

intro x goal 是 forall x, P 或 A -> B 时，把 x 或 A 移到 hypothesis ∀\forall∀i、→\to→i

Resident 的 Nat.add 满足上面的 specification：

Theorem Nat_add_satisfies_the_recursive_specification_of_addition :
  recursive_specification_of_addition Nat.add.
Proof.
  unfold recursive_specification_of_addition.
  split.
  - intro y.
    exact (Nat.add_0_l y).
  - intros x' y.
    exact (Nat.add_succ_l x' y).
Qed.

  apply H.           (* goal : A \/ ~ A *)

  left.
  exact a.

按定义算不下去的地方

add 按第一个 argument 递归。0 + n = n 按定义一步就出来：reflexivity。可是 n + 0 = n 呢？n 是一个不知道是 O 还是 S 的 variable，match n with 选不了分支，simpl 算不动。

对 n 分情况（destruct n）：n = O 时 goal 是 0 + 0 = 0，算得出来；n = S n' 时 goal 是 S n' + 0 = S n'，算一步得 S (n' + 0) = S n'，又卡在 n' + 0 上，和原来是同一个问题。再分情况还是一样，永远分不完。

需要的是一条 rule：处理 S n' 的情况时，可以假定 n' 的情况已经成立。

Peano 的 induction principle

定义 nat 时，Coq 自动生成一个 theorem：

nat_ind : forall P : nat -> Prop,
  P 0 ->
  (forall n : nat, P n -> P (S n)) ->
  forall n : nat, P n

这就是 Peano axioms 里的 induction axiom，在 Coq 里它是一个可以直接用的 term。P 0 是 base case，forall n, P n -> P (S n) 是 induction step，其中的 P n 是 induction hypothesis。它为什么对：每个 natural number 都是从 O 开始用 S 一次次造出来的，base case 给出 P O，step 用一次就把 P 沿着 S 往前推一格，推 nnn 次就到达 nnn。

induction n as [| n' IHn'] 就是 apply nat_ind，然后给 step 里的 variable 和 hypothesis 起名。

在 step 里，simpl 用 add 的第二条 equation 把 S n' + 0 算成 S (n' + 0)；这正好露出了 IHn' 的左边 n' + 0，rewrite -> IHn' 把它换成 n'，剩下 S n' = S n'。

Danvy 的讲义用同样的方法证明 specification 的唯一性。前面问的第 2 个问题，“满足 recursive_specification_of_addition 的 function 至多一个”：

Proposition there_is_at_most_one_recursive_addition :
  forall add1 add2 : nat -> nat -> nat,
    recursive_specification_of_addition add1 ->
    recursive_specification_of_addition add2 ->
    forall x y : nat, add1 x y = add2 x y.
Proof.
  intros add1 add2.
  unfold recursive_specification_of_addition.
  intros [H_add1_O H_add1_S] [H_add2_O H_add2_S].
  intro x.
  induction x as [ | x' IHx'].
  - intro y.
    rewrite -> (H_add2_O y).
    exact (H_add1_O y).
  - intro y.
    rewrite -> (H_add1_S x' y).
    rewrite -> (H_add2_S x' y).
    rewrite -> (IHx' y).
    reflexivity.
Qed.

Step 里 goal 是 add1 (S x') y = add2 (S x') y。两次 rewrite 把它变成 S (add1 x' y) = S (add2 x' y)，再用 IHx' y 把左边的 add1 x' y 换成 add2 x' y。

注意 intro y 写在 induction 之后。这样 IHx' 是 forall y, add1 x' y = add2 x' y，对任何 y 都能用。下一小节会看到这一点什么时候是关键。

Accumulator：induction hypothesis 不够用了

另一种写加法的方式，把“还要加的 1”在调用时就加到第二个 argument 上：

Fixpoint add_acc (n a : nat) : nat :=
  match n with
    O => a
  | S n' => add_acc n' (S a)
  end.

第二个 argument a 叫 accumulator。每次递归调用都是 tail call，返回时什么也不用做。想证明 forall n, add_acc n 0 = n。

直接对 n 做 induction。Step 里 goal 是 add_acc (S n') 0 = S n'，按定义算一步得

add_acc n' 1 = S n'

而 induction hypothesis 是 add_acc n' 0 = n'。Goal 里 accumulator 是 1，hypothesis 里是 0，用不上。图里看得很清楚：从第二步起 accumulator 就不再是 0 了，一个只谈 accumulator 为 0 的 statement 跟不上计算。

办法是先证一个对所有 accumulator 都成立的 statement：

Lemma about_add_acc : forall n a : nat, add_acc n a = n + a.

对 n 做 induction，并且 a 在 induction 之后才 intro，这样 hypothesis 是 forall a, add_acc n' a = n' + a。Step 的 goal 是 add_acc (S n') a = S n' + a。左边算一步是 add_acc n' (S a)；用 hypothesis 时把 a 取成 S a，得 n' + S a。右边按 add 的定义是 S (n' + a)。剩下 n' + S a = S (n' + a)，是库里的 Nat.add_succ_r。原来的目标是 a=0a=0a=0 的特例：add_acc n 0 = n + 0 = n。

Danvy 把这种为了让 induction 过得去而推广出来的 lemma 叫 Eureka lemma。讲义第八周把它写成“reset the accumulator”的统一形式：add_acc n a = add_acc n 0 + a，power_acc x n a = power_acc x n 1 * a。也就是：从任意 accumulator 开始算，等于从初始值开始算，再把 accumulator 合并进去。

看起来对，其实不对先 intros n a 再 induction n，效果一样

intros n a 把 a 固定成一个具体的、不知道是什么的数，induction n 生成的 hypothesis 就是 add_acc n' a = n' + a，只对这一个 a。Step 里需要的是 add_acc n' (S a)，accumulator 是 S a，和 hypothesis 里的 a 不同，又卡住了。Danvy 讲义在 specification 唯一性的 proof 后面专门提醒：intro x 之后再在每个 case 里 intro y，得到的 induction hypothesis 比 intros x y 强。

Fold-unfold lemma

simpl 有时把一个递归 function 展开成一大团 fix 表达式，或者在不想展开的地方也展开。Danvy 的讲义改为对每个递归 function 证两条 lemma，正好是它定义里的两条 equation，以后只用 rewrite 来展开或收起一次调用：

Lemma fold_unfold_power_acc_O :
  forall x a : nat, power_acc x 0 a = a.

Loop 执行多少次事先不知道，不能一条条往上推。要找一个 assertion III，每执行一次 body 都保持它：

Program 就是一组 Horn clause

Prolog 程序由 fact 和 rule 组成：

f(a).  f(b).
g(a).  g(b).
h(b).

k(X) :- f(X), g(X), h(X). 读作 ∀X (f(X)∧g(X)∧h(X)→k(X))\forall X\,(f(X)\land g(X)\land h(X)\to k(X))∀X(f(X)∧g(X)∧h(X)→k(X))，写成 clause 是 {¬f(X),¬g(X),¬h(X),k(X)}\{\neg f(X),\neg g(X),\neg h(X),k(X)\}{¬f(X),¬g(X),¬h(X),k(X)}，只有一个 positive literal，正是第 2 站的 Horn clause。Fact 是没有 body 的 rule。

Unification

Resolution 要消掉 k(Y)k(Y)k(Y) 和 ¬k(X)\neg k(X)¬k(X)，它们不是同一个 literal，要先找一个替换让两边一样，这叫 unification。规则：

  1. 两个 constant 相同才 unify。
  2. 一个 variable 和任何 term unify，把 variable 换成那个 term。
  3. 两个 compound term 要 functor 和 argument 个数都相同，然后逐个 argument unify，而且各处得到的替换要相容。

例子：k(s(g), Y) = k(X, t(k)) 得 X = s(g)、Y = t(k)。loves(X, X) = loves(marsellus, mia) 失败：第一个 argument 给出 X = marsellus，第二个 argument 就要求 marsellus = mia。

Search：从上到下，从左到右，失败就回头

一个 goal 可能和好几个 clause 的 head unify。Prolog 的选择是固定的：clause 按程序里从上到下的顺序试；rule body 里的 goal 从左到右解；一条路失败了，回到最近一个还有别的 clause 可试的地方（choice point），撤销那之后做的替换，试下一个。这叫 backtracking。

第一步把 rule 里的 X 改名为一个新的 variable V，因为每次使用 rule 都要用一份全新的 variable，否则不同次调用之间的 X 会互相干扰。h(a) 失败时，最近的 choice point 是 f(V)（还有 f(b) 没试）；g(a) 那里只有一个 clause 可用，不是 choice point。

逻辑相同，执行不同

child(martha, charlotte).
child(charlotte, caroline).
child(caroline, laura).
child(laura, rose).

descend(X, Y) :- child(X, Y).
descend(X, Y) :- child(X, Z), descend(Z, Y).

问 ?- descend(martha, rose).：第一条 rule 要 child(martha, rose)，失败；第二条 rule 先找 child(martha, Z)，得 Z = charlotte，再问 descend(charlotte, rose)，一路往下，到 child(laura, rose) 成功。

把两条 rule 的顺序对调，并把第二条 rule 的 body 里两个 goal 对调：

descend(X, Y) :- descend(Z, Y), child(X, Z).
descend(X, Y) :- child(X, Y).

作为 logic，这两个程序是同一组 formula（conjunction 和 clause 的顺序都不影响真假）。作为 program，第二个不 terminate。

看起来对，其实不对只要每条 rule 在逻辑上都对，Prolog 就能找到答案

右边那个程序的每条 rule 都是对“descendant”的正确描述，descend(martha, rose) 也确实是它的 logical consequence。可 Prolog 总是先试第一条 rule、先解最左边的 goal，而那个 goal 和 head 形状一样、argument 没有变小：descend(martha, rose) 变成 descend(W1, rose), child(martha, W1)，descend(W1, rose) 又变成 descend(W2, rose), child(W1, W2)，每一步都多一个 goal，最后 out of stack。Prolog 的 search 是 depth-first 的，它对 logical consequence 不 complete；写程序时要同时考虑 declarative meaning（它说了什么）和 procedural meaning（它按什么顺序找）。
