概念线

排成一列

Thread 抢一个 counter、两个 core 的 cache、两份 ledger、GPU 里的 producer 和 consumer、八块卡上的 model：问的都是这些 operation 能不能排成一列；OS、hardware、network、blockchain 各课换的是谁来排、靠什么排、怎样让每份副本排出同一列。

Alice 的 account 里有 5 块钱，她同时发出两个 withdraw(5)。每个 withdraw 只碰 bal 两次：

void withdraw(int amt) {
    int b = bal;            /* R：读 balance */
    if (b >= amt) {
        bal = b - amt;      /* W：写回 */
        dispense(amt);
    }
}

单独看这段 code 是对的：执行前 bal≥0\text{bal}\ge0bal≥0 且 bal+paid=5\text{bal}+\text{paid}=5bal+paid=5，执行后仍然成立。两个 withdraw 一个接一个执行，第一个付出 5、bal 变成 0，第二个读到 0，什么也不做。

第一处。 两个 thread 各执行一个 withdraw，bal 是共享的 global variable。顺序是 T1 读、T2 读、T1 写、T2 写时，两个都读到 5，都通过检查，都付出 5，bal 是 0。一共付出 10。

第二处。 没有 bank，ledger 有两份：一份在 Bob 收款用的 node 上，一份在 Carol 的 node 上。Alice 签了两笔 transaction，用同一个 coin c 分别付给 Bob 和 Carol。每个 node 先检查“c 在我这份 ledger 上还没花”（R），通过后把它标成 spent（W），再把这件事告诉对方。两边的 R 都发生在对方的消息到达之前，两笔都被收下。这是 IS4302 第 1 站的 double spending。

两处的错是同一个：每个 operation 自己是对的，step 一交错，就出现了任何“一个接一个”的执行都不会出现的结果。各门课里的 race condition、lost update、coherence、memory consistency、double spend、consensus，问的都是：怎样保证执行的结果和把 operation 排成一列、一个一个做的结果相同；有多份副本时，怎样让每一份排出同一列。下面先把这件事推一遍，再逐门课看谁在排、靠什么排。

骨架：能不能排成一列

一次执行是 progress graph 上的一条路

把每个 operation 拆成 step。一个 step 是 machine 保证不可分割的最小动作：一次 load、一次 store、一条 atomic instruction、一个 node 处理一条消息。T1 的 step 是 R1,W1R_1,W_1R1​,W1​，T2 的是 R2,W2R_2,W_2R2​,W2​。一次 concurrent execution 就是把两串 step 合成一串，各自内部的先后不变，叫一个 interleaving。

画成图：横轴是 T1 走过的 step，纵轴是 T2 的。点 (i,j)(i,j)(i,j) 表示 T1 做完了 iii 步、T2 做完了 jjj 步，每一步向右（T1 走）或向上（T2 走）。一个 interleaving 就是从 (0,0)(0,0)(0,0) 到 (2,2)(2,2)(2,2) 的一条只向右、向上的路。CMU 15-213 把这种图叫 progress graph，路叫 trajectory。4 步里选 2 步给 T1，一共 (42)=6\binom42=6(24​)=6 条路，逐条执行：

(1,1)(1,1)(1,1) 是“两人都读过、都还没写”。经过它的 4 条全错，不经过的 2 条正是两个 serial order。CS2106 第 3 站的 counter = counter + 1 是三步（load、add、store），两个 thread 有 (63)=20\binom63=20(36​)=20 条路；中间 4 个点都表示“两人都 load 过、都还没 store”，绕开它们只有沿边走的 2 条，其余 18 条都把 50 变成 51（程序枚举过）。CMU 15-213 把这些点叫 unsafe region，并且说：一条 trajectory 正确，当且仅当它不进 unsafe region。

正确的标准：和一个 serial order 等价

为什么偏偏要求“和某个 serial order 的结果相同”？因为写 code 的人只能对单个 operation 做证明。withdraw 的证明是：执行前 invariant bal≥0, bal+paid=5\text{bal}\ge0,\ \text{bal}+\text{paid}=5bal≥0, bal+paid=5 成立，执行完一个 withdraw 后仍成立。如果一次执行和 serial order o1,o2,…,omo_1,o_2,\dots,o_mo1​,o2​,…,om​ 的结果相同，对 kkk 做 induction：开始时 invariant 成立；oko_kok​ 看到的正是 ok−1o_{k-1}ok−1​ 留下的 state，invariant 成立，oko_kok​ 保持它；所以最后仍成立。不等价的执行里，oko_kok​ 看到的 state 可能是任何 serial 执行里都不出现的半成品：R1 R2 之后 T2 看到的“还有 5”，是 T1 已经决定付钱以后的 state。对单个 operation 的证明在这里用不上。

“结果相同”要说得能检查。两个 step conflict，指它们属于不同的 operation、访问同一个 item，而且至少一个是 write。Bernstein、Hadzilacos、Goodman 的 database 教材定义：两个 interleaving equivalent，如果它们把每一对 conflicting step 排成同样的先后。这个定义够用，理由有两条（设每个 operation 是 deterministic 的）：

  • 一个 read 返回它之前最后一次 write 这个 item 的值。别的 operation 对同一个 item 的 write 都和这个 read conflict，它们在 read 之前还是之后，两个 equivalent 的 interleaving 一样；同一个 operation 自己的 write 和 read 由 program order 固定，也一样。所以每个 read 读到同一个值，每个 operation 走同样的 branch、写同样的值。
  • 每个 item 最后的值来自最后一次 write 它的 step。同一个 item 上不同 operation 的 write 两两 conflict，先后一样，最后一个是同一个。

和某个 serial order equivalent 的 interleaving 叫 serializable。

Serialization graph：没有 cycle 就能排成一列

检查 serializable，不必把 m!m!m! 个 serial order 一个个试。给 interleaving HHH 画一张 graph SG(H)SG(H)SG(H)：每个 operation 一个 node；TiT_iTi​ 的某个 step 在 HHH 里排在 TjT_jTj​ 的某个 conflicting step 之前，就画 edge Ti→TjT_i\to T_jTi​→Tj​。

Lemma. 有限的 directed graph 没有 cycle，当且仅当能给 node 编号，使每条 edge 都从小号指向大号。

Proof. 有这样的编号时，cycle T1→T2→⋯→T1T_1\to T_2\to\cdots\to T_1T1​→T2​→⋯→T1​ 会给出 n(T1)<n(T2)<⋯<n(T1)n(T_1)<n(T_2)<\cdots<n(T_1)n(T1​)<n(T2​)<⋯<n(T1​)，不可能。反过来，没有 cycle 时一定有一个 node 没有 incoming edge：否则从任一 node 出发沿 incoming edge 往回走，走 mmm 步经过 m+1m+1m+1 个 node，必有一个重复，就是一个 cycle。给这个 node 编 1，删掉它，剩下的 graph 仍然没有 cycle，重复下去。这就是 topological sort。

Theorem（Serializability Theorem）. HHH serializable 当且仅当 SG(H)SG(H)SG(H) 没有 cycle。

Proof. “当”：按 lemma 的编号把 operation 排成 serial order SSS。任一对 conflicting step，HHH 里 TiT_iTi​ 的在前，就有 edge Ti→TjT_i\to T_jTi​→Tj​，TiT_iTi​ 的编号小，SSS 里 TiT_iTi​ 整个在前。SSS 和 HHH 把每一对 conflicting step 排得一样，equivalent。

“仅当”：设 HHH equivalent 于 serial order SSS。每条 edge Ti→TjT_i\to T_jTi​→Tj​ 来自一对 conflicting step，HHH 里 TiT_iTi​ 的在前，SSS 里也在前；serial order 里 TiT_iTi​ 的一个 step 在 TjT_jTj​ 的一个 step 之前，就是整个 TiT_iTi​ 在 TjT_jTj​ 之前。于是 SSS 里的位置就是一个让每条 edge 朝前的编号，按 lemma 没有 cycle。

拿 withdraw 核对。R1 R2 W1 W2：R2R_2R2​ 在 W1W_1W1​ 之前，edge T2→T1T_2\to T_1T2​→T1​；R1R_1R1​ 在 W2W_2W2​ 之前，edge T1→T2T_1\to T_2T1​→T2​。Cycle，不 serializable，和表里的“付出 10”一致。R1 W1 R2 W2：W1W_1W1​ 在 R2R_2R2​、W2W_2W2​ 之前，R1R_1R1​ 在 W2W_2W2​ 之前，只有 T1→T2T_1\to T_2T1​→T2​，排成 T1,T2T_1,T_2T1​,T2​。

后面每门课里出事的执行，都能指出这样一个 cycle；每一个修法，都是在保证某种编号存在。

三种办法

把一段变成一步。 Mutual exclusion 让 critical section（从 R 到 W 的那一段）在别人看来不可分割。Progress graph 上，“两人都在 critical section 里”的点围成一个矩形，unsafe 的点在它里面；lock 让任何 trajectory 都进不去这个矩形，CMU 15-213 叫它 forbidden region。进不去，就只能从矩形的左上方或右下方绕过，一人的 critical section 整个在另一人的之前，里面的 conflicting step 全部朝同一个方向，SG 里没有 cycle。TestAndSet、CAS、fetch_add 是 hardware 直接给的一步：读和写在一条 instruction 里，中间插不进别人的 step。

给 operation 编号。 Lemma 说没有 cycle 等于存在一个让每条 edge 朝前的编号，所以很多 protocol 的正确性 proof 就是指出编号是什么。BHG 第 3 章的 two-phase locking：每个 transaction 先只拿 lock、后只放 lock，放了一个之后不再拿。记 lp(T)\text{lp}(T)lp(T) 为 TTT 拿完最后一个 lock 的时刻（lock point）。若 Ti→TjT_i\to T_jTi​→Tj​，两者有一对 conflicting step 落在同一个 item 上，TiT_iTi​ 先拿这个 item 的 lock，在时刻 aaa 放掉，TjT_jTj​ 在时刻 b>ab>ab>a 拿到；TiT_iTi​ 放 lock 时已经拿完了所有 lock，lp(Ti)<a\text{lp}(T_i)<alp(Ti​)<a；TjT_jTj​ 的 lock point 不早于它拿这个 lock 的时刻，b≤lp(Tj)b\le\text{lp}(T_j)b≤lp(Tj​)。所以

lp(Ti) < a < b ≤ lp(Tj)\text{lp}(T_i)\ <\ a\ <\ b\ \le\ \text{lp}(T_j)lp(Ti​) < a < b ≤ lp(Tj​)

编号就是 lock point，cycle 会给出 lp(T1)<⋯<lp(T1)\text{lp}(T_1)<\cdots<\text{lp}(T_1)lp(T1​)<⋯<lp(T1​)。编号也可以事先发好写在 operation 上：后面的 nonce、sequence number、Raft 的 term 都是这样。

让顺序无所谓。 每个 operation 只有一步（atomic），而且任意两个 operation 谁先结果都一样（commute），那么每个 interleaving 都是 serial 的，所有 serial order 又给出同一个结果，连“是哪一列”都不必约定。两个 fetch_add(&counter, 1) 无论先后都得 52。

看起来对，其实不对每次访问 bal 都加了 lock，withdraw 就安全了

int  read_bal(void)   { lock(&L); int b = bal; unlock(&L); return b; }
void write_bal(int b) { lock(&L); bal = b;     unlock(&L); }

R1 R2 W1 W2 照样会发生：每个 R、每个 W 各自不可分割，可 T1 在 R 和 W 之间放掉了 L，T2 的 R 插了进来，SG 还是那个 cycle。Lock 要罩住一个 operation 里所有 conflicting 的 step；按 two-phase locking 的说法，T1 放掉 L 之后又去拿 L，违反了“放了之后不再拿”。

有副本时：每份都按同一列执行

一块 memory 上，step 的先后由 memory 自己决定，只有一列。有副本时，每份副本各自执行，各有一列。Schneider 的 state machine approach 把要求写成：每个 replica 是一个 deterministic 的 state machine，output 只由它处理过的 request 序列决定；Replica Coordination 要求每个 non-faulty replica 收到每个 request（Agreement），并且按同样的相对顺序处理（Order）。两条都满足时，所有 replica 从同一个 initial state 出发，对同一串 command 一步步做下去，按 induction 每一步之后都相同。

开头第二处坏在 Order：Bob 的 node 先处理付给 Bob 的那笔，Carol 的 node 先处理付给 Carol 的那笔，两份 ledger 各自是一个合法的 serial order，但不是同一个。

这一列从哪里来，各课只有两种答案。

  • 一个 serialization point。 所有 request 都经过同一个地方，它看到的先后就是 order：IS4302 的 Scrooge、CS149 的 bus 和 directory、Raft 的 leader、ring all-reduce 里负责一段的那条路。代价是这个地方要被信任，而且要一直在。
  • Quorum。 没有可以信任的单点，就要求每个决定拿到 QQQ 个 node 的同意，并让任意两个 quorum 的重叠里至少有一个不会同意两次的 node。

QQQ 要多大，用数票推。nnn 个 node，honest 的 node 在同一个位置（同一个 height、同一个 term）上最多同意一次，至多 fff 个作恶的 node 可以同意任意多次。设这个位置上有 mmm 个互相冲突的决定都拿到了 QQQ 票。把所有票加起来，左边按决定数，右边按 node 数：

mQ ≤ (n−f)⋅1+f⋅m⟹m ≤ n−fQ−fmQ\ \le\ (n-f)\cdot1+f\cdot m\qquad\Longrightarrow\qquad m\ \le\ \frac{n-f}{Q-f}mQ ≤ (n−f)⋅1+f⋅m⟹m ≤ Q−fn−f​

要 m≤1m\le1m≤1，需要 n−fQ−f<2\frac{n-f}{Q-f}<2Q−fn−f​<2，即 2Q>n+f2Q>n+f2Q>n+f。另一方面作恶的 fff 个可以不投票，剩下的必须凑得够，Q≤n−fQ\le n-fQ≤n−f。两条合起来 2(n−f)>n+f2(n-f)>n+f2(n−f)>n+f，n≥3f+1n\ge3f+1n≥3f+1，这是 IS4302 第 3 站的结论。只会 crash、不会作恶时，没有 node 同意两次，第一条取 f=0f=0f=0 得 2Q>n2Q>n2Q>n，就是 majority；crash 的 fff 个不投票，仍要 Q≤n−fQ\le n-fQ≤n−f，得 n≥2f+1n\ge2f+1n≥2f+1。Raft 是这一种：每个 server 每个 term 最多投一票，拿到 majority 才当 leader，所以每个 term 最多一个 leader。

边界情况Serializable 不管真实时间

Serializable 只要求存在某个 serial order：T1 在 T2 开始之前就已经结束，排成 T2、T1 也算。对一个共享的 object（一个 register、一个 queue），通常还要求这一列不违背真实时间：已经结束的 operation 排在之后才开始的 operation 前面，这叫 linearizability。CS149 的 coherence 定义只要求保持每个 processor 的 program order，没有提真实时间。

CS2106 与 CS2030：一块 memory 上的一列

CS2106 第 3 站的结论，逐条换成骨架里的话：

  • counter = counter + 1 丢掉一次加法：20 条路里 18 条进了 unsafe region，SG 是 T1⇄T2T_1\rightleftarrows T_2T1​⇄T2​。
  • Flag lock 失败：lock() 本身就是一个 check-then-act，“读 flag”和“写 flag”两步，两个 lock() 自己就能走出 R1 R2 W1 W2 那种路。CS2106 表里的 6 步正是一条经过 (1,1)(1,1)(1,1) 的路：Thread 1 读到 0，Thread 2 读到 0，Thread 2 写 1，Thread 1 写 1。
  • Peterson 的 proof 里“turn 只有一个值，看谁最后写的”：两人对 turn 的写在 memory 上有一个先后，它是一个 serialization point，proof 用它决定谁让谁。下面 CS149 一节会看到，这个 proof 还暗中用了另一个 order。
  • TestAndSet 把读和写合成一条 instruction，是“把一段变成一步”的 hardware 版本。

CS2030：不共享就没有 edge。 CS2030 第 8 站说 race condition 要两个条件：多个 thread 共享一个 state，而且这个 state 会被改。这正是 conflict 定义的后两条：同一个 item，至少一个是 write。CS2030 的办法是不共享 mutable state，lambda 写成第 5 站意义上的 pure function：没有 conflicting step，SG 里一条 edge 都没有，任何 interleaving 都 serializable。forEach(x -> result.add(x)) 出错（6 次里 2 次少了元素，40861 和 26205），是因为 ArrayList.add 要读出 size、写进 element、写回 size + 1，又是一次 check-then-act。

reduce 走的是“让顺序无所谓”那条路，只是要无所谓的对象换成了括号。Parallel 时各段从 identity 开始，再两两合并，括号怎么加由 thread 的快慢决定。Associativity 保证每一种括号结果相同；identity 保证每段多出来的那个 identity 不改变结果。减法不 associative，sequential 得 −10-10−10，parallel 得 0。后面 data parallel 一节会看到，float 的加法也不 associative。

CompletableFuture 的 dependency 是一张事先画好的 graph：A 指向 B、C、D，B 和 C 指向 E。Pool 里的 thread 任意抢 task，但每个 task 要等所有指向它的 task 完成才开始，所以实际的执行顺序总是这张 graph 的一个 topological order。这张 graph 也必须没有 cycle：两个 future 互相等对方的结果，就是 deadlock。CS2030 那次运行里 B、C、D 都在 300 ms 开始，谁先谁后无所谓，因为它们之间没有 edge。

STANFORD-CS149：hardware 给出的一列

Coherence 是每个 address 各排一列

CS149 第 6 站的 coherence 定义是：对每一个 address，存在所有 processor 对它的 operation 的一个 serial order，每个 processor 自己的 operation 在其中保持 program order，每次 read 返回这个 order 里它之前最后一次 write 的值。这就是骨架里的 serializable，缩小了两处：item 只有一个 address，operation 只是一次 load 或 store。

SWMR（任何时刻一个 address 要么只有一个 processor 能读写，要么有多个 processor 只读）是给每条 cache line 配一把 readers-writer lock：

MSI 换成 lock 的说法
M 拿着 write lock，memory 里的值是旧的
S 拿着 read lock，可以有好几个人同时拿
I 什么都没拿
BusRdX 申请 write lock，其他人的 read lock 全部收回（invalidate）
别人的 BusRd 让 M 降到 S write lock 换成 read lock，先把改过的值交出来

Bus 或 directory 是这把 lock 的 serialization point：两个 BusRdX 同时发出，bus 一次只放一个上去，先上去的先拿到 M。

这张表直接解释 CS149 第 7 站的 lock 为什么慢。Test-and-set 是一次 write，执行一次就要拿一次这条 line 的 write lock；P−1P-1P−1 个等着的 thread 不停执行它，就是不停收回彼此的 write lock，line 在 cache 之间来回搬。Test-and-test-and-set 等待时只读，大家都拿着 read lock，没有 traffic。在一把 lock 上 spin，在 hardware 里是在另一把 lock 上排队。

DRF 为什么让一般的 program 不必管这些。 CS149 说 data-race-free 的 program 在 relaxed 的 hardware 上表现得和 SC 一样。用 SG 的话说：data race 是一对没有被 synchronization 排好先后的 conflicting access；DRF 的 program 里，每一对 conflicting access 之间都隔着同一把 lock 的 unlock 和 lock，而 library 的 lock 里放好了 fence。于是每条 conflict edge 都和“这把 lock 被谁先拿到”同向，lock 被拿到的先后是一列，edge 合起来不会有 cycle。Peterson 自己就是在实现 lock，处在这个保证的下面一层，所以 fence 要自己放。

GPU：block 不能等 block

IS4302：没有共享的 memory 时，谁来排

Double spend 是 SG 里的 cycle。 开头第二处，tx1 和 tx2 都花 coin c，各自读“c 还没花”、写“c 已 spent”。Bob 的 node 上 tx1 先，Carol 的 node 上 tx2 先，合起来两个 R 都在两个 W 之前，tx1⇄tx2\text{tx}_1\rightleftarrows\text{tx}_2tx1​⇄tx2​。IS4302 第 1 站从 GoofyCoin 走到 ScroogeCoin，就是加了一个 serialization point：所有 transaction 都由 Scrooge 一个人检查、记账，“检查尚未花掉，再记下”在他那里是一步。Nakamoto 论文那句“确认一笔 transaction 没有发生过的唯一办法是知道所有 transaction”，换成这里的话：一个 node 只看自己那份副本的一列，看不出另一份副本里有没有冲突的 W。

UTXO 的 conflict 是精确的。 IS4302 第 4 站的 UTXO model 里，一笔 transaction 读写的 item 就是它的 input 指向的那几个 output。两笔 transaction conflict，当且仅当它们花同一个 output；不 conflict 的 transaction 之间 SG 没有 edge，按什么顺序验证都行，这就是 IS4302 对比表里的“不碰同一个 output 的 transaction 互不影响”。Account model 里，同一个 account 的每笔 transaction 都读写同一个 balance 和 nonce，两两 conflict，必须排成一列，nonce 就是事先发好的号：lemma 里的编号直接写在 transaction 上。

Longest chain 给出一列会变的 order。 IS4302 第 2 站的 chain 就是全网约定的那一列 transaction。Fork 时两条 branch 各是一列，longest chain rule 选其中一列。Private attack 成功，意味着约定的那一列改了：tx1 从 chain 上消失，冲突的 tx2 占了它的位置。IS4302 算出 q=0.3q=0.3q=0.3、等 6 个 confirmation 时这件事的 probability 是 13.2%。Nakamoto consensus 给的是一列以越来越高的 probability 不再变的 order，没有哪个时刻之后它保证不变，这就是 IS4302 说的没有 finality。

Proof of stake 的 finality 就是骨架里的数票。 IS4302 第 3 站的 validator 在每个 epoch 只签一个 block，签两个会被 slashing，这就是“honest 的 node 在同一个位置最多同意一次”。Quorum 图第三行就是 IS4302 的 n=9n=9n=9、Q=6Q=6Q=6。Slashing 多给了一样东西：一旦 m=2m=2m=2，数票时多出来的那些票一定来自签了两次的 validator，两个 signature 本身就是证据。

Reentrancy 是没有 thread 的 race。 IS4302 第 5 站的 withdrawAll 先读 amount、转钱，最后才写 balances[msg.sender] = 0。转钱把控制权交给 attacker 的 receive()，它再调一次 withdrawAll。外层是 T1T_1T1​，里层是 T2T_2T2​：R1R_1R1​（读到 75）、R2R_2R2​（也读到 75）、W2W_2W2​、W1W_1W1​，正是骨架那张 progress graph 上经过 (1,1)(1,1)(1,1) 的 R1 R2 W2 W1，SG 是同一个 cycle。IS4302 的例子嵌套了 5 层，每一层都夹在外面各层的 R 和 W 之间，Bank 付出 375。

EVM 只有一个 thread，interleaving 只可能发生在 external call 处。这有两个推论。第一，checks-effects-interactions 把 W 挪到 external call 之前，R 和 W 之间不再有交错的机会，这段 check-then-act 自动不可分割。第二，IS4302 提到的另一个修法“加一个锁”，就是 CS2106 那个会失败的 flag lock：

bool locked;
modifier noReentry() {
    require(!locked);   // 读 flag
    locked = true;      // 写 flag
    _;
    locked = false;
}

require(!locked) 和 locked = true 之间没有 external call，没有人插得进来，这个 flag lock 在 EVM 里是对的。CS2106 里它错，是因为 timer interrupt 能落在任意两条 instruction 之间。同一段 code 对不对，取决于交错可能发生在哪里。

看起来对，其实不对只有多个 thread 才会有 race condition

Reentrancy 只有一个 thread，照样走出 R1 R2 W2 W1。Race 要的是两个 operation 的 step 交错，交错可以来自 thread 调度，也可以来自一次把控制权交出去的 call。判断一段 check-then-act 安不安全，先找出它中间所有可能交出控制权的地方：CS2106 是每两条 instruction 之间，EVM 是每个 external call。

CMU-10714 与 STANFORD-CS336：data parallel 是 state machine replication

CMU-10714 第 7 站的 data parallel：每个 worker 一份完整的 model，各对 B/PB/PB/P 个 sample 算 gradient，allreduce 求和，再各自做同样的 optimizer step。按 Schneider 的两条看：state 是 parameter 和 optimizer state，command 是“用这个 gradient 做一步”，Agreement 是每个 worker 都拿到这一步的 gradient，Order 是大家一步一步按同样的顺序做，optimizer step 是 deterministic 的。所以 PPP 份 replica 始终相同，任何一份都可以拿去存 checkpoint。

这要求 allreduce 给每个 worker 的结果 bitwise 相同。CS2030 的 reduce 已经提醒过：结果和括号有关时，不同的人按不同的括号算，会得到不同的答案。Float 的加法就是这样：

看起来对，其实不对Data parallel 算出的 gradient 和一张卡上算的完全一样

CMU-10714 的论证在实数上成立：gradient 的和可以拆成每个 worker 那一份的和，再相加。Float 的和与括号有关：一张卡上 BBB 个 sample 按一种顺序加，PPP 个 worker 先各加 B/PB/PB/P 个、再 allreduce 是另一种顺序，上面的 0.1 到 0.4 换一个顺序就差了一个 ulp。Data parallel 保证的是 PPP 份 replica 彼此相同，不保证和单卡 bitwise 相同；换一个 worker 数，最后几位也会变。

Parameter server：一个 Scrooge，以及放弃 Order。 CMU-10714 的另一种写法是 parameter server：worker push gradient，server 加起来、更新 weight，worker 再 pull。Server 是 serialization point。如果 server 不等齐所有 worker，谁的 gradient 先到就先用，worker 手里的 weight 就是若干步之前的：它算 gradient 时读的是旧的 www，写回的 update 却作用在新的 www 上，和 withdraw 里读到旧的 bal 是同一个形状。Hogwild（Niu 等人 2011）连 server 也不要：多个 processor 不加 lock，直接在 shared memory 里更新同一个 parameter vector。单个 component 的加法是 atomic 的（paper 说可以用 compare-and-exchange 实现），这是“让顺序无所谓”的那一步；可一次 SGD 要改的几个 component 之间不保证不可分割，读到的 xxx 也可能是很多个 cycle 之前的。Paper 承认 processor 可能 overwrite 彼此的 progress，论证是在 sparse 的问题里每一步只碰很少几个 component，这种 overwrite 很少，带来的误差很小。这是有意放弃 serializability：允许 SG 里有 cycle，换来不用 lock 的速度，再用 sparsity 说明 cycle 少到不影响 convergence。

ZeRO：每一段只有一个 writer。 CS336 第 6 站和 CMU-15442 第 2 站的 ZeRO 让每个 rank 只负责更新 1/N1/N1/N 的 parameter：reduce-scatter 之后，这一段 gradient 的和只在它的 owner 那里，owner 用自己那份 optimizer state 更新，再 all-gather 给大家，别的 rank 拿到的只是用完就丢的只读副本。每一段 parameter 恰好一个 writer，这是 CS149 的 SWMR 换了单位：cache line 换成 shard，M 换成 owner。
