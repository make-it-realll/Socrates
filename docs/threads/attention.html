RB4301、EE4706 与 HF-LEROBOT：action 怎样去读 observation

一个 VLA 的 observation 是几百个 image token、几十个 language token 和一个 state token。Action 要从里面取出“现在该怎么动”所需的东西，这又是一次 attention。三种设计的差别全在 query 是什么、mask 怎样画。

把 action 写成 token

RB4301 第 8 站的 OpenVLA 把每个 action 的 7 个 dimension 各切成 256 个 bin，当作 7 个 token 接在 prompt 后面，用 causal mask 照常做 next-token prediction（RT-2 多一个 terminate flag，是 8 个）。Inference 时 image token 和指令一次 prefill，K、V 进 cache；之后每个 action token 是一步 decode：query 是最新的那个 token，key、value 是 cache 里的全部。一个 action 要 7 步 decode。每一步 decode 都要把 7B 的 weight 读一遍，EE4706 第 7 站按 bandwidth 算出 RTX 4090 上 bf16 的上限是每秒 72 个 token、10.3 个 action，实测 6 Hz。这一路的速度受 decode 那一节的账限制。

ACT：query 只说“第几步”

RB4301 第 7 站的 ACT 是另一种结构。论文的描述：4 个 camera 的 image 各经 ResNet18 变成 15×20×51215\times20\times51215×20×512 的 feature map，拉平成 300 个 token，加 2D sinusoidal position embedding，4 个 camera 共 1200 个，再加 joint position 和 style variable zzz，transformer encoder 的 input 是 1202×5121202\times5121202×512。Decoder 的 query 是一组固定的 position embedding，大小 k×512k\times512k×512，key 和 value 来自 encoder，cross-attention 之后经 MLP 降成 k×14k\times14k×14：接下来 kkk 步两条 arm 的 joint target。

π0 与 SmolVLA：prefix 只算一次

π0（RB4301 第 8 站）用 flow matching 一次生成 50 步的 action chunk，要做 10 步 Euler integration，每一步都要让 noisy action 去读 observation。如果每一步都把 3B 的 VLM 连同全部 prefix 重跑一遍，一个 chunk 就是 10 次完整的 forward。π0 的解法是一个 mask。论文附录：sequence 分三个 block，image 与 language prompt 一块，robot state qtq_tqt​ 一块，noisy action 一块；block 内部是 bidirectional attention，每个 block 只能看前面的 block，看不到后面的。

用 KV cache 的 claim 换一个说法就能看出后果：prefix 看不到 noisy action，所以 prefix 在每一层的 hidden state、key、value 都和 noisy action 无关，10 个 flow step 里一个数都不变，算一次存起来即可。论文对 state 单独成块的解释正是这一点：state 在 flow step 之间不变，让它看不到最后一块，它的 key 和 value 就能在 sampling 时 cache。每个 flow step 只剩 action token 过 action expert（width 1024，mlp_dim 4096，约 300M parameter），它的 query 读 cache 里 prefix 的 key、value 和 action token 自己的。两组 weight 只在 attention 里交汇：VLM 的 weight 处理 image 和 language，action expert 的 weight 处理 state 和 action，拼成同一个 sequence 做 attention。

论文在 RTX 4090 上测的时间（3 个 camera）：image encoder 14 ms，observation 的 forward 32 ms，10 次 action 的 forward 共 27 ms，on-board 合计 73 ms。EE4706 第 7 站引用 RTC 论文说 “π0 仅 KV-cache 的 prefill 在 RTX 4090 上就要 46 ms”，恰好是这里的 14 加 32。Cache 一份 prefix 也很便宜：backbone 是 18 层、num_kv_heads 为 1、head_dim 256，每个 prefix token 的 KV cache 是 2×18×1×256×2=18,4322\times18\times1\times256\times2=18{,}4322×18×1×256×2=18,432 byte，1000 个 token 才 18.4 MB。

看起来对，其实不对π0 把 image token 和 action token 放进同一个 sequence，所以每个 flow step 都要把整个 VLM 重跑一遍

放进同一个 sequence 不等于互相都能看见。Block-causal mask 让 prefix 看不到 noisy action，prefix 的 key、value 在 10 步里不变，只算一次。如果 prefix 也能看见 action，每一步 noisy action 一变，prefix 在第 1 层以上的 hidden state 全都跟着变，32 ms 的 observation forward 就得做 10 遍：14+10×(32+2.7)≈36114+10\times(32+2.7)\approx36114+10×(32+2.7)≈361 ms，而现在是 73 ms。

HF-LEROBOT 第 4 站的 SmolVLA 把同一件事拆成两种 layer：cross-attention layer 里 action token 是 query，key 和 value 来自 VLM；self-attention layer 里 action token 互相看，用 causal mask。论文在 LIBERO 上的 ablation：只用 cross-attention 79.0%，只用 self-attention 74.5%，交替 85.5%；self-attention 用 causal 74.5%，bidirectional 67.5%。那一站的图画了它的 inference：3 个 camera 时 prefix 最多 3×64+48+1=2413\times64+48+1=2413×64+48+1=241 个 token，过一遍 VLM 存成 KV cache，10 步 Euler integration 每步只过 action expert，读同一份 cache。

两个对照可以帮助记住这个设计。MIT-6.S184 第 7 站的 DiT 每个 denoising step 都要重算全部 token 的 attention，因为那里被 denoise 的就是所有 image token 本身，每一步都在变；π0 的 prefix 是 condition，不被 denoise，所以能 cache。MIT-6.S978 第 4 站的 VAR 用的是同一种 block-causal mask：同一个 scale 内部互相看见，只看见更粗的 scale，每生成一个 scale，前面的 scale 的 key、value 都可以留在 cache 里。
