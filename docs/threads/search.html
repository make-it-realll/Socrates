搜索

从 BFS、Dijkstra、A* 到 branch and bound、RRT*、MCTS 和 LLM 的 best-of-N：同一个 loop，同一个“什么时候可以停”的 proof，各门课换的是 node、bound 和 successor 的来路。

手里有一个 start state S、一个 goal test，和一个 function successors(s)：给它一个 state，它返回一步能到的 state 和这一步的 cost。要找从 S 到 goal 最便宜的 path。下面这张 graph 是 CS2109S 第 1 站用的那张。我们看得到全貌：从 S 到 G 一共六条 path，最便宜的是 S-A-C-B-G，cost 8。Algorithm 看不到。它 expand 了 S 之后，知道的只有三条长度为 1 的 path 和它们的 cost。

假设某一刻 algorithm 已经找到一条到 G 的 path，cost 是 C′C'C′。它能不能停？没见过的 path 可能非常多，每一条都是从 frontier 里某个 node 往下长出来的。要说“没有更便宜的了”，algorithm 必须对 frontier 里的每个 node 说出一个数：从它往下长出来的任何 solution，cost 至少是这么多。这些数全都不小于 C′C'C′，才能停。

BFS 和 DFS 手里没有这样的数。BFS 在这张 graph 上返回 cost 11 的 S-C-G，DFS 返回 cost 9 的 S-A-B-G，它们都没有办法知道自己不对。这条线的主角就是这个数，一个 lower bound。下面先把“有了 lower bound 怎样搜、凭什么能停”完整推一遍，它是 Dijkstra、UCS、A*、branch and bound、CBS 共用的一个 proof。然后逐门课看它换成了什么名字；在 sampling-based planning、MCTS 和 LLM 的 best-of-N 里 lower bound 拿不到了，各门课用什么顶替。最后是 CS3231 给出的边界：space 无限大时，有 lower bound 也证明不了“没有 solution”。

骨架：一个 loop，两个条件

只看得见 successor

Algorithm 保存的是 path。一条从 start 出发的 path 记成一个 node：末端的 state、parent node、到这里的 cost ggg。已经生成、还没 expand 的 node 放在 frontier 里：

def search(start, successors, is_goal, f):
    frontier = PriorityQueue()             # 每次 pop f 最小的
    frontier.push(Node(start, parent=None, g=0))
    while not frontier.empty():
        n = frontier.pop()                 # (1) priority f
        if is_goal(n.state):               # (2) pop 时做 goal test
            return n
        for s2, cost in successors(n.state):   # (3) successor
            frontier.push(Node(s2, parent=n, g=n.g + cost))
    return None

能证明“有”，不能证明“没有”。 Loop 返回 None 的唯一途径是 frontier 变空，而空的 frontier 就是“没有 solution”的 certificate：P2 说每个 solution 都从 frontier 里的 node 长出来，frontier 空了就没有 solution。Graph 有限时 frontier 迟早会空：CS2040 的 BFS 把到不了的 vertex 留在 D=−1D=-1D=−1，CS3231 第 7 站的 EDFAE_{DFA}EDFA​ 就是这样 decide 的。TM 的 ID 构成的 tree 是无限的，frontier 可以永远不空。这时 search 只给出 recognizer：有 accept 的运行就一定找到，没有就一直跑。
