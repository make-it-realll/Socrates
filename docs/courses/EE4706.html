从进度块恢复

先看三次失败。每一次，model 本身都没有错，错在它和身体、时间、旁边的人接不上。

第一次。 对一个 large language model 说“I spilled my drink, can you help?”，它会建议用 vacuum cleaner，或者叫清洁工来。这些话都合理，但面前这台 robot 没有 vacuum cleaner 这个 skill，也打不了电话。Language model 知道“该做什么”，不知道“这台 robot 此刻能做什么”。

第二次。 一个 vision-language-action model（VLA）控制一台 50 Hz 的 robot arm，每次 inference 要 100 ms，output 一个 action chunk，执行其中 25 步（0.5 s）。等 chunk 执行完再算下一个，robot 每走 0.5 s 就停 0.1 s；提前开始算、算完立刻换上，新 chunk 可能选了另一种走法，action 在切换处跳一下。

第三次。 桌上并排放着两个杯子，robot 要拿右边那个，它走了最短、最顺的直线。旁边的人看着 robot 的手朝两个杯子中间伸过去，直到很晚才看出它要哪个，伸手去拿右边的杯子，两只手撞在一起。

Subsumption：把反应放到最底下

Brooks 在 1986 年提出的 subsumption architecture 走到了另一个极端：不建中心的 world model，把系统拆成一层层 behavior，每一层自己就是一个完整的 sensor 到 actuator 的 loop。最底层是“前方 0.3 m 内有东西就停”，上面一层是“随机游走”，再上面是“朝 goal 走”。上层通过压制（suppress）下层的 input 或 output 来接管，但下层一直在跑，上层坏了，robot 至少还会避障。

拿上面的表检验：最底层只做一次 range 比较，30 ms 的 loop 很容易做到，所以 0.4 m 外的 person 能被躲开。它解决了反应的问题。

它解决不了的是需要记住进度的任务。“把桌上的空罐扔掉，再拿一块 sponge 过来”要先后做两件事，做完第一件要知道该做第二件；每一层都只看当前 sensor 的 reactive behavior 没有地方存“第一件做完了”这个 state。

三层 architecture

把两边的长处合起来，就是 robot 系统里最常见的三层分法（Gat 在 1998 年的一篇综述里把这类系统归纳成三层）。三层按时间尺度和各自存多少 state 区分：

  • Controller：每秒几十到几百次，把一个 skill 变成 motor command。几乎不存 state，延迟最小，避障和 emergency stop 放在这里。
  • Sequencer：每个 subtask 一次，决定现在执行哪个 skill、什么时候切换、skill 失败了怎么办。它存的是“做到第几步”。
  • Deliberator：秒级或更慢，做需要推理的事：把一句 instruction 拆成步骤、plan 一条路线。它存的是对世界的 model。

层与层之间传什么，是这种设计里最要紧的选择。Deliberator 交给 sequencer 的可以是一列 skill 的名字（第 4 站的 SayCan 就这么做，robot 一共只有几百个 skill），也可以是一句任意的话。前者每一步都能检查“这个 skill 存在吗”，但表达不了 skill list 之外的事；后者什么都能说，但下层必须真的理解任意一句话。

Closed-set 的 detector 找不到“the yellow sponge”

一个在 COCO 上 train 的 object detector，classification head 有 80 个 output，每个对应一个固定的 category。“sponge”不在其中，所以不管 image 里的 sponge 多清楚，它都没有办法说出来。要换成能识别 sponge 的 detector，就要重新标 data、重新 train。

Robot 收到的 instruction 是任意的文字。需要的是一个 image 和 text 能直接比较的空间：image encoder 把 image 变成 vector，text encoder 把任意一句话变成同一个空间里的 vector，两者 cosine similarity 高就说明配得上。这样，“sponge”只是另一句 text，不需要新的 output。

边界情况Negative 只来自同一个 batch

上面的 3×3 里，每张 image 只要从 3 条 caption 里认出对的那条，所以很容易。CLIP 的 batch size 是 32768，每张 image 要从 32768 条里认出一条，相近的 caption（“a white mug”和“a white cup”）更可能同时出现在 batch 里，才逼得 model 分清细节。Batch 小，contrastive learning 学到的区分就粗。

Zero-shot：classification 变成和一组 text 比

Train 完之后，classification 不需要再 train。把每个 category 写成一句 text，比如“A photo of a {label}.”，送进 text encoder，image 和每句 text 算 cosine，乘 sss 做 softmax，就是 classifier。这正是上面每一 row 的计算。

Prompt 的写法有影响：用“A photo of a {label}.”代替单独一个词，ImageNet accuracy 提高 1.3%；把 80 种 prompt 的 text embedding 平均起来再用，又提高约 3.5%。最好的 CLIP 在 ImageNet 上 zero-shot 达到 76.2%，和原版 ResNet-50 持平，而它一张 ImageNet 的 training image 都没看过。

对 robot 来说，这意味着：拿 camera 里的若干个 crop 和“a yellow sponge”比，最高的那个就是要找的东西，category list 可以随 instruction 临时写。

CLIP 给不了什么：位置、距离、数量

CLIP 论文自己列出的弱点里，对 robot 最要紧的三条是：数不清物体的个数；判断“离最近的车有多远”接近随机猜；fine-grained 的类别（车的型号、花的品种）分不好。原因在结构上：一张 image 只变成一个 vector，“sponge 在左下角、离 gripper 12 cm”这样的信息被压掉了。

Robot 需要知道东西在哪里，所以要保留空间结构的 feature。两种做法：

  • Dense feature。 给每个 pixel 一个和 text 对齐的 vector（LSeg 就是这样，第 3 站用它建 map），某个 pixel 和“sponge”的 cosine 高，那个位置就是 sponge。
  • Patch token。 Vision Transformer 把 image 切成 patch，每个 patch 一个 token，送进 language model 和文字 token 一起处理。224×224 的 image、14×14 的 patch，每边 224/14=16224/14=16224/14=16 个，一共 16×16=25616\times16=25616×16=256 个 token。

Patch token 是 VLA 的标准做法，它直接决定计算量：三个 camera 就是 3×256=7683\times256=7683×256=768 个 image token，加上 instruction 和 proprioception 的 token，每次 inference 都要先把这些全部过一遍 model（第 7 站的 prefill）。Proprioception（joint angle、gripper 开合）是低维、精确的数，通常 normalize 后经一个 linear layer 投影成一个 token，和 image token 拼在一起。

Language model 知道该做什么，不知道此刻能做什么

开头的第一次失败：“I spilled my drink”得到的是 vacuum cleaner。LLM 读过大量关于“打翻饮料怎么办”的文字，它的知识是对的；缺的是两件事：这台 robot 有哪些 skill，以及在当前这个 state 下哪个 skill 做得成。

打分，而不是生成

LLM 有两种用法。一种是让它自由生成下一步，再把生成的文字映射到最接近的 skill（SayCan 的 Generative baseline 用 sentence embedding 找最近的 skill）；另一种是给每个 skill 的描述算 likelihood，即“在 prompt 后面接上这段文字”的 probability。SayCan 用后者：output 一定落在 robot 的 skill 里，而且得到的是一个 distribution，可以和 affordance 相乘。

Prompt 写成对话的样子，例如“How would you bring me a coke can? I would: 1. find a coke can, 2. pick up the coke can, 3. bring it to you, 4. done.”。每选定一步，就把它接到 prompt 后面，再给下一步打分，直到“done”得分最高。

Closed loop：把执行结果写回去

上面最后一种失败的根源是 open loop：plan 按“每一步都成功”往下排。设每个 skill 一次成功的 probability 是 0.8，各次独立，一个 3 步的 plan 全部成功的 probability 是 0.83=0.5120.8^3=0.5120.83=0.512。

如果每步执行后有一个 success detector 判断成没成，失败就把“failed”写进 prompt，让 LLM 重新打分（多半会再选同一个 skill），每步最多试 3 次，单步失败的 probability 降到 0.23=0.0080.2^3=0.0080.23=0.008，整个 plan 的 success rate 是

(1−0.008)3=0.976(1-0.008)^3=0.976(1−0.008)3=0.976

这个数假设 detector 不出错、各次尝试独立，实际会低一些，但方向说明了为什么之后的工作都把 feedback 接回 LLM：Inner Monologue 把 success detection 和 scene description 写进 prompt；SayCan 论文自己在 limitation 里也提出用 prompting 做 correction。

SayCan 的 LLM 和 skill 是分开 train 的两个系统，接口是 551 个固定的 skill 描述。第 1 站的 π0.5 换了做法：同一个 VLA 先 output 文字 subtask，再 output action，接口是任意的一句话，没有 skill list。

这样做需要 low-level 真的听得懂各种 subtask，所以 π0.5 的 data 里专门有两类：robot episode 被人分段标上 subtask 和相关物体的 bounding box（high-level 的 training data），以及 post-training 时由人用语言一步步指挥 robot 的 verbal instruction。它的 mobile manipulator data 约 400 小时、来自约 100 个真实的 home，第一阶段的 training example 里 97.6% 来自其他来源（固定的 arm、其他 embodiment、web data）。用 104 个 location 的 data train 的 model，在没见过的 test home 里，和直接在 test home 里收 data train 的 control 表现相近。论文还有一个 high-level 的 ablation（不预测 subtask、或改用 GPT-4 做 high-level），我没有读到那一节的数字。

为什么要在想象里练

在真实 robot 上，每一条 transition 都花时间、磨损 hardware，还有安全风险（RB4301 第 1 站算过一条 transition 有多贵）。如果能从已有的 data 学一个 dynamics model，就可以在 model 里大量 rollout，train policy 时不再碰真实世界。

DreamerV3 是这条路上的代表：同时 train 三个 network，一个 world model 从 replay buffer 里的真实 data 学 dynamics，一个 critic 估计 value，一个 actor 选 action；actor 和 critic 完全在 world model 想象出来的 trajectory 上 train，每条想象 16 步。它用同一套固定的 hyperparameter 跑了 150 多个任务，在 Minecraft 里不用任何 human data 第一次挖到了 diamond。

RB4301 第 3 站讲过 learned model 用来 plan 时会被 planner 利用错误、rollout 的 error 会累积。这一站讲另一半：observation 是 image 时，model 该学在哪个空间里。

为什么不直接预测下一张 image

CS285 把从 image 学 model 的困难归成三条：维度高、冗余、partially observable。一张 64×64 的 RGB image 是 64×64×3=1228864\times64\times3=1228864×64×3=12288 个数，robot 动一下，其中大部分（背景、桌面）几乎不变；真正决定接下来发生什么的只是少数几个量（物体的位置、速度）。而单独一张 image 连速度都看不出来，state 本来就不在一帧里。

所以 model 在一个低维的 latent state 上做 dynamics：encoder 把 image 压进 latent，dynamics 在 latent 里往前推，reward 从 latent 读出。CS285 比较了 encoder 的几种选法：看整条 sequence 的 smoothing posterior 最准、最复杂，只看当前一帧的 single-step encoder 最简单、最不准。Dreamer 走中间的路：encoder 看当前一帧，再加上一个 recurrent state 记住过去。

一个 decision 的 latency 由什么组成

从 camera 曝光到 action 送进 controller，中间依次是：image 传输与 preprocessing；把所有 image token、文字 token、proprioception token 过一遍 model（prefill）；生成 action（autoregressive decoding 一个个 token，或 flow matching 的若干步 denoising）；如果 model 不在 robot 上，还有 network。RTC 论文给的一个参考：π0 仅 KV-cache 的 prefill 在 RTX 4090 上就要 46 ms，加上 network 还会更多。而 50 Hz 的 controller 每 20 ms 就要一个 action。

这几段里，prefill 主要受计算量限制（几百个 token 一起算，GPU 的 matrix multiply 能吃满）；decoding 则受另一个东西限制。

Decoding 被 memory bandwidth 卡住

Batch size 为 1 时，每生成一个 token，model 的全部 weight 都要从 memory 里读一遍，而每个 weight 只参与一次乘加。读 weight 的时间远多于算的时间，所以 token 速率的上限是

Synchronous：执行完 sss 步再开始算，robot 停 δ\deltaδ。Robot 在动的时间比例是 s/(s+d)s/(s+d)s/(s+d)。取 Δt=20\Delta t=20Δt=20 ms、s=25s=25s=25：δ=100\delta=100δ=100 ms 时 d=5d=5d=5，比例 25/30=83%25/30=83\%25/30=83%；δ=300\delta=300δ=300 ms 时 d=15d=15d=15，比例 25/40=62.5%25/40=62.5\%25/40=62.5%。停顿不只是慢：robot 每 0.5 s 停一下，dynamics 和 training data 里的连续动作不一样，state 落到了 training distribution 之外。

Naive asynchronous：提前 ddd 步开始算，算完立刻换上新 chunk，robot 不停。问题在新 chunk 是对一个新 observation 重新 sample 的，它可能选了另一个 mode（旧 chunk 从 obstacle 上方绕，新 chunk 从下方绕），切换那一步 action 跳变，acceleration 很大，同样落到 training distribution 之外。

Real-time chunking：把切换写成 inpainting
