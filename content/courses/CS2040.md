先看三件事，它们都发生在 $n=10^6$ 的时候。

**第一件。** 把 $10^6$ 个 integer 排成 sorted。Insertion sort 在随机的 input 上平均要做大约 $n^2/4=2.5\times10^{11}$ 次 comparison，merge sort 不超过 $n\log_2n\approx2\times10^7$ 次。同一件事，两种做法相差一万倍以上。

**第二件。** 在 $10^6$ 个 key 里找一个 key 在不在。Unsorted array 最坏要比 $10^6$ 次；sorted array 用 binary search 只要 20 次。可是往 sorted array 里 insert 一个新 key，平均要把一半的 element 往后挪一格，五十万次。查得快的摆法，改起来慢。

**第三件。** 把 $1,2,\dots,10^6$ 依次 insert 进一棵 binary search tree。每个新 key 都比已有的大，只能挂在最右下角，tree 的 height 是 999999，search 和扫一遍 linked list 没有区别。同样这些 key，换一种挂法，height 可以只有 19。

::fig[cs2040-chain] 同样 7 个 key，挂法不同，height 差了两倍；key 越多差得越多。

三件事是同一个道理：数据怎么摆，决定了每个 operation 要碰多少个 element。这门课里的每个 data structure 都是一条约定，要求数据始终满足某个 invariant。Invariant 让某些 operation 可以少看很多 element，代价是每次改动之后要把它修回来。所以每学一个结构都问三件事：它的 invariant 是什么；这个 invariant 让哪个 operation 变快、为什么；insert 或 delete 之后把它修回来要花多少。

| Data structure | Invariant | 换来什么 | 代价 |
|---|---|---|---|
| sorted array | $A[i-1]\le A[i]$ | binary search，$O(\log n)$ | insert 要挪动，$O(n)$ |
| hash table | key $k$ 在 slot $h(k)$，或在从那里出发的 probe sequence 上 | search、insert、delete 都是 expected $O(1)$ | 不保留任何 order |
| binary max heap | 每个 node 不小于它的 child，tree 是 complete 的 | max 就在 root | insert、extractMax 各 $O(\log n)$ |
| AVL tree | BST property，加上每个 node 两边 subtree 的 height 最多差 1 | 所有和 order 有关的 operation 都是 $O(\log n)$ | 每次 insert 最多两次 rotation |
| union-find | 每个 set 是一棵 tree，矮的挂到高的下面 | findSet、unionSet 几乎是 $O(1)$ | 顺手做 path compression |

课程的顺序是：先学会数 operation，并用 sorting 练手（第 1 站）；然后是线性的结构（第 2 站）、hash table（第 3 站）、heap（第 4 站）和 balanced BST（第 5 站）；后三站是 graph：怎么走遍它（第 6 站）、怎么用最小的 total weight 把它连起来（第 7 站）、怎么求 shortest path（第 8 站）。前五站的结构在后三站里都要用到：queue 给 BFS，stack 给 DFS，priority queue 给 Prim 和 Dijkstra，union-find 给 Kruskal。

### 数 operation，不计时

比较两个 algorithm 不能靠计时，机器和语言一换数字就变。能比的是它做了多少次基本 operation，以及这个次数怎样随 input size $n$ 增长。拿 insertion sort 来数：

```java
static void insertionSort(int[] A) {
    for (int i = 1; i < A.length; i++) {
        int x = A[i], j = i - 1;
        while (j >= 0 && A[j] > x) {   // 一次 comparison
            A[j + 1] = A[j];            // 一次 shift
            j--;
        }
        A[j + 1] = x;
    }
}
```

它的 invariant 是：第 $i$ 轮开始时，$A[0..i-1]$ 已经 sorted。这一轮把 $A[i]$ 从右往左比过去，比它大的都往右挪一格，腾出的位置放它。对 $[8,2,4,9,3]$：

| $i$ | 要放的 $x$ | comparison | shift | 这一轮之后 |
|---|---|---|---|---|
| 1 | 2 | 1 | 1 | 2 8 4 9 3 |
| 2 | 4 | 2 | 1 | 2 4 8 9 3 |
| 3 | 9 | 1 | 0 | 2 4 8 9 3 |
| 4 | 3 | 4 | 3 | 2 3 4 8 9 |

一共 8 次 comparison、5 次 shift。第 $i$ 轮最少比 1 次（$x$ 不小于左边那个），最多比 $i$ 次（$x$ 比前面的都小）。所以 comparison 的总数取决于 input：

$$\text{best case（已经 sorted）：}\ n-1,\qquad\text{worst case（倒序）：}\ 1+2+\dots+(n-1)=\frac{n(n-1)}{2}$$

$n=5$ 时是 4 和 10，上面的例子落在中间。除非另外说明，running time 指 worst case：它是对所有 input 都成立的保证。

$\frac{n(n-1)}2=\frac12n^2-\frac12n$ 里真正要紧的是 $n^2$：$n$ 翻倍，次数变成约 4 倍，$\frac12$ 和 $-\frac12n$ 都改变不了这一点。Big-O 就是把这句话说准确：

> $f(n)=O(g(n))$：存在 constant $c>0$ 和 $n_0$，使得所有 $n\ge n_0$ 都有 $f(n)\le c\cdot g(n)$。

用一次：$\frac{n(n-1)}2\le\frac12n^2$ 对所有 $n\ge1$ 成立，取 $c=\frac12$、$n_0=1$，所以 insertion sort 的 worst case 是 $O(n^2)$。再用一次：$2n^2+100n$ 也是 $O(n^2)$，因为 $n\ge100$ 时 $100n\le n^2$，于是 $2n^2+100n\le3n^2$，取 $c=3$、$n_0=100$。

按定义，$O$ 只是 upper bound，说 insertion sort 是 $O(n^3)$ 也没错，只是没有用。课上说“某个 algorithm 是 $O(n^2)$”，默认指增长率正好是 $n^2$ 的那个 bound。

分析 loop 时反复用到三个 sum，各推一遍。

**逐次加一。** $S=1+2+\dots+n$。把它正着、倒着各写一遍相加，每一对都是 $n+1$，共 $n$ 对，所以 $2S=n(n+1)$，$S=\frac{n(n+1)}2=O(n^2)$。Inner loop 跑 $i$ 次、$i$ 从 1 到 $n$ 的 nested loop 就是它。

**逐次翻倍。** $1+2+4+\dots+2^k=2^{k+1}-1$：给左边再加一个 1，$1+1=2$，$2+2=4$，$4+4=8$，一路进位到 $2^{k+1}$。也就是说，每项翻倍的 sum 小于最后一项的两倍。

**逐次减半。** `for (int i = n; i >= 1; i /= 2)` 跑几轮？第 $k$ 轮时 $i$ 大约是 $n/2^k$，它不小于 1 当且仅当 $k\le\log_2n$，所以是 $\lfloor\log_2n\rfloor+1$ 轮，$n=10^6$ 时是 20 轮。Binary search 的 20 次就是这么来的。

:::wrong 两层 loop，外层跑 $\log n$ 轮，内层最多跑 $n$ 次，所以是 $O(n\log n)$
```java
for (int i = 1; i < n; i *= 2)
    for (int j = 0; j < i; j++)
        count++;
```
外层确实只有约 $\log_2n$ 轮，但内层的次数是 $1,2,4,\dots$，只有最后一轮才接近 $n$。总数是逐次翻倍的 sum，小于 $2n$。$n=1024$ 时外层 10 轮，`count` 最后是 $1+2+\dots+512=1023$，而 $n\log_2n=10240$。“轮数乘以最坏的一轮”给出的 upper bound 是对的，但不是这段 code 真实的增长率，它是 $O(n)$。要把每一轮实际的次数加起来。
:::

### 另外两个 $n^2$ 的 sort

Selection sort 和 bubble sort 的 comparison 次数与 input 无关，正好拿来和 insertion sort 对照。

**Selection sort**：第 $i$ 轮在 $A[i..n-1]$ 里找出 minimum，和 $A[i]$ swap。Invariant 是 $A[0..i-1]$ 已经是最小的 $i$ 个 element 并且 sorted。找 minimum 要把剩下的全看一遍，所以无论 input 如何，comparison 都是 $(n-1)+(n-2)+\dots+1=\frac{n(n-1)}2$ 次；swap 最多 $n-1$ 次。

**Bubble sort**：每一轮从左到右比较相邻的两个，顺序反了就 swap，一轮下来最大的那个被推到末尾。加一条“某一轮一次 swap 都没发生就停”，已经 sorted 的 input 只要 $n-1$ 次 comparison。

对同一个 $[8,2,4,9,3]$：

| | comparison | 搬动 |
|---|---|---|
| Insertion sort | 8 | 5 次 shift |
| Selection sort | 10 | 3 次 swap |
| Bubble sort | 10 | 5 次 swap |

Insertion sort 的 shift 和 bubble sort 的 swap 都是 5 次，这不是巧合：两者每次只把一对相邻的、顺序反了的 element 纠正过来，而这个 array 里顺序反了的 pair 正好有 5 对（8 在 2、4、3 前面，4 在 3 前面，9 在 3 前面）。倒序的 input 有 $\frac{n(n-1)}2$ 对，所以只靠相邻交换的 sort 不可能快过 $n^2$。要更快，必须让一个 element 一次跨过很多位置。

### Merge sort

如果手里已经有两个 sorted 的 half，合成一个 sorted array 很便宜：两边各放一根手指指着最前面的 element，每次比较这两个，把小的抄出去，那根手指前进一格。合并 $[1,5,6,7]$ 和 $[2,3,4,9]$：

| 比较 | 抄出 | | 比较 | 抄出 |
|---|---|---|---|---|
| 1 和 2 | 1 | | 5 和 9 | 5 |
| 5 和 2 | 2 | | 6 和 9 | 6 |
| 5 和 3 | 3 | | 7 和 9 | 7 |
| 5 和 4 | 4 | | 左边空了 | 9 |

7 次 comparison，8 个 element 各写一次。一般地，merge 出 $k$ 个 element 最多要 $k-1$ 次 comparison、$k$ 次写入，是 $O(k)$。

两个 sorted 的 half 从哪来？对每个 half 再做同样的事，一直分到 size 为 1，那时不用排。

```java
static void mergeSort(int[] A, int lo, int hi) {   // 排 A[lo..hi]
    if (lo >= hi) return;                           // size 0 或 1
    int mid = (lo + hi) / 2;
    mergeSort(A, lo, mid);
    mergeSort(A, mid + 1, hi);
    merge(A, lo, mid, hi);                          // 把两个 sorted 的 half 合起来
}
```

::fig[cs2040-mergetree] 上半部分是往下 split，下半部分是往回 merge。看右边：每一层 merge 的总工作量都是 $n$。

把图里的数法写成 recurrence。设 $T(n)$ 是排 $n$ 个 element 的写入次数：两个 half 各要 $T(n/2)$，merge 要 $n$，size 为 1 时不用做事。

$$T(n)=2\,T\!\left(\tfrac n2\right)+n,\qquad T(1)=0$$

把右边的 $T$ 一次次代开：

$$T(n)=2\,T\!\left(\tfrac n2\right)+n=4\,T\!\left(\tfrac n4\right)+2\cdot\tfrac n2+n=4\,T\!\left(\tfrac n4\right)+2n=8\,T\!\left(\tfrac n8\right)+3n=\dots=2^k\,T\!\left(\tfrac n{2^k}\right)+kn$$

代到 $n/2^k=1$ 为止，也就是 $k=\log_2n$，这时 $T(1)=0$，剩下 $T(n)=n\log_2n$。$n=8$ 时是 24 次写入；comparison 是 $4+6+7=17$ 次，比写入少。

这个数和 input 的内容无关，best case 和 worst case 都是 $O(n\log n)$。代价在 merge：它要一个额外的 array 来放抄出去的 element，所以 merge sort 不是 in-place 的，需要 $O(n)$ 的额外空间。

### Quick sort

Quick sort 把工作挪到 recursion 之前，换来 in-place。挑一个 element 当 pivot，把比它小的都放到它左边，其余的放到右边，这一步叫 partition。之后 pivot 已经在最终的位置上，左右两段各自再排，不需要 merge。

课上的 partition 取第一个 element $A[i]$ 当 pivot $p$，从左往右扫，始终保持三段：$A[i+1..m]$ 都小于 $p$，$A[m+1..k-1]$ 都不小于 $p$，$A[k..j]$ 还没看。

```java
static int partition(int[] A, int i, int j) {
    int p = A[i], m = i;
    for (int k = i + 1; k <= j; k++)
        if (A[k] < p) {                  // A[k] 该去左边那段
            m++;
            int t = A[k]; A[k] = A[m]; A[m] = t;
        }
    int t = A[i]; A[i] = A[m]; A[m] = t; // pivot 放到两段中间
    return m;
}

static void quickSort(int[] A, int i, int j) {
    if (i >= j) return;
    int m = partition(A, i, j);
    quickSort(A, i, m - 1);
    quickSort(A, m + 1, j);
}
```

对 $[27,38,12,39,29,16]$ 做一次 partition，pivot 是 27：

| $k$ | $A[k]$ | 动作 | array | $m$ |
|---|---|---|---|---|
| 1 | 38 | 不小于 27，不动 | 27 38 12 39 29 16 | 0 |
| 2 | 12 | $m$ 变成 1，swap $A[2]$ 和 $A[1]$ | 27 12 38 39 29 16 | 1 |
| 3 | 39 | 不动 | 27 12 38 39 29 16 | 1 |
| 4 | 29 | 不动 | 27 12 38 39 29 16 | 1 |
| 5 | 16 | $m$ 变成 2，swap $A[5]$ 和 $A[2]$ | 27 12 16 39 29 38 | 2 |
| 结束 | | swap $A[0]$ 和 $A[2]$ | 16 12 27 39 29 38 | |

27 落在 index 2，左边两个都比它小，右边三个都不比它小。接着分别排 $[16,12]$ 和 $[39,29,38]$。

Partition 把 pivot 和其余每个 element 各比一次，$n$ 个 element 是 $n-1$ 次 comparison。总数取决于 pivot 落在哪里。

**Pivot 每次落在正中间**：两边各一半，$T(n)=2T(n/2)+n$，和 merge sort 一样是 $n\log_2n$。

**Pivot 每次是最小或最大的那个**：一边是空的，另一边有 $n-1$ 个，$T(n)=T(n-1)+(n-1)$，一路代开是 $(n-1)+(n-2)+\dots+1=\frac{n(n-1)}2$。

:::wrong 已经 sorted 的 input 是最省事的
对 insertion sort 是这样，只要 $n-1$ 次 comparison。对上面这个取第一个 element 当 pivot 的 quick sort 正好相反：input 已经 sorted 时，pivot 永远是当前这段的 minimum，左边那段永远是空的。实际数一下，$n=1000$ 的 sorted input 要 499500 次 comparison，恰好是 $\frac{n(n-1)}2$；而顺序随机的 input 平均只要大约 10986 次。倒序的 input 同样糟。
:::

治法是不让 input 决定 pivot：partition 之前，先在 $A[i..j]$ 里随机挑一个 element 和 $A[i]$ swap。这样没有哪个特定的 input 是坏的，坏的只是运气。设 $C_n$ 是 expected comparison 数。Pivot 在这一段里排第几是等可能的；如果它排第 $k$（从 0 数起），两边的 size 是 $k$ 和 $n-1-k$。对 $k$ 取平均，两边合起来每个 $C_k$ 出现两次：

$$C_n=(n-1)+\frac2n\sum_{k=0}^{n-1}C_k,\qquad C_0=C_1=0$$

用它算两个小的：$C_2=1+\frac22(0+0)=1$；$C_3=2+\frac23(0+0+1)=\frac83$。后一个可以直接验证：三个 element 里 pivot 是 median 的 probability 是 $\frac13$，这时只要 2 次；否则剩下的两个 element 还要再比 1 次，共 3 次；平均 $\frac{2+3+3}3=\frac83$。

这个 recurrence 的 solution 是 $C_n=2(n+1)H_n-4n$，其中 $H_n=1+\frac12+\dots+\frac1n\approx\ln n$，leading term 是 $2n\ln n\approx1.39\,n\log_2n$。推导在 Princeton COS226 的 slides 里，这里只核对数字：$n=3$ 时 $2\cdot4\cdot\frac{11}6-12=\frac83$；$n=1000$ 时是 10986，上面那个“大约 10986”就是它。所以 randomized quick sort 对任何 input 都是 expected $O(n\log n)$，worst case 仍是 $O(n^2)$，只是要每一次都抽到极端的 pivot 才会发生。

### 两个性质：in-place 与 stable

**In-place**：除了 input 本身只用 $O(1)$ 的额外空间（recursion 的 stack 不算）。Insertion sort、selection sort、bubble sort 和 quick sort 是；merge sort 不是。

**Stable**：key 相等的 element，排完之后保持原来的先后。先按一个 field 排、再按另一个 field 排的时候需要它，下面的 radix sort 就完全靠它。

判断的办法是看 algorithm 会不会让一个 element 跳过一个和它相等的 element。Insertion sort 遇到不大于 $x$ 的就停，不会越过相等的；bubble sort 只 swap 严格反序的相邻两个；merge 时两边相等就先抄左边的。这三个是 stable 的。Quick sort 的 partition 做的是远距离的 swap：对 $[2,3_a,3_b,1]$（两个 3 用下标区分），pivot 是 2，扫到 1 时把它和 $3_a$ swap，得到 $[2,1,3_b,3_a]$，最后 pivot 归位成 $[1,2,3_b,3_a]$，两个 3 的先后反了。Selection sort 也一样：$[2_a,2_b,1]$ 的第一轮把 $2_a$ 和 1 swap，得到 $[1,2_b,2_a]$。

### 为什么快不过 $n\log n$

Merge sort 是 $n\log_2n$。有没有只靠 comparison 就更快的 sort？

把任何一个 comparison-based sort 看成一连串“是或否”的提问。排 3 个不同的 element，input 的顺序有 $3!=6$ 种可能，algorithm 必须分清是哪一种才能排对。每次 comparison 只有两种结果，$k$ 次 comparison 最多区分 $2^k$ 种情况。$2^2=4<6$，所以 2 次不够，至少要 3 次。

::fig[cs2040-dtree] 把 insertion sort 对三个 element 做的 comparison 画成一棵 tree：每个 node 是一次提问，每个 leaf 是一种排好的结果。

对 $n$ 个 element 是同一句话：$2^k\ge n!$，即 worst case 至少要 $k\ge\log_2n!$ 次 comparison。$n!$ 的后一半 factor（从 $n/2$ 到 $n$）每个都不小于 $n/2$，所以

$$n!\ge\left(\frac n2\right)^{n/2}\qquad\Longrightarrow\qquad\log_2n!\ \ge\ \frac n2\log_2\frac n2$$

右边按 $n\log n$ 增长。Lower bound 用 $\Omega$ 记：任何 comparison-based sort 的 worst case 都是 $\Omega(n\log n)$。代入数字：$n=1000$ 时 $\log_2n!\approx8530$，而 merge sort 最多 $n\log_2n\approx9966$，离任何 comparison-based sort 所能达到的最好结果只差 17%。

### Radix sort：不做 comparison

上面的论证只约束“只通过 comparison 了解 input”的 algorithm。如果 key 是 integer，可以把它的一个 digit 直接当作 array 的 index：看一眼就分出 10 种情况，而不是 2 种。

先只按一个 digit 排：准备 10 个 queue，编号 0 到 9；把 element 依次放进它那个 digit 对应的 queue；再按编号把 10 个 queue 首尾接起来。工作量是 $n+10$，而且是 stable 的，因为 queue 先进先出。

Radix sort 对每个 digit 都这样做一遍，从个位开始。对 $[329,457,657,839,436,720,355]$：

| pass | 按哪个 digit | 结果 |
|---|---|---|
| 1 | 个位 | 720 355 436 457 657 329 839 |
| 2 | 十位 | 720 329 436 839 355 457 657 |
| 3 | 百位 | 329 355 436 457 657 720 839 |

它正确的理由是一个 invariant：第 $t$ 个 pass 之后，array 按每个 key 的最后 $t$ 个 digit 是 sorted 的。看任意两个 key 在第 $t$ 个 pass 里的遭遇。如果它们的第 $t$ 个 digit 不同，这个 pass 把它们放进不同的 queue，先后就对了。如果相同，它们进同一个 queue，保持进来时的先后，而那是前 $t-1$ 个 pass 按后 $t-1$ 个 digit 排好的。拿 329 和 355 核对：第 2 个 pass 之后 329 在 355 前面（29 小于 55），第 3 个 pass 里两个都进 3 号 queue，先后不变。

:::edge 每一个 pass 都必须 stable，并且从个位开始
第 3 个 pass 如果不 stable，329 和 355 在 3 号 queue 里就可能换位，前两个 pass 的成果作废。反过来从百位开始也不行：同样三个 pass 按百位、十位、个位的顺序做，最后得到的是 720 355 436 457 657 329 839，只按个位排好了，因为后做的 pass 说了算。
:::

$d$ 个 digit、每个 digit 有 $k$ 种取值时，running time 是 $O(d\,(n+k))$。$10^6$ 个 9 位的 integer，$d=9$、$k=10$，约 $9\times10^6$ 次操作，比 $n\log_2n\approx2\times10^7$ 少。它需要额外的 queue，不是 in-place 的；$d$ 很大时（比如很长的 string）也不划算。

| Algorithm | Worst case | Best case | In-place | Stable |
|---|---|---|---|---|
| Insertion sort | $n^2$ | $n$ | 是 | 是 |
| Selection sort | $n^2$ | $n^2$ | 是 | 否 |
| Bubble sort（提前停） | $n^2$ | $n$ | 是 | 是 |
| Merge sort | $n\log n$ | $n\log n$ | 否 | 是 |
| Quick sort（random pivot） | $n^2$，expected $n\log n$ | $n\log n$ | 是 | 否 |
| Radix sort | $d\,(n+k)$ | $d\,(n+k)$ | 否 | 是 |

:::from
Insertion sort 的例子 $[8,2,4,9,3]$、merge sort 的例子 $[7,1,5,6,2,4,9,3]$、把 recurrence 画成 recursion tree 逐层相加的数法，来自 [MIT 6.006 第 3 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec3/)的讲义；decision tree 的论证和 $n!\ge(n/2)^{n/2}$ 来自[第 4 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec4/)和[第 5 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec5/)，“每个 pass 要 stable、从 least significant digit 开始”也在第 5 讲。Partition 的写法（第一个 element 当 pivot，用 $m$ 记左边那段的末尾）和 $[27,38,12,39,29,16]$ 这个例子来自 [VisuAlgo 的 sorting e-Lecture](https://visualgo.net/en/sorting/print)，这是 NUS 课上的写法。Expected comparison 的 recurrence 来自 [Princeton COS226 的 Quicksort slides](https://www.cs.princeton.edu/courses/archive/fall21/cos226/lectures/23Quicksort.pdf)；那里的 partition 每次算 $n+1$ 次 comparison，这里按上面的 code 改成 $n-1$ 次，closed form 和 10986、499500 这些数是为这一页算的。三个 sum、selection sort 与 bubble sort 的对照、stable 的两个反例是凭自己的知识写的。Radix sort 的七个三位数是 CLRS 教材里的例子，凭记忆取用，三个 pass 的结果是重新算的。

## [list] List、stack 与 queue

:::skip

### Array 快在哪，慢在哪

Array 的 element 在内存里一个挨一个，第 $i$ 个的地址是“起始地址加 $i$ 乘以每个 element 的大小”，一次乘法一次加法就到，所以 `get(i)` 是 $O(1)$。同一个事实也是它的弱点：要在 index $i$ 处 insert，后面 $n-i$ 个 element 都得往后挪一格才能保持“一个挨一个”。在 $10^6$ 个 element 的最前面 insert 一个，要挪 $10^6$ 次；remove 同理。

Linked list 放弃“挨着”。每个 element 住在一个 node 里，node 另外存一个 pointer 指向下一个 node：

```java
class ListNode { int item; ListNode next; }

// 在 cur 后面 insert 一个值为 x 的 node
ListNode node = new ListNode();
node.item = x;
node.next = cur.next;   // 新 node 先接上后半段
cur.next = node;        // 再让 cur 指向新 node
```

两次 pointer 赋值，和 list 有多长无关。代价是没有地址可算了：要到第 $i$ 个 node，只能从 head 出发沿 `next` 走 $i$ 步。

:::wrong 那两行赋值谁先谁后都一样
反过来写，先执行 `cur.next = node`，这时原来的后半段只有 `cur.next` 记着，已经被覆盖了。接下来 `node.next = cur.next` 等于 `node.next = node`，新 node 指向自己，后半段再也找不回来。改 pointer 之前，先确认被覆盖的那个地址还有别处记着。
:::

::fig[cs2040-linsert] 左边是正确的顺序，右边是反过来的顺序。B 代表原来 `cur` 后面的那一整段。

把常用的 operation 列出来。Linked list 都假设存了 head 和 tail 两个 pointer；doubly linked list 的每个 node 多一个 `prev`。

| Operation | Array | Singly linked list | Doubly linked list |
|---|---|---|---|
| `get(i)` | 1 | $i$ | $\min(i,\,n-i)$ |
| 在最前面 insert 或 remove | $n$ | 1 | 1 |
| 在最后面 insert | 1（见下一小节） | 1 | 1 |
| 在最后面 remove | 1 | $n$ | 1 |
| 已经拿到某个 node，在它后面 insert | 不适用 | 1 | 1 |

表里最容易错的是 singly linked list“在最后面 remove”那一格。有 tail pointer，找到最后一个 node 不费事；但 remove 之后倒数第二个 node 要成为新的 tail，它的 `next` 要改成 `null`，而 singly linked list 里没有任何 pointer 指向前一个 node，只能从 head 走 $n-1$ 步去找。Doubly linked list 用 `tail.prev` 一步就到。

### Array 满了怎么办

Java 的 `ArrayList` 底下是一个 array，capacity 是固定的。满了以后再 add，只能开一个更大的 array，把原来的 element 全部 copy 过去。开多大？

每次把 capacity 翻倍。从 capacity 1 开始连续 add：

| 第几次 add | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| add 之后的 capacity | 1 | 2 | 4 | 4 | 8 | 8 | 8 | 8 | 16 |
| 这一次 copy 了几个 | 0 | 1 | 2 | 0 | 4 | 0 | 0 | 0 | 8 |

Copy 只发生在 capacity 是 $1,2,4,8,\dots$ 的时候，每次 copy 的个数就是当时的 capacity。做 $n$ 次 add，发生过的 copy 是 $1+2+4+\dots+2^k$，其中 $2^k<n$。按第 1 站“逐次翻倍”的 sum，它小于 $2\cdot2^k<2n$。再加上每次 add 自己写入的那 1 次，$n$ 次 add 的 total cost 小于 $3n$。

单独一次 add 可能要 copy 整个 array，是 $O(n)$；但任意连续 $n$ 次加起来不超过 $3n$，平均每次不超过 3。这种“单次可以贵，一连串的平均有保证”的 bound 叫 amortized：

> 一个 operation 的 amortized cost 是 $T$，意思是任意连续 $k$ 次这个 operation 的 total cost 不超过 $k\cdot T$。

`ArrayList` 的 add 是 amortized $O(1)$。$n=10^6$ 时实际数出来，copy 一共 1048575 次，平均每次 add 一次多一点。（Java 的实现每次把 capacity 乘 1.5 而不是 2，数法完全一样：只要按比例增长，copy 的总数就是一个每项成倍增长的 sum，和最后一项同一个量级。）

:::wrong 每次满了多开 10 格，也是“隔一阵才 copy 一次”，所以也是 amortized $O(1)$
多开 10 格时 capacity 是 $10,20,30,\dots$，每 10 次 add 就 copy 一次，每次 copy 当时全部的 element。做 $10^6$ 次 add，copy 的总数是 $10+20+\dots+999990=49999500000$，约 $5\times10^{10}$，平均每次 add 要 copy 五万个。两种做法的差别在于：多开固定格数时，两次 copy 的间隔不变，而 copy 的代价随 $n$ 增长；翻倍时，间隔和代价一起增长，后面那一长串便宜的 add 正好摊掉这一次 copy。
:::

### Stack 与 queue

很多时候不需要在任意位置 insert 和 remove，只需要“放进去一个”和“拿出来一个”。限制越多，越容易让每个 operation 都是 $O(1)$。

**Stack**：最后放进去的最先拿出来（LIFO）。`push` 和 `pop` 都在同一端。用 array 实现时让这一端是 array 的末尾，表里“在最后面 insert、remove”两格都是 1。它适合“最近开始的事最先结束”的场合。检查括号是否配对就是这样：读到左括号 push，读到右括号就 pop 一个出来看是不是同一种。对 `[ ( ] )`：

| 读到 | 动作 | stack（右边是 top） |
|---|---|---|
| `[` | push | `[` |
| `(` | push | `[` `(` |
| `]` | pop 出 `(`，和 `]` 不是一对 | 不合法，停 |

最后打开的 `(` 必须最先关上，stack 的 top 记住的正是它。Recursion 用的 call stack 是同一回事，第 6 站的 DFS 靠它。

**Queue**：最先放进去的最先拿出来（FIFO）。`enqueue` 在 back，`dequeue` 在 front，两端各管一件事。用 array 实现时，如果让 front 固定在 index 0，每次 dequeue 都要把剩下的往前挪，是 $O(n)$。办法是不挪 element，挪 index：front 和 back 都只往右走，走到 array 的末尾就绕回 0。

::fig[cs2040-cqueue] Capacity 为 6 的 circular array。上面一行里 a、b 已经 dequeue；下面一行里 g 被放到了 index 0。

```java
class ArrayQueue {
    int[] A = new int[6];
    int front = 0, back = 0, size = 0;       // back 是下一个空位

    void enqueue(int x) { A[back] = x; back = (back + 1) % A.length; size++; }
    int dequeue() { int x = A[front]; front = (front + 1) % A.length; size--; return x; }
}
```

（完整的写法要在 enqueue 前检查是否已满、dequeue 前检查是否为空；满了可以像 `ArrayList` 那样翻倍。）

:::edge `front == back` 有两种意思
刚建好时 `front == back == 0`，queue 是空的。在图的下面一行再 enqueue 一个 h，它放进 index 1，`back` 变成 2，又等于 `front`，而这时 queue 是满的。只看两个 index 分不清空和满，所以上面的 code 另外记了 `size`。另一种做法是永远留一格不用，约定 `(back + 1) % capacity == front` 就算满。
:::

用 linked list 实现 queue 时，方向不能选错：在 tail enqueue，在 head dequeue。前面那张表说明了原因：singly linked list 在 tail 做 insert 是 1，在 tail 做 remove 是 $n$，所以 remove 的那一端只能是 head。

Java 里现成的是 `ArrayDeque`（circular array）和 `LinkedList`（doubly linked list），两者都能当 stack 和 queue 用。第 6 站的 BFS 用的就是 queue。

:::from
Array 与 linked list 各个 operation 的代价、amortized 的定义、“满了就开 $\Theta(n)$ 的额外空间，之后要再 insert $\Theta(n)$ 次才会再 copy”的论证，来自 [MIT 6.006 第 2 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec2/)的讲义。那一讲没有把 copy 的次数写成 sum，也没有讨论“多开固定格数”；翻倍的表、$3n$ 的数法和两个 $10^6$ 的数字是为这一页算的。两行 pointer 赋值的顺序、括号配对的例子、circular array 的 queue 和它的 full 与 empty，是这门课的标准内容，凭自己的知识写的，没有对照某一份讲义。
:::

## [hash] Hash table

:::skip

### 要比 $\log n$ 快，就不能靠 comparison

在 sorted array 里找一个 key，binary search 要大约 $\log_2n$ 次 comparison。第 1 站的 decision tree 论证对 search 同样成立：search 的结果有 $n+1$ 种（在 $n$ 个位置之一，或者不在），每次 comparison 只分两路，所以至少要 $\log_2(n+1)$ 次。只靠 comparison，search 快不过 $\log n$。

和 radix sort 一样，出路是把 key 直接当 index。如果 key 是 0 到 $u-1$ 的 integer，开一个 size 为 $u$ 的 array，key 为 $k$ 的 item 就放在 $A[k]$，search、insert、delete 都是一次访问。这叫 direct addressing。它的问题是空间：存 1000 个 8 位的电话号码，array 要 $10^8$ 格，其中 99.999% 是空的。

Hash table 把这个 array 缩小到和 key 的个数差不多大。取 table size $m$，用一个 hash function 把 key 映到 0 到 $m-1$，最常用的是

$$h(k)=k\bmod m$$

key $k$ 放在 slot $h(k)$。可能的 key 有 $u$ 个，slot 只有 $m$ 个，$u>m$ 时必然有两个不同的 key 落到同一个 slot，这叫 collision。

Collision 来得比直觉早。把 $n$ 个 key 随机放进 $m$ 个 slot，全都不撞的 probability 是 $\frac mm\cdot\frac{m-1}m\cdots\frac{m-n+1}m$。取 $m=365$、$n=23$，这个乘积是 0.493：table 才用了 6%，就已经有一半以上的可能出现 collision。所以 hash table 的设计重点是 collision 发生之后怎么办。

这一站用同一组数据：$m=11$，依次 insert 14, 25, 3, 36, 9, 20, 5。它们的 $h$ 值是 3, 3, 3, 3, 9, 9, 5。

### Separate chaining

每个 slot 不直接放 key，而是挂一条 linked list，落到这个 slot 的 key 都接在上面。Search 时先算 $h(k)$，再把那条 list 走一遍。

::fig[cs2040-hash] 左边是 separate chaining，右边是下一小节的 linear probing，放的是同一组 key。

Search 的代价是“算一次 $h$”加上“那条 chain 的长度”。Chain 平均多长？定义 load factor

$$\alpha=\frac nm$$

也就是平均每个 slot 摊到几个 key。例子里 $\alpha=7/11\approx0.64$。假设每个 key 落到每个 slot 的可能性相同，而且各个 key 互不影响。找一个不在 table 里的 key 时，它的 slot 上平均有 $n\cdot\frac1m=\alpha$ 个 key，全要看一遍。找一个在 table 里的 key 时，其余 $n-1$ 个 key 各有 $\frac1m$ 的 probability 和它同一个 slot，chain 的 expected length 是 $1+\frac{n-1}m$，小于 $1+\alpha$。所以

$$\text{search 的 expected cost}=O(1+\alpha)$$

只要 $m$ 跟着 $n$ 一起增大，让 $\alpha$ 不超过某个 constant，search、insert、delete 都是 expected $O(1)$。

例子里 slot 3 上挂了 4 个 key，远多于 $\alpha=0.64$。上面的结论是对“key 随机”说的平均；而 14, 25, 3, 36 恰好两两相差 11 的倍数，是专门挑来撞的。对任何固定的 $h$，这样的坏 input 总是存在，worst case 仍是 $O(n)$。实际能做的，是不让常见的 key 的规律正好撞上 $m$。

:::wrong Table size 取 1000 这样的整数，mod 起来方便
设 key 是 100, 200, 300, …, 5000 这 50 个数（比如以分为单位的价格）。$m=1000$ 时，$k\bmod1000$ 只可能是 0, 100, …, 900，50 个 key 挤在 10 个 slot 里，每个 slot 5 个，其余 990 个 slot 空着。换成 $m=997$，同样 50 个 key 落在 50 个不同的 slot。原因是 key 都是 100 的倍数，而 100 和 1000 有 common factor 100，$k\bmod1000$ 于是也只能是 100 的倍数。997 是 prime，和任何小于它的数都没有 common factor，key 里的规律带不进 $h$ 值。所以 $m$ 取 prime，而且不取靠近 2 或 10 的 power 的。
:::

### Open addressing：linear probing

另一种办法是不用 linked list，所有 key 都放在 array 本身里，这要求 $n\le m$。Insert 时如果 slot $h(k)$ 被占了，就按一个固定的规则去看别的 slot，这个依次查看的序列叫 probe sequence。最简单的规则是往后一格一格看，到末尾绕回 0：

$$h(k),\ h(k)+1,\ h(k)+2,\ \dots\pmod m$$

| insert | home slot | 依次看了哪些 slot | 放在 |
|---|---|---|---|
| 14 | 3 | 3 | 3 |
| 25 | 3 | 3, 4 | 4 |
| 3 | 3 | 3, 4, 5 | 5 |
| 36 | 3 | 3, 4, 5, 6 | 6 |
| 9 | 9 | 9 | 9 |
| 20 | 9 | 9, 10 | 10 |
| 5 | 5 | 5, 6, 7 | 7 |

Search 沿同一个 probe sequence 走：找到了就停；遇到空 slot 也停，结论是“不在”。后一条的理由是，如果这个 key 在 table 里，insert 它的时候会把它放进这条 sequence 上第一个空 slot，不会越过一个空 slot 放到后面去。

:::wrong Delete 一个 key，把它的 slot 清空就行了
在上面的 table 里 delete 25，把 slot 4 清空。然后 search 3：$h(3)=3$，slot 3 里是 14，不是；slot 4 是空的，于是回答“不在”。可是 3 明明在 slot 5。“遇到空 slot 就停”依赖一个前提：sequence 上的 slot 一旦被占就不会再变空，delete 把它破坏了。正确的做法是在 slot 4 留一个 DELETED 标记：search 把它当作“有东西，继续往后看”，insert 可以把新 key 放进去。
:::

Linear probing 的毛病在表的最后一行：5 的 home slot 是 5，那里并没有 home 相同的 key，占着 slot 5 和 6 的是 home 为 3 的那一串。连成一片的 occupied slot 叫 cluster，不同 home 的 key 会被同一个 cluster 拖累，这叫 primary clustering。

它还会自己加重。现在 table 里有两个 cluster：slot 3 到 7（长 5）和 slot 9 到 10（长 2）。下一个 key 的 home 只要落在 3 到 8 这 6 个 slot 之一，它最后都会被放进 slot 8，probability 是 $\frac6{11}\approx55\%$；这一放还把两个 cluster 连成了一个长 8 的。Cluster 越长，接住下一个 key 的可能越大，于是越长越快。

### Quadratic probing 与 double hashing

要打散 cluster，就让 probe 的步子不是固定的 1。

**Quadratic probing**：第 $j$ 次看 $h(k)+j^2$，即依次偏移 $0,1,4,9,\dots$（mod $m$）。还是那四个 home 为 3 的 key：14 放在 3；25 看 3、4，放在 4；3 看 3、4、7，放在 7；36 看 3、4、7、$3+9=12\bmod11=1$，放在 1。之后 5 一次就放进了自己的 slot 5，没有被拖累。Home 相同的 key 走的仍是同一条 sequence（这叫 secondary clustering），但不同 home 的 key 不再互相妨碍。

新的问题是 probe sequence 不一定走遍所有 slot。$m=11$ 时 $j^2\bmod11$ 依次是

$$0,\ 1,\ 4,\ 9,\ 5,\ 3,\ 3,\ 5,\ 9,\ 4,\ 1,\ 0,\ \dots$$

只有 6 个不同的值。在一个空的 table 里依次 insert 3, 14, 25, 36, 47, 58（home 都是 3），它们占掉 slot 3, 4, 7, 1, 8, 6。再 insert 69（home 也是 3），看的是 3, 4, 7, 1, 8, 6, 6, 8, 1, 7, 4, 3, …，永远是这 6 个 slot，而 table 里还有 5 个空 slot。

::fig[cs2040-quad] 上：home 相同的四个 key 被 $0,1,4,9$ 的偏移打散，5 不再被拖累。下：probe sequence 只走得到一半多一点的 slot。

什么时候不会这样？

> 如果 $m$ 是 prime 且 $\alpha<\frac12$，quadratic probing 一定能找到空 slot。

证明：只需说明前 $\frac{m+1}2$ 次 probe（$j=0,1,\dots,\frac{m-1}2$）看的 slot 两两不同，因为那样它们就超过 slot 总数的一半，而被占的 slot 不到一半，其中必有空的。假设有 $0\le x<y\le\frac{m-1}2$ 看的是同一个 slot，即 $h+x^2$ 和 $h+y^2$ 除以 $m$ 的 remainder 相同，那么 $m$ 整除它们的差

$$y^2-x^2=(y-x)(y+x)$$

$m$ 是 prime，整除一个 product 就必须整除其中一个 factor。但 $0<y-x<m$，并且 $0<y+x\le\frac{m-1}2+\frac{m-3}2=m-2<m$，两个 factor 都是 1 到 $m-1$ 之间的数，$m$ 都除不尽。矛盾。

用例子核对：$m=11$，$\frac{m+1}2=6$，前 6 个偏移 $0,1,4,9,5,3$ 确实互不相同；上面 insert 失败时 $\alpha=\frac6{11}>\frac12$，正好在保证之外。

**Double hashing**：让步子的大小也由 key 决定。再取一个 hash function $h_2$，第 $j$ 次看 $h(k)+j\cdot h_2(k)$。取 $h_2(k)=7-(k\bmod7)$，它的值在 1 到 7 之间：

| insert | $h(k)$ | $h_2(k)$ | 依次看了哪些 slot | 放在 |
|---|---|---|---|---|
| 14 | 3 | $7-0=7$ | 3 | 3 |
| 25 | 3 | $7-4=3$ | 3, 6 | 6 |
| 3 | 3 | $7-3=4$ | 3, 7 | 7 |
| 36 | 3 | $7-1=6$ | 3, 9 | 9 |

四个 home 相同的 key，步子各不相同，第二次 probe 就各走各的了。有两条要求。$h_2(k)$ 不能是 0，否则原地不动。$m$ 要取 prime：这时步子 $s=h_2(k)$ 在 1 到 $m-1$ 之间，$m$ 除不尽它，于是 $0\cdot s,\ 1\cdot s,\ \dots,\ (m-1)\cdot s$ 除以 $m$ 的 remainder 两两不同（若 $js$ 和 $j's$ 的 remainder 相同，$m$ 整除 $(j-j')s$，只能整除 $j-j'$，而 $|j-j'|<m$，所以 $j=j'$），probe sequence 走遍全部 $m$ 个 slot。

### 让 $\alpha$ 保持小，以及 hash table 做不到的事

三种 open addressing 都是 $\alpha$ 越接近 1 越慢，separate chaining 的 cost 也随 $\alpha$ 增长。所以 table 要跟着 $n$ 长大：$\alpha$ 超过某个阈值（open addressing 常取 $\frac12$）时，开一个大约两倍大的新 table（size 仍取 prime），换成新的 $h$，把所有 key 重新 insert 一遍。这叫 rehash，一次 $O(n)$；按第 2 站翻倍 array 的同一个数法，摊下来每次 insert 仍是 amortized $O(1)$。

Java 的 `HashMap` 和 `HashSet` 用的是 separate chaining：先用 key 的 `hashCode()` 决定 slot，再在那条 chain 上用 `equals()` 逐个比较。

:::edge 自己写的 class 当 key，`equals` 和 `hashCode` 要一起改
如果只重写了 `equals`，两个内容相同的 object 的 `hashCode()` 仍然不同，会被分到不同的 slot。`map.get(key)` 只在一个 slot 的 chain 上找，于是找不到明明“相等”的那个 key。规则是：`equals` 认为相等的两个 object，`hashCode` 必须相同。
:::

Hash table 换来 $O(1)$ 的 search，付出的是 order：key 在 table 里的位置由 $h$ 决定，和大小无关。要找 minimum，或者找“比 $k$ 大的最小的 key”，只能把 $m$ 个 slot 全看一遍。需要这类 operation 时用第 5 站的 balanced BST。

:::back
“comparison 最多分两路”的 lower bound 和“把 key 当 index”的出路，是[第 1 站](#sort)讲 sorting lower bound 与 radix sort 时的同一对想法。Rehash 的 amortized 分析用的是[第 2 站](#list)的 doubling。
:::

:::from
“comparison-based search 至少要 $\log n$ 次，所以改用 key 当 index”、direct addressing 的空间问题、collision 不可避免、chaining 的 expected chain length 是 $1+\frac{n-1}m$ 的算法，来自 [MIT 6.006 第 4 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec4/)的讲义。那一讲用 universal hashing 来保证“两个 key 相撞的 probability 不超过 $1/m$”；这里按 CS2040 的做法直接假设 key 均匀地落到各个 slot。Linear、quadratic、double 三种 probing 的 formula，DELETED 标记，“$m$ 是 prime 且 $\alpha<\frac12$”的证明，$h_2(k)=M'-k\bmod M'$ 的取法，$m$ 取 prime 和 rehash 的阈值，来自 [VisuAlgo 的 hashtable e-Lecture](https://visualgo.net/hashtable)。$m=11$ 的那组 key 和所有的表、生日数字 0.493、$m=1000$ 对 $m=997$ 的对比、cluster 的 $\frac6{11}$，是为这一页算的。`hashCode` 与 `equals` 的约定是凭自己的知识写的。
:::

## [heap] Binary heap 与 priority queue

:::skip
能解释 shiftDown 为什么要和较大的 child 交换，能推出 bottom-up 的 build heap 是 $O(n)$，并能在 array 上手动做完一遍 heap sort，就可以去第 5 站。
:::

### 只要 max，不要全部 sorted

Priority queue 只有两个 operation：`insert(x)` 放进一个 element，`extractMax()` 取走当前最大的。第 7、8 站的 Prim 和 Dijkstra 都在反复问“剩下的里面最小的是哪个”，问的就是它（把大小反过来即可）。

用前面的结构来做，有两种极端：

| 实现 | insert | extractMax |
|---|---|---|
| unsorted array | 放在末尾，1 | 扫一遍找 max，$n$ |
| sorted array | 找到位置、挪动，$n$ | 取末尾，1 |

各做 $n$ 次，两种都是 $n^2$。Sorted array 做了多余的事：它维持了全部 element 的 order，而这里只需要知道谁最大。Binary heap 维持一个弱得多的 invariant，换来两个 operation 都是 $\log n$。

### Invariant：complete binary tree 上的 heap property

Binary heap 是一个 array，但要把它看成一棵 binary tree：$A[1]$ 是 root，接下来的两个是它的 child，再接下来的四个是第三层，一层一层从左到右填。这样的 tree 除了最后一层都是满的，最后一层靠左排，叫 complete binary tree。

::fig[cs2040-heap] 同一个 heap 的两种画法。

用 1-based 的 index，tree 里的关系全是算术：

$$\text{left}(i)=2i,\qquad\text{right}(i)=2i+1,\qquad\text{parent}(i)=\lfloor i/2\rfloor$$

第 $d$ 层最多有 $2^d$ 个 node，所以 height 为 $h$ 的 complete binary tree 的 node 数在 $2^h$ 和 $2^{h+1}-1$ 之间，反过来 $h=\lfloor\log_2n\rfloor$。图里 $n=10$，$h=3$；$n=10^6$ 时 $h=19$。Tree 的 height 由 $n$ 决定，不可能长歪，这是把它存成 array 换来的。

Max heap property：

> 对每个 $i\ge2$，$A[\text{parent}(i)]\ge A[i]$。

对图里的 heap 逐个检查：70 和 80 不超过 90；30 和 60 不超过 70；50 和 20 不超过 80；10 和 25 不超过 30；40 不超过 60。九条全部成立。

由它推出 max 在 root：从任意一个 node 往上走到 root，沿途的值只增不减，比如 $40\le60\le70\le90$，所以每个 node 都不超过 root。

它没有承诺的事同样要紧：兄弟之间、不同 subtree 之间没有任何大小关系。图里第三层的 30 比第四层的 40 小。所以在 heap 里找一个任意的 key，只能把 array 扫一遍，$O(n)$。

### Insert：shiftUp

新 element 只能放在 index $n+1$，否则 tree 不再 complete。放上去之后，唯一可能被破坏的是它和 parent 之间的那一条。那就和 parent 比，比 parent 大就 swap，然后在新位置上重复。

往图里的 heap insert 85：

| 步骤 | array（index 1 到 11） |
|---|---|
| 放在 index 11 | 90 70 80 30 60 50 20 10 25 40 **85** |
| parent 是 index 5 的 60，swap | 90 70 80 30 **85** 50 20 10 25 40 60 |
| parent 是 index 2 的 70，swap | 90 **85** 80 30 70 50 20 10 25 40 60 |
| parent 是 index 1 的 90，不小于 85，停 | |

::fig[cs2040-shiftup] Insert 85 前后的 tree。

为什么只需要盯着一条 path？一次 swap 把较大的 85 换上去、较小的 60 换下来。60 落到的位置下面，原本就都是它的 descendant，不超过它；85 的另一个 child（index 10 的 40）原来不超过 60，更不超过 85。所以 swap 之后，可能不成立的仍然只有“85 和它的新 parent”这一条，问题往上挪了一层。最多挪 $h$ 层，insert 是 $O(\log n)$。

### ExtractMax：shiftDown

Max 在 root，取走以后 root 空了。为了保持 complete，只能拿最后一个 element $A[n]$ 来补，然后 $n$ 减 1。补上来的值通常太小，要往下换。

从刚才那 11 个 element 里 extractMax：

| 步骤 | array（index 1 到 10） |
|---|---|
| 取走 90，把 index 11 的 60 放到 root | **60** 85 80 30 70 50 20 10 25 40 |
| child 是 85 和 80，和较大的 85 swap | 85 **60** 80 30 70 50 20 10 25 40 |
| child 是 30 和 70，和较大的 70 swap | 85 70 80 30 **60** 50 20 10 25 40 |
| child 只有 index 10 的 40，不比 60 大，停 | |

::fig[cs2040-shiftdown] ExtractMax 前后的 tree。

:::wrong 往下换的时候，和哪个 child 换都行，只要它比自己大
第二行里 60 的两个 child 是 85 和 80，都比 60 大。如果和 80 换，root 变成 80，而它的 left child 是 85，$80<85$，heap property 在 root 这里不成立，而接下来只会沿着右边继续往下，这个错误没有人再去看。换上去的那个要同时不小于另一个 child，所以必须取较大的。
:::

每一层做两次 comparison（先在两个 child 里挑大的，再和它比），最多 $h$ 层，所以 extractMax 也是 $O(\log n)$。

```java
// A[1..n] 是 heap，swap(i, j) 交换 A[i] 和 A[j]
void shiftUp(int i) {
    while (i > 1 && A[i / 2] < A[i]) { swap(i, i / 2); i /= 2; }
}

void shiftDown(int i) {
    while (2 * i <= n) {
        int c = 2 * i;                              // left child
        if (c + 1 <= n && A[c + 1] > A[c]) c++;     // 取较大的 child
        if (A[i] >= A[c]) break;
        swap(i, c);
        i = c;
    }
}
```

### Build heap：$O(n)$

给一个任意的 array，要把它整理成 heap。

**办法一**：从空 heap 开始 insert $n$ 次。每个 element 最坏要从自己的位置一路升到 root，swap 的次数是它的 depth。

**办法二**（bottom-up）：直接把 array 当成一棵 complete binary tree，对 $i=\lfloor n/2\rfloor,\ \dots,\ 2,\ 1$ 依次做 `shiftDown(i)`。这个顺序保证做到 $i$ 时，它的两个 subtree（index 都比 $i$ 大）已经是 heap，shiftDown 正是在这个前提下把以 $i$ 为 root 的整棵 subtree 变成 heap。Index 大于 $\lfloor n/2\rfloor$ 的都是 leaf，本身就是 heap，不用处理。

对 $[4,1,7,3,8,5,9]$：

| `shiftDown(i)` | 发生的 swap | array |
|---|---|---|
| $i=3$（值 7，child 是 5 和 9） | 和 9 换 | 4 1 9 3 8 5 7 |
| $i=2$（值 1，child 是 3 和 8） | 和 8 换 | 4 8 9 3 1 5 7 |
| $i=1$（值 4，child 是 8 和 9） | 和 9 换，再和 7 换 | 9 8 7 3 1 5 4 |

4 次 swap。同一个 array 用办法一要 7 次。

::fig[cs2040-buildheap] 对 $[4,1,7,3,8,5,9]$ 做 bottom-up build heap，每一步之后的 tree。

:::wrong Build heap 做了 $n/2$ 次 shiftDown，每次 $O(\log n)$，所以它是 $\Theta(n\log n)$
$n\log n$ 作为 upper bound 没有错，但不是真实的增长率。`shiftDown(i)` 最多 swap 的次数是 node $i$ 的 height，而 tree 里绝大多数 node 都在底下，height 很小。拿 $n=15$ 的满 tree 数一下：8 个 leaf 的 height 是 0，4 个 node 是 1，2 个是 2，root 是 3，

$$4\times1+2\times2+1\times3=11<15$$
:::

一般地，$n=2^{H+1}-1$ 的满 tree 里，height 为 $h$ 的 node 有 $2^{H-h}=\frac{n+1}{2^{h+1}}$ 个，所以 swap 的总数不超过

$$\sum_{h=0}^{H}h\cdot\frac{n+1}{2^{h+1}}=\frac{n+1}2\sum_{h=0}^{H}\frac h{2^h}$$

后面那个 sum 不管加多少项都小于 2。记 $S=\frac12+\frac24+\frac38+\frac4{16}+\cdots$，那么 $\frac S2=\frac14+\frac28+\frac3{16}+\cdots$，两式逐项相减：

$$S-\frac S2=\frac12+\frac14+\frac18+\frac1{16}+\cdots=1\qquad\Longrightarrow\qquad S=2$$

所以总数小于 $\frac{n+1}2\cdot2=n+1$，build heap 是 $O(n)$。

两种办法的差别就在“height”和“depth”这两个词上。办法一里每个 node 付的是它的 depth，而多数 node 很深；办法二里每个 node 付的是它的 height，而多数 node 很矮。$n=10^6$ 时，所有 node 的 height 加起来是 999993，depth 加起来是 17951445，差 18 倍。

### Heap sort

有了 max heap，sorting 只差一步。把 root（当前的 max）和 $A[n]$ swap，max 就到了它最终的位置；然后 $n$ 减 1，对新的 root 做 shiftDown；重复。Extract 出来的 max 正好填进 heap 缩小后空出来的那一格，不需要额外的 array。

接着上面 build 好的 $[9,8,7,3,1,5,4]$，竖线左边是 heap，右边是已经排好的部分：

| 第几次 extract | array |
|---|---|
| 1 | 8 4 7 3 1 5 ∣ 9 |
| 2 | 7 4 5 3 1 ∣ 8 9 |
| 3 | 5 4 1 3 ∣ 7 8 9 |
| 4 | 4 3 1 ∣ 5 7 8 9 |
| 5 | 3 1 ∣ 4 5 7 8 9 |
| 6 | 1 ∣ 3 4 5 7 8 9 |

Build 是 $O(n)$，之后 $n-1$ 次 shiftDown 各 $O(\log n)$，一共 $O(n\log n)$，worst case 也是如此。Heap sort 是 in-place 的；它不 stable，因为 root 和末尾的 swap 是远距离的。

:::edge Java 的 `PriorityQueue` 是 min heap，而且不能改一个 element 的 priority
要 max heap，就在 constructor 里传 `Collections.reverseOrder()` 或自己的 `Comparator`。更要紧的是第二点：heap 里找不到一个指定的 element 在哪（上面说过，只能扫一遍），所以 `PriorityQueue` 没有“把某个 element 的 key 改小”的 operation。绕开的办法是不改，直接再 insert 一个新的，旧的留在里面，等它被 poll 出来时认出它过期了、丢掉。[第 8 站](#sssp)的 Dijkstra 就是这么写的。
:::

:::from
“unsorted array 和 sorted array 是两个极端，heap 是折中”、array 与 complete binary tree 的对应、heap property 推出 root 最大的证明、insert 与 delete max 的做法、把 heap 当作 array 的前缀来做 in-place 的 heap sort、“办法一付的是 depth，办法二付的是 height”，来自 [MIT 6.006 第 8 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec8/)的讲义。那一讲用 0-based 的 index，build heap 的 sum 是用 Stirling's approximation 估的；这里改成 NUS 用的 1-based index，sum 改用错位相减，按 [VisuAlgo 的 heap e-Lecture](https://visualgo.net/en/heap/print)“height 为 $h$ 的 node 至多 $\lceil n/2^{h+1}\rceil$ 个”的数法来写。“和较大的 child 换”的反例、`PriorityQueue` 不能改 key 的说明，以及所有 array 和数字，是为这一页写和算的。
:::

## [bst] Binary search tree 与 AVL tree

:::skip
能由 $N_h=1+N_{h-1}+N_{h-2}$ 说明 AVL tree 的 height 是 $O(\log n)$，能对四种 case 各做出正确的 rotation 并说出 left-right 为什么要两次，就可以去第 6 站。
:::

### 既要 order，又要改得快

到这里还缺一种结构。Sorted array 能回答所有和 order 有关的问题（minimum、“比 $k$ 大的下一个 key”、第 $k$ 小），但 insert 是 $O(n)$。Hash table 的 insert 是 $O(1)$，但完全没有 order。Heap 只知道 max。

Binary search tree 把 binary search 的过程本身存成一棵 tree。每个 node 存一个 key，并满足 BST property：

> 对每个 node $x$：left subtree 里所有的 key 都小于 $x$ 的 key，right subtree 里所有的 key 都大于 $x$ 的 key。

这一站的例子，是依次 insert 50, 30, 70, 20, 40, 60, 80, 35 得到的 tree：

```
              50
            /    \
          30      70
         /  \    /  \
       20    40 60   80
            /
          35
```

**Search**：从 root 开始，要找的 key 比当前 node 小就往左，大就往右。找 35：比 50 小，往左；比 30 大，往右；比 40 小，往左；找到。每比一次，就排除掉另一边的整棵 subtree，这正是 BST property 允许的。

**Insert**：按 search 的走法一直走到走不下去的空位，把新 node 挂在那里。上面那棵 tree 就是这样长出来的：35 是最后来的，它比 50 小、比 30 大、比 40 小，于是成了 40 的 left child。

**Inorder traversal**：先走 left subtree，再输出自己，再走 right subtree。按 BST property，输出的是 sorted 的：20 30 35 40 50 60 70 80。

Search 和 insert 都只走一条从 root 往下的 path，代价是 $O(h)$，$h$ 是 tree 的 height。

:::wrong 只要每个 node 的 left child 比它小、right child 比它大，就是 BST
把例子里的 35 拿掉，在 40 的右边挂一个 55。每个 node 和自己的 child 之间都没有问题（55 比 40 大）。可是 55 在 50 的 left subtree 里，却比 50 大。Search 55 时在 root 就往右走了，永远找不到它。BST property 约束的是整棵 subtree，不只是 child。检查一棵 tree 是不是 BST，要么对每个 node 记下它的 key 允许的范围，要么看 inorder traversal 是不是 sorted。
:::

### Successor 与 delete

$x$ 的 successor 是 sorted order 里紧跟在 $x$ 后面的 key。在 tree 里分两种情况找。

**$x$ 有 right subtree**：successor 是 right subtree 里的 minimum，即往右走一步，再一直往左。30 的 successor：往右到 40，往左到 35，再往左没有了，是 35。理由：inorder traversal 输出 $x$ 之后，紧接着进入它的 right subtree，最先输出的就是那里最小的。

**$x$ 没有 right subtree**：往上走，直到某一步是“从 left child 走上去的”，到达的那个 ancestor 就是 successor。40 的 successor：40 是 30 的 right child，继续；30 是 50 的 left child，停，是 50。理由：$x$ 是那个 ancestor 的 left subtree 里最大的 key，inorder traversal 走完这棵 left subtree 之后输出的就是这个 ancestor。

如果一路走到 root 都是从 right child 上去的（比如 80），$x$ 就是 maximum，没有 successor。

**Delete** 按被删的 node 有几个 child 分三种情况：

- **没有 child**（删 20）：直接摘掉。
- **一个 child**（删 40）：让它唯一的 child 35 顶替它，挂到 30 的右边。
- **两个 child**（删 50）：不能直接摘，因为它留下两棵 subtree，而 parent 那里只空出一个位置。办法是把它的 key 换成 successor 的 key，再去删 successor 那个 node。50 的 successor 是 60，于是 root 的 key 改成 60，再删掉原来的 60。

::fig[cs2040-bstdel] 三种情况各自删完之后的 tree。

第三种情况为什么可行：$x$ 有两个 child，successor 就是 right subtree 的 minimum，它没有 left child（有的话就不是 minimum），所以删它属于前两种情况。换上来的 key 比 left subtree 的全部 key 大，又是 right subtree 里最小的，BST property 仍然成立。

三种情况都只走一条 path，$O(h)$。

### Height 可以有多糟

:::wrong BST 的 search 是 $O(\log n)$
它是 $O(h)$，而 $h$ 由 insert 的顺序决定。依次 insert 1, 2, 3, 4, 5, 6, 7，每个新 key 都比已有的大，都成为上一个的 right child，得到一条 height 为 6 的链。$n=10^6$ 时 height 是 999999；光是把它建起来，第 $i$ 个 key 要比 $i-1$ 次，一共约 $5\times10^{11}$ 次 comparison。同样的 key 最矮可以摆成 height $\lfloor\log_2n\rfloor=19$。按顺序到来的 key（学号、时间戳）在实际中很常见，所以这不是可以忽略的坏运气。
:::

需要一个 invariant，它既能保证 $h=O(\log n)$，又能在每次 insert、delete 之后便宜地修回来。要求 tree 完全对称太严，改一个 key 可能要重排整棵 tree。AVL tree 的要求松一些。

### AVL 的 invariant

每个 node 多存一个数：以它为 root 的 subtree 的 height。空 tree 的 height 记为 $-1$，leaf 是 0，一般地

$$h(x)=1+\max\big(h(x.\text{left}),\ h(x.\text{right})\big)$$

定义 balance factor $\mathrm{bf}(x)=h(x.\text{left})-h(x.\text{right})$。AVL tree 是满足下面这条 invariant 的 BST：

> 对每个 node $x$，$\mathrm{bf}(x)\in\{-1,0,+1\}$。

检查上面那棵 8 个 node 的 tree：$\mathrm{bf}(40)=0-(-1)=+1$；$\mathrm{bf}(30)=h(20)-h(40)=0-1=-1$；$\mathrm{bf}(70)=0-0=0$；$\mathrm{bf}(50)=h(30)-h(70)=2-1=+1$；四个 leaf 都是 0。它是 AVL tree。

这条 invariant 只管每个 node 自己的两边，它能管住整棵 tree 的 height 吗？问：height 为 $h$ 的 AVL tree 最少有几个 node，记作 $N_h$。$N_0=1$，$N_1=2$。Height 为 $h$ 的 tree，root 的两个 subtree 里必须有一个 height 是 $h-1$；另一个按 invariant 至少是 $h-2$。要 node 最少，两个 subtree 各取最少的：

$$N_h=1+N_{h-1}+N_{h-2}$$

| $h$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| $N_h$ | 1 | 2 | 4 | 7 | 12 | 20 | 33 |

::fig[cs2040-minavl] Height 为 0 到 3、node 最少的 AVL tree。

因为 $N_{h-1}>N_{h-2}$，有 $N_h>2N_{h-2}$：height 每增加 2，最少的 node 数至少翻一倍。从 $h$ 往下每次减 2，一路代到 $N_0=1$ 或 $N_1=2$：

$$N_h>2N_{h-2}>4N_{h-4}>\dots>2^{h/2}\qquad(h\ge1)$$

一棵有 $n$ 个 node、height 为 $h$ 的 AVL tree 满足 $n\ge N_h>2^{h/2}$，两边取 $\log_2$：

$$h<2\log_2n$$

代入 $n=10^6$：这个 bound 给出 $h<39.9$；直接按 recurrence 往下算，$N_{27}=832039\le10^6<N_{28}=1346268$，所以 height 最多是 27。一次 search 最多看 28 个 node，而那条链要看 $10^6$ 个。

### Rotation

Insert 会破坏 invariant。取 tree 50(30(20, 40), 70)，也就是依次 insert 50, 30, 70, 20, 40 的结果，再 insert 45。它比 50 小、比 30 大、比 40 大，成为 40 的 right child。现在 $h(40)=1$，$h(30)=2$，于是

$$\mathrm{bf}(30)=h(20)-h(40)=0-1=-1,\qquad\mathrm{bf}(50)=h(30)-h(70)=2-0=+2$$

50 不满足 invariant 了。注意两点：height 变了的只可能是新 leaf 的 ancestor，别的 node 的 subtree 里什么都没变；每个 ancestor 的 height 最多加 1，所以 balance factor 最坏是 $\pm2$。

修复的工具是 rotation：

::fig[cs2040-rotate] 一次 rotation 只改三个 pointer。三角形是整棵 subtree。

`rotateRight(Q)` 做三件事：$P$ 的 right subtree $B$ 改挂为 $Q$ 的 left subtree；$Q$ 成为 $P$ 的 right child；原来指向 $Q$ 的那个 pointer（$Q$ 的 parent 的，或者 root）改指 $P$。然后重算 $Q$ 和 $P$ 的 height，先 $Q$ 后 $P$，因为 $Q$ 现在在下面。全部是 $O(1)$。

Rotation 前后 inorder 都是 $A\ P\ B\ Q\ C$，所以 BST property 不受影响。变的是 depth：$A$ 整体升一层，$C$ 整体降一层，$B$ 不动。这就是用它调 height 的办法。

### 四种 case

设 $Q$ 是从新 leaf 往上走遇到的第一个不平衡的 node，先看 $\mathrm{bf}(Q)=+2$（左边高）。沿用图里的名字，$P$ 是 $Q$ 的 left child。设 $h(C)=k$，那么 $h(P)=k+2$。多出来的 height 在 $A$ 里还是在 $B$ 里，处理不同。

**Left-left：$\mathrm{bf}(P)=+1$**，即 $h(A)=k+1$，$h(B)=k$。做 `rotateRight(Q)`，把 $A$ 升一层：

| | $Q$ 的两个 subtree | $h(Q)$ | $P$ 的两个 subtree | $\mathrm{bf}(P)$ |
|---|---|---|---|---|
| 之后 | $B$（$k$）和 $C$（$k$） | $k+1$ | $A$（$k+1$）和 $Q$（$k+1$） | 0 |

两个 node 都平衡了，整棵 subtree 的 height 从 $k+3$ 回到 $k+2$。

**Left-right：$\mathrm{bf}(P)=-1$**，即 $h(A)=k$，$h(B)=k+1$。

:::wrong 左边高就 `rotateRight`，一次就够
同样做 `rotateRight(Q)`：$Q$ 的两个 subtree 是 $B$（$k+1$）和 $C$（$k$），$h(Q)=k+2$；$P$ 的两个 subtree 是 $A$（$k$）和 $Q$（$k+2$），$\mathrm{bf}(P)=-2$。不平衡从左边搬到了右边。原因在上一小节：rotation 只升 $A$、降 $C$，$B$ 的 depth 不变，而这次高出来的正是 $B$。用刚才的例子核对：对 50 直接 `rotateRight`，得到 30(20, 50(40(–, 45), 70))，$\mathrm{bf}(30)=h(20)-h(50)=0-2=-2$。
:::

所以先对 $P$ 做一次 `rotateLeft`，把高出来的部分从“里侧”挪到“外侧”，变成 left-left，再 `rotateRight(Q)`。

::fig[cs2040-avllr] 刚才的例子：insert 45 之后是 left-right case。

用 height 核对这两步。设 $B$ 的 root 是 $R$，它的两个 subtree $B_1$、$B_2$ 的 height 是 $k$ 或 $k-1$（至少一个是 $k$）。两次 rotation 之后 $R$ 在最上面，左边是 $P$ 带着 $A$（$k$）和 $B_1$，右边是 $Q$ 带着 $B_2$ 和 $C$（$k$）。$h(P)=h(Q)=k+1$，$\mathrm{bf}(R)=0$；$\mathrm{bf}(P)=k-h(B_1)$ 是 0 或 $+1$，$\mathrm{bf}(Q)=h(B_2)-k$ 是 0 或 $-1$。整棵 subtree 的 height 同样从 $k+3$ 回到 $k+2$。图里 $k=0$，$R$ 是 40，$B_1$ 是空的，$B_2$ 是 45。

$\mathrm{bf}(Q)=-2$ 时左右对调，一共四种：

| $\mathrm{bf}(Q)$ | 高的那个 child 的 bf | Case | 做法 |
|---|---|---|---|
| $+2$ | $+1$（delete 时也可能是 0） | left-left | `rotateRight(Q)` |
| $+2$ | $-1$ | left-right | `rotateLeft(Q.left)`，再 `rotateRight(Q)` |
| $-2$ | $-1$（delete 时也可能是 0） | right-right | `rotateLeft(Q)` |
| $-2$ | $+1$ | right-left | `rotateRight(Q.right)`，再 `rotateLeft(Q)` |

Right-right 最小的例子：依次 insert 10, 20, 30，$\mathrm{bf}(10)=-1-1=-2$，$\mathrm{bf}(20)=-1$，`rotateLeft(10)` 之后是 20(10, 30)。

**Insert 的完整过程**：按 BST 的办法 insert；沿 path 往回走，每到一个 ancestor 就重算 height、检查 bf；遇到第一个 $\pm2$ 的 node，按表处理。处理完就可以停了：insert 之前这棵 subtree 的 height 是 $k+2$，insert 让它变成 $k+3$，修完又回到 $k+2$，再往上的 ancestor 看到的和 insert 之前一样。所以一次 insert 最多做一组 rotation（一次或两次）。把 1 到 7 依次 insert 进 AVL tree，在 insert 3、5、6、7 时各做一次 `rotateLeft`，最后是一棵 height 为 2 的满 tree，而不是 height 为 6 的链。

**Delete**：按 BST 的办法 delete；从被摘掉的 node 的 parent 开始往上走到 root，每个 ancestor 都重算、检查、需要时按表处理。和 insert 不同，这里不能提前停：delete 之前 subtree 的 height 是 $k+3$，修完可能变成 $k+2$，上面的 ancestor 看到它矮了一层，可能轮到自己不平衡。最多每个 ancestor 修一次，$O(\log n)$ 组 rotation。表里“也可能是 0”那两格只在 delete 时出现：$h(A)=h(B)=k+1$ 时做 `rotateRight(Q)`，$Q$ 的两个 subtree 是 $B$（$k+1$）和 $C$（$k$），$P$ 的是 $A$（$k+1$）和 $Q$（$k+2$），$\mathrm{bf}$ 分别是 $+1$ 和 $-1$，一次就够。

AVL tree 上 search、insert、delete、minimum、successor 全部是 $O(\log n)$。

### 多存一个 size：rank 与 select

再问两个 hash table 和 heap 都答不了的问题：第 $k$ 小的 key 是谁（`select(k)`），$v$ 在 sorted order 里排第几（`rank(v)`）。做 inorder traversal 是 $O(n)$。

办法和存 height 一样：每个 node 多存一个 $\text{size}(x)$，即它的 subtree 里的 node 数，$\text{size}(x)=\text{size}(x.\text{left})+\text{size}(x.\text{right})+1$。拿上图最右边那棵 tree：

```
          40 (6)
         /      \
     30 (2)     50 (3)
     /          /    \
  20 (1)    45 (1)   70 (1)
```

**select(k)**：在 node $x$ 处，设 $L=\text{size}(x.\text{left})$，那么 $x$ 在自己这棵 subtree 里排第 $L+1$。$k=L+1$ 就是 $x$；$k\le L$ 往左，$k$ 不变；否则往右，同时把 $k$ 减去 $L+1$（左边那 $L$ 个和 $x$ 自己都排在前面）。

`select(4)`：在 40 处 $L=2$，$4>3$，往右，$k$ 变成 1；在 50 处 $L=1$，$1\le1$，往左；在 45 处 $L=0$，$k=1=L+1$，答案是 45。核对：sorted order 是 20 30 40 45 50 70，第 4 个是 45。

**rank(v)**：像 search 一样往下走，同时累加。每次往右走，就加上 $\text{size}(x.\text{left})+1$；找到 $v$ 时，再加上它自己的 $\text{size}(\text{left})+1$。`rank(50)`：在 40 处往右，加 $2+1=3$；在 50 处找到，加 $1+1=2$；一共 5。

两个都只走一条 path，$O(\log n)$。Size 的维护也和 height 一样：insert、delete 时沿 path 更新；rotation 只改变 $Q$ 和 $P$ 两个 node 的 subtree，先重算 $Q$ 再重算 $P$。

一般的规则是：一个 node 上的附加信息，只要能由它的两个 child 的信息在 $O(1)$ 内算出来，就能这样维护。Height、size、subtree 里的 sum 或 max 都属于这一类。

Java 的 `TreeSet` 和 `TreeMap` 是 balanced BST，提供 `first`、`last`、`higher`、`lower`、`floor`、`ceiling`，都是 $O(\log n)$；它们没有 rank 和 select，需要时得自己写带 size 的 AVL tree。

:::back
[第 3 站](#hash)的 hash table 给 $O(1)$ 但没有 order，[第 4 站](#heap)的 heap 只管 max；需要 successor、range、rank 这类 operation 时才轮到这一站。
:::

:::from
“每个 operation 是 $O(h)$，所以目标是让 $h=O(\log n)$”、successor 的两种情况、把有两个 child 的 delete 归结到删 leaf，来自 [MIT 6.006 第 6 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec6/)的讲义（那一讲的 delete 是把 item 一路换到 leaf 再摘掉；这里写的是 VisuAlgo 的三种情况）。Rotation 保持 traversal order、$N_h$ 的 recurrence、“只有 ancestor 的 height 会变，且最多差到 2”、用 $k$ 表示各个 subtree 的 height 来逐个核对 case、insert 只需修一处而 delete 可能一路修到 root、“能由 child 在 $O(1)$ 内算出的信息都可以维护”，来自 [6.006 第 7 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec7/)。那一讲用的是 skew（右减左）；这里用 NUS 的 balance factor（左减右）和四种 case 的叫法，这些以及 $N_h$ 的表、$h<2\log_2n$ 的写法取自 [VisuAlgo 的 bst e-Lecture](https://visualgo.net/en/bst/print)。VisuAlgo 定义了 Rank 和 Select 但没有给做法，这里的做法是把 6.006 第 6 讲按 subtree size 找第 $i$ 个 node 的办法改成从 1 数起。所有的 tree 和数字是为这一页构造和算的。

### 怎么把 graph 存下来

Graph $G=(V,E)$ 是一组 vertex 和连接它们的 edge。下面把 vertex 的个数、edge 的条数也直接写成 $V$、$E$。这一站前半部分用一个 undirected graph：vertex 是 a, b, c, d, e, f, g, s，edge 有 8 条：a–b, a–s, c–s, c–d, c–e, d–e, d–f, e–f。g 不和任何 vertex 相连。

::fig[cs2040-ugraph] 这一站前半部分用的 graph 和它的 adjacency list（neighbor 按字母顺序）。

存法有三种，差别在两个问题上：“$u$ 和 $v$ 之间有没有 edge”和“列出 $u$ 的所有 neighbor”。

| 存法 | 空间 | 有没有 edge $(u,v)$ | 列出 $u$ 的 neighbor |
|---|---|---|---|
| adjacency matrix：$V\times V$ 的表，有 edge 的格子是 1 | $V^2$ | 1 | $V$（扫一整行） |
| adjacency list：每个 vertex 一条 list，放它的 neighbor | $V+E$ | $\deg(u)$ | $\deg(u)$ |
| edge list：一个 array，每个 element 是一条 edge | $E$ | $E$ | $E$ |

例子的 adjacency list，neighbor 按字母顺序：

```
a: b s        e: c d f
b: a          f: d e
c: d e s      g:
d: c e f      s: a c
```

每条 undirected edge 在两端各出现一次，所以所有 list 的长度加起来是 $2E$：$2+1+3+3+3+2+0+2=16=2\times8$。这个等式是后面所有“$O(V+E)$”的来源。Traversal 要不断地列出 neighbor，所以用 adjacency list；edge list 适合要把 edge 按 weight 排序的场合（第 7 站的 Kruskal）。

### BFS

问题：从 s 出发，到每个 vertex 最少要走几条 edge？

想法是一层一层往外：第 0 层是 s 自己，第 1 层是 s 的 neighbor，第 2 层是第 1 层的 neighbor 里还没到过的，依此类推。用一个 queue 就能按这个顺序处理：先发现的先处理。

```java
int[] D = new int[V];  Arrays.fill(D, -1);   // -1：还没到过
int[] p = new int[V];  Arrays.fill(p, -1);   // p[v]：从谁那里第一次到 v
Queue<Integer> q = new ArrayDeque<>();
D[s] = 0;  q.add(s);
while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : adj.get(u))
        if (D[v] == -1) { D[v] = D[u] + 1;  p[v] = u;  q.add(v); }
}
```

| dequeue | 新发现的 vertex | 之后的 queue |
|---|---|---|
| s | a（D = 1），c（1） | a c |
| a | b（2） | c b |
| c | d（2），e（2） | b d e |
| b | 没有 | d e |
| d | f（3） | e f |
| e | 没有 | f |
| f | 没有 | 空 |

g 始终没有进 queue，D 保持 $-1$，意思是从 s 到不了。

**D 为什么正确。** 先看 queue 的一个性质：进 queue 的 vertex，D 值是不减的。新进来的 $v$ 的 D 是正在处理的 $u$ 的 D 加 1，而 $u$ 是按进来的先后出去的，表里依次进 queue 的 D 是 0, 1, 1, 2, 2, 2, 3。

再对真实的 distance 做 induction：distance 为 $i$ 的 vertex 都得到 $D=i$。$i=0$ 只有 s。设 distance 小于 $i$ 的都对了，取一个 distance 为 $i$ 的 $v$ 和一条到它的 shortest path，path 上 $v$ 的前一个 vertex $u$ 的 distance 是 $i-1$，所以 $D[u]=i-1$。$u$ 出 queue 时会看到 $v$。如果 $v$ 还没有 D，它得到 $D[v]=i$。如果已经有了，那是更早出 queue 的某个 $x$ 给的，$D[v]=D[x]+1\le D[u]+1=i$。另一方面，$D[v]$ 是一条真实存在的 path 的 edge 数（沿着 $p$ 可以一步步走回 s），不可能小于 distance $i$。所以 $D[v]=i$。

**Running time。** 每个 vertex 最多进一次 queue（进的时候 D 就不再是 $-1$）。它出 queue 时把自己的 adjacency list 扫一遍，$\deg(u)$ 次。全部加起来是 $V+\sum\deg(u)=V+2E$，即 $O(V+E)$。

:::wrong BFS 是 $O(V+E)$，和 graph 怎么存没有关系
上面数 running time 时用了“扫 $u$ 的 neighbor 要 $\deg(u)$ 次”，这是 adjacency list 才有的。换成 adjacency matrix，列出一个 vertex 的 neighbor 要扫一整行，$V$ 次，BFS 变成 $O(V^2)$。$V=10^5$、$E=2\times10^5$ 时，$V+2E=5\times10^5$，而 $V^2=10^{10}$，这样的 matrix 连存都存不下。
:::

### DFS

DFS 换一种走法：到了一个 vertex，立刻去它的第一个没到过的 neighbor，一路走到走不动，再退回上一个 vertex 试下一个 neighbor。Recursion 自带的 call stack 记住了“退回哪里”。

```java
void dfs(int u) {
    visited[u] = true;
    for (int v : adj.get(u))
        if (!visited[v]) { p[v] = u;  dfs(v); }
    // 走到这里，u 的 neighbor 全部处理完了：u finish
}
```

在同一个 graph 上 `dfs(s)`：s 先去 a；a 的 neighbor 里 b 没到过，去 b；b 的 neighbor 只有 a，到过了，b finish，退回 a；a 的另一个 neighbor s 到过了，a finish，退回 s。s 的下一个 neighbor 是 c；c 去 d；d 的 neighbor 里 c 到过了，去 e；e 的 neighbor 里 c、d 到过了，去 f；f 的 neighbor 都到过了。然后 f、e、d、c、s 依次 finish。Visit 的次序是 s a b c d e f。

::fig[cs2040-bfsdfs] 同一个 graph，同一个起点。左边按 distance 分层，右边一条路走到底。

Running time 的数法和 BFS 一样：每个 vertex 被 visit 一次，每条 adjacency list 被扫一次，$O(V+E)$。

:::wrong DFS 也走遍了所有到得了的 vertex，所以沿它的 tree 走也是 shortest path
图里 DFS tree 上 s 到 f 是 s → c → d → e → f，4 条 edge，而 BFS 给出的是 3 条；s 到 e 在 DFS tree 上是 3 条，实际 2 条就到。DFS 第一次到达一个 vertex 时走的只是“碰巧先试的那条路”。要最少的 edge 数，用 BFS。
:::

DFS 给出而 BFS 没有的，是 finish 的先后，后两小节都靠它。

**数 connected component。** 一次 `dfs(s)` 只到得了 s 所在的那一块。外面套一层 loop，每遇到一个还没 visit 的 vertex 就从它再出发一次，出发的次数就是 component 的个数：

```java
int cc = 0;
for (int u = 0; u < V; u++)
    if (!visited[u]) { cc++;  dfs(u); }
```

例子里是 2：一块是 a, b, c, d, e, f, s，另一块只有 g。每个 vertex 仍然只被 visit 一次，total 还是 $O(V+E)$。

### Topological sort

现在看 directed graph。Edge $u\to v$ 表示“$u$ 必须排在 $v$ 前面”（先修课、编译的依赖都是这种关系）。要把所有 vertex 排成一行，使每条 edge 都从前指向后，这样的次序叫 topological order。

有 directed cycle 就排不出来：cycle 上的每个 vertex 都得排在自己前面。没有 directed cycle 的 directed graph 叫 DAG；下面的两个 algorithm 说明 DAG 一定排得出来。

::fig[cs2040-dag] 例子：6 个 vertex，6 条 edge：0→1, 0→2, 1→3, 2→3, 3→5, 4→5。

**Kahn's algorithm。** In-degree 为 0 的 vertex 没有任何前置，可以排在最前面。把它输出，再把它发出的 edge 划掉（对应的 in-degree 减 1），又会出现新的 in-degree 为 0 的 vertex。用一个 queue 放“现在 in-degree 为 0”的 vertex。

开始时 in-degree 是 $[0,1,1,2,0,2]$，queue 里是 0 和 4。

| dequeue | in-degree 的变化 | 之后的 queue |
|---|---|---|
| 0 | vertex 1：1 → 0；vertex 2：1 → 0 | 4 1 2 |
| 4 | vertex 5：2 → 1 | 1 2 |
| 1 | vertex 3：2 → 1 | 2 |
| 2 | vertex 3：1 → 0 | 3 |
| 3 | vertex 5：1 → 0 | 5 |
| 5 | | 空 |

输出 0 4 1 2 3 5。每个 vertex 进出 queue 一次，每条 edge 被划掉一次，$O(V+E)$。

DAG 里为什么总找得到 in-degree 为 0 的 vertex？如果每个 vertex 都有 incoming edge，就可以从任意一个 vertex 出发沿 incoming edge 一直倒着走；vertex 只有有限个，迟早走回到过的 vertex，那就是一个 cycle。划掉一个 vertex 之后剩下的仍是 DAG，同一个理由继续适用。反过来，graph 里有 cycle 时，cycle 上的 vertex 的 in-degree 永远减不到 0，输出的 vertex 会少于 $V$ 个：Kahn's algorithm 顺带检测了 cycle。

**DFS 的做法。** 对整个 graph 做 DFS（外面套上数 component 用的那层 loop），每个 vertex finish 时把它记下来，最后把记下的次序倒过来。

例子里按 0 到 5 的顺序起步：`dfs(0)` 走 0 → 1 → 3 → 5，然后 5、3、1 依次 finish；回到 0，去 2，2 的 neighbor 3 到过了，2 finish；0 finish。再 `dfs(4)`，它的 neighbor 5 到过了，4 finish。Finish 的次序是 5 3 1 2 0 4，倒过来是 4 0 2 1 3 5。

要证明的是：对每条 edge $u\to v$，$v$ 比 $u$ 先 finish（倒过来之后 $u$ 就在 $v$ 前面）。分两种情况。

- **$u$ 先被 visit。** `dfs(u)` 会查看 edge $u\to v$。那一刻 $v$ 要么已经在 `dfs(u)` 的过程中被 visit 并 finish 了，要么现在就被 visit。两种情形下 $v$ 都在 `dfs(u)` 返回之前 finish，也就是比 $u$ 先。
- **$v$ 先被 visit。** `dfs(v)` 的过程中会不会走到 $u$？那需要一条从 $v$ 到 $u$ 的 path，加上 $u\to v$ 就是一个 cycle，DAG 里没有。所以 `dfs(v)` 返回时 $u$ 还没被 visit，$v$ 先 finish。

两个 algorithm 给的次序不同，都是对的。Topological order 一般不唯一，这个例子一共有 10 个：5 必须在最后（3 和 4 都在它前面，而 0、1、2 都在 3 前面）；0, 1, 2, 3 之间 0 最先、3 最后，1 和 2 可以互换，2 种；4 只要求在 5 之前，可以插进这四个之间的 5 个空位中的任何一个；$2\times5=10$。

**用 DFS 检测 cycle。** 给每个 vertex 三种状态：还没 visit；已经 visit 但还没 finish（它正在 call stack 上）；已经 finish。DFS 途中查看 edge $u\to v$ 时，如果 $v$ 处在第二种状态，说明 $v$ 是 $u$ 的 ancestor，从 $v$ 沿 tree 走到 $u$ 再走这条 edge 就回到 $v$，这是一个 cycle。只用“visit 过没有”两种状态是分不清的：上面 `dfs(2)` 查看 2→3 时，3 也 visit 过了，但它已经 finish，这条 edge 不构成 cycle。

### Strongly connected component：Kosaraju's algorithm

在 directed graph 里，“$u$ 能到 $v$”不等于“$v$ 能到 $u$”。如果两个方向都有 path，就说 $u$ 和 $v$ 在同一个 strongly connected component（SCC）里。

::fig[cs2040-scc] 8 个 vertex，11 条 edge：5→6, 6→7, 7→5, 6→0, 0→1, 1→0, 1→2, 7→2, 2→3, 3→4, 4→2。灰色的三块是它的三个 SCC。

把每个 SCC 缩成一个点，得到的一定是 DAG（图的下半部分）：如果两个 SCC 之间来回都有 edge，它们里面的 vertex 就互相到得了，本该是同一个 SCC。

数 SCC 不能照搬数 connected component 的办法。在这个 graph 上 `dfs(0)` 会 visit 0, 1, 2, 3, 4，把 $C_2$ 和 $C_3$ 混在了一起，因为有 edge 从 $C_2$ 通向 $C_3$。但如果从 $C_3$ 里的 vertex 出发，$C_3$ 没有通向别的 SCC 的 edge，DFS 恰好 visit 完 $C_3$ 就停。所以思路是：每次都从一个“出不去”的 SCC 里起步，走完一块，划掉，再找下一个出不去的。难处是事先不知道 SCC，怎么知道哪个 vertex 在出不去的 SCC 里。

Kosaraju's algorithm 用两遍 DFS 解决：

1. 在 $G$ 上做一遍 DFS（套外层 loop），记下每个 vertex 的 finishing time $f$，第几个 finish 就是几。
2. 把每条 edge 反向，得到 transpose graph $G^\top$。
3. 在 $G^\top$ 上再做一遍 DFS，外层 loop 按 $f$ 从大到小挑起点。每次从外层 loop 起步所 visit 到的 vertex，就是一个 SCC。

它依赖一条 lemma：

> 如果 $G$ 里有 edge 从 SCC $C$ 指向另一个 SCC $C'$，那么第一遍 DFS 里，$C$ 中最大的 $f$ 大于 $C'$ 中最大的 $f$。

证明：看 $C\cup C'$ 里最先被 visit 的 vertex $x$。

- **$x$ 在 $C$ 里。** 这时 $C$ 和 $C'$ 的其他 vertex 都还没被 visit，而它们都是从 $x$ 到得了的（$C$ 内部互相可达，再经过那条 edge 进入 $C'$，途中经过的也都是这些还没 visit 的 vertex）。DFS 在返回之前会把这样到得了的 vertex 全部走完，所以它们都在 `dfs(x)` 返回之前 finish，$f(x)$ 比 $C'$ 里所有的 $f$ 都大。
- **$x$ 在 $C'$ 里。** 从 $C'$ 走不到 $C$（否则两者互相可达，是同一个 SCC）。`dfs(x)` 走完整个 $C'$ 就返回，这时 $C$ 里一个 vertex 都还没被 visit，它们之后才 finish，$f$ 全都比 $C'$ 里的大。

用图核对：按 0, 1, …, 7 的顺序起步，`dfs(0)` 走 0 → 1 → 2 → 3 → 4，finish 的次序是 4, 3, 2, 1, 0；`dfs(5)` 走 5 → 6 → 7（6 的 neighbor 0、7 的 neighbor 2 和 5 都到过了），finish 的次序是 7, 6, 5。所以 $f$ 依次是：vertex 4, 3, 2, 1, 0, 7, 6, 5 得到 1 到 8。三个 SCC 里最大的 $f$ 是 8、5、3，三条跨 SCC 的 edge（$C_1\to C_2$，$C_2\to C_3$，$C_1\to C_3$）都从大指向小。

**第三步为什么正确。** 全图 $f$ 最大的 vertex 所在的 SCC，不可能有别的 SCC 的 edge 指向它（按 lemma，指向它的那个 SCC 的最大 $f$ 会更大）。在 $G^\top$ 里方向全反过来，这就成了“它没有 edge 指向别的 SCC”，正是出不去的那一块；而 SCC 内部反向之后仍然互相可达。所以从这个 vertex 在 $G^\top$ 上 DFS，恰好 visit 完它的 SCC。接下来挑剩下的 vertex 里 $f$ 最大的：它的 SCC 在 $G^\top$ 里只可能有 edge 通向最大 $f$ 更大的 SCC，而那些已经被 visit 过了，DFS 进不去。每次起步都恰好圈出一个 SCC。

走一遍。$G^\top$ 的 adjacency list：

```
0: 1 6      4: 3
1: 0        5: 7
2: 1 4 7    6: 5
3: 2        7: 6
```

按 $f$ 从大到小，起点的候选次序是 5, 6, 7, 0, 1, 2, 3, 4。

| 起点 | 走到的 vertex | 得到的 SCC |
|---|---|---|
| 5 | 5 → 7 → 6（6 的 neighbor 5 到过了） | {5, 6, 7} |
| 0（6、7 已经 visit） | 0 → 1；0 的另一个 neighbor 6 到过了 | {0, 1} |
| 2（1 已经 visit） | 2 → 4 → 3；2 的 neighbor 1、7 都到过了 | {2, 3, 4} |

三个 SCC。两遍 DFS 加上建 $G^\top$，都是 $O(V+E)$。

### 问题：用最小的 total weight 把所有 vertex 连起来

给一个 connected 的 undirected graph，每条 edge 有 weight。要选出一部分 edge，使所有 vertex 连在一起，并且选中的 edge 的 total weight 最小。

选出来的一定是一棵 tree：如果里面有 cycle，去掉 cycle 上任意一条 edge，vertex 仍然连着，total weight 不会变大。连着 $V$ 个 vertex 的 tree 恰好有 $V-1$ 条 edge，叫 spanning tree；total weight 最小的叫 minimum spanning tree（MST）。

::fig[cs2040-mst] 这一站的例子：6 个 vertex，9 条 edge，weight 互不相同。

把所有 spanning tree 列出来比较行不通。这个小 graph 就有 55 棵；20 个 vertex 两两相连的 graph 有 $20^{18}\approx2.6\times10^{23}$ 棵。需要一条判断规则，只看局部就能断定某条 edge 在不在 MST 里。

### Cut property

把 vertex 分成非空的两组，叫一个 cut；两端分属两组的 edge 叫 crossing edge。

> Cut property：设各条 edge 的 weight 互不相同。对任何一个 cut，weight 最小的 crossing edge 一定在 MST 里。

证明：设 $e$ 是这个 cut 上最轻的 crossing edge，假设 MST $T$ 不含 $e$。

1. 把 $e$ 加进 $T$。$T$ 本来已经把 $e$ 的两端连起来了，所以多出一个包含 $e$ 的 cycle。
2. 沿这个 cycle 走一圈：$e$ 从 cut 的一边跨到另一边，要回到起点就必须再跨回来，所以 cycle 上至少还有一条 crossing edge $f$。
3. 从 $T$ 加上 $e$ 的结果里去掉 $f$。Cycle 断开了，所有 vertex 仍然连着，edge 数回到 $V-1$，得到另一棵 spanning tree $T'$。
4. $e$ 是最轻的 crossing edge，$f$ 也是 crossing edge 且 weight 不同，所以 $w(e)<w(f)$，$T'$ 的 total weight 比 $T$ 小，与 $T$ 是 MST 矛盾。

用一次：图的右半边那个 cut 把 vertex 分成 {0, 1, 2} 和 {3, 4, 5}，crossing edge 是 1–3（6）、2–3（5）、2–4（7），最轻的 2–3 一定在 MST 里。再取 cut {0} 和其余：crossing edge 是 0–1（4）和 0–2（1），所以 0–2 在 MST 里。

Prim 和 Kruskal 都是在反复使用这条性质，差别只在每次挑哪个 cut。

### Prim's algorithm

从一个 vertex 出发，维护一棵不断长大的 tree $T$。每一步取的 cut 是“已经在 $T$ 里的 vertex”对“还不在的”，把最轻的 crossing edge 和它那一端的新 vertex 加进来。按 cut property，加进来的每条 edge 都在 MST 里；加满 $V-1$ 条，就是 MST。

要反复取“最轻的 crossing edge”，用 priority queue（min heap）放候选的 edge。一个 vertex 加入 $T$ 时，把它通向 $T$ 外面的 edge 都放进 PQ。取出来的 edge 可能已经过期：它的另一端在这期间也进了 $T$，它不再是 crossing edge，丢掉就行。

从 vertex 0 开始，PQ 里先有 0–2（1）和 0–1（4）：

| 从 PQ 取出 | 处理 | 新放进 PQ 的 edge |
|---|---|---|
| 0–2（1） | 加入，$T$ = {0, 2} | 2–1（3），2–3（5），2–4（7） |
| 2–1（3） | 加入，$T$ = {0, 1, 2} | 1–3（6） |
| 0–1（4） | 1 已经在 $T$ 里，丢掉 | |
| 2–3（5） | 加入，$T$ = {0, 1, 2, 3} | 3–4（2），3–5（8） |
| 3–4（2） | 加入，$T$ 多了 4 | 4–5（9） |
| 1–3（6） | 丢掉 | |
| 2–4（7） | 丢掉 | |
| 3–5（8） | 加入，$T$ 包含全部 6 个 vertex | |

Total weight 是 $1+3+5+2+8=19$。

Running time：每条 edge 最多进一次 PQ（在它先加入 $T$ 的那一端加入时；另一端加入时它已经不通向 $T$ 外面了），所以 PQ 里最多 $E$ 个 element，进出各 $E$ 次，每次 $O(\log E)$。又因为 $E<V^2$，$\log E<2\log V$，所以 Prim 是 $O(E\log V)$。

### Kruskal's algorithm

Kruskal 不从某个 vertex 出发，而是看全局：把所有 edge 按 weight 从小到大排好，依次考虑，只要一条 edge 不和已经选中的 edge 形成 cycle 就选中它，选满 $V-1$ 条为止。

| edge | weight | 两端已经连着了吗 | 结果 |
|---|---|---|---|
| 0–2 | 1 | 没有 | 选中 |
| 3–4 | 2 | 没有 | 选中 |
| 1–2 | 3 | 没有 | 选中 |
| 0–1 | 4 | 连着（0–2–1） | 丢掉 |
| 2–3 | 5 | 没有 | 选中 |
| 1–3 | 6 | 连着 | 丢掉 |
| 2–4 | 7 | 连着 | 丢掉 |
| 3–5 | 8 | 没有 | 选中，够 5 条，停 |

选中的 edge 和 Prim 的一样。

**为什么正确。** 选中 $e=u$–$v$ 的时候，$u$ 和 $v$ 在已选 edge 构成的不同 component 里。取 cut：$u$ 所在的 component 对其余所有 vertex。已选的 edge 没有一条跨这个 cut（跨的话，它另一端的 vertex 就该在 $u$ 的 component 里）。比 $e$ 轻的 edge 都已经考虑过，它们当中没有被选中的，都是因为当时两端已经连着；连着的两个 vertex 之后永远在同一个 component 里，所以它们也不跨这个 cut。于是 $e$ 是这个 cut 上最轻的 crossing edge，按 cut property 在 MST 里。被丢掉的 edge 会和已经确定在 MST 里的 edge 形成 cycle，tree 里没有 cycle，所以它不在 MST 里。

**瓶颈在哪。** 排序是 $O(E\log E)$。麻烦的是表里第三列：“这两个 vertex 已经连着了吗”要问 $E$ 次。每次在已选的 edge 上做一遍 DFS 是 $O(V)$，合计 $O(EV)$，比排序慢得多。需要一个结构专门回答这个问题，并且支持“把两个 component 合成一个”。

### Union-find：从贴标签到 tree

要维护的是一些互不相交的 set（每个 component 一个），支持两个 operation：`findSet(i)` 返回 $i$ 所在 set 的代表，两个 element 的代表相同就在同一个 set 里；`unionSet(i, j)` 把两个 set 合并。

**第一个想法：贴标签。** 用一个 array 记每个 element 所属 set 的编号。`findSet` 是一次访问。但合并两个 set 时，要把其中一个 set 的所有 element 的编号都改掉，得扫整个 array，$O(n)$。$n-1$ 次合并是 $O(n^2)$。

**第二个想法：每个 set 是一棵 tree。** 用 array $p$ 记每个 element 的 parent，root 的 parent 是它自己，root 就是这个 set 的代表。`findSet(i)` 从 $i$ 沿 $p$ 往上走到 root。`unionSet(i, j)` 先找到两边的 root，再让其中一个 root 指向另一个，只改一个格子。

合并变便宜了，`findSet` 的代价变成 $i$ 的 depth。如果合并时随手挂，tree 可以很高：依次把 {0} 挂到 1 下面，把 1 这棵挂到 2 下面，再挂到 3 下面……得到一条链 $0\to1\to2\to\dots\to n-1$，`findSet(0)` 要走 $n-1$ 步，又回到了 $O(n)$。

**Union by rank。** 每个 root 记一个 rank，初始为 0，它是这棵 tree 的 height 的 upper bound。合并时让 rank 小的 root 指向 rank 大的 root，rank 不变；两边 rank 相等时任选一个当新的 root，它的 rank 加 1。

> Rank 为 $r$ 的 root，它的 tree 里至少有 $2^r$ 个 element。

对 $r$ 做 induction。Rank 0 的 tree 至少有它自己 1 个，$2^0=1$。一个 root 的 rank 变成 $r+1$ 只有一种途径：两棵 rank 都是 $r$ 的 tree 合并，按假设各自至少有 $2^r$ 个 element，合起来至少 $2^{r+1}$ 个。Rank 不等的合并不改变 rank，只让 element 更多，结论仍然成立。

所以 $2^r\le n$，$r\le\log_2n$，tree 的 height 不超过 $\log_2n$，`findSet` 是 $O(\log n)$。下图左边是 8 个 element 做 union(0,1), (2,3), (4,5), (6,7), (1,3), (5,7), (3,7) 的结果：rank[7] = 3，tree 里恰好 $2^3=8$ 个 element，`findSet(0)` 要走 3 步。这是 8 个 element 能达到的最坏情况。

**Path compression。** `findSet` 既然已经花力气走到了 root，就顺手把 path 上经过的每个 element 都直接挂到 root 下面。这次多做的事和走的步数一样多，以后再找这些 element 就只要一步。

::fig[cs2040-ufds] 对左边的 tree 做一次 findSet(0)。

```java
int findSet(int i) {
    if (p[i] == i) return i;
    return p[i] = findSet(p[i]);            // 回来的路上把 p[i] 改成 root
}

void unionSet(int i, int j) {
    int x = findSet(i), y = findSet(j);
    if (x == y) return;
    if (rank[x] > rank[y]) p[y] = x;
    else { p[x] = y;  if (rank[x] == rank[y]) rank[y]++; }
}
```

两样都用上之后，任意 $m$ 次 operation 的 total time 是 $O(m\,\alpha(n))$，$\alpha$ 是 inverse Ackermann function，对任何实际会遇到的 $n$ 都不超过 4。这个结论的证明不在这门课的范围里，这里只给出结论；使用时把每次 operation 当作几乎 $O(1)$。

:::wrong rank[x] 就是以 x 为 root 的 tree 的 height
只做 union by rank 时确实相等。加上 path compression 就不是了：图里 findSet(0) 之后 tree 的 height 从 3 降到 2，而 rank[7] 仍然是 3，因为 path compression 不去改 rank。Rank 只增不减，是 height 的 upper bound，合并时拿它做比较已经足够。题目问“若干次 operation 之后 rank 是多少”时，要按 unionSet 的规则一步一步算，不能照着最后的 tree 去量 height。
:::

回到 Kruskal，把刚才那张表用 union-find 重走一遍。开始时 $p=[0,1,2,3,4,5]$，rank 全是 0。

| edge | 两个 root | 动作 | 之后的 $p$ |
|---|---|---|---|
| 0–2 | 0 和 2，rank 相等 | $p[0]=2$，rank[2] 变成 1 | 2 1 2 3 4 5 |
| 3–4 | 3 和 4，rank 相等 | $p[3]=4$，rank[4] 变成 1 | 2 1 2 4 4 5 |
| 1–2 | 1（rank 0）和 2（rank 1） | $p[1]=2$ | 2 2 2 4 4 5 |
| 0–1 | 都是 2 | 丢掉 | 2 2 2 4 4 5 |
| 2–3 | 2 和 4，rank 都是 1 | $p[2]=4$，rank[4] 变成 2 | 2 2 4 4 4 5 |
| 1–3 | 都是 4；findSet(1) 走了 1 → 2 → 4 | 丢掉，path compression 把 $p[1]$ 改成 4 | 2 4 4 4 4 5 |
| 2–4 | 都是 4 | 丢掉 | 2 4 4 4 4 5 |
| 3–5 | 4（rank 2）和 5（rank 0） | $p[5]=4$ | 2 4 4 4 4 4 |

每条 edge 做两次 findSet、最多一次 unionSet，都几乎是 $O(1)$。Kruskal 的 running time 于是由排序决定：$O(E\log E)$，也就是 $O(E\log V)$。

:::wrong MST 上 u 到 v 的 path，就是 u 到 v 的 shortest path
在例子里看 1 到 3。MST 上的 path 是 1–2–3，weight 是 $3+5=8$；而 graph 里有一条直接的 edge 1–3，weight 是 6，它不在 MST 里（Kruskal 考虑它时 1 和 3 已经连着了）。MST 让所有选中的 edge 的 total weight 最小，对某两个 vertex 之间的 distance 没有任何承诺。Shortest path 是另一个问题，在[第 8 站](#sssp)。
:::

:::edge 有 weight 相同的 edge 时
MST 可能不止一棵，但它们的 total weight 相同，Prim 和 Kruskal 给出的都是其中之一。这时 cut property 要改成“最轻的 crossing edge 当中，至少有一条在某一棵 MST 里”，上面证明的第 4 步从“$T'$ 更轻”变成“$T'$ 不比 $T$ 重，所以也是 MST”。Weight 是负数不影响任何一步。
:::

:::back

:::

## [sssp] Shortest paths

:::skip

### Relax：只会把估计改小，而且永远不会改过头

给一个 directed graph，每条 edge $u\to v$ 有 weight $w(u,v)$，一个起点 $s$。一条 path 的 weight 是它上面各条 edge 的 weight 之和，$\delta(v)$ 记从 $s$ 到 $v$ 的所有 path 里最小的 weight。要对每个 $v$ 求出 $\delta(v)$。

第 6 站的 BFS 数的是 edge 的条数，对 weight 视而不见。上一站最后的例子说明 MST 也答不了这个问题。

所有 shortest path algorithm 用的是同一个动作。给每个 vertex 一个估计值 $D[v]$，开始时 $D[s]=0$，其余是 $\infty$。对一条 edge $u\to v$ 做 relax：

```java
if (D[u] + w < D[v]) { D[v] = D[u] + w;  p[v] = u; }
```

意思是：到 $u$ 已经有一条 weight 为 $D[u]$ 的 path，接上这条 edge 就是一条到 $v$ 的 path；它比现在知道的更短，就记下来。

Relax 有一条保证：$D[v]$ 要么是 $\infty$，要么是某一条真实存在的、从 $s$ 到 $v$ 的 path 的 weight。开始时成立（$D[s]=0$ 是空 path）；每次 relax 把 $D[v]$ 设成“一条到 $u$ 的真实 path 的 weight 加上一条 edge”，仍是一条真实 path 的 weight。所以无论按什么顺序 relax 多少次，

$$D[v]\ge\delta(v)$$

估计值只会从上面往下靠近正确答案，不会低过头。各个 algorithm 的全部差别，在于按什么顺序 relax 才能让每个 $D[v]$ 都降到 $\delta(v)$，以及要做多少次。

### Bellman–Ford

最不动脑的顺序：把所有 edge 各 relax 一遍，算一轮；一共做 $V-1$ 轮。

```java
for (int i = 1; i <= V - 1; i++)
    for (Edge e : edges)                          // e 是 u → v，weight 为 w
        if (D[e.u] != INF && D[e.u] + e.w < D[e.v])
            D[e.v] = D[e.u] + e.w;
```

例子：vertex 是 s, a, b, c；edge list 里的顺序是 a→c（1），b→a（−4），s→a（2），s→b（5）。

::fig[cs2040-bf] Bellman–Ford 的例子。虚线那条 edge 只在后面讲 negative cycle 时才加进来。

| | $D[s]$ | $D[a]$ | $D[b]$ | $D[c]$ | 这一轮里起作用的 relax |
|---|---|---|---|---|---|
| 开始 | 0 | ∞ | ∞ | ∞ | |
| 第 1 轮之后 | 0 | 2 | 5 | ∞ | s→a，s→b（前两条 edge 的起点还是 ∞） |
| 第 2 轮之后 | 0 | 1 | 5 | 3 | a→c 给出 $2+1=3$；b→a 给出 $5-4=1$ |
| 第 3 轮之后 | 0 | 1 | 5 | 2 | a→c 给出 $1+1=2$ |

到 c 的 shortest path 是 s → b → a → c，weight 是 $5-4+1=2$。

**为什么 $V-1$ 轮够了。** 要证的是：第 $i$ 轮之后，凡是 shortest path 不超过 $i$ 条 edge 的 vertex $v$，都有 $D[v]=\delta(v)$。对 $i$ 做 induction。$i=0$ 时只有 $s$，$D[s]=0$。设对 $i-1$ 成立。取一个 shortest path 不超过 $i$ 条 edge 的 $v$，设这条 path 的最后一条 edge 是 $u\to v$。Path 去掉最后一条 edge 的部分是到 $u$ 的一条 shortest path（如果到 $u$ 还有更短的，换上去就得到一条到 $v$ 更短的 path），它不超过 $i-1$ 条 edge，所以第 $i-1$ 轮之后 $D[u]=\delta(u)$。第 $i$ 轮里 $u\to v$ 被 relax 一次，之后 $D[v]\le\delta(u)+w(u,v)=\delta(v)$；加上 $D[v]\ge\delta(v)$，两者相等。

没有 negative cycle 时，shortest path 不需要重复经过任何 vertex（重复经过就是绕了一个 cycle，它的 weight 不是负的，去掉它不会变长），所以最多 $V-1$ 条 edge，$V-1$ 轮之后全部正确。例子里到 c 的 shortest path 恰好有 $3=V-1$ 条 edge，而 edge list 的顺序又正好和 path 的方向相反，所以三轮一轮都省不掉。

Running time 是 $(V-1)\times E=O(VE)$。

**Negative cycle。** 在例子里再加一条 edge c→b（1）。现在 b → a → c → b 是一个 cycle，weight 是 $-4+1+1=-2$。每绕一圈，到这三个 vertex 的 path 的 weight 就少 2，没有最小值，shortest path 没有定义。

检测的办法是多做一轮，第 $V$ 轮：如果还有 $D$ 值变小，就有从 $s$ 到得了的 negative cycle。加了那条 edge 之后实际跑一下，第 3 轮之后 $D[a]=0$，第 4 轮里 b→a 又把它改成 $-1$。

这个判断为什么对：没有 negative cycle 时，上面证明了 $V-1$ 轮之后每个 $D[v]$ 已经等于 $\delta(v)$，而 $D$ 不可能低于 $\delta$，第 $V$ 轮什么都改不动。反过来，假设有一个到得了的 negative cycle，而某一轮里它上面没有一条 edge 能 relax，即对 cycle 上的每条 edge 都有 $D[v]\le D[u]+w(u,v)$。把这些 inequality 沿 cycle 加起来，每个 vertex 的 $D$ 在左右两边各出现一次，全部消掉，剩下 $0\le$ cycle 的 total weight，与它是负的矛盾。所以只要有这样的 cycle，每一轮都还会有 $D$ 变小。

### Dijkstra's algorithm

Bellman–Ford 慢在它不知道正确的顺序，只好把每条 edge relax $V-1$ 遍。$V=10^5$、$E=2\times10^5$ 时是 $2\times10^{10}$ 次。

如果所有 weight 都不是负的，正确的顺序是存在的：按 $\delta$ 从小到大处理 vertex。处理一个 vertex 时它的 $D$ 已经是最终值，把它发出的 edge 各 relax 一次就够了，以后不必再碰。问题是 $\delta$ 正是要求的东西，事先并不知道谁小。Dijkstra 的发现是不需要事先知道：

> 所有 weight 非负时，在还没处理的 vertex 里，$D$ 最小的那个，它的 $D$ 已经等于 $\delta$。

所以每一步只要从还没处理的 vertex 里取出 $D$ 最小的，这正是 priority queue 做的事。

::fig[cs2040-dijkstra] 例子：5 个 vertex，7 条 edge。每个小图是 pop 出一个 vertex 并 relax 它的 outgoing edge 之后的样子。

Java 的 `PriorityQueue` 改不了已经在里面的 element 的 key（第 4 站），所以 $D[v]$ 变小时不去改旧的那一项，而是再放一个新的 $(D[v],v)$ 进去；旧的那一项迟早会被 pop 出来，那时它的第一个数比当前的 $D[v]$ 大，据此认出它过期，跳过。

```java
PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));
D[s] = 0;
pq.add(new long[]{0, s});
while (!pq.isEmpty()) {
    long[] top = pq.poll();
    long d = top[0];
    int u = (int) top[1];
    if (d > D[u]) continue;                       // 过期的一项
    for (Edge e : adj.get(u))
        if (D[u] + e.w < D[e.v]) {
            D[e.v] = D[u] + e.w;
            pq.add(new long[]{D[e.v], e.v});
        }
}
```

图里的 graph 有 edge 0→1（2），0→2（6），1→2（3），1→3（8），2→3（2），2→4（9），3→4（3），起点是 0：

| pop 出的 $(d,u)$ | 处理 | $D[0..4]$ | 之后的 PQ |
|---|---|---|---|
| (0, 0) | relax 0→1，0→2 | 0 2 6 ∞ ∞ | (2,1) (6,2) |
| (2, 1) | relax 1→2：$2+3=5<6$；1→3：10 | 0 2 5 10 ∞ | (5,2) (6,2) (10,3) |
| (5, 2) | relax 2→3：$5+2=7<10$；2→4：14 | 0 2 5 7 14 | (6,2) (7,3) (10,3) (14,4) |
| (6, 2) | $6>D[2]=5$，过期，跳过 | | (7,3) (10,3) (14,4) |
| (7, 3) | relax 3→4：$7+3=10<14$ | 0 2 5 7 10 | (10,3) (10,4) (14,4) |
| (10, 3) | 过期，跳过 | | (10,4) (14,4) |
| (10, 4) | 4 没有 outgoing edge | 0 2 5 7 10 | (14,4) |
| (14, 4) | 过期，跳过 | | 空 |

**证明那条性质。** 设到目前为止处理过的 vertex 的 $D$ 都已经等于 $\delta$，它们发出的 edge 都 relax 过了。设 $u$ 是还没处理的 vertex 里 $D$ 最小的。取一条从 $s$ 到 $u$ 的 shortest path，沿着它从 $s$ 往 $u$ 走，设 $y$ 是遇到的第一个还没处理的 vertex（可能就是 $u$），$x$ 是它前面那个，$x$ 处理过。

- $x$ 处理时 relax 过 $x\to y$，而且 $D[x]=\delta(x)$，所以 $D[y]\le\delta(x)+w(x,y)=\delta(y)$。后一个等号是因为 shortest path 的前一段也是 shortest path。
- 从 $y$ 沿 path 继续走到 $u$，经过的 edge 的 weight 都不是负的，所以 $\delta(y)\le\delta(u)$。**这是唯一用到 weight 非负的地方。**
- $u$ 是没处理的 vertex 里 $D$ 最小的，$y$ 也没处理，所以 $D[u]\le D[y]$。

连起来：$D[u]\le D[y]\le\delta(y)\le\delta(u)$。而 relax 保证 $D[u]\ge\delta(u)$，所以 $D[u]=\delta(u)$。

**Running time。** 每个 vertex 只有一项不是过期的，所以它的 adjacency list 只被扫一次，每条 edge 最多 relax 一次，放进 PQ 的 element 最多 $E$ 个（另加起点那一个）。PQ 的每次进出是 $O(\log E)=O(\log V)$，合计 $O((V+E)\log V)$。对 $V=10^5$、$E=2\times10^5$，大约是 $3\times10^5\times17\approx5\times10^6$，比 Bellman–Ford 的 $2\times10^{10}$ 少四千倍。

:::wrong 有 negative edge 时，把每条 edge 都加上同一个 constant 变成非负，再跑 Dijkstra
取三条 edge：s→a（2），s→b（5），b→a（−4）。真正的 $\delta(a)$ 是走 s → b → a 的 $5-4=1$。每条 edge 加 4 之后是 s→a（6），s→b（9），b→a（0），这时到 a 最短的是直接走 s→a 的 6，另一条是 9。选出来的 path 变了。原因是有 $k$ 条 edge 的 path 一共被加了 $4k$，edge 多的 path 被罚得多，不同长短的 path 之间的比较被改掉了。
:::

:::edge 上面这段 code 遇到 negative edge 会怎样
教科书上的 Dijkstra 把 pop 过的 vertex 标成“完成”，之后不再碰它。在 s→a（2），s→b（5），b→a（−4）上，它先 pop s，再 pop a（$D=2$）并标成完成，最后 pop b 时发现 $5-4=1<2$，但 a 已经完成，答案停在错的 2。证明里的第二步 $\delta(y)\le\delta(u)$ 在这里不成立了。

上面的 code 没有“完成”这个标记：b 把 $D[a]$ 改成 1 时会放一个新的 (1, a) 进 PQ，a 被重新处理，最后答案是对的。VisuAlgo 把这种写法叫 Modified Dijkstra。它在有 negative edge 但没有 negative cycle 时能给出正确答案，代价是一个 vertex 可能被反复处理，“每条 edge 最多 relax 一次”不再成立，在特意构造的 graph 上会慢到 exponential；有 negative cycle 时它永远停不下来。所以除非题目另有说明，有 negative edge 就用 Bellman–Ford。
:::

### 更特殊的 graph，更快的做法

Graph 有额外的结构时，正确的 relax 顺序可以更便宜地得到。

| Graph | 做法 | Running time | 为什么可以 |
|---|---|---|---|
| 没有 weight，或者 weight 全相同 | BFS | $O(V+E)$ | edge 数最少的 path 就是 weight 最小的 |
| tree（有 weight） | 从 $s$ 做一遍 DFS 或 BFS，$D[v]=D[\text{parent}]+w$ | $O(V)$ | 两个 vertex 之间只有一条 path；$E=V-1$ |
| DAG（weight 可以是负的） | 按 topological order，把每个 vertex 发出的 edge relax 一次 | $O(V+E)$ | 见下 |
| weight 非负 | Dijkstra | $O((V+E)\log V)$ | 上一小节 |
| 有 negative edge | Bellman–Ford | $O(VE)$ | $V-1$ 轮 |

DAG 那一行的理由：在 topological order 里，指向 $v$ 的每条 edge 的起点都排在 $v$ 前面。按这个次序处理到 $v$ 时，所有进入 $v$ 的 edge 都已经从一个 $D$ 值正确的起点 relax 过了，其中包括 shortest path 上的最后一条，所以 $D[v]$ 已经等于 $\delta(v)$（按次序做 induction）。这里不需要 weight 非负，因为 DAG 里没有 cycle，更没有 negative cycle。

Bellman–Ford 的那个例子就是一个 DAG，它的一个 topological order 是 s, b, a, c：

| 处理 | relax | $D[s],D[a],D[b],D[c]$ |
|---|---|---|
| s | s→a，s→b | 0, 2, 5, ∞ |
| b | b→a：$5-4=1$ | 0, 1, 5, ∞ |
| a | a→c：$1+1=2$ | 0, 1, 5, 2 |
| c | 没有 outgoing edge | 0, 1, 5, 2 |

4 次 relax 得到了 Bellman–Ford 用 $3\times4=12$ 次得到的结果。

:::back
“按 distance 从小到大处理”是[第 6 站](#graph) BFS 的想法，Dijkstra 用[第 4 站](#heap)的 priority queue 把它搬到了有 weight 的 graph 上；DAG 的做法直接用第 6 站的 topological order。
:::

:::from
“$D$ 始终是某条真实 path 的 weight，所以不会低于 $\delta$”、weighted path 的定义、negative cycle 让 shortest path 没有定义、DAG 上按 topological order relax 及其 induction，来自 [MIT 6.006 第 11 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec11/)的讲义。“没有 negative cycle 时 shortest path 可以取成不重复经过 vertex 的，所以最多 $V-1$ 条 edge”来自[第 12 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec12/)；那一讲的 Bellman–Ford 是把 graph 复制成 $V+1$ 层再做 DAG relaxation，这里写的是 NUS 讲的原地做 $V-1$ 轮的版本，轮数、$O(VE)$ 和“多做一轮检测 negative cycle”取自 [VisuAlgo 的 sssp e-Lecture](https://visualgo.net/en/sssp/print)，“第 $i$ 轮之后不超过 $i$ 条 edge 的都对了”的 induction 和“沿 cycle 把 inequality 加起来”的论证是凭自己的知识写的标准证明。Dijkstra“按 distance 从小到大 relax”的想法、正确性证明里那一串 inequality、按 PQ 的 operation 次数算 running time，来自 [6.006 第 13 讲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec13/)；那一讲假设 PQ 有 decrease-key，这里的 code 是 VisuAlgo 称为 Modified Dijkstra 的写法，它遇到 negative edge 和 negative cycle 时的表现以及几种特殊 graph 的清单也来自 VisuAlgo。所有的 graph、表和数字是为这一页构造和算的。
:::
