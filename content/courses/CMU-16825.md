先看三次失败。三次都在做同一件事：从 image 得到 3D。

**第一次。** 一张照片里有一把 chair，在 image 上 250 px 高。Camera 的 focal length 是 500 px。按 pinhole model，image 上的高度是 $f\,H/Z$，所以 $H/Z=0.5$：可以是 1 m 高的 chair 放在 2 m 处，也可以是 2 m 高的 chair 放在 4 m 处。两者的顶端落在同一条 ray 上。

::fig[cmu-16825-ambig] 一张 image 只给出 ray 的方向，不给出沿 ray 走了多远。$H/Z$ 相同的两把 chair 产生完全相同的 pixel。

[CS4277](../courses/CS4277.html) 的经典做法是加 view：两张 image 里同一个点的两条 ray 相交，交点就定了。只有一张 image 时，几何上没有办法，只能靠“chair 一般多高、长什么样”这种从大量 data 里学来的 prior。

**第二次。** 有了 3D 的 mesh，用 rasterization render 出 image，和照片比，想用 gradient descent 去改 vertex。看一个 pixel：它的值只取决于 pixel center 在不在 triangle 里。Edge 从左往右挪，pixel 的值一直是 0，越过 center 的一瞬间跳成 1，之后一直是 1。

::fig[cmu-16825-soft] 左：一行 pixel 和一个 triangle 的 edge。右：pixel 3 的值随 edge 位置的变化。Hard rasterization 是阶跃，对 vertex 的 derivative 几乎处处是 0；平滑的那条是第 2 站末尾的 SoftRas。

Derivative 是 0，gradient descent 不知道往哪边挪。Rendering 这一步必须换成可微的。

**第三次。** 那就用 voxel：把空间切成格子，每格存一个 occupancy，处处光滑可微。要表示细节，resolution 得高。$1024^3$ 个 float32 是 $1024^3\times4=4.29\times10^9$ byte，4.3 GB，只存一个 object。NeRF 换成一个 MLP 存场景，memory 小了，但渲染一张 $256\times256$ 的 image、每个 pixel 取 224 个点，要算 $256\times256\times224=1.47\times10^7$ 次 MLP，原文里 training 一个场景要 1 到 2 天。

这门课就是在这三件事之间找路：用什么 representation 存 3D（第 1 站），怎样从一张 image 学出 3D（第 2 站），怎样把 rendering 写成可微的积分（第 3 站），在它上面建 NeRF、neural SDF、3D Gaussian Splatting（第 4 到 6 站），view 很少时怎样借 diffusion model 或在很多场景上训练的 transformer 补上信息（第 7 站），以及怎样直接处理 point cloud（第 8 站）。Camera model、intrinsics、homogeneous coordinates 在 [CS4243 的 camera 一站](../courses/CS4243.html#camera)，multi-view geometry 和 bundle adjustment 在 [CS4277](../courses/CS4277.html)，这一页不再重复。

### 同一个 shape，四种存法

一个 2D 的例子就能看出差别：radius 1 的 circle 右边多一个小凸起。

::fig[cmu-16825-repr] 同一个 shape 的四种 representation。前三种是 explicit 的：直接列出“哪里有东西”；SDF 是 implicit 的：给任意一点，回答它离 surface 多远、在里面还是外面。

| representation | 存什么 | 3D 的存储量 | 天生擅长 |
|---|---|---|---|
| voxel grid | 每格一个 occupancy（或 SDF 值） | $N^3$ | 3D convolution、布尔运算 |
| point cloud | $P$ 个点的 coordinates | $P\times3$ | sensor（LiDAR、RGB-D）直接给出 |
| mesh | $V$ 个 vertex coordinates + $F$ 个 triangle 的 index | $V\times3+F\times3$ | rasterization、graphics 的标准格式 |
| implicit | 一个 function $f:\mathbb R^3\to\mathbb R$ | function 的参数 | 任意分辨率查询、topology 自由 |

Voxel 的问题是 memory 跟着 volume 涨，而有用的信息只在 surface 上。把 radius 1 的 sphere 放进 $[-1.5,1.5]^3$ 数一数：surface 穿过的格子（中心到 sphere 的距离小于半个 cell diagonal）在 $32^3$ 时是 2576 个，占 32768 格的 7.9%；在 $128^3$ 时是 39680 个，占 2097152 格的 1.9%。分辨率放大 4 倍，总格数乘 64，surface 上的格子只乘 15.4（大约 16，也就是 $4^2$）。Surface 是 2 维的，按 $N^2$ 涨；volume 按 $N^3$ 涨；分辨率越高，浪费的比例越大。Octree 和 implicit representation 都是为这件事出现的。

### Implicit surface 与 signed distance function

Implicit representation 把 surface 定义成一个 function 的 zero level set：$\{x: f(x)=0\}$。$f$ 可以是公式，也可以是 neural network。最常用的一种是 signed distance function（SDF）：$|f(x)|$ 等于 $x$ 到 surface 的最近距离，外面取正、里面取负。

Sphere 的 SDF 是 $f(x)=\|x-c\|-r$。Box 的 SDF 是 A3 代码里那一个：中心 $c$、边长 $b$，令 $q=|x-c|-b/2$（逐个分量），

$$f(x)=\big\|\max(q,0)\big\|+\min\big(\max(q_x,q_y,q_z),\,0\big)$$

两项分别管外面和里面。用 A3 的 box（中心在原点，边长 1.75，$b/2=0.875$）检验三个点：

| 点 | $q$ | $\|\max(q,0)\|$ | $\min(\max q,0)$ | $f$ | 对不对 |
|---|---|---|---|---|---|
| $(1.2,0.3,0)$ | $(0.325,-0.575,-0.875)$ | 0.325 | 0 | 0.325 | 到 $x=0.875$ 那个面的距离 |
| $(1.2,1.2,0)$ | $(0.325,0.325,-0.875)$ | $\sqrt2\times0.325=0.460$ | 0 | 0.460 | 到棱边的距离，不是到面 |
| $(0.5,0.2,0)$ | $(-0.375,-0.675,-0.875)$ | 0 | $-0.375$ | $-0.375$ | 在里面，离最近的面 0.375 |

第二行说明为什么外面那一项要取 $\max(q,0)$ 的 norm：点在两个面的“外侧拐角”时，最近的是棱边，距离是两个分量的 Pythagoras。

SDF 有一个后面会反复用的性质。沿 $\nabla f$ 方向走 $\Delta$，到 surface 的距离也恰好变 $\Delta$（离开最近点的方向就是 gradient 方向），所以

$$\|\nabla f(x)\|=1$$

叫 eikonal equation。Sphere 的 $\nabla f=(x-c)/\|x-c\|$，长度确实是 1。

:::wrong 任何一个 zero level set 正确的 function 都可以当 SDF 用
$f(x)=2(\|x\|-1)$ 和 $\|x\|-1$ 有同一个 zero level set，在 marching cubes 眼里一模一样。但第 5 站的 sphere tracing 每步走 $f(x)$ 那么远，前者每步都走两倍的真实距离：从 $(-2.6,0.55)$ 出发朝 $+x$ 走，第一步就走了 3.31，落到 $x=0.715$，已经越过前表面（$x=-0.835$）1.55。凡是要用“$f$ 就是距离”的算法，都需要 $\|\nabla f\|=1$；第 5 站用 eikonal loss 去逼它。
:::

### 互相转换

**Implicit 或 voxel 到 mesh：marching cubes。** 在 grid 的每个 vertex 上算 $f$。一条 cell edge 两端的 $f$ 异号，surface 就穿过这条 edge；沿 edge 做 linear interpolation 找 zero crossing。两端在 $x=0.8$（$f=-0.2$）和 $x=1.1$（$f=0.1$），crossing 在离左端 $\dfrac{0.2}{0.2+0.1}=\dfrac23$ 的地方，$x=0.8+0.3\times\tfrac23=1.0$，正是 unit sphere 的 surface。每个 cell 按 8 个 corner 在 isovalue 哪一边编成一个 8 bit 的 index（$2^8=256$ 种），查一张 256 行的表，得到这个 cell 里要连哪几条 edge 上的 crossing；表里最长的一行列了 15 条 edge，也就是一个 cell 最多 5 个 triangle（PyTorch3D 的 `marching_cubes` 用的就是这样一张 `FACE_TABLE`）。A1 用 `mcubes` 库做这一步，A2 评测 voxel 时用 isovalue 0.5 对 occupancy 做同样的事。查表这一步是离散的，PyTorch3D 的文档直接写明它 non-differentiable，所以它只能用在评测和可视化里，不能放进 loss。

**Mesh 到 point cloud：按面积 sampling。** 直接拿 vertex 当点是错的，见下面的 wrong。正确做法是 A1 extra credit 的三步：按面积的比例选一个 face；在 face 上 uniform 地取一个点；重复。第二步用 barycentric coordinates：

$$p=(1-\sqrt{r_1})\,A+\sqrt{r_1}(1-r_2)\,B+\sqrt{r_1}\,r_2\,C,\qquad r_1,r_2\sim U(0,1)$$

PyTorch3D 的 `sample_points_from_meshes`（A2 每一步都在调它）内部就是这两步：用 `multinomial` 按面积选 face，再用 $w_0=1-\sqrt u$、$w_1=\sqrt u(1-v)$、$w_2=\sqrt u\,v$ 作 barycentric coordinates。

$\sqrt{r_1}$ 是这样来的。令 $s=\sqrt{r_1}$，上式写成 $p=(1-s)A+s\,[(1-r_2)B+r_2C]$：先在 $BC$ 上 uniform 地取一点 $Q$，再在 $AQ$ 上取 $p$。$s$ 固定时，所有可能的 $p$ 组成一条平行于 $BC$ 的 segment，长度是 $s\,|BC|$。Uniform 意味着 $s$ 附近的 probability 和这条 segment 的长度成正比，即 $s$ 的 density 是 $2s$，CDF 是 $s^2$。用 inverse CDF 从 $U(0,1)$ 生成：$s^2=r_1$，$s=\sqrt{r_1}$。直接用 $s=r_1$ 会让点挤在 $A$ 附近。

:::wrong 把 mesh 的 vertex 当成 point cloud，点就均匀分布在 surface 上
两块面积都是 1 的正方形。A 只用 2 个 triangle，4 个 vertex；B 切成 $10\times10$ 的格子，200 个 triangle、121 个 vertex。拿 vertex 当点，B 占 $121/125=96.8\%$，A 只有 3.2%，可两块面积一样。Vertex 的疏密反映的是建模的人在哪里加了细节，和 surface 本身无关。按面积 sampling时两块各占 50%。
:::

**Point cloud 到 mesh** 最难：点之间没有连接关系，要靠 Poisson reconstruction 一类的方法先拟合一个 implicit function，再 marching cubes。CS231n 的 slide 把这列为 point cloud 的缺点：它不 explicit 地表示 surface，要得到 mesh 必须做 post-processing。

:::from

### 只有一张 image：从 data 里学 prior

开头第一次失败已经说明，单张 image 在几何上不决定 3D。A2 的做法是在 ShapeNet 的 chair 上 supervised training：input 是一张 RGB，ground truth 是这把 chair 的 mesh。Encoder 是 ImageNet pretrained 的 ResNet18，去掉最后一层，得到一个 512 维的 feature；decoder 把它变成三种 representation 之一。

| decoder 输出 | shape | loss |
|---|---|---|
| voxel | $32\times32\times32$ 的 occupancy | 每格一个 binary cross entropy |
| point cloud | $n\times3$（默认 $n=1000$） | Chamfer distance |
| mesh | 在 `ico_sphere(4)` 上每个 vertex 的位移 | 在 mesh 上采点算 Chamfer，加 Laplacian smoothing |

Network 能“猜”出看不见的 chair 背面，是因为 training set 里几千把 chair 的背面都长得差不多。它学到的是 $p(\text{shape}\mid\text{image})$ 的一个平均，对见过的类别有效；A2 的 Q3.3 让你比较只在 chair 上训练和在 chair、car、plane 三类上训练的差别。

### Voxel：每格一个 binary classification

每格的 ground truth $y\in\{0,1\}$，network 给出 logit $s$，$p=\mathrm{sigmoid}(s)$，

$$\ell=-\big[y\log p+(1-y)\log(1-p)\big]$$

对 $32^3=32768$ 格取平均。PyTorch 里用 `BCEWithLogitsLoss` 直接吃 logit，比先 sigmoid 再 `BCELoss` 数值上稳定：$p$ 极接近 0 或 1 时 $\log p$ 会变成 $-\infty$。

### Point cloud：Chamfer distance

Network 输出 $n$ 个点，ground truth 也是从 mesh 上采的 $n$ 个点。两组点没有对应关系：第 $i$ 个 predicted point 不必对应第 $i$ 个 ground-truth point。所以 loss 不能逐个相减，只能问“每个点离对面最近的点有多远”：

$$d_{\text{CD}}(S_1,S_2)=\frac1{|S_1|}\sum_{x\in S_1}\min_{y\in S_2}\|x-y\|^2+\frac1{|S_2|}\sum_{y\in S_2}\min_{x\in S_1}\|x-y\|^2$$

（CS231n 的 slide 用求和不取平均的版本，两者只差常数倍。）算一个小例子：prediction $S_1=\{(0,0),(1,0),(2,0.5)\}$，ground truth $S_2=\{(0,0.5),(1,0),(2,0),(3,0)\}$。

::fig[cmu-16825-chamfer] 实线箭头是第一项（每个 prediction 找最近的 GT），虚线是第二项（每个 GT 找最近的 prediction）。(3, 0) 附近没有 prediction，只有第二项看得见它。

| 方向 | 每个点到对面最近点的 squared distance | 和 | 平均 |
|---|---|---|---|
| $S_1\to S_2$ | $(0,0)$：0.25；$(1,0)$：0；$(2,0.5)$：0.25 | 0.5 | 0.167 |
| $S_2\to S_1$ | $(0,0.5)$：0.25；$(1,0)$：0；$(2,0)$：0.25；$(3,0)$：$1^2+0.5^2=1.25$ | 1.75 | 0.4375 |

$d_{\text{CD}}=0.167+0.4375=0.604$，大半来自 $(3,0)$ 那个没被覆盖的 GT 点。

:::wrong 只算 prediction → GT 一个方向就够了：每个 predicted point 都贴在 surface 上，形状就对了
把三个 predicted point 全放在 $(1,0)$。第一项：三个点到最近 GT 的距离都是 0，和为 0。可是这个 prediction 只有一个点的位置。第二项立刻暴露它：$(0,0.5)$ 到 $(1,0)$ 是 1.25，$(1,0)$ 是 0，$(2,0)$ 是 1，$(3,0)$ 是 4，和是 6.25。第一项防的是“预测了不存在的东西”（precision），第二项防的是“漏了存在的东西”（recall），缺一个方向，network 就会钻另一个方向的空子。
:::

A2 要求自己写 Chamfer，可以用 `pytorch3d.ops.knn_points` 找最近邻（README 允许），不能直接调 PyTorch3D 的 `chamfer_distance`。

### 评测：F1@t

Chamfer 是一个平均值，很难说多少算好。A2 的 `eval_model.py` 用的是阈值式的 precision 和 recall：predicted point 到最近 GT 点的距离小于 $t$ 的比例是 precision，GT point 到最近 prediction 的距离小于 $t$ 的比例是 recall，

$$F1=\frac{2\cdot\text{precision}\cdot\text{recall}}{\text{precision}+\text{recall}}$$

注意这里是 distance，不是 squared distance。用上面的例子取 $t=0.6$：predicted point 的最近距离是 $0.5,0,0.5$，全部小于 0.6，precision 100%；GT point 的最近距离是 $0.5,0,0.5,\sqrt{1.25}=1.118$，四个里三个达标，recall 75%；$F1=\dfrac{2\times100\times75}{175}=85.7$。A2 在单位尺度的 chair 上取 $t$ 从 0.01 到 0.05，报告 F1@0.05。

### Mesh：deform 一个 sphere

Mesh 的 connectivity 很难由 network 直接输出，A2 的做法是固定 connectivity，只预测位移。`ico_sphere(4)` 由 icosahedron（12 个 vertex、20 个 face）细分 4 次：每次细分每个 triangle 变 4 个，$F=20\times4^4=5120$；vertex 数由 Euler 公式 $V-E+F=2$ 和 $E=\tfrac32F$ 得 $V=2+\tfrac12F=2562$。Decoder 输出 $2562\times3=7686$ 个数。

Loss 是在 predicted mesh 和 GT mesh 上各采 $n$ 个点（`sample_points_from_meshes`，就是上一站的按面积 sampling）算 Chamfer。只用 Chamfer，vertex 可以乱跑：采样点只看 surface 在哪，不管 vertex 怎么排，相邻 vertex 往相反方向拉出尖刺、triangle 互相穿插，Chamfer 都可能很低。所以加一项 Laplacian smoothing：每个 vertex 和它的 neighbor 的平均之差

$$\delta_i=v_i-\frac1{|N(i)|}\sum_{j\in N(i)}v_j$$

越大，这个 vertex 越“凸出”于周围。A2 的 README 允许直接用现成的 loss，PyTorch3D 的 `mesh_laplacian_smoothing`（默认 `method="uniform"`）算的是

$$\mathcal L_{\text{smooth}}=\frac1V\sum_i\|\delta_i\|$$

注意是 norm，不平方（源码里是 `loss.norm(dim=1)` 再按 $1/V$ 加权求和），batch 里多个 mesh 再取平均。它把 Laplacian matrix 当常数（在 `no_grad` 里建），gradient 只经过 vertex 坐标。一个 vertex 在 $(0,0,0.3)$，四个 neighbor 在 $(\pm1,0,0)$、$(0,\pm1,0)$，平均是原点，$\delta=(0,0,0.3)$，贡献 $\|\delta\|=0.3$；把它压回平面就是 0。自己写成平方的版本也可以，那时这一项是 0.09，$w_{\text{smooth}}$ 要相应重调。A2 默认 $w_{\text{chamfer}}=1$、$w_{\text{smooth}}=0.1$。

:::edge Deform sphere 改不了 topology
Sphere 是 genus 0：没有洞。Chair 的靠背常有镂空、扶手和腿围出洞，sphere 怎么 deform 都长不出洞，只能拿薄膜把洞糊上。CS231n 的 slide 提到 Mesh R-CNN 的解法：先预测 voxel（topology 自由），把 voxel 转成 mesh 作为初始形状，再 deform。A2 也鼓励换掉 `ico_sphere` 试别的初始形状。
:::

### 用 2D image 做 supervision：rasterization 要可微

上面三种 loss 都需要 3D 的 ground truth。如果只有 image，就得把 predicted 3D render 出来和 image 比，开头的第二次失败就出在这里。Pixel 的值是 pixel center 是否在 triangle 内的 indicator，对 edge 位置 $e$ 的 derivative 在 $e\ne2.5$ 时都是 0。SoftRas 的原文把问题说成：rasterization 按 pixel 和 triangle 的位置做 binary mask，z-buffer 按 depth 做 one-hot 的选择，两步都是离散的，gradient 回不到 vertex。

SoftRas（L12 的 reading）把 binary mask 换成一个 probability：triangle $j$ 盖住 pixel $i$ 的 probability 是

$$D_j^i=\mathrm{sigmoid}\Big(\delta_j^i\,\frac{d^2(i,j)}{\sigma}\Big)$$

$d(i,j)$ 是 pixel center 到 triangle $j$ 的 edge 的最近距离，$\delta_j^i=+1$ 表示 center 在 triangle 里，$-1$ 表示在外面，$\sigma$ 控制边缘有多软（原文默认 $10^{-4}$）。Center 在 triangle 里，$D>\tfrac12$，离 edge 越远越接近 1；在外面，$D<\tfrac12$，越远越接近 0。好几个 triangle 都可能盖住同一个 pixel，silhouette 取“至少被一个盖住”的 probability：

$$I_s^i=1-\prod_j\big(1-D_j^i\big)$$

（Color 还要按 depth 做一个 softmax 式的加权，原文 Eq. 3，这里只看 silhouette。）PyTorch3D 的 `softmax_rgb_blend` 和 `sigmoid_alpha_blend` 就是这两个式子，只是把符号约定反过来：它存的是 signed squared distance，里面为负，算 `sigmoid(-dists / sigma)`。

拿开头那张图算。Pixel 3 的 center 在 2.5，triangle 在 edge 左边，edge 在 $e$ 时 center 到 edge 的距离 $d=|e-2.5|$，$e>2.5$ 时 center 在里面。只有这一个 triangle，$I_s=D$。距离以 pixel 为单位，取 $\sigma=0.05$：

$$D(e)=\mathrm{sigmoid}\Big(\mathrm{sign}(e-2.5)\,\frac{(e-2.5)^2}{0.05}\Big)$$

对 $e$ 求导。$\mathrm{sigmoid}'=D(1-D)$；$\mathrm{sign}(e-2.5)(e-2.5)^2$ 对 $e$ 的 derivative 是 $2|e-2.5|$（两边分开求导，$e>2.5$ 时是 $2(e-2.5)$，$e<2.5$ 时是 $-2(e-2.5)$）。所以

$$\frac{dD}{de}=D(1-D)\cdot\frac{2|e-2.5|}{\sigma}$$

| $e$ | $d$ | $\delta\,d^2/\sigma$ | $D$ | $dD/de$ |
|---|---|---|---|---|
| 2.0 | 0.5 | $-5$ | 0.0067 | 0.133 |
| 2.3 | 0.2 | $-0.8$ | 0.310 | 1.71 |
| 2.5 | 0 | 0 | 0.5 | 0 |
| 2.7 | 0.2 | 0.8 | 0.690 | 1.71 |
| 3.0 | 0.5 | 5 | 0.9933 | 0.133 |

Edge 离 center 0.5 pixel 以内，derivative 都在 0.1 以上，gradient 能把 edge 往正确方向推；hard rasterization 在这些位置的 derivative 全是 0。$e=2.5$ 那一行的 0 来自 $d^2$：它在 $d=0$ 处是平的，edge 恰好压在 center 上那一点没有 gradient，稍微偏开就有，最大值 1.76 出现在 $d=0.23$。$\sigma$ 越大，过渡带越宽，gradient 覆盖的范围越广，代价是 render 出的边缘越模糊。

Volume rendering 从一开始就是可微的：density 在空间里是连续的，没有“在不在 triangle 里”的跳变。这是下一站的内容，也是这门课后半段的主线。

:::from
CMU 的 L5 到 L7b slides 读不到。A2 的整体设定（ResNet18、三种 decoder、BCE、Chamfer 的实现限制、`ico_sphere(4)`、$w_{\text{smooth}}=0.1$、F1 的阈值）来自 [A2 README](https://github.com/learning3d/assignment2) 和 `model.py`、`train_model.py`、`eval_model.py` 的代码；F1 的定义照 `compute_sampling_metrics` 写。Laplacian smoothing 的式子对照了 [PyTorch3D](https://github.com/facebookresearch/pytorch3d) 的 `loss/mesh_laplacian_smoothing.py`。Scale ambiguity、Chamfer 的定义、Pixel2Mesh 用 Chamfer、Mesh R-CNN 因为 mesh 的 topology 被初始 mesh 固定而先预测 voxel，来自 [CS231n Lecture 15](https://cs231n.stanford.edu/slides/2026/lecture_15.pdf) 的 slide 16、40 到 44、50 到 55。Soft rasterization 的 Eq. 1、Eq. 4、默认 $\sigma$ 和“离散操作没有 gradient”的说法来自 [SoftRas 原文](https://arxiv.org/pdf/1904.01786v1) 第 3 节，PyTorch3D 的对应实现在 `renderer/blending.py`。$\sigma=0.05$ 的数表、Chamfer 的数值例子、两个方向的反例、Laplacian 的例子、$V$ 和 $F$ 的计数是为这一页算的。

## [volume] Volume rendering

:::skip
快速路线必读（L9 Volume Rendering，reading 是 Volume Rendering Digest；A3 part A 的核心）。能从 $T(t+dt)=T(t)(1-\sigma dt)$ 推到 $\sum T_i\alpha_ic_i$，并对一条 ray 手算 weight、color 和 depth，就可以去第 4 站。
:::

### 从 pixel 到 ray

Rendering 一个 pixel，先要知道它对应哪条 ray。A3 的 `ray_utils.py` 分三步：把 pixel coordinates 换到 $[-1,1]$ 的 normalized device coordinates；在 camera coordinate frame 里取 $z=1$ 平面上的对应点，用 `camera.unproject_points` 变到 world；ray 的 origin 是 camera center，direction 是这个点减 origin。Camera 的 intrinsics、extrinsics 和这些变换的推导在 [CS4243 的 camera 一站](../courses/CS4243.html#camera)。

Ray 写成 $r(t)=o+t\,d$，只在 $[t_n,t_f]$（near、far）之间取点。A3 的 lego 场景取 near 2、far 6。

### 把场景当成一团会发光、会吸光的粒子

Surface 的麻烦在于“碰到还是没碰到”是跳变的。换一个模型：空间每一点有一个 density $\sigma(x)\ge0$，意思是 ray 每走单位长度被挡住的 rate；被挡住的地方发出 color $c(x)$。这叫 emission-absorption model。

设 $T(t)$ 是 ray 从 $t_n$ 走到 $t$ 一直没被挡住的 probability。再走一小段 $dt$，被挡住的 probability 是 $\sigma(t)\,dt$，所以

$$T(t+dt)=T(t)\big(1-\sigma(t)\,dt\big)$$

移项除以 $dt$，令 $dt\to0$：

$$T'(t)=-\sigma(t)\,T(t)\quad\Longrightarrow\quad\frac{T'(t)}{T(t)}=-\sigma(t)\quad\Longrightarrow\quad\log T(t)-\log T(t_n)=-\int_{t_n}^t\sigma(s)\,ds$$

$T(t_n)=1$，所以

$$T(t)=\exp\!\Big(-\int_{t_n}^t\sigma(s)\,ds\Big)$$

$T$ 叫 transmittance。$1-T(t)$ 是“在 $t$ 之前已经被挡住”的 probability，是一个 CDF；对 $t$ 求导得到“恰好在 $t$ 处被挡住”的 density：$\dfrac{d}{dt}(1-T)=-T'=\sigma(t)T(t)$。Pixel 看到的 color 是 ray 停下的地方的 color 的 expectation：

$$C=\int_{t_n}^{t_f}T(t)\,\sigma(t)\,c(t)\,dt\;+\;T(t_f)\,c_{\text{bg}}$$

最后一项是 ray 穿过了整个场景、看到背景的情况。

### Piecewise constant：积分变成求和

Network 只能在有限个点上算 $\sigma$ 和 $c$。在 $t_1<t_2<\dots<t_N$ 上取点，假设第 $i$ 段 $[t_i,t_i+\delta_i)$ 内 $\sigma=\sigma_i$、$c=c_i$ 不变。记 $T_i=T(t_i)$。

先要一个工具：transmittance 可以分段相乘。把 $[a,c]$ 在 $b$ 处切开，exponent 里的积分拆成两段之和，exp 把和变成积：

$$T(a\to c)=\exp\!\Big(-\int_a^b\sigma-\int_b^c\sigma\Big)=\exp\!\Big(-\int_a^b\sigma\Big)\exp\!\Big(-\int_b^c\sigma\Big)=T(a\to b)\,T(b\to c)$$

（概率上就是“前一段没被挡”和“后一段没被挡”两件事独立。）于是段内 $T(t)=T(t_n\to t_i)\,T(t_i\to t)=T_i\,e^{-\sigma_i(t-t_i)}$，第二个因子是常数 $\sigma_i$ 积了长度 $t-t_i$。这一段的贡献是

$$\int_{t_i}^{t_i+\delta_i}T_i\,e^{-\sigma_i(t-t_i)}\,\sigma_i\,c_i\,dt=T_i\,c_i\,\sigma_i\int_0^{\delta_i}e^{-\sigma_iu}\,du=T_i\,c_i\big(1-e^{-\sigma_i\delta_i}\big)$$

走完这一段，$T_{i+1}=T_i\,e^{-\sigma_i\delta_i}$。记 $\alpha_i=1-e^{-\sigma_i\delta_i}$（这一段的 opacity），就得到

$$C=\sum_{i=1}^NT_i\,\alpha_i\,c_i,\qquad T_i=\prod_{j<i}(1-\alpha_j),\qquad w_i=T_i\,\alpha_i$$

$w_i$ 是第 $i$ 段的 weight。从 $T_i=\exp(-\sum_{j<i}\sigma_j\delta_j)$ 到 $\prod_{j<i}(1-\alpha_j)$ 只用了 $e^{-\sum x_j}=\prod e^{-x_j}$ 和 $e^{-\sigma_j\delta_j}=1-\alpha_j$。这正是 A3 `_compute_weights` 要写的东西：README 里的两张公式图写的是 $L=\sum_iT(x,x_{t_i})(1-e^{-\sigma_{t_i}\Delta t})L_e$ 和 $T(x,x_{t_i})=T(x,x_{t_{i-1}})e^{-\sigma_{t_{i-1}}\Delta t}$，$L_e$ 就是这里的 $c$，README 特别提醒 $T_1=1$。

### 算一条 ray

Near 2、far 6，分 8 段，每段 $\delta=0.5$。$[3,4)$ 是一团 fog（$\sigma=0.8$，$c=0.2$），$[4.5,5.5)$ 是 solid（$\sigma=6$，$c=0.9$），其余是空的。

$\sigma$ 是单位长度上的 rate，可以大于 1：solid 的 $\sigma=6$。$\alpha$ 才是 probability，而且是“这一段”的，所以必须带 $\delta$。如果把每个 sample 的 $\alpha$ 当成与 $\delta$ 无关的常数，换个 sample 数结果就变：fog 长 1，真实的 $T$ 是 $e^{-0.8}=0.449$。按 $\delta=0.5$ 取 2 个 sample，$(1-0.3297)^2=0.449$，对；把 $\alpha=0.3297$ 照搬到 $\delta=0.25$ 的 4 个 sample，得 $0.6703^4=0.202$，fog 凭空浓了一倍多。用 $1-e^{-\sigma\delta}$，4 个 sample 是 $(e^{-0.2})^4=e^{-0.8}$，和 sample 数无关。

$$D=\sum_iw_i\,t_i=3\times0.3297+3.5\times0.2210+4.5\times0.4270+5\times0.0213=3.790$$

:::wrong Depth map 上的值就是 ray 碰到 surface 的位置
上面的 ray 上，fog 在 3 到 4，solid 的 surface 在 4.5，算出的 depth 是 3.79，那里什么都没有。$D$ 是 ray 停下位置的平均：55% 的 weight 停在 fog 里，43% 停在 solid 上，平均落在中间。只有 weight 集中在一个窄峰上（opaque 的 surface 前面没有半透明的东西），expected depth 才接近 surface。第 5 站的 SDF 就是为了得到真正的 surface 而引入的。A3 要求把 depth 除以最大值再可视化（README）。
:::

### Sample 放在哪里

均匀地取 $N$ 个点，每条 ray 都只在同样的 $N$ 个 depth 上查询 network，两点之间的东西永远看不见。NeRF 原文用 stratified sampling：把 $[t_n,t_f]$ 分成 $N$ 个 bin，每个 bin 里 uniform 地随机取一个点，

$$t_i\sim\mathcal U\Big[t_n+\tfrac{i-1}N(t_f-t_n),\;t_n+\tfrac iN(t_f-t_n)\Big]$$

每次 iteration 取的点都不同，training 时整条 ray 上的连续位置都会被查到。A3 的 `StratifiedRaysampler` 的 TODO 只要求在 $[t_n,t_f]$ 之间均匀取点，NeRF 的随机版本是可以自己加的改进。

:::edge 最后一段的 $\delta$ 是 $10^{10}$
A3 的 `renderer.py` 把最后一个 sample 的 $\delta$ 设成 $10^{10}$。只要最后一点的 $\sigma>0$，$\alpha\approx1$，它就吸收掉剩下的全部 transmittance，相当于把它当成不透明的背景。只有最后一点 $\sigma=0$ 时，才有 transmittance 留到背景，这对应 Digest 里 $T(t_f)\,c_{\text{bg}}$ 那一项。`renderer.py` 读了一个 `white_background` 选项，但怎么用留给你写，所有 config（lego、materials、volsdf）里都是 `False`，背景按黑色处理。
:::

### 先用一个 box 试一试

A3 第 2 部分用的场景不是 network，是一个参数化的 box：中心和边长是要 optimize 的参数（`train_box.yaml` 从边长 1.5、中心原点出发）。`SDFVolume` 先把 SDF 换成一个 0 到 1 之间的数

$$v(x)=\alpha\cdot\begin{cases}\tfrac12e^{-f(x)/\beta}&f(x)>0\\[2pt]1-\tfrac12e^{f(x)/\beta}&f(x)\le0\end{cases}$$

$\alpha=1$、$\beta=0.05$ 时，$v$ 在 surface 里面 0.1 处是 $1-\tfrac12e^{-2}=0.932$，外面 0.1 处是 $\tfrac12e^{-2}=0.068$，中间平滑过渡。然后它交给 renderer 的 density 是 $\sigma=-\log(1-v)/\delta$，renderer 算 $\alpha_i=1-e^{-\sigma\delta}=1-e^{\log(1-v)}=v$。所以在这个 box 场景里，$v$ 直接就是每个 sample 的 opacity，不管 sample 之间隔多远。Box 挪一点，每个 sample 的 $v$ 就连续地变一点，rendering 的结果也连续地变，gradient 存在。用 4 个 camera 的 image（`data/box_0.npy` 到 `box_3.npy`）和 MSE，就能把中心和边长 optimize 出来。这和第 2 站 soft rasterization 是同一个想法：把跳变换成一个窄的光滑过渡。

:::edge Box 场景里的 opacity 不随 $\delta$ 变
这正是上面 wrong 里说的那种做法：$\alpha_i$ 被直接定死成 $v$，换 sample 数，box 边缘那层过渡的“厚度”就跟着变。Box 场景固定 64 个 sample，又只是拿来练 renderer 和 optimization，所以无妨。第 5 站的 VolSDF 用的是同一个 Laplace CDF，但乘上 $\alpha$ 之后当真正的 density $\sigma$，再经过 $1-e^{-\sigma\delta}$，两者不要混用。
:::

:::from
CMU 的 L9 slides 读不到，这一站跟 L9 的 reading [Volume Rendering Digest](https://arxiv.org/pdf/2209.02417v1) 走：Eq. 1 到 7 的 transmittance 推导、CDF 与 PDF 的解释、Eq. 8 的 rendering integral 和背景项、Eq. 9 到 15 的 homogeneous segment、Eq. 16 到 18 的 transmittance 可乘、Eq. 19 到 25 的 piecewise-constant 与 alpha compositing，以及 $\alpha$ 依赖 segment 长度的说法（WebFetch 逐节读了全部公式和步骤）。Digest 不讲 depth，depth 和 stratified sampling 分别来自 A3 README 和 [NeRF 原文](https://ar5iv.labs.arxiv.org/html/2003.08934) 第 4 节。Ray 生成的三步、$T_1=1$、README 的两张公式图、depth 归一化、$\delta=10^{10}$、`white_background` 的现状、box 场景的 `SDFVolume`（Laplace CDF 当 opacity、$\sigma=-\log(1-v)/\delta$）和 $\beta=0.05$ 来自 [A3 仓库](https://github.com/learning3d/assignment3) 的 README、`renderer.py`、`implicit.py`、`sampler.py`、`ray_utils.py` 和 configs。8 段 ray 的例子、两个 wrong 里的数字是为这一页算的。
:::

## [nerf] NeRF：MLP、positional encoding 与 hierarchical sampling

:::skip
快速路线必读（L10 Neural Radiance Fields，reading 是 NeRF 原文；A3 Q3）。能写出 NeRF 的 network 结构和 positional encoding 的维数，能从 coarse weight 生成 fine sample，就可以去第 5 站；“gradient 去了哪里”一小节可以先跳。
:::

### 用一个 MLP 代替 box

Box 只有 6 个参数。真实场景要一个能表示任何东西的 $\sigma(x)$ 和 $c(x)$，NeRF 用一个 MLP：

$$F_\Theta:\;(x,d)\;\mapsto\;(\sigma,\;c)$$

$x$ 是 3D 位置，$d$ 是 ray 的方向。原文的结构：$\gamma(x)$ 经过 8 层 256 宽的 fully connected 层（ReLU），第 5 层把 $\gamma(x)$ 再拼进来一次（skip connection，附录说是跟 DeepSDF 学的），输出 $\sigma$（过 ReLU，非负）和一个 256 维 feature；feature 和 $\gamma(d)$ 拼起来再过一层 128 宽的层，输出 RGB（过 sigmoid）。$\sigma$ 只由 $x$ 决定，color 才看 $d$，原文的理由是这样能让 representation 在多个 view 之间一致。A3 的 `nerf_lego.yaml` 缩小了：`n_layers_xyz: 6`、128 宽、`append_xyz: [3]`（starter code 的 `MLPWithInputSkips` 在 index 3 的 layer 之前把 embedding 再拼进来），direction 分支 64 宽；README 要求 $\sigma$ 用 ReLU，color 用 Sigmoid，并且先不加 view dependence。

Training 就是第 3 站的 rendering 加 MSE：每个 iteration 从 training image 里随机取一批 pixel（A3 是 1024 条 ray，原文 4096 条），每条 ray 取点、查 MLP、按 $\sum T_i\alpha_ic_i$ 算 color，和 pixel 的真实 color 比。原文的 loss 把 coarse 和 fine 两个 network 的 rendering 都算进去：$\sum_r\big(\|\hat C_c(r)-C(r)\|^2+\|\hat C_f(r)-C(r)\|^2\big)$。原文用 Adam，learning rate 从 $5\times10^{-4}$ 指数衰减到 $5\times10^{-5}$，一个场景 10 到 30 万步，单张 V100 上 1 到 2 天。A3 在 $128\times128$ 的 lego 上训练 250 epoch，learning rate 从 $5\times10^{-4}$ 起每 epoch 乘 $0.8^{1/50}$，250 epoch 后剩 $0.8^5=0.33$ 倍。

:::wrong 让 $\sigma$ 也依赖 view direction，network 更灵活，fit 得更好
更灵活正是问题。如果 $\sigma$ 能随 $d$ 变，network 可以给每个 training camera 单独准备一套 geometry：比如在每个 camera 正前方放一张不透明的“海报”，上面画的就是那张 training image，从别的方向看这张海报是透明的。Training loss 可以是 0，换一个新 view 就什么都不对。$\sigma$ 只依赖 $x$，等于强制所有 view 共用同一份 geometry，这正是 multi-view 的约束所在。Color 依赖 $d$ 是为了表示反光；A3 的 README 也提醒，view dependence 加得太多会 overfit training image。反过来完全去掉 view dependence 也有代价：原文 Table 2 里只去掉它，PSNR 从 31.01 掉到 27.66。
:::

### 为什么直接喂 $(x,y,z)$ 会糊

把问题缩到一维看清楚：用一个两层、每层 32 个 ReLU 的 MLP 去 fit 一行 image（128 个 pixel），右半边有一段方波。同样的 network、同样的 Adam（learning rate $3\times10^{-3}$）、同样 600 步，只换 input。

::fig[cmu-16825-pe] 上面三条是 image 本身，下面是同样的值画成 curve。直接输入 $x$：600 步之后只学到平滑的趋势，方波的边全被抹平。输入 positional encoding $\gamma(x)$：每条边都对上了。

直接输入 $x$ 时，在 128 个 training pixel 上 PSNR 是 15.6 dB；输入

$$\gamma(p)=\big(\sin(2^0\pi p),\cos(2^0\pi p),\;\dots,\;\sin(2^{L-1}\pi p),\cos(2^{L-1}\pi p)\big)$$

（$L=4$，再拼上 $p$ 本身，共 9 维）时是 41.1 dB。

NeRF 原文给的原因只有一句：deep network 偏向先学 low frequency 的 function（引 Rahaman et al. 的 spectral bias），先把 input 映射到高频，就能 fit 含高频的 data。Tancik et al.（2020）把这件事算清楚了。在 network 很宽、learning rate 很小的极限下，gradient descent 训练出的 network 等价于用 neural tangent kernel（NTK）做 kernel regression。把 training set 上的 kernel matrix 分解成 $K=Q\Lambda Q^\top$，第 $t$ 步的 training residual 在 eigenvector 方向上的分量是

$$Q^\top\big(\hat y^{(t)}-y\big)\approx-e^{-\eta\Lambda t}\,Q^\top y$$

第 $i$ 个分量按 $e^{-\eta\lambda_it}$ 衰减：eigenvalue 大的分量学得快，小的学得慢。对直接吃坐标的 MLP，NTK 的 eigenvalue 随频率升高衰减得很快，所以 target 里的高频分量几乎不动，这就是上图里方波的边学不出来。加了 $\gamma$ 之后，network 看到的两个 input 之间的相似度从 feature 的内积开始算。每个频率的 $\sin$、$\cos$ 两项配成一对，用 $\cos a\cos b+\sin a\sin b=\cos(a-b)$：

$$\gamma(x_1)^\top\gamma(x_2)=\sum_{k=0}^{L-1}\Big[\sin(2^k\pi x_1)\sin(2^k\pi x_2)+\cos(2^k\pi x_1)\cos(2^k\pi x_2)\Big]=\sum_{k=0}^{L-1}\cos\big(2^k\pi(x_1-x_2)\big)$$

它只依赖 $x_1-x_2$，所以 Tancik et al. 说 composed NTK 变成 stationary（shift-invariant）的，而且它的带宽由选的频率直接决定：放进了 $2^{L-1}\pi$ 这样的高频，对应的 eigenvalue 就不再小，高频分量也能在有限步内学到。

NeRF 原文对 $x$ 的三个分量各用 $L=10$（$3\times2\times10=60$ 维），对 $d$ 用 $L=4$（24 维）。A3 的 `HarmonicEmbedding` 有两处不同：频率是 $2^k$，没有乘 $\pi$；默认把 input 本身也拼上。所以 `n_harmonic_functions_xyz: 6` 给出 $6\times2\times3+3=39$ 维，direction 的 2 给出 $2\times2\times3+3=15$ 维。

:::edge $L$ 不是越大越好
同一个实验把 $L$ 换成 6：128 个 training pixel 上的 PSNR 升到 89.9 dB，几乎完全背下来了；可是在 pixel 之间也取点（共 257 个点）和 target 比，PSNR 只有 20.7 dB，$L=4$ 是 26.8 dB，直接输入 $x$ 是 15.7 dB。最高频的 $\sin(2^{L-1}\pi p)$ 周期太短，network 用它在 training sample 之间插出了来回震荡的噪声。Tancik et al. 对 Fourier feature 的频率尺度做了同样的观察：太小 underfit，太大 overfit，结果是 noisy interpolation。NeRF 原文的 Table 2 也看得到上限：$L$ 从 10 降到 5，PSNR 从 31.01 掉到 30.59；升到 15，是 30.81，没有变好。原文的解释是 $2^L$ 一旦超过 sampled input image 里的最高频率（他们的数据里约 1024），再加频率就没有用。$L$ 要和场景的尺度、training image 的分辨率配合。
:::

### 看着它 converge

真实的 NeRF training 要几个小时，这里在一个平面里做同一件事：场景是一个 disk（$c=1$）和一个 square（$c=0.45$），$\sigma=12$；外圈 8 个 camera，每个拍一张 32 pixel 的 1D image，一共 256 条 ray。为了能在页面里算出来，用一个 $16\times16$ 的 grid 代替 MLP：每格存 $\sigma=e^{a}$ 和 $c=\mathrm{sigmoid}(b)$，ray 上每 0.04 取一个点、查所在的格子。Rendering 公式和 loss 与 NeRF 完全相同，Adam 的 learning rate 0.08，400 步。

::fig[cmu-16825-fit] 第一帧是 training 结束的样子；之后从 iteration 0 播放。loss 从 0.16 降到 $7.9\times10^{-4}$。注意两件事：square 的内部没有填满；grid 的几个角上长出了 camera 看不到的“floater”。

### Gradient 去了哪里

:::skip
解释上面动图里两个现象的推导。跳过只少了“为什么 opaque object 内部和 camera 看不到的地方学不到”的理由。
:::

对一条 ray，$C=\sum_iT_i\alpha_ic_i$。对 $c_i$ 的 derivative 直接就是 weight：

$$\frac{\partial C}{\partial c_i}=T_i\alpha_i=w_i$$

对 $\sigma_i$，它出现在两个地方：本段的 $\alpha_i$，以及后面所有段的 $T_j$（$j>i$）里那个因子 $1-\alpha_i=e^{-\sigma_i\delta_i}$。记 $S_i=\sum_{j>i}w_jc_j$ 为第 $i$ 段后面的贡献。$\dfrac{\partial\alpha_i}{\partial\sigma_i}=\delta_ie^{-\sigma_i\delta_i}=\delta_i(1-\alpha_i)$，$\dfrac{\partial S_i}{\partial\sigma_i}=-\delta_iS_i$（每一项都含一个 $e^{-\sigma_i\delta_i}$），所以

$$\frac{\partial C}{\partial\sigma_i}=T_i\,\delta_i(1-\alpha_i)\,c_i-\delta_iS_i=\delta_i\big(T_{i+1}c_i-S_i\big)$$

括号里是“这一段如果多挡一点，自己的 color 多进来多少”减“后面被它挡掉多少”。两项都带着 $T$：$T_{i+1}c_i$ 直接带，$S_i$ 里的每个 $w_j$ 也带着 $T_j\le T_{i+1}$。Ray 进入 opaque object 之后 $T\approx0$，里面的格子 gradient 是 0，怎么改都不影响任何 pixel，所以 square 的内部留着初始值附近的样子。Grid 的角上那几格根本不在任何 ray 上，或者只在少数几条 ray 的末端，loss 管不着它们；真实 NeRF 里的 floater 也是这样来的：只被很少 view 看到的区域，network 可以随意放东西。

### Hierarchical sampling：把 sample 放到有东西的地方

第 3 站的 ray 上，8 段里有 4 段是空的，weight 为 0，在那里查 network 白算。NeRF 用两个 network：coarse network 先用 $N_c=64$ 个 stratified sample 算出 weight $w_i$，归一化成一个 piecewise-constant 的 PDF $\hat w_i=w_i/\sum_jw_j$；再从这个 PDF 里用 inverse transform sampling 取 $N_f=128$ 个新点；fine network 在全部 $64+128$ 个点上算最终的 color。两个 network 的 rendering 都进 loss。

用第 3 站那条 ray 的 weight 演示（取 8 个确定的 $u=\tfrac{k+0.5}8$ 代替随机数）。归一化后 $\hat w=(0,0,0.330,0.221,0,0.427,0.021,0)$，CDF 在第 3、4、6、7 段末是 $0.330,0.551,0.979,1$。每个 $u$ 落进 CDF 跨过它的那一段，段内按比例线性插值：$t=t_i+\delta\,\dfrac{u-\text{CDF}_{i-1}}{\hat w_i}$。

| $u$ | 0.0625 | 0.1875 | 0.3125 | 0.4375 | 0.5625 | 0.6875 | 0.8125 | 0.9375 |
|---|---|---|---|---|---|---|---|---|
| 落在 | 段 3 | 段 3 | 段 3 | 段 4 | 段 6 | 段 6 | 段 6 | 段 6 |
| $t$ | 3.095 | 3.284 | 3.473 | 3.743 | 4.513 | 4.659 | 4.806 | 4.952 |

8 个新点全部落在 fog 和 solid 的前半段，空的 4 段一个都没有。段 7 的 weight 只有 0.021，也没分到：它被 solid 的前半段挡住了，查得再细也不影响 color。A3 的 4.2 是选做这一部分。

### 三个部件各值多少

原文 Table 2 在 Blender 的 8 个合成场景上把这一站的三个部件逐个拿掉（PSNR 取 8 个场景的平均，越高越好）：

| 设定 | input | image 数 | $L$ | $(N_c,N_f)$ | PSNR |
|---|---|---|---|---|---|
| 完整模型 | $xyz\theta\phi$ | 100 | 10 | (64, 128) | 31.01 |
| 去掉 positional encoding | $xyz\theta\phi$ | 100 | 无 | (64, 128) | 28.77 |
| 去掉 view dependence | $xyz$ | 100 | 10 | (64, 128) | 27.66 |
| 去掉 hierarchical sampling | $xyz\theta\phi$ | 100 | 10 | (256, 无) | 30.06 |
| 三个都去掉 | $xyz$ | 100 | 无 | (256, 无) | 26.67 |
| 只用 50 张 image | $xyz\theta\phi$ | 50 | 10 | (64, 128) | 29.79 |
| 只用 25 张 image | $xyz\theta\phi$ | 25 | 10 | (64, 128) | 27.78 |

:::from
CMU 的 L10 slides 读不到，这一站跟 L10 的 reading [NeRF 原文](https://ar5iv.labs.arxiv.org/html/2003.08934) 走：第 3 节（$\sigma$ 只依赖位置的理由）、第 4 节、第 5 节（positional encoding、hierarchical sampling、loss、batch size、learning rate、训练时间）、第 6.4 节和 Table 2 的全部数字、附录的 network 结构（第 5 层 skip、ReLU、sigmoid）。Spectral bias 的 NTK 解释、内积只依赖 $x_1-x_2$、频率太高时 noisy interpolation 来自 [Tancik et al.](https://arxiv.org/pdf/2006.10739)；内积那一行的三角恒等式展开是自己补的。A3 的网络尺寸、`append_xyz`、ReLU/Sigmoid、`HarmonicEmbedding` 不乘 $\pi$ 且包含 input、learning rate schedule、overfit 的提醒来自 [A3 仓库](https://github.com/learning3d/assignment3) 的 README、`implicit.py`、`volume_rendering_main.py` 和 `nerf_lego.yaml`。$\sigma$ 不能依赖 $d$ 的“海报”论证是自己的（原文只说要 multiview consistent）。一维 MLP 的对比实验、平面里的 grid 重建（含 PSNR、loss 的数字）、$\partial C/\partial\sigma_i$ 的推导和 hierarchical sampling 的数表都是为这一页做的，图里的数由代码算出。

## [sdf] Neural SDF、sphere tracing 与 VolSDF

:::skip
快速路线可跳（对应 L11 Neural Implicit Rendering，reading 是 IDR、VolSDF、NeuS 等；这一讲不在调研条目的快速路线里，A3 的 4.3 是三选一的 extension）。能手算 sphere tracing、写出交点对参数的 derivative、eikonal loss 和 VolSDF 的 density，就可以去第 6 站。
:::

### NeRF 给不出 surface

第 3 站算过：fog 后面有 solid 时，expected depth 落在两者之间。即使场景里没有 fog，NeRF 学出的 $\sigma$ 也常在 surface 前后拖出一段半透明的过渡，“surface 在哪里”只能对 $\sigma$ 取一个随意的 threshold。要 mesh、要准确的 depth、要 relighting，都需要一个明确的 surface。办法是让 network 输出 SDF $f(x)$，surface 就是 $f=0$。

### Sphere tracing

有了 SDF，ray 和 surface 的交点可以直接找。站在 $p$，$f(p)$ 是到最近 surface 的距离，以 $p$ 为中心、$f(p)$ 为 radius 的 ball 里没有任何 surface，沿 ray 走 $f(p)$ 一定不会穿过 surface：

$$p_{k+1}=p_k+f(p_k)\,d$$

$f$ 小于 $10^{-3}$ 时停。对 radius 1 的 sphere，从 $(-2.6,0.55)$ 沿 $+x$ 出发：

::fig[cmu-16825-sphere] 每个虚线圆是一步的“安全 ball”。正对着 sphere 的 ray 4 步就到；擦着边的 ray（$y=0.97$）每一步的最近点都在侧面，步子很小，要 16 步。

| 步 | $x$ | $f=\sqrt{x^2+0.55^2}-1$ |
|---|---|---|
| 0 | $-2.6000$ | 1.6575 |
| 1 | $-0.9425$ | 0.0913 |
| 2 | $-0.8513$ | 0.0134 |
| 3 | $-0.8378$ | 0.0022 |
| 4 | $-0.8356$ | 0.00036 |

真实交点是 $x=-\sqrt{1-0.55^2}=-0.8352$。第一步就走了 1.66，之后每步的 $f$ 大约缩小 7 倍。

:::edge 没打中的 ray
$y=1.05$ 的 ray 永远离 sphere 至少 0.05，$f$ 不会小于 $10^{-3}$，它要走 20 步才走出 $x=2.6$。实现时必须同时设最大步数和 far bound，否则擦边而过的 ray 会把整个 batch 拖住。
:::

L11 的 reading IDR（Yariv et al. 2020）给了一套实际用的设定：object 假设在 unit sphere 里，ray 从它和 unit sphere 的第一个交点出发；$|f|<5\times10^{-5}$ 算收敛，走出 unit sphere 算发散；最多走 10 步。没收敛的 ray 再从 unit sphere 的远端往回走 10 步，然后在两端之间等距取 100 个点，找第一对 $f$ 变号的相邻点，在这一对之间做 8 次 secant 迭代得到交点。擦边的 ray 正是靠这一步兜底。

### 交点的 gradient 只看一个点

找到交点 $\hat x=c+t\,v$（$c$ 是 camera center，$v$ 是 ray 方向）之后，pixel 的 color 由 $\hat x$ 处的 network 给出。Loss 要改 SDF 的参数 $\theta$，就需要 $\partial\hat x/\partial\theta$。Sphere tracing 是一个循环，不能直接对它 backprop；IDR 用的是交点满足的方程。不管 $\theta$ 怎么变，交点处 $f$ 都是 0：

$$f\big(c+t(\theta)\,v;\ \theta\big)=0$$

两边对 $\theta$ 求导。$f$ 通过两条路依赖 $\theta$：直接依赖，以及通过位置 $c+t\,v$ 依赖。Chain rule 给出

$$\nabla_xf(\hat x)^\top v\;\frac{\partial t}{\partial\theta}+\frac{\partial f}{\partial\theta}(\hat x)=0\quad\Longrightarrow\quad\frac{\partial t}{\partial\theta}=-\frac{1}{\langle\nabla_xf(\hat x),\,v\rangle}\,\frac{\partial f}{\partial\theta}(\hat x),\qquad\frac{\partial\hat x}{\partial\theta}=v\,\frac{\partial t}{\partial\theta}$$

右边只有 $\hat x$ 这一个点上的 $\partial f/\partial\theta$。用上面那条 $y=0.55$ 的 ray 代进去：交点 $\hat x=(-0.8352,\,0.55)$，unit sphere 的 $\nabla f=\hat x$，$v=(1,0)$，$\langle\nabla f,v\rangle=-0.8352$，所以 $\partial t/\partial\theta=1.197\,\partial f/\partial\theta$：network 在交点处的值升高 $\varepsilon$，交点往后退 $1.197\varepsilon$。擦边的 $y=0.97$ 那条，交点 $(-0.2431,\,0.97)$，系数变成 $1/0.2431=4.11$，同样的 $\varepsilon$ 把交点推出 4 倍远，gradient 在 silhouette 附近被放大。完全没打中的 ray 没有 $\hat x$，这个式子根本不存在，IDR 只好给这些 pixel 另加一个 mask loss。

### Network 输出的不一定是 distance：eikonal loss

Sphere tracing 每一步都依赖“$f$ 就是距离”。Network 输出的 $f$ 只要 zero level set 对，loss 就满足了，它完全可以是两倍的距离。第 1 站的 wrong 里已经算过 $f=2d$ 的后果：第一步走 3.31，落到 $x=0.715$，冲过前表面 1.55，对 sphere 这样厚的 object 还能靠负的 $f$ 往回走，薄的 object 就直接穿过去了。反过来 $f=0.5d$ 不会冲过头，但每步只走一半，要 12 步，是正确 SDF 的三倍。

所以要逼 network 满足第 1 站的 eikonal equation。在空间里随机取点，惩罚 gradient 的长度偏离 1：

$$\mathcal L_{\text{eik}}=\mathbb E_x\Big[\big(\|\nabla_xf(x)\|-1\big)^2\Big]$$

IDR 和 VolSDF 都用这个式子，weight 都是 0.1；IDR 的取点是 bounding box 里 uniform 的 1024 个点加上 rendering 过程中经过的点。$\nabla_xf$ 要对 input 求导，而且这个 gradient 本身还要再被 backprop，所以要用 `torch.autograd.grad(..., create_graph=True)`。A3 的 starter code 已经在 `NeuralSurface.get_distance_and_gradient` 里写好了这一步，要你写的只是 `losses.py` 里的 `eikonal_loss(gradients)`。A3 每个 iteration 在 $[-4,4]^3$ 里 uniform 取 1024 个点（和 ray 的 batch size 相同），eikonal 的 weight 是 0.02。

### VolSDF：SDF 也用 volume rendering 来 train

上一小节的式子说明了 sphere tracing 的毛病：每条 ray 只有交点那一个点拿到 gradient，surface 离正确位置远时，交点附近的修改推不动它，没打中的 ray 什么也给不了。VolSDF（Yariv et al. 2021，A3 README 指定读第 3.1 节）的办法是把 SDF 换成 density，然后沿用第 3 站的 volume rendering，ray 上每个 sample 都有 weight，也就都有 gradient。换法是：

$$\sigma(x)=\alpha\,\Psi_\beta\big(-f(x)\big),\qquad\Psi_\beta(s)=\begin{cases}\tfrac12e^{s/\beta}&s\le0\\[2pt]1-\tfrac12e^{-s/\beta}&s>0\end{cases}$$

原文的 SDF 约定和这一页一样：外面正、里面负（原文写成 $d_\Omega(x)=(-1)^{\mathbf 1_\Omega(x)}\min_{y\in\mathcal M}\|x-y\|$）。$\Psi_\beta$ 是均值 0、scale $\beta$ 的 Laplace distribution 的 CDF：离 surface 很远的外面 $\sigma\to0$，很深的里面 $\sigma\to\alpha$，surface 上正好 $\alpha/2$。这和第 3 站 box 场景的 $v(x)$ 是同一个式子，区别在用法：box 场景把它当每个 sample 的 opacity，VolSDF 把 $\alpha\Psi_\beta$ 当 density $\sigma$，再经过 $1-e^{-\sigma\delta}$。原文里 $\alpha$、$\beta$ 都是 learnable 的，实现中取 $\alpha=\beta^{-1}$，$\beta$ 初值 0.1。$\beta$ 决定过渡带的宽度：

| $f(x)$ | 0.2（外） | 0.1（外） | 0 | $-0.1$（内） |
|---|---|---|---|---|
| $\sigma/\alpha$，$\beta=0.05$ | 0.0092 | 0.0677 | 0.5 | 0.9323 |
| $\sigma/\alpha$，$\beta=0.2$ | 0.1839 | 0.3033 | 0.5 | 0.6967 |

$\beta$ 小，density 几乎是一个 step，rendering 出的 depth 就在 surface 上；但离 surface 0.2 以外 density 已经不到 1%，ray 在那里得不到 gradient，training 初期 surface 不在正确位置时很难被拉过去。$\beta$ 大，density 渗到 surface 外面，远处的 ray 也有 gradient，但 weight 的峰偏离 surface。拿一个垂直于 ray、在 $t=4$ 的平面试（$f(t)=4-t$），取 VolSDF 的 $\alpha=1/\beta$，在 $[2,6]$ 上数值积分，按 weight 归一化后的 expected depth：$\beta=0.05$ 是 4.017，$\beta=0.2$ 是 4.069，$\beta=0.5$ 是 4.153。$\beta$ 越大，learned surface 的位置 bias 越大。VolSDF 原文第 3.3 节从另一面讲同一件事：它给 opacity 的数值误差证了一个上界，$\beta$ 越小，上界里的 $\frac{\alpha}{4\beta}e^{-d^\star/\beta}$ 这类项越大，要更密的 sample 才能把误差压住，所以原文专门设计了一个按这个上界加点的 sampling algorithm。A3 的 4.3 正好问这三件事（high/low $\beta$ 的 bias、哪个好训练、哪个 surface 准）；`volsdf_surface.yaml` 取 $\alpha=10$、$\beta=0.05$，并没有按 $\alpha=1/\beta$（那会是 20），两个都是固定的超参数。

:::wrong SDF 的 network 和 NeRF 的 density network 结构一样，最后一层照搬就行
A3 的 README 专门提醒：density 和 distance 的取值范围不同。NeRF 的 density 最后接 ReLU，非负；SDF 必须能取负值（surface 里面），最后一层不能接 ReLU 或 Sigmoid。如果照搬 ReLU，$f\ge0$ 处处成立，$\Psi_\beta(-f)\le\tfrac12$，density 永远到不了 $\alpha/2$ 以上， object 内部“不实”，而且 zero level set 只能是 $f$ 恰好为 0 的一片区域，marching cubes 抽不出闭合的 surface。
:::

:::from
CMU 的 L11 slides 读不到，这一站跟 L11 的两篇 reading 走。Sphere tracing 的实际设定、交点的 implicit differentiation、eikonal loss 和它的 weight、mask loss 来自 [IDR](https://arxiv.org/pdf/2003.09852v3) 第 3 节和附录；$\langle\nabla f,v\rangle$ 的两个数值例子是自己算的。“沿 ray 走 $f(p)$ 不会穿过 surface”的论证和 eikonal equation 的推导是自己写的。VolSDF 的 Eq. 1 到 3、$\alpha=\beta^{-1}$、$\beta$ 初值、eikonal weight 0.1、第 3.3 节的误差上界来自 [VolSDF 原文](https://arxiv.org/pdf/2106.12052v2)。$\alpha=10$、$\beta=0.05$、eikonal 的 weight 0.02、1024 个点和取点范围来自 [A3 仓库](https://github.com/learning3d/assignment3) 的 `volsdf_surface.yaml`、`losses.py`、`volume_rendering_main.py`，`get_distance_and_gradient` 已写好这一点来自 `implicit.py`，三个问题和“density 与 distance 范围不同”的提醒来自 README。NeuS 没有读。Sphere tracing 的数表、擦边和没打中的步数、$f=2d$ 与 $0.5d$ 的步数、density 表和平面上的 depth bias 是为这一页算的。

## [gs] 3D Gaussian Splatting

:::skip
快速路线必读（L12 Differentiable Primitive Rendering (Meshes, Gaussians)，reading 是 SoftRas 和 3DGS 原文；A3 part B 占 60 分）。能对一个 Gaussian 算出 2D covariance 和一个 pixel 上的 $\alpha$，并完成 front-to-back blending，就可以去第 7 站。

### NeRF 慢在哪里

开头算过：$256\times256$ 的 image，每个 pixel 224 个 sample，是 $1.47\times10^7$ 次 MLP evaluation，其中大部分落在空的地方。3D Gaussian Splatting 的想法是不再沿 ray 去“问”空间，而是把场景直接存成一堆有形状的 primitive，每个 primitive 自己投到 image 上。原文在 Mip-NeRF360 数据集上的对比：

| method | PSNR | SSIM | LPIPS | training 时间 | rendering fps | memory |
|---|---|---|---|---|---|---|
| Plenoxels | 23.08 | 0.626 | 0.463 | 25 m 49 s | 6.79 | 2.1 GB |
| Instant-NGP（Base） | 25.30 | 0.671 | 0.371 | 5 m 37 s | 11.7 | 13 MB |
| Mip-NeRF360 | 27.69 | 0.792 | 0.237 | 48 h | 0.06 | 8.6 MB |
| 3DGS，7K iteration | 25.60 | 0.770 | 0.279 | 6 m 25 s | 160 | 523 MB |
| 3DGS，30K iteration | 27.21 | 0.815 | 0.214 | 41 m 33 s | 134 | 734 MB |

（Mip-NeRF360 那一行的 PSNR、SSIM、LPIPS 是原文从 Mip-NeRF360 论文里抄的。）30K iteration 的 3DGS，PSNR 比 Mip-NeRF360 低 0.48 dB，SSIM 和 LPIPS 反而更好（SSIM 越高越好，LPIPS 越低越好）；rendering 快了 $134/0.06\approx2200$ 倍，training 从 48 小时降到 42 分钟。代价是 memory：734 MB 对 8.6 MB，大了 85 倍。一个 MLP 用几 MB 的参数“压缩”整个场景，3DGS 把几百万个 Gaussian 的参数一个个列出来。

### 一个 Gaussian 存什么

每个 Gaussian 有中心 $\mu$、covariance $\Sigma$、opacity $o$ 和 color。形状是

$$G(x)=\exp\!\Big(-\tfrac12(x-\mu)^\top\Sigma^{-1}(x-\mu)\Big)$$

$\Sigma$ 不直接存，而是存一个 scale vector $s$ 和一个 quaternion $q$：

$$\Sigma=RSS^\top R^\top,\qquad S=\mathrm{diag}(s),\quad R=R(q/\|q\|)$$

$o$ 过 sigmoid 落在 $(0,1)$，$s$ 存 log、用时取 exp（A3 的 `apply_activations`）。Color 原文用 4 个 band 的 spherical harmonics（degree 0 到 3，每个 channel $1+3+5+7=16$ 个 coefficient；training 先只学 degree 0，每 1000 iteration 加一个 band），A3 的主体只用 degree 0，也就是与方向无关的一个 RGB。A3 Q6 进一步用 isotropic 的 Gaussian：$s$ 只有一个数，$\Sigma=s^2I$，quaternion 根本用不到。

:::wrong 直接把 $\Sigma$ 的 6 个数当参数，gradient descent 自己会把它学好
Covariance 必须是 positive semi-definite。在 2D 里看：$\Sigma=\begin{pmatrix}1&0.9\\0.9&1\end{pmatrix}$ 合法（eigenvalue 1.9、0.1）。一步 gradient 把非对角元推到 1.2，$\begin{pmatrix}1&1.2\\1.2&1\end{pmatrix}$ 的 determinant 是 $1-1.44=-0.44$，eigenvalue 是 2.2 和 $-0.2$。沿 $v=(1,-1)/\sqrt2$，$v^\top\Sigma^{-1}v=-5$，$G$ 的 exponent 变成 $+2.5$，$e^{2.5}=12.2$：离中心越远越“亮”，$\alpha$ 远超 1。用 $RSS^\top R^\top$，无论 $s$ 和 $q$ 取什么值，结果都是 PSD。（A3 的 `compute_alphas` 里把 exponent 大于 0 的情况直接置 0，就是在防这种数值问题。）
:::

### 投到 image 上

Camera coordinate frame 里一点 $(x,y,z)$ 投到 pixel $u=f_x\,x/z$、$v=f_y\,y/z$（再加 principal point）。这个 map 不是 linear 的，Gaussian 投过去不再是 Gaussian。在 $\mu$ 附近做一阶近似，用 Jacobian：

$$J=\frac{\partial(u,v)}{\partial(x,y,z)}=\begin{pmatrix}f_x/z&0&-f_x\,x/z^2\\0&f_y/z&-f_y\,y/z^2\end{pmatrix}$$

一个 Gaussian 经过 linear map $A$ 之后 covariance 变成 $A\Sigma A^\top$。World 到 camera 先转一个 rotation $W$，再过 $J$：

$$\Sigma'=J\,W\,\Sigma\,W^\top J^\top\qquad(2\times2)$$

算一个具体的。Camera coordinate frame 里（$W=I$）一个 Gaussian：$\mu=(0.4,-0.2,4)$，$s=(0.3,0.1,0.05)$，绕 $y$ 轴转 30°；$f_x=f_y=500$。

$$\Sigma=RSS^\top R^\top=\begin{pmatrix}0.0681&0&-0.0379\\0&0.01&0\\-0.0379&0&0.0244\end{pmatrix},\qquad J=\begin{pmatrix}125&0&-12.5\\0&125&6.25\end{pmatrix}$$

$J$ 的第一行：$500/4=125$，$-500\times0.4/16=-12.5$；第二行第三个数 $-500\times(-0.2)/16=6.25$。相乘得

$$\Sigma'=J\Sigma J^\top=\begin{pmatrix}1186.7&-31.5\\-31.5&157.2\end{pmatrix}$$

Eigenvalue 是 1187.6 和 156.2（A3 再给对角元各加 0.3，变成 1187.9 和 156.5），standard deviation 34.5 px 和 12.5 px：一个横向的椭圆，中心在 principal point 右 50 px、上 25 px（$500\times0.4/4=50$，$500\times(-0.2)/4=-25$，image 的 $v$ 轴朝下时是“上”）。如果忘了 $J$ 的第三列，$\Sigma'_{11}$ 会算成 $125^2\times0.0681=1064.5$，少 10%：离开 optical axis 的 Gaussian，depth 方向的伸展也会被斜着投到 image 上。

:::edge 每个 2D Gaussian 至少一个 pixel 大
A3 的 `compute_cov_2D` 在算完之后给 $\Sigma'$ 的对角元各加 0.3，官方 rasterizer（graphdeco-inria/diff-gaussian-rasterization 的 `forward.cu`）里是同样两行，注释叫它 low-pass filter，“every Gaussian should be at least one pixel wide/high”。问题出在很远或很小的 Gaussian：$\Sigma'=0.01I$（standard deviation 0.1 px）、$o=0.8$、中心落在两个 pixel center 正中间，离最近的 center 0.5 px，那里 $\alpha=0.8\,e^{-\frac12\cdot0.25/0.01}=0.8\,e^{-12.5}=3.0\times10^{-6}$，低于 $1/255$ 被跳过，这个 Gaussian 在哪个 pixel 上都看不见，中心挪 0.5 px 又突然出现。加了 0.3，$\Sigma'=0.31I$，同一个 pixel 上 $\alpha=0.8\,e^{-0.403}=0.535$。

两个 Gaussian 做 convolution，covariance 相加：$\mathcal N(\mu,\Sigma')*\mathcal N(0,0.3I)=\mathcal N(\mu,\Sigma'+0.3I)$。所以加 0.3 等于和一个 standard deviation $\sqrt{0.3}=0.55$ px 的 isotropic Gaussian 做 convolution。它不是“一个 pixel 大小的 box filter”：宽 1 px 的 box filter 的 variance 是 $\int_{-1/2}^{1/2}x^2\,dx=\tfrac1{12}=0.083$，standard deviation 0.29 px，0.3 是它的 3.6 倍。还有一点和真正的 convolution 不同：rasterizer 算的是 $\alpha=o\,e^{P}$，没有乘 normalize 的 $\frac1{2\pi\sqrt{|\Sigma'|}}$（A3 README 写出了归一化的 2D Gaussian，但 5.4 的 $\alpha$ 公式和代码都只用 exponent）。真正的 convolution 保持总量不变、峰值变低；这里换掉的只是形状，中心的 $\alpha$ 仍是 $o$，于是一个很小的 Gaussian 被放大后，在 image 上占的“量”反而变多了。

原文的 rasterizer 也用 99% confidence interval 做 frustum culling，靠近 near plane 或远在 frustum 外的 Gaussian 用 guard band 直接丢掉，因为它们投影后的 covariance 不稳定。A3 的 `_compute_jacobian` 把 $x/z$、$y/z$ clamp 在 $\pm1.3\tan(\text{fov}/2)$ 以内再算 $J$，防的是同一件事。
:::

### 在一个 pixel 上：$\alpha$ 与 blending

在 pixel $p$，Gaussian $i$ 的 $\alpha$ 是 opacity 乘 2D Gaussian 的值：

$$\alpha_i(p)=o_i\exp\!\Big(-\tfrac12(p-\mu_i')^\top\Sigma_i'^{-1}(p-\mu_i')\Big)$$

上面那个 Gaussian，$o=0.8$，pixel 离中心 $(10,3)$ px：$\Sigma'^{-1}$（含 0.3）代进去，exponent 是 $-0.076$，$\alpha=0.8\times e^{-0.076}=0.741$。

然后把所有 Gaussian 按 depth 从近到远排好，和第 3 站一模一样地做 front-to-back compositing：

$$C(p)=\sum_ic_i\,\alpha_i(p)\,T_i(p),\qquad T_i(p)=\prod_{j<i}\big(1-\alpha_j(p)\big)$$

NeRF 的 $\alpha_i=1-e^{-\sigma_i\delta_i}$ 来自沿 ray 的一段 volume；这里的 $\alpha_i$ 由 primitive 直接给出。原文的 Eq. 2 和 Eq. 3 就是在说两者是同一个 image formation model，差别只在 $\alpha$ 从哪里来、要不要沿 ray 取点。

三个 Gaussian 在一个 pixel 上的 $\alpha$ 是 0.6（red）、0.5（green）、0.9（blue），按这个顺序从近到远：$T=1,\,0.4,\,0.2$，weight $0.6,\,0.2,\,0.18$，pixel 是 $(0.6,0.2,0.18)$，偏红。如果蓝色那个其实最近，顺序变成蓝、红、绿，weight 是 $0.9,\,0.06,\,0.02$，pixel 几乎是纯蓝。排序决定结果。

在一个平面里把整个过程画出来：camera 在原点看 $+z$，image 是 $z=1$ 的一条 line，$u=x/z$。2D 里的 $J$ 只有一行 $(1/z,\;-x/z^2)$，$\Sigma'$ 是一个数，就是 image 上的 variance。

::fig[cmu-16825-splat] 左：三个 Gaussian（画的是 2 个 standard deviation 的椭圆）和它们在 image line 上的 footprint（$\mu'\pm2\sigma'$）。右：image 上每个 $u$ 处的 weight 按 depth 依次叠上去，虚线是剩下的 $T$。第一帧是三个都加完的样子。

在 $u=0.1$ 处，A、B、C 的 weight 是 0.56、0.17、0.13，剩下 $T=0.13$，四者加起来是 1（四舍五入后差 0.01）。B 的 opacity（0.9）比 A（0.8）大，拿到的 weight 却不到 A 的一半，因为它在 A 后面。

:::edge Sorting 是近似的
Sorting 用的是每个 Gaussian 中心的 depth，一个 Gaussian 只有一个位置。两个 Gaussian 在空间里互相穿插时，真实的前后关系随 pixel 变，按中心排就会错；camera 一动，两个中心的 depth 交换次序，画面会“跳”一下（popping），原文第 7.4 节把这列为局限。A3 的 Q5.3 要求先丢掉 depth 小于 0 的 Gaussian 再排序。原文的 rasterizer 把屏幕切成 $16\times16$ 的 tile，每个 Gaussian 对它覆盖的每个 tile 生成一个 64 bit 的 key（高位是 tile ID，低 32 bit 是 depth），整帧只做一次 GPU radix sort，排完同一 tile 的 Gaussian 自然按 depth 排在一起，每个 pixel 累计的 opacity 接近 1（原文是 0.9999）时就停；$\alpha<1/255$ 跳过、$\alpha$ 上限 0.99。A3 的代码保留了后两条，并在 $T<10^{-4}$ 时截断。
:::

### Training 与 adaptive density control

参数是所有 Gaussian 的 $\mu$、$s$、$q$、$o$、color，loss 是 rendering 和真实 image 的差：

$$\mathcal L=(1-\lambda)\mathcal L_1+\lambda\,\mathcal L_{\text{D-SSIM}},\qquad\lambda=0.2$$

原文的初始 Gaussian 放在 SfM 给出的 sparse point 上（SfM 本身见 [CS4277](../courses/CS4277.html#sfm)），这些点没有 normal；初始 covariance 是 isotropic 的，axis 长度取到最近三个点的平均距离。Training 开始时 image 的分辨率先降到 1/4，在第 250 和 500 iteration 各放大一次。Gaussian 的数目要随 training 增减（adaptive density control）：每 100 iteration 检查一次，view-space 位置 gradient 的平均大于 0.0002 的 Gaussian 说明它所在的区域没表示好。小的 Gaussian 复制一个（clone），大的拆成两个、scale 除以 1.6（split）；opacity 太低的删掉；每 3000 iteration 把所有 opacity 压到接近 0，需要的会自己长回来，不需要的随之被删。

A3 的 Q6 用 truck 的 point cloud 初始化 isotropic Gaussian（`_load_points`）：scale 取每个点到最近 50 个点的平均距离再取 log，opacity 的 pre-activation 是 8（sigmoid 之后 0.9997），color 随机，quaternion 是 identity；默认 1000 iteration，README 说 L1 loss 就够。Q7.2 换成多 object 的 materials 场景，从随机点出发（`_load_random`）：10000 个 mean 取自 $\mathcal N(0,0.2^2I)$，也就是 README 说的“原点附近的一个 sphere”，scale 在 0 到 0.01 之间随机。README 列出的改进方向正是上面这些：不同参数不同 learning rate 和 schedule、加 SSIM、简化版的 density control、anisotropic Gaussian、调初始化参数。

:::from

## [sparse] 少量 view：diffusion prior 与 multi-view transformer

:::skip
Multi-view transformer 一半是快速路线必读（L15、L16 Multi-view Transformers: View Synthesis / Reconstruction，reading 有 LVSM、VGGT；A4 的前置）；SDS 一半（L17 Generative 3D Modeling 的 reading DreamFusion，以及 L18 Single-view 3D: A generative approach）在调研条目里列为可跳，代价是对 3D 生成了解少一些。能写出 SDS 的 gradient、算一条 ray 的 Plücker coordinates、说出 LVSM 和 VGGT 的输入输出，就可以去第 8 站。
:::

### 第 3 到 6 站都假设有很多张带 pose 的 image

NeRF 和 3DGS 每个场景从头 optimize，需要几十到上百张 image，而且每张的 camera pose 已知（通常先跑 SfM）。只有一两张 image，或者只有一句 text 时，问题回到开头的第一次失败：几何上不确定，只能靠 prior。这门课讲了两条路。一条是保留 per-scene optimization，但用一个在海量 2D image 上训练好的 diffusion model 来判断“渲染出来的 image 像不像”；另一条是不再 per-scene optimize，在很多场景上训练一个 feed-forward network，直接从几张 image 输出新 view 或 geometry。

### Score distillation sampling

DreamFusion 只有一句 text $y$，要生成一个 3D object。参数 $\theta$ 是一个 NeRF；每一步随机取一个 camera，render 出 image $x=g(\theta)$。手上有一个训练好的 text-to-image diffusion model，它的 training loss 是：给 $x$ 加 noise 得 $z_t=\alpha_tx+\sigma_t\varepsilon$，让 network 预测 noise，

$$\mathcal L_{\text{diff}}(\theta)=\mathbb E_{t,\varepsilon}\Big[w(t)\,\big\|\hat\varepsilon_\phi(z_t;y,t)-\varepsilon\big\|^2\Big]$$

直觉上，$x$ 越像“$y$ 描述的 image”，这个 loss 越小，所以对 $\theta$ 最小化它。Chain rule：$z_t$ 通过 $x$ 依赖 $\theta$，

$$\nabla_\theta\mathcal L_{\text{diff}}=\mathbb E_{t,\varepsilon}\Big[w(t)\,\big(\hat\varepsilon_\phi(z_t;y,t)-\varepsilon\big)\,\frac{\partial\hat\varepsilon_\phi}{\partial z_t}\,\alpha_t\,\frac{\partial x}{\partial\theta}\Big]$$

（常数 2 并进 $w(t)$。）中间的 $\partial\hat\varepsilon_\phi/\partial z_t$ 是 U-Net 的 Jacobian：要 backprop 穿过整个 U-Net，很贵；原文还指出它在 noise 小时 poorly conditioned。DreamFusion 直接把它丢掉（$\alpha_t$ 也并进 $w$），得到 SDS：

$$\nabla_\theta\mathcal L_{\text{SDS}}=\mathbb E_{t,\varepsilon}\Big[w(t)\,\big(\hat\varepsilon_\phi(z_t;y,t)-\varepsilon\big)\,\frac{\partial x}{\partial\theta}\Big]$$

Diffusion model 是冻住的：它看一眼加了 noise 的 rendering，说出“noise 应该是这样”，预测值和真实加进去的 noise 之差，就是 image 应该怎么改；这个改动经由 $\partial x/\partial\theta$ 回到 NeRF。

::fig[cmu-16825-sds] 上：SDS 的一步。回传只经过 rendering 的 Jacobian，不经过 U-Net。下：一维例子，6 个起点在 SDS 下全部收敛到 prior 的 mode。

### SDS 找的是 mode，不是 sample

下面这个一维例子能把 SDS 收敛到哪里算出来。“Image” 是一个数 $x=\theta$，data 的 distribution 是 $N(\mu,s^2)$，diffusion model 取最优的 noise predictor。$z=\alpha x_0+\sigma\varepsilon$，$x_0\sim N(\mu,s^2)$，$(z,\varepsilon)$ 是 jointly Gaussian：$\mathrm{Cov}(\varepsilon,z)=\sigma$，$\mathrm{Var}(z)=\alpha^2s^2+\sigma^2$，所以最优的 predictor 是 conditional expectation

$$\hat\varepsilon(z)=\mathbb E[\varepsilon\mid z]=\frac{\sigma\,(z-\alpha\mu)}{\alpha^2s^2+\sigma^2}$$

代入当前的 $x$：$z=\alpha x+\sigma\varepsilon$，

$$\hat\varepsilon-\varepsilon=\frac{\sigma\alpha(x-\mu)}{\alpha^2s^2+\sigma^2}+\varepsilon\Big(\frac{\sigma^2}{\alpha^2s^2+\sigma^2}-1\Big)$$

第二项对 $\varepsilon$ 取 expectation 是 0，所以

$$\mathbb E_\varepsilon\big[\hat\varepsilon-\varepsilon\big]=\frac{\sigma\alpha}{\alpha^2s^2+\sigma^2}\,(x-\mu)$$

对每个 $t$ 都和 $x-\mu$ 同号。沿负 gradient 走，$x$ 一定被推向 $\mu$，不管起点在哪。图里取 $\mu=2$、$s=0.5$，6 个起点从 $-2.5$ 到 $3.8$，300 步后 mean 1.98、sd 0.07；prior 本身的 sd 是 0.5。真正从 prior 里 sample，6 个数应该散开；SDS 把它们全部挤到 mode。

这解释了 DreamFusion 原文写的局限：不同 random seed 的结果差别很小，结果 oversaturated、oversmoothed。它用的 classifier-free guidance weight 是 $\omega=100$，远大于 2D 生成常用的值；原文的解释是 SDS 的 mode-seeking 性质让小的 guidance 只会得到过分平滑的结果。其他设定：$t\sim U(0.02,0.98)$（避开两端的数值不稳定），Imagen 的 $64\times64$ base model，15000 iteration，在 4 chip 的 TPUv4 上约 1.5 小时。

:::edge 每个 view 单独看都对，合起来不对
Diffusion model 每次只看一张 rendering，问的是“这张像不像 $y$”，不知道其他 view 长什么样。Object 的正面最常见，于是每个方向都被推成正面：一只狗长出好几个头（原文的 ablation 里写到 multiple heads，通常叫 Janus problem）。DreamFusion 按 camera 的位置改 prompt 来缓解：elevation 大于 60° 时在 prompt 后面加 “overhead view”，否则按 azimuth 加 “front view”、“side view” 或 “back view”。原文的 ablation 里，去掉这一招的狗变成多张脸、geometry 是扁的。
:::

### Feed-forward：camera 怎么交给 network

另一条路是在很多场景上 train 一个 transformer，输入几张 image 和它们的 camera，直接输出结果。A4 用 ScanNet++ 的 280 个室内场景做两件事：mini-LVSM 做 novel view synthesis，mini-VGGT 从 RGB 预测 camera 和 depth。

先要把 camera 变成 network 能吃的东西。A4 的做法是给每个 pixel 一条 ray，用 Plücker coordinates 表示：

$$(d,\;m),\qquad m=o\times d$$

$o$ 是 ray 上任意一点（A4 取 camera center），$d$ 是 unit direction。为什么不直接用 $(o,d)$：$o$ 在 line 上换一个点，$(o,d)$ 就变，可那还是同一条 ray。Plücker 的 $m$ 不变：

::fig[cmu-16825-plucker] 平行于 $z$ 轴、过 $(1,2,0)$ 的 line。$o$ 换成 line 上的另一点 $o'$，$m$ 不变；$|m|$ 是 origin 到 line 的距离。

$o=(1,2,0)$，$d=(0,0,1)$：

$$m=o\times d=\big(2\cdot1-0\cdot0,\;0\cdot0-1\cdot1,\;1\cdot0-2\cdot0\big)=(2,-1,0)$$

换成 $o'=o+3d=(1,2,3)$：$o'\times d=o\times d+3\,d\times d=m$，因为 $d\times d=0$。$|m|=\sqrt5$，正好是 origin 到这条 line 的距离（line 上离 origin 最近的点是 $(1,2,0)$）。一个 pixel 的 6 个数 $[d_x,d_y,d_z,m_x,m_y,m_z]$ 和 RGB 拼在一起，就是这个 pixel 的“带 camera 的 input”。

### Canonicalization：scale 必须固定

不同场景的 world coordinate frame 是随意的：原点在哪、哪个方向朝上、单位多大都不一样。A4 Part 1 的 canonicalization 做两件事：所有 camera 表示在第一个 camera 的 coordinate frame 里（camera 0 的 pose 是 identity）；整体缩放，使有效点的 centroid 到原点的距离是 1。

后一件是开头第一次失败的直接后果。只看 image，整个场景放大 2 倍、camera 之间的距离也放大 2 倍，每张 image 一个 pixel 都不变。Network 不可能从 image 里知道绝对的 scale，如果 target 的 scale 随场景乱变，loss 会逼它去猜一个猜不出的数。固定 centroid 的距离，等于替所有场景约定了一个单位。

A4 的 scale 用的是 `compute_scene_scale`：把所有 view 的有效点放在 camera 0 的 frame 里，取它们的平均点，再取这个平均点的 norm，$s=\big\|\tfrac1N\sum_kp_k\big\|$；然后 translation、depth、point 都除以 $s$，不减去 centroid（docstring 特别写明 do not subtract the centroid，camera 0 必须留在原点）。VGGT 原文用的是另一个量：所有点到原点距离的平均，$\tfrac1N\sum_k\|p_k\|$。两者不同。只有两个点 $(1,0,0)$ 和 $(-1,0,2)$ 时，平均点是 $(0,0,1)$，A4 的 $s=1$；VGGT 的是 $\tfrac12(1+\sqrt5)=1.618$。所以 A4 的 checker 要求 centroid 的距离约为 1，而不是点到原点的平均距离约为 1。

:::wrong Depth map 里的值就是 pixel 沿 ray 到 object 的距离
A4 的 data contract 写明 depth 是沿 optical axis 的 z-depth。一个 pixel 的 ray 和 optical axis 夹 30°，z-depth 2 m，沿 ray 的距离是 $2/\cos30°=2.309$ m，差了 15%。Unprojection 要用 $X_{\text{cam}}=z\cdot K^{-1}(u,v,1)^\top$（$K^{-1}(u,v,1)^\top$ 的第三个分量是 1，乘 $z$ 正好落在 z-depth 上），而不是 $z$ 乘 unit direction。A4 还规定 depth 存成毫米的 16-bit PNG，0 表示缺失，读进来要换单位并 mask 掉 0。
:::

### LVSM 与 VGGT

**Mini-LVSM（novel view synthesis）。** Source view 的 RGB（移到 $[-1,1]$）和 Plücker 拼起来，每个 pixel 9 个 channel，切成 $p\times p$ 的 patch，linear projection 成 token（LVSM 原文写成 $x_{ij}=\mathrm{Linear}_{\text{input}}([I_{ij},P_{ij}])$）；target view 只有 Plücker ray，没有 RGB，也切成 patch 变成 query token。每个 target 一条序列：所有 source token 后面接这个 target 的 query token，加 2D sin-cos positional embedding，过 full attention 的 transformer，只取 target token，经 RGB head、sigmoid、unpatchify 得到 image，和真实 target image 算 MSE。没有任何 3D representation：geometry 全在 attention 里。评测的 ablation 把 target ray 换成别的 view 的 ray（shuffled）或全 0（none），看 network 是不是真的在用 camera。

数一下序列有多长。`configs/lvsm.json` 取 $p=8$、image $224\times224$，每个 view $28\times28=784$ 个 token；2 个 source view 加 1 个 target，一条序列 $3\times784=2352$ 个 token，过 8 层、宽 384（6 个 head，每个 64 维）的 transformer。Attention 的计算量按序列长度的平方涨，source view 从 2 个加到 4 个，序列变成 $5\times784=3920$，attention 的计算量变成 $(3920/2352)^2=2.8$ 倍。原文的 decoder-only LVSM 是 24 层、宽 768、$p=8$，loss 是 MSE 加 perceptual loss，在 64 张 A100 上训练 3 到 7 天；mini 版去掉了 perceptual loss（A4 的 bonus 2.3 正好让你加回来）。

**Mini-VGGT（从 RGB 预测 camera 和 depth）。** 冻住的 DINOv2 ViT-B/14 把每张 $224\times224$ 的 image 切成 $16\times16=256$ 个 patch feature，投影到宽 384。每个 view 前面再加 1 个 camera token 和 4 个 register token，一共 261 个 token；camera 0 用自己的一套 camera/register token，其余 view 共用另一套，network 靠这个认出哪个是 reference camera（VGGT 原文的做法）。然后交替做 frame attention（$261$ 个 token，只在一张 image 内部）和 global attention（8 个 view 的 $8\times261=2088$ 个 token 一起），8 对共 16 个 block；最后一对的 frame 输出和 global 输出拼起来，宽 768。Camera head 拿 camera token，再过 4 个跨 view 的 transformer block，每个 view 输出 9 个数：world-to-camera translation 3 个、quaternion 4 个、vertical 和 horizontal FoV 2 个。Depth head 把 patch token 解码回 dense 的 depth 和 confidence（$\ge1$）。

Loss（`models/vggt/losses.py`）是 $5\,\mathcal L_{\text{camera}}+1\cdot\mathcal L_{\text{depth}}$：

$$\mathcal L_{\text{camera}}=\overline{|\hat t-t|}+\overline{|\hat q-q|}+0.5\,\overline{|\widehat{\text{fov}}-\text{fov}|}$$

（L1，translation 的每个误差先 clamp 在 100 以内），

$$\mathcal L_{\text{depth}}=\mathrm{tm}\big(|\hat D-D|\big)+\mathrm{tm}\big(c\,|\hat D-D|-0.2\log c\big)+\mathcal L_{\text{grad}}$$

$\mathrm{tm}$ 是去掉最大 2% 的 trimmed mean，$c$ 是 confidence，$\mathcal L_{\text{grad}}$ 在 stride 1、2、4、8 四个尺度上比较 residual 的相邻差。中间那项是在学 confidence：误差大的 pixel，把 $c$ 调小可以降低 $c|\hat D-D|$，但 $-0.2\log c$ 不让 $c$ 无限变小。只看一个 pixel，对 $c$ 求导令它为 0：$|\hat D-D|-0.2/c=0$，$c=0.2/|\hat D-D|$，误差越大，最优的 confidence 越低（又因为 $c\ge1$，误差小于 0.2 的 pixel 都停在 $c=1$）。Target 就是 Part 1 canonicalize 过的 camera 和 depth。原文的 VGGT 是 24 对 alternating attention、约 12 亿参数，camera loss 用 Huber，dense head 用 DPT，还预测 point map 和 tracking，在 64 张 A100 上训练 9 天；A4 的 handout 也写明 mini 版只做一次 camera 预测，depth decoder 用 RGB refinement 代替 DPT。评测报告 depth 的 AbsRel、$\delta_1$（$\max(\hat d/d,d/\hat d)<1.25$ 的比例），以及 rotation、translation 的 AUC。

:::from
CMU 的 L15 到 L18 slides 读不到。SDS 的 Eq. 1 到 4、丢掉 U-Net Jacobian 的两个理由、“mode-seeking” 的说法、$\omega=100$ 及其理由、$t\sim U(0.02,0.98)$、elevation 60° 的 prompt 规则、64×64、15000 iteration 与 TPUv4 4 chip 约 1.5 小时、oversaturated、oversmoothed、seed 之间差别小和 multiple heads 的局限来自 L17 的 reading [DreamFusion 原文](https://ar5iv.labs.arxiv.org/html/2209.14988)（WebFetch 分两段读）。Chain rule 那一行是自己补的。一维 Gaussian 的推导和图里的 6 条轨迹是为这一页做的。Plücker 的约定 $m=o\times d$、canonicalization 的规定和 `compute_scene_scale`、z-depth 与毫米 PNG、mini-LVSM 与 mini-VGGT 的结构、config、loss 和评测来自 [A4 仓库](https://github.com/learning3d/assignment4_f26) 的 README、`docs/`、`a4data/geometry.py`、`a4data/scale.py`、`models/lvsm/model.py`、`models/vggt/model.py`、`models/vggt/losses.py` 和 `configs/`。原版的规模、token 设计、camera 参数化、loss 和 normalization 来自 L15、L16 的 reading [LVSM](https://arxiv.org/pdf/2410.17242v2) 和 [VGGT](https://arxiv.org/pdf/2503.11651v1) 的 method 与附录。Scale 必须固定的理由、两种 scale 的数值例子、序列长度与 attention 计算量、confidence 的最优值、z-depth 的数值例子是自己写的。
:::

## [point] Point cloud processing：PointNet 与 locality

:::skip
快速路线必读（L19 Processing Point Clouds I: Classification and Segmentation，reading 有 PointNet、Point Transformer；A5 的前置，也是机器人里 point cloud policy 的基础）。能手算 max pooling 的 global feature，说出它对 permutation 不变、对 rotation 却会变，就可以去作业。
:::

### Point cloud 是一个 set

前几站都在“生成”3D；这一站反过来，input 是 point cloud（LiDAR、depth camera 直接给的就是它），要做 classification 或 segmentation。A5 的每个 object 有 10000 个点，排列顺序是任意的：同一个 object 有 $10000!$ 种排法，network 的输出必须对它们全部一样。

把 coordinates 拼成一个 30000 维的 vector 送进 MLP 是不行的。两个点的情况就能看出来：$f(p_1,p_2)=w_1^\top p_1+w_2^\top p_2$，交换 $p_1$、$p_2$ 得 $w_1^\top p_2+w_2^\top p_1$，除非 $w_1=w_2$，结果不同。

### Shared MLP 加 symmetric function

对 permutation 不变的 function 有一个简单的构造：每个点用同一个 $h$ 变成 feature，再用一个与顺序无关的运算合起来，

$$g(p_1,\dots,p_N)=\max_{i}\;h(p_i)\qquad(\text{逐个 channel 取 max})$$

PointNet 的 $h$ 是一个 shared MLP（实现上是 kernel size 1 的 Conv1d），max 之后再接一个 MLP 输出 class score。用一个手写的 $h$ 走一遍：6 个 2D 点，$h(x,y)=(x,\;y,\;\mathrm{ReLU}(x-y))$。

::fig[cmu-16825-pointnet] 每一行是一个点的 feature，每一列取 max。Global feature $(0.95,\,2.00,\,0.85)$ 只由 p3、p5、p2 三个点决定。

把 6 行任意重排，每列的 max 不变，这就是 permutation invariance。PointNet 原文第 4.2 节比较过三条路：先把点排成一个 canonical 的顺序（高维里没有对扰动稳定的排序）、把点当 sequence 喂 RNN 再用随机排列做 augmentation（顺序仍然有影响，几千个点也太长），以及这里的 symmetric function。它的 Eq. 1 写成 $f(\{x_1,\dots,x_n\})\approx g\big(h(x_1),\dots,h(x_n)\big)$，$g$ 是 max pooling 再接一个 function；Theorem 1 证明这种形式能任意逼近对 Hausdorff distance 连续的 set function。

取到 max 的点叫 critical point：删掉 p1、p4、p6 中的任何一个甚至全部，global feature 一个数都不变。原文的 Theorem 2 把这件事说成一般结论：存在一个 critical point set $\mathcal C_S$，只要输入的点集 $T$ 满足 $\mathcal C_S\subseteq T\subseteq\mathcal N_S$（$\mathcal N_S$ 是一个“上界形状”），输出就和原来一样；而且 $|\mathcal C_S|\le K$，$K$ 是 max pooling 那一层的维数。这里 $K=3$，critical point 恰好 3 个。原文的分类网络 $K=1024$，可视化出的 critical point 大致是 object 的骨架。这说明 PointNet 对点数变化比较鲁棒：原文在 ModelNet40 上丢掉一半的点，accuracy 只掉 2.4%（用 farthest point sampling 留点）或 3.8%（随机留点）。A5 的 Q3 用 `--num_points` 做的正是这个实验（`eval_cls.py` 用 `np.random.choice` 不放回地随机留点）；它也说明 global feature 只“记住”了少数极端点。

**Segmentation** 要给每个点一个 label，只有 global feature 不够。PointNet 把每个点自己的 local feature 和 global feature 拼起来，再过一个 shared MLP，输出这个点的 class。A5 的 chair 有 6 个 part，`seg_model` 的输出是 $(B,N,6)$。

:::wrong 对点的顺序不变，所以对 rotation 也不变
上面 6 个点转 90°，$(x,y)\to(-y,x)$。新的 global feature：$h_1=\max(-y)=0$（p1 的 $y=0$），$h_2=\max x=0.95$，$h_3=\max\mathrm{ReLU}(-y-x)=0$，得 $(0,\,0.95,\,0)$，原来是 $(0.95,\,2.00,\,0.85)$。Permutation 改的是行的顺序，rotation 改的是每一行的内容，max 只管前者。PointNet 原文用一个 T-Net（自己也是一个小 PointNet）预测一个 $3\times3$ 的 transformation 把 input 对齐，再用第二个 T-Net 预测 $64\times64$ 的 feature transformation，并加 regularization $\|I-AA^\top\|_F^2$（weight 0.001）让它接近 orthogonal；A5 的 README 说这一块可以不做；A5 的 Q3 让你在 eval 时把 input 转一个固定角度，看 accuracy 掉多少。
:::

### 缺的是 locality

$h$ 一次只看一个点，点和点之间唯一的交互是最后那一次 max。一个点周围的局部形状（是不是在一条棱上、局部是平的还是弯的）它看不到。CNN 在 image 上之所以好用，正是因为每层只看一个邻域、层层往上组合；PointNet++ 把这个结构搬到 point set 上：

1. Sampling：用 farthest point sampling 选出 $N'$ 个中心点，每次选离已选集合最远的点。上面 6 个点从 p1 开始：p5 离 p1 最远（2.00），选 p5；剩下各点到 $\{p_1,p_5\}$ 的最近距离里 p3 最大（1.24），选 p3。三个中心点散布在整个 object 上，不会挤在一处；原文说同样多的中心点，它比随机选覆盖得好。
2. Grouping：每个中心点用 ball query 取 radius 内的 neighbor（最多 $K$ 个），得到 $N'\times K\times(d+C)$ 的 tensor。原文更推荐 ball query 而不是 kNN：固定 radius 意味着每组代表的空间尺度固定。
3. PointNet layer：每组的 coordinates 减去中心点，$x_i^{(j)}\leftarrow x_i^{(j)}-\hat x^{(j)}$，变成 local coordinates，对每组跑一个小 PointNet，输出 $N'\times(d+C')$。
4. 中心点连同 feature 作为新的 point set，重复以上几步，radius 逐层变大。

原文还处理了点的疏密不均（同一组里叠几种 radius，或叠两层的 feature），以及 segmentation 时怎样把 feature 传回所有原始点：对每个原始点，取下一层最近的 $k=3$ 个点，按 $w_i=1/d(x,x_i)^2$ 加权平均它们的 feature，再和同层 skip 过来的 feature 拼起来。

**DGCNN** 的 EdgeConv 让 $h$ 同时看一个点和它的 neighbor。对点 $x_i$ 取 $k$ 个 nearest neighbor（分类用 $k=20$），每条 edge 算

$$e'_{ijm}=\mathrm{ReLU}\big(\theta_m\cdot(x_j-x_i)+\phi_m\cdot x_i\big),\qquad x'_{im}=\max_{j}\,e'_{ijm}$$

$x_j-x_i$ 是局部形状，$x_i$ 是它在整个 object 里的位置；原文说只留前者会丢掉各个 patch 的位置，只留后者就退回 PointNet。上面的 p2 取 $k=2$：最近的是 p6（距离 0.64）和 p1（0.80），EdgeConv 看到的两个 offset 是 $(-0.4,\,0.5)$ 和 $(-0.8,\,-0.05)$，整个点云平移多少，这两个数都不变。“Dynamic”指每一层都在当前的 feature space 里重新找 kNN，而不是一直用 input 空间里的 neighbor。

**Point Transformer** 在 $k=16$ 个 nearest neighbor 之间做 vector attention：

$$y_i=\sum_{x_j\in\mathcal X(i)}\rho\Big(\gamma\big(\varphi(x_i)-\psi(x_j)+\delta\big)\Big)\odot\big(\alpha(x_j)+\delta\big),\qquad\delta=\theta(p_i-p_j)$$

$\varphi,\psi,\alpha$ 是 linear map，$\gamma$ 和 position encoding $\theta$ 是小 MLP，$\rho$ 是 softmax。和普通 attention 的区别是 weight 由 $\varphi(x_i)-\psi(x_j)$ 这个差经过 MLP 得到，而且是一个 vector，每个 channel 一个 weight；位置只以相对位置 $p_i-p_j$ 进来。

| 方法 | 怎样引入 locality | 原文的 ModelNet40 accuracy |
|---|---|---|
| PointNet | 没有，只有最后一次 max | 89.2% |
| PointNet++ | FPS + ball query + 逐层 PointNet | 90.7% |
| DGCNN | kNN graph 上的 EdgeConv，每层重建 graph | 92.9% |
| Point Transformer | kNN 内的 vector attention | 93.7% |

A5 的 Q4 bonus（20 分）要求从这几种里选一种实现，和 Q1、Q2 的结果比。
