## [pipe] Rendering 的两条路与 OpenGL 程序

:::skip
能用 similar triangles 算 pinhole camera 上的投影点，说出 ray casting 和 rasterization 的循环怎样互换，写得出 GLUT 程序的 display、reshape、idle callback 和 double buffering，就可以去第 2 站。
:::

### 一个点落在 image 的哪里

Rendering 的输入是一个 scene：viewer、object、light、material 四样东西。输出是一张 image，每个 pixel 一个颜色。最基本的问题是：3D 空间里一个点，落在 image 的哪个位置？

把 camera 看成一个 pinhole。眼睛在 origin，image plane 在眼前距离 $d$ 处，和 $z$ 轴 perpendicular。点 $P=(x,y,z)$ 发出的光穿过 pinhole 打到 image plane 上的 $(x_p,y_p)$。从侧面看，origin、$P$ 在 $z$ 轴上的垂足、$P$ 组成一个 right triangle；origin、image plane 与 $z$ 轴的交点、$(x_p,y_p)$ 组成另一个。两个 triangle 有同一个 angle，所以 similar：

$$\frac{y_p}{d}=\frac{y}{z},\qquad y_p=\frac{d\,y}{z},\qquad x_p=\frac{d\,x}{z}$$

例如 $d=1$，$P=(2,1,4)$ 投到 $(0.5,0.25)$；把它沿着视线推远一倍到 $(4,2,8)$，投影还是 $(0.5,0.25)$。同一条穿过 pinhole 的 line 上所有的点，投到同一个位置，这就是“远处的东西看起来小”。

::fig[cs3241-pinhole] 侧面看 pinhole camera。$P$ 和推远一倍的 $P'$ 在同一条穿过眼睛的 line 上，投到同一个 $y_p$。

这个 formula 里有一个 division，除数是 $z$，每个点都不一样。后面第 3 站会看到，这一个 division 决定了整个 pipeline 的形状。

### 两种算法：同一个双重循环

知道了每个点投到哪里，生成 image 有两种办法。

**Ray casting。** 对每个 pixel，从眼睛穿过它射出一条 ray，和场景里每个 object 求 intersection，留下最近的那个。

**Rasterization。** 对每个 triangle，把三个 vertex 投到 image 上，找出它盖住了哪些 pixel；同一个 pixel 被几个 triangle 盖住时，留下最近的那个。

写成 pseudocode，两者是同一个双重循环，内外层换了一下：

```
// Ray casting                        // Rasterization
for each pixel:                       for each triangle:
    for each triangle:                    for each pixel it covers:
        keep closest hit                      keep closest (z-buffer)
```

换顺序带来的差别在 memory 上。Ray casting 的外层是 pixel，处理一个 pixel 时要能访问整个场景，所以整个场景必须在 memory 里。Rasterization 的外层是 triangle，一次只看一个 triangle，看完就可以扔掉；但每个 pixel 的“目前最近的距离”要一直留着，于是要有一块和 image 一样大的 depth buffer。MIT 6.837 第 21 讲算过：1920×1080 的 image，每个 pixel 存 64 bit 颜色加 32 bit depth，大约 24 MB。Triangle 可以像流水一样一个个送进来，这正适合做成硬件，GPU 走的就是这条路。

代价是 rasterization 只回答“这个 triangle 盖住哪些 pixel”。Shadow、mirror 里的倒影、玻璃的折射都需要知道“从这一点往某个方向看能看到什么”，这是 ray 的问题。所以第 7 站会回到 ray tracing。

### Pipeline：一个 vertex 走过的路

Rasterization 的每个 triangle 依次经过这些 stage：

1. **Vertex processing。** 把每个 vertex 从它自己的 object coordinates 变换到 camera 的 coordinates，再做 projection（第 2、3 站）；在这里算 per-vertex lighting（第 5 站）。
2. **Clipping 与 primitive assembly。** 三个 vertex 组成 triangle，裁掉视野外面的部分；然后做 perspective division 和 viewport transformation，得到 window coordinates（第 3、4 站）。
3. **Rasterization。** 找出 triangle 盖住的 pixel，每个 pixel 生成一个 fragment，带着从 vertex 插值来的颜色、depth、texture coordinate（第 4 站）。
4. **Fragment processing。** 给 fragment 上色、查 texture（第 6 站）；用 z-buffer 决定它能不能写进 frame buffer（第 4 站）。

::fig[cs3241-pipeline] 一个 triangle 经过 pipeline 的四个 stage。上一行是每个 stage 之后 triangle 的样子，下一行是它所在的 coordinate system。

Frame buffer 就是存最终 image 的那块 memory：一个 color buffer，加上第 4 站要用的 depth buffer。

### OpenGL 是一个 state machine

OpenGL 不负责开窗口、读键盘，这些交给 GLUT。OpenGL 只做 rendering，而且是按 state machine 的方式：`glColor3f` 不画任何东西，它只把“当前颜色”这个 state 改掉，之后画的所有 primitive 都用这个颜色，直到下一次改。Transformation matrix、lighting 开关、texture 也都是 state。

一个 GLUT 程序的骨架：

```c
void display(void) {
    glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
    glBegin(GL_POLYGON);
        glVertex3f(0.0, 0.0, 0.0);
        glVertex3f(1.0, 0.0, 0.0);
        glVertex3f(0.0, 1.0, 0.0);
    glEnd();
    glutSwapBuffers();
}

int main(int argc, char **argv) {
    glutInit(&argc, argv);
    glutInitDisplayMode(GLUT_DOUBLE | GLUT_RGB | GLUT_DEPTH);
    glutInitWindowSize(600, 600);
    glutCreateWindow("demo");
    glutDisplayFunc(display);   // 窗口需要重画时调用
    glutReshapeFunc(reshape);   // 窗口大小改变时调用（第一次打开也算）
    glutIdleFunc(idle);         // 没有 event 时反复调用
    glutMainLoop();             // 进入 event loop，不再返回
}
```

`main` 只登记 callback，然后进入 event loop。之后程序的一切行为都由 event 触发：键盘、mouse、窗口改变大小、重画请求。Callback 的 signature 是固定的，不能多传参数，所以 callback 之间共享的变量只能是 global variable。

**`glutPostRedisplay`。** 一次 event loop 里可能有好几件事都想重画（键盘改了一个参数，mouse 又拖了一下）。`glutPostRedisplay` 不立即重画，只设一个 flag；这一轮 loop 结束时 flag 是亮的，display callback 就调用一次。十次请求合成一次重画。

**Double buffering。** Display callback 先 `glClear` 再一个个画 primitive。如果显示器读的就是正在画的这块 buffer，它会在某一帧读到“清空了一半、画了一半”的内容，画面就会闪。办法是准备两块 color buffer：front buffer 给显示器读，不往里写；back buffer 只写不显示。画完一整帧，`glutSwapBuffers()` 把两块对调。显示器永远只看到画完的帧。所以 `main` 里要用 `GLUT_DOUBLE`，display 的最后要 swap。

**Animation。** Idle callback 里推进时间，再请求重画：

```c
void idle(void) {
    t += dt;                 // global variable
    glutPostRedisplay();
}
```

:::wrong 在 idle callback 里直接调用 display() 就能做 animation
能动，但每次 idle 都会完整重画一次，而且和 event loop 里其他请求的重画叠加，一轮 loop 可能画好几遍。更严重的是 display 依赖的 state（例如 reshape 刚改过的 projection）可能还没准备好。`glutPostRedisplay` 把重画交还给 event loop，保证每轮最多画一次，并且在所有 event 处理完之后。
:::

:::edge Window coordinates 和 mouse coordinates 的 origin 不同
OpenGL 的 window coordinates 以左下角为 origin，$y$ 向上；GLUT 传给 mouse callback 的 $(x,y)$ 以左上角为 origin，$y$ 向下。窗口高 $h$ 时，mouse 的 $y$ 要换成 $h-y$ 才能和画出来的东西对上。
:::

## [xform] Transformation：homogeneous coordinates、composition 与 matrix stack

:::skip
能写出 translation、rotation、scaling、shear 的 homogeneous matrix，知道 OpenGL 的调用顺序和作用顺序相反，会用“搬到 origin、做、搬回去”处理绕任意点 rotate 和沿任意 line reflect，会用 push 和 pop 写 hierarchical model，知道 normal 要乘 $(M^{-1})^\top$，就可以去第 3 站。
:::

### Translation 装不进 $2\times2$ matrix

把一个 2D 点 rotate、scale 都是 linear map，写成 $2\times2$ matrix：

$$R(\theta)=\begin{pmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{pmatrix},\qquad S(s_x,s_y)=\begin{pmatrix}s_x&0\\0&s_y\end{pmatrix},\qquad H_x(a)=\begin{pmatrix}1&a\\0&1\end{pmatrix}$$

最后一个是 shear：$x'=x+ay$，$y$ 不变，square 被推成 parallelogram。

Translation $p\mapsto p+t$ 不行。任何 matrix 都把 origin 送到 origin，而 translation 要把 origin 送到 $t$。它不是 linear map：$f(2p)=2p+t\ne2f(p)=2p+2t$。

可是一个场景要做几十次 rotate、scale、translate，如果有的是乘 matrix、有的是加 vector，就不能先把它们合成一个 matrix 再一次性用到所有 vertex 上。办法是给每个 2D 点补一个 coordinate，写成 $(x,y,1)$：

$$\begin{pmatrix}1&0&t_x\\0&1&t_y\\0&0&1\end{pmatrix}\begin{pmatrix}x\\y\\1\end{pmatrix}=\begin{pmatrix}x+t_x\\y+t_y\\1\end{pmatrix}$$

Translation 借第三个 coordinate 的那个 1 变成了 matrix 乘法。Rotation、scaling 的 $2\times2$ block 放在左上角，右边一列是 0。3D 同理，用 $4\times4$ matrix 和 $(x,y,z,1)$。这叫 homogeneous coordinates。

### Point 的末位是 1，vector 的末位是 0

一个 vector 表示的是位移、方向，例如一个 triangle 的两条边之差、一个 surface 的 normal。把一个物体搬走，它上面的点都变了，但两点之差不变，normal 的方向也不变。

Homogeneous coordinates 正好分得开这两种东西：vector 的第四个 coordinate 写 0。Translation matrix 右边那一列乘的是第四个 coordinate，遇到 0 就不起作用：

$$\begin{pmatrix}1&0&t_x\\0&1&t_y\\0&0&1\end{pmatrix}\begin{pmatrix}v_x\\v_y\\0\end{pmatrix}=\begin{pmatrix}v_x\\v_y\\0\end{pmatrix}$$

而且运算自动守规矩：point 减 point，末位 $1-1=0$，得到 vector；point 加 vector，末位 $1+0=1$，还是 point；point 加 point，末位是 2，不是合法的 point。

用 OpenGL 给 light 定位置时，`light_pos[3]` 写 1.0 是一个在那个位置上的 point light，写 0.0 是一个从那个方向射来的 directional light（无穷远处）。就是这条规则。

### 先做哪个

MIT 6.837 第 3 讲用的例子：$S=S(2,2)$，$T=T(3,1)$，点 $p=(1,1)$。

先 scale 再 translate：$Sp=(2,2)$，再 $T$ 得 $(5,3)$。写成 matrix product 是 $TSp$，作用在最右边的先做。

$$TS=\begin{pmatrix}1&0&3\\0&1&1\\0&0&1\end{pmatrix}\begin{pmatrix}2&0&0\\0&2&0\\0&0&1\end{pmatrix}=\begin{pmatrix}2&0&3\\0&2&1\\0&0&1\end{pmatrix}$$

先 translate 再 scale：$Tp=(4,2)$，再 $S$ 得 $(8,4)$。

$$ST=\begin{pmatrix}2&0&0\\0&2&0\\0&0&1\end{pmatrix}\begin{pmatrix}1&0&3\\0&1&1\\0&0&1\end{pmatrix}=\begin{pmatrix}2&0&6\\0&2&2\\0&0&1\end{pmatrix}$$

差别在右上角：后做 scale 时，前面那次 translation 也被放大了一倍，$(3,1)$ 变成了 $(6,2)$。Matrix multiplication 不 commute。

::fig[cs3241-order] 同一个 unit square，左边先 scale 再 translate，右边先 translate 再 scale。看角上那个点 $(1,1)$ 的去向：$(5,3)$ 和 $(8,4)$。

### OpenGL 里写的顺序和作用顺序相反

OpenGL 维护一个 current transformation matrix（CTM）$C$。每个 vertex 送进来都被乘上 $C$。`glTranslatef`、`glRotatef`、`glScalef` 都是把对应的 matrix 乘在 $C$ 的**右边**：

$$C\leftarrow C\,M$$

所以

```c
glLoadIdentity();        // C = I
glTranslatef(3, 1, 0);   // C = T
glScalef(2, 2, 1);       // C = T S
drawSquare();            // 每个 vertex p 变成 T S p
```

最后写的 `glScalef` 在最右边，最先作用到 vertex 上。读 OpenGL 代码时，从 draw 那一行往上读，就是物体经历的顺序：先 scale，再 translate。

另一种读法同样正确：从上往下读，每一句都是在移动“画笔的 coordinate system”。`glTranslatef(3,1,0)` 把 coordinate system 的 origin 搬到 $(3,1)$，`glScalef(2,2,1)` 把这个新 coordinate system 的单位长度放大一倍，然后在里面画一个 unit square。两种读法得到同一个结果，考试时选一种用到底。

### 绕任意一点 rotate

$R(\theta)$ 绕 origin 转。要绕点 $p_f$ 转，就把 $p_f$ 先搬到 origin，转完再搬回去：

$$M=T(p_f)\,R(\theta)\,T(-p_f)$$

从右往左读：$T(-p_f)$ 把 $p_f$ 送到 origin；$R$ 绕 origin 转，origin 不动，所以 $p_f$ 的像还在 origin；$T(p_f)$ 送回原处。$p_f$ 自始至终没动，其他点绕着它转了 $\theta$。Scale 也一样：绕 $p_f$ 放大是 $T(p_f)\,S\,T(-p_f)$，否则物体会在放大的同时被推离 origin。

### 往年题：沿 $y=-x-5$ 做 reflection

（据公开 repo 里的解答代码，这是 AY2016/17 S1 的第 2 题。）用 `glTranslatef`、`glRotatef`、`glScalef` 把一个以 $(1,1)$、$(3,1)$、$(3,-1)$、$(1,-1)$ 为 vertex 的 square 沿直线 $y=-x-5$ 做 reflection。

`glScalef(1, -1, 1)` 是沿 $x$ 轴的 reflection。要的是沿另一条 line，同样的思路：把这条 line 搬成 $x$ 轴，reflect，再搬回去。

1. 取 line 上一点 $p_0=(0,-5)$。$T(0,5)$ 把它送到 origin，line 变成过 origin 的 $y=-x$。
2. $y=-x$ 的方向是 $(1,-1)$，和 $x$ 轴的 angle 是 $-45^\circ$。$R(45^\circ)$ 把它转到 $x$ 轴上。
3. $S(1,-1)$ 沿 $x$ 轴 reflect。
4. 倒着做回去：$R(-45^\circ)$，$T(0,-5)$。

$$M=T(0,-5)\,R(-45^\circ)\,S(1,-1)\,R(45^\circ)\,T(0,5)$$

乘出来：

$$M=\begin{pmatrix}0&-1&-5\\-1&0&-5\\0&0&1\end{pmatrix},\qquad (x,y)\mapsto(-y-5,\;-x-5)$$

检验：line 上的点 $(-5,0)$ 送到 $(-0-5,\,5-5)=(-5,0)$，不动，对。四个 vertex：$(1,1)\mapsto(-6,-6)$，$(3,1)\mapsto(-6,-8)$，$(3,-1)\mapsto(-4,-8)$，$(1,-1)\mapsto(-4,-6)$。以 $(1,1)$ 和它的像 $(-6,-6)$ 为例，中点 $(-2.5,-2.5)$ 满足 $-2.5=2.5-5$，在 line 上；两点之差 $(7,7)$ 与 line 的方向 $(1,-1)$ 的 dot product 是 $7-7=0$，perpendicular。正是 reflection。

OpenGL 代码按 matrix product 从左往右写：

```c
glTranslatef(0, -5, 0);
glRotatef(-45, 0, 0, 1);
glScalef(1, -1, 1);
glRotatef(45, 0, 0, 1);
glTranslatef(0, 5, 0);
drawSquare();
```

::fig[cs3241-reflect] 五步依次作用在 square 上（动图）。中间三步发生在 line 被搬到 $x$ 轴的那个 coordinate system 里；最后一帧的 square 和原来的关于 $y=-x-5$ 对称。

那份解答代码写的是另一串：`glTranslatef(-5,-5,0); glRotatef(90,0,0,1); glScalef(-1,1,1);`。乘出来：$S(-1,1)$ 把 $(x,y)$ 变成 $(-x,y)$，$R(90^\circ)$ 再变成 $(-y,-x)$，加上 $(-5,-5)$ 得 $(-y-5,-x-5)$，和上面完全一样。它用了一个事实：沿一条不过 origin 的 line 做 reflection，等于沿过 origin 的平行 line 做 reflection，再平移“origin 到 line 的垂足”的两倍。$y=-x-5$ 离 origin 最近的点是 $(-2.5,-2.5)$，两倍正是 $(-5,-5)$。这条捷径对，但只有在知道这个事实时才写得出来；五步的写法对任何 line 都能照做。

:::wrong 沿 line 做 reflection，先 translate 到 line 上任意一点就行了，后面那一步 translate 回来可以省掉
省掉最后的 $T(0,-5)$，得到的是 $R(-45^\circ)S(1,-1)R(45^\circ)T(0,5)$，它把 $(x,y)$ 送到 $(-y-5,\,-x)$。$(1,1)\mapsto(-6,-1)$，中点 $(-2.5,0)$ 不在 line $y=-x-5$ 上（$-x-5=-2.5\ne0$）。检验 reflection 的最快办法：line 上的点必须不动。$(-5,0)$ 被送到 $(-5,5)$，动了，所以错。
:::

### Hierarchical model 与 matrix stack

（据同一份解答代码，AY2013/14 S2 的第 2 题。）画 sun、earth、moon：earth 绕 sun 转，moon 绕 earth 转。解答是这样一串：

```c
drawSun();
glRotatef(earthAngle, 0, 0, -1);
glTranslatef(0, 5, 0);
drawEarth();
glRotatef(moonAngle, 0, 0, -1);
glTranslatef(0, 1, 0);
drawMoon();
```

用“移动 coordinate system”的读法从上往下读：把 coordinate system 转 earthAngle，沿新的 $y$ 轴走 5，这里就是 earth 的 origin，画 earth；在 earth 的 coordinate system 里再转 moonAngle，走 1，画 moon。Moon 的 CTM 是 $R_e\,T(0,5)\,R_m\,T(0,1)$，它绕 earth 转是因为它的 transformation 是在 earth 的 transformation 之后**接着**乘上去的。

取 earthAngle $=45^\circ$、moonAngle $=0^\circ$（第 1 天）：`glRotatef(45, 0, 0, -1)` 绕 $-z$ 转 $45^\circ$，即 clockwise。Earth 的中心是 $(0,5)$ 顺时针转 $45^\circ$，即 $(5\sin45^\circ,5\cos45^\circ)=(3.54,3.54)$；moon 的中心是 $(0,6)$ 转同样的角度，$(4.24,4.24)$。

::fig[cs3241-orbit] 第 1 天的 sun、earth、moon。Earth 的 coordinate system 跟着转了 $45^\circ$，moon 是在这个转过的 coordinate system 里沿 $y$ 走 1 得到的。

问题出在“一个物体画完，要回到上一层”的时候。（AY2015/16 S1 的第 4 题。）画一个 square，在它四个角上各画一个缩小一半的 square，每个小 square 的四个角上再各画一个，递归 $n$ 层。四个角的 transformation 是 `glTranslatef(±1, ±1, 0); glScalef(0.5, 0.5, 1)`，它们都应该相对于**父 square** 的 coordinate system。如果画完第一个角直接画第二个，第二个角的 translate 和 scale 就乘在了第一个角的 CTM 后面，跑到第一个小 square 的角上去了。

办法是在改 CTM 之前把它存起来，画完再恢复。OpenGL 为每个 matrix mode 维护一个 stack：`glPushMatrix()` 把当前的 $C$ 复制一份压进 stack，`glPopMatrix()` 弹出 stack 顶，恢复成它。

```c
void drawRecursiveSquare(int n) {
    drawSquare();                       // [-1, 1] x [-1, 1]
    if (n > 1)
        for (int i = -1; i <= 1; i += 2)
            for (int j = -1; j <= 1; j += 2) {
                glPushMatrix();         // 记住父 square 的 C
                glTranslatef(i, j, 0);
                glScalef(0.5, 0.5, 1);
                drawRecursiveSquare(n - 1);
                glPopMatrix();          // 回到父 square 的 C
            }
}
```

::fig[cs3241-stack] `drawRecursiveSquare(3)` 画出来的样子，以及画右上角那一支时 stack 里的内容。每一层的四个 child 都从同一个 $C$ 出发。

Push 和 pop 必须成对。递归函数里每次 push 都在同一个循环体内 pop，所以函数返回时 CTM 和进入时一样，调用者不用操心。

### Normal 不能和 vertex 乘同一个 matrix

第 5 站算 lighting 要用 surface normal。物体被 $M$ 变换以后，normal 是不是也乘 $M$？

用一个例子试。2D 里一条线段沿 $(1,1)$ 方向，它的 normal 是 $n=(1,-1)/\sqrt2$。用 $S(2,1)$ 把 $x$ 方向拉长一倍：线段的方向变成 $t'=S(1,1)^\top=(2,1)$。Normal 也乘 $S$：$Sn=(2,-1)/\sqrt2$，和新的方向的 dot product 是 $(4-1)/\sqrt2=2.12$，不是 0，不再 perpendicular。

正确的 transformation 从“normal 和 tangent perpendicular”这个条件反推。Tangent 是两个 point 之差，它跟着 $M$ 变（只看左上角的 linear 部分，记作 $M$）：$t'=Mt$。要找 $n'$ 使 $n'^\top t'=0$。原来有 $n^\top t=0$，在中间插入 $M^{-1}M=I$：

$$0=n^\top t=n^\top M^{-1}M\,t=(n^\top M^{-1})\,(Mt)=\big((M^{-1})^\top n\big)^\top t'$$

所以 $n'=(M^{-1})^\top n$ 和每个变换后的 tangent 都 perpendicular。

检验：$S(2,1)^{-1}=S(\tfrac12,1)$，transpose 不变，$n'=(\tfrac12,-1)/\sqrt2$，和 $(2,1)$ 的 dot product 是 $(1-1)/\sqrt2=0$。

::fig[cs3241-normal] 把 $x$ 方向拉长一倍。直接乘 $M$ 的 normal 歪了；乘 $(M^{-1})^\top$ 的仍和 surface perpendicular。

$M$ 是 rotation 时 $M^{-1}=M^\top$，$(M^{-1})^\top=M$，直接乘 $M$ 没错；uniform scaling $sI$ 时 $(M^{-1})^\top=\tfrac1sI$，方向也对，只差长度，normalize 一下即可。出错的只有 non-uniform scaling 和 shear。Normal 是 vector，第四个 coordinate 是 0，translation 本来就不影响它，所以只用左上角 $3\times3$ 的 block。

:::edge Rotation 的 inverse 是 transpose，整个 homogeneous matrix 的不是
$R^{-1}=R^\top$ 只对左上角的 rotation block 成立。$T(t)R$ 的 inverse 是 $R^\top T(-t)$，右边一列是 $-R^\top t$，不是把整个 $4\times4$ matrix transpose。推导和更多 frame 链的例子见 [RB2202 第 2 站](../courses/RB2202.html#tf)。
:::

:::back
用到 [MA2101 第 4 站](../courses/MA2101.html#rep)的 matrix representation：一个 linear map 由它把 basis 送到哪里决定。
:::

## [view] Viewing 与 projection

:::skip
能由 gluLookAt 求 $u,v,n$ 和 view matrix，写出 glOrtho、glFrustum 的 matrix，对一个点一路算到 window coordinates，并说清 depth 为什么不均匀，就可以去第 4 站。

### 先把世界搬到 camera 前面

第 1 站的 pinhole formula $x_p=dx/z$ 假设眼睛在 origin、看向 $z$ 轴。真实场景里 camera 可以在任何地方、朝任何方向。所以先做一次 transformation，把所有点表示成 camera 自己的 coordinates，之后的 projection 就只需要处理“眼睛在 origin”这一种情况。

`gluLookAt(eye, at, up)` 给出三样东西：眼睛的位置 $e$、看向的点 $a$、大致朝上的方向 $\text{up}$。OpenGL 约定 camera 看向自己的 $-z$ 方向。由此造出 camera 的三个 axis：

$$n=\frac{e-a}{\|e-a\|},\qquad u=\frac{\text{up}\times n}{\|\text{up}\times n\|},\qquad v=n\times u$$

$n$ 是 camera 的 $z$ 轴，从看的点指回眼睛（因为看向 $-z$）。$u$ 是 camera 的 $x$ 轴，要和 $n$、$\text{up}$ 都 perpendicular，cross product 给的就是这个。$v$ 是 camera 真正的 $y$ 轴：$\text{up}$ 不必和 $n$ perpendicular，$v=n\times u$ 把它校正成 perpendicular 的那个。三个是 unit vector，两两 perpendicular，顺序 $u,v,n$ 是 right-handed。

View matrix 先把眼睛搬到 origin，再把 $u,v,n$ 转到 $x,y,z$ 轴：

$$M_\text{view}=\begin{pmatrix}u_x&u_y&u_z&0\\v_x&v_y&v_z&0\\n_x&n_y&n_z&0\\0&0&0&1\end{pmatrix}\begin{pmatrix}1&0&0&-e_x\\0&1&0&-e_y\\0&0&1&-e_z\\0&0&0&1\end{pmatrix}$$

左边那个 matrix 的 row 是 $u,v,n$。一个 vector $w$ 乘上它，结果是 $(u\cdot w,\,v\cdot w,\,n\cdot w)$，正是 $w$ 在 $u,v,n$ 这组 orthonormal basis 下的 coordinates。

**例子。** `gluLookAt(3, 0, 4,  0, 0, 0,  0, 1, 0)`：

$$n=\frac{(3,0,4)}{5}=(0.6,\,0,\,0.8),\qquad \text{up}\times n=(0,1,0)\times(0.6,0,0.8)=(0.8,\,0,\,-0.6)$$

它已经是 unit vector，$u=(0.8,0,-0.6)$。$v=n\times u=(0,1,0)$。

检验看的点 $a=(0,0,0)$：$a-e=(-3,0,-4)$，

$$u\cdot(a-e)=-2.4+2.4=0,\qquad v\cdot(a-e)=0,\qquad n\cdot(a-e)=-1.8-3.2=-5$$

在 camera 正前方（$-z$ 方向）5 个单位，和眼睛到 $a$ 的距离 $\|e-a\|=5$ 一致。再取 world 的点 $(1,0,0)$：$(1,0,0)-e=(-2,0,-4)$，camera coordinates 是 $(-1.6+2.4,\;0,\;-1.2-3.2)=(0.8,\,0,\,-4.4)$。下面一直用这个点。

::fig[cs3241-lookat] 从上方（$+y$）俯视这个 gluLookAt。$n$ 从 origin 指回眼睛，$u$ 指向 camera 的右边；点 $(1,0,0)$ 在 camera coordinates 里是 $(0.8,0,-4.4)$。

### Projection 要做成 matrix，但它里面有一个 division

Projection 把 camera coordinates 里的 view volume 映射到 canonical view volume，$[-1,1]^3$ 这个 cube，叫 normalized device coordinates（NDC）。之后的 clipping 只需要和这个固定的 cube 比较。

**Orthographic。** `glOrtho(l, r, b, t, near, far)` 的 view volume 是一个 box：$x\in[l,r]$，$y\in[b,t]$，$z_e\in[-\text{far},-\text{near}]$（near、far 都写成正数，表示到眼睛的距离）。映射成 $[-1,1]^3$ 只要每个 axis 先把中点平移到 0、再缩放，例如 $x$：

$$x_n=\frac{2}{r-l}\Big(x-\frac{r+l}{2}\Big)$$

$z$ 要额外翻个方向：$z_e=-\text{near}\mapsto-1$，$z_e=-\text{far}\mapsto1$，离眼睛越远越大。三个 axis 合起来：

$$M_\text{ortho}=\begin{pmatrix}\frac{2}{r-l}&0&0&-\frac{r+l}{r-l}\\0&\frac{2}{t-b}&0&-\frac{t+b}{t-b}\\0&0&\frac{-2}{f-n}&-\frac{f+n}{f-n}\\0&0&0&1\end{pmatrix}$$

（这里 $n,f$ 是 near、far。）检验 $z$ 那一行：$z_e=-n$ 时 $\frac{2n}{f-n}-\frac{f+n}{f-n}=\frac{n-f}{f-n}=-1$，对。

**Perspective。** `glFrustum(l, r, b, t, n, f)` 的 view volume 是一个 frustum：near plane $z_e=-n$ 上的 rectangle $[l,r]\times[b,t]$，四条边向眼睛收拢。先用 pinhole 投到 near plane 上：

$$x_p=\frac{n\,x_e}{-z_e},\qquad y_p=\frac{n\,y_e}{-z_e}$$

（分母是 $-z_e$，因为前方的 $z_e$ 是负数。）再把 $[l,r]$ 线性映射到 $[-1,1]$：

$$x_n=\frac{2x_p}{r-l}-\frac{r+l}{r-l}=\frac{1}{-z_e}\Big(\frac{2n}{r-l}x_e+\frac{r+l}{r-l}z_e\Big)$$

最后一步把 $-\frac{r+l}{r-l}$ 写成 $\frac{1}{-z_e}\cdot\frac{r+l}{r-l}z_e$，于是括号里是 $x_e,z_e$ 的 linear combination，前面统一除以 $-z_e$。

问题来了：matrix 只能做 linear combination，做不了“除以 $-z_e$”。Homogeneous coordinates 在这里第二次派上用场。规定 $(x,y,z,w)$ 和 $(x/w,y/w,z/w,1)$ 代表同一个点。让 matrix 的第四个 row 是 $(0,0,-1,0)$，输出的 $w_c=-z_e$；前三个 row 只算括号里的 linear 部分；之后硬件统一把前三个 coordinate 除以 $w_c$。这一步叫 perspective division。Matrix 算出来、还没除的那组 coordinates 叫 clip coordinates。

$z$ 那一行呢？near plane 上所有点的 $x_p$ 都是投影后的位置，$z$ 却全都等于 $-n$，depth 的信息丢光了。第 4 站的 z-buffer 需要 depth。所以 $z$ 那一行另设两个 unknown $A,B$：$z_c=Az_e+B$，除以 $w_c$ 后

$$z_n=\frac{Az_e+B}{-z_e}$$

要求 near plane 映射到 $-1$、far plane 映射到 $1$：

$$z_e=-n:\ \frac{-An+B}{n}=-1\ \Rightarrow\ -An+B=-n,\qquad z_e=-f:\ \frac{-Af+B}{f}=1\ \Rightarrow\ -Af+B=f$$

第一式减第二式：$A(f-n)=-(f+n)$，$A=-\frac{f+n}{f-n}$。代回第一式：$B=-n+An=-n-\frac{n(f+n)}{f-n}=\frac{-n(f-n)-n(f+n)}{f-n}=-\frac{2fn}{f-n}$。

$$M_\text{persp}=\begin{pmatrix}\frac{2n}{r-l}&0&\frac{r+l}{r-l}&0\\0&\frac{2n}{t-b}&\frac{t+b}{t-b}&0\\0&0&-\frac{f+n}{f-n}&-\frac{2fn}{f-n}\\0&0&-1&0\end{pmatrix}$$

`gluPerspective(fovy, aspect, n, f)` 是对称的 frustum：$t=n\tan(\text{fovy}/2)$，$b=-t$，$r=t\cdot\text{aspect}$，$l=-r$。第三个 column 的两个 entry 变成 0，左上角变成 $n/r$ 和 $n/t$。

### 一个点从 world 走到 window

接着上面的点。取 `gluPerspective(90, 1, 1, 100)`：$t=1\cdot\tan45^\circ=1$，$r=1$，$A=-\frac{101}{99}=-1.0202$，$B=-\frac{200}{99}=-2.0202$。

Camera coordinates $(0.8,\,0,\,-4.4,\,1)$ 乘 $M_\text{persp}$：

$$x_c=0.8,\quad y_c=0,\quad z_c=-1.0202\times(-4.4)-2.0202=2.4687,\quad w_c=4.4$$

Perspective division：

$$x_n=\frac{0.8}{4.4}=0.1818,\qquad y_n=0,\qquad z_n=\frac{2.4687}{4.4}=0.5611$$

最后是 viewport transformation。`glViewport(x_0, y_0, w, h)` 把 $[-1,1]$ 线性映射到 pixel：

$$x_w=x_0+\frac{w\,(x_n+1)}{2},\qquad y_w=y_0+\frac{h\,(y_n+1)}{2},\qquad z_w=\frac{z_n+1}{2}$$

$400\times400$ 的 viewport：$x_w=200\times1.1818=236.4$，$y_w=200$，$z_w=0.7805$。$z_w$ 存进 depth buffer。

::fig[cs3241-frustum] 从上方看 frustum（左）和变换后的 NDC square（右）。动图里一个点沿着同一条穿过眼睛的 line 由近到远移动：左边它离 near plane 越来越远，右边它的 $x_n$ 不变（同一条视线），$z_n$ 一开始飞快增大，之后挤在 1 附近。

### Depth 不是均匀的

$z_n=-A-B/z_e$ 是 $1/z_e$ 的 affine function，不是 $z_e$ 的。同样 $n=1$、$f=100$：

| $z_e$ | $-1$ | $-2$ | $-4.4$ | $-10$ | $-50$ | $-100$ |
|---|---|---|---|---|---|---|
| $z_n$ | $-1$ | $0.0101$ | $0.5611$ | $0.8182$ | $0.9798$ | $1$ |

Near plane 到 2 倍 near 这 1 个单位就用掉了 $[-1,1]$ 的一半；最远的 50 个单位只分到 0.02。这是为了让 matrix 能完成 projection 付出的代价：要保证 projection 把 line 映射成 line、把 plane 映射成 plane（第 4 站在 window 里对 depth 做线性插值靠的就是这一点），depth 只能是 $1/z_e$ 的 affine function。代价在第 4 站的 z-fighting 里兑现。

:::wrong 为了不让近处的东西被 near plane 切掉，把 near 设成 0.0001 没有坏处
看 $A,B$：$n\to0$ 时 $B=-\frac{2fn}{f-n}\to0$，$z_n=-A-B/z_e\to-A\approx1$。几乎所有 depth 都被压到 1 附近，depth buffer 分辨不出远近。第 4 站算了具体数字：depth buffer 24 bit、$f=100$ 时，在 50 个单位远处，$n=1$ 能分辨约 0.00015 个单位的差，$n=0.01$ 只能分辨约 0.015。Near 不能是 0：$n=0$ 时 $B=0$，所有点的 $z_n$ 都等于 $-A$，depth 完全丢失。
:::

:::edge Perspective division 之后 $w$ 才是 1，不要在 vertex shader 里提前除
Matrix 算出的是 clip coordinates，$w_c=-z_e$ 可以是 0（点和眼睛在同一个 plane 上）甚至负数（点在眼睛后面）。第 4 站会说明 clipping 为什么必须在除之前、对 clip coordinates 做。
:::

## [raster] Clipping、rasterization 与 hidden surface removal

:::skip
能写 Cohen–Sutherland 的 outcode 并完成一次 clipping，手算一条 Bresenham line，说出 edge function 怎样判断 pixel 在 triangle 内、z-buffer 怎样工作、z-fighting 取决于什么，就可以去第 5 站。
:::

### 为什么要先 clip

第 3 站的 perspective division 除以 $w_c=-z_e$。眼睛后面的点 $z_e>0$，$w_c<0$，除完 $x_n$ 的符号翻过来，点跑到了画面的另一边；$z_e=0$ 的点直接除以 0。一个 triangle 只要有一个 vertex 在眼睛后面，投影出来就是错的。所以在除之前，先把每个 primitive 切成只剩 view volume 里面的部分。

在 clip coordinates 里，“除完以后落在 $[-1,1]$”可以不做除法就判断：$w_c>0$ 时，

$$-1\le\frac{x_c}{w_c}\le1\iff-w_c\le x_c\le w_c$$

$y,z$ 同理。六个不等式就是六个 clipping plane，它们对 clip coordinates 是 linear 的，可以直接求 line 和它们的 intersection。

### Cohen–Sutherland：先把容易的情况挑出来

先看 2D：把 line segment 裁到 window $x_{\min}\le x\le x_{\max}$、$y_{\min}\le y\le y_{\max}$ 里。直接和四条边求 intersection 要做 division，大多数 segment 要么完全在里面、要么完全在外面，算 intersection 是浪费。

Window 的四条边把 plane 分成 9 个区域。每个点给一个 4-bit 的 outcode，每个 bit 回答一个问题（按 CMU 15-462 的顺序，从左到右）：在 top 之上？在 bottom 之下？在 right 之右？在 left 之左？Window 内部是 `0000`。

对 segment 的两个 endpoint 的 outcode $o_1,o_2$：

- $o_1=o_2=0000$：两端都在里面，window 是 convex 的，整段都在里面。**Accept。**
- $o_1\;\&\;o_2\ne0000$（bitwise AND）：两端在同一条边的外侧，整段都在那条边外侧。**Reject。**
- 其余：取一个在外面的 endpoint，取它的一个为 1 的 bit，和对应的那条边求 intersection，用 intersection 替换这个 endpoint，重新算 outcode，回到第一步。

**例子。** Window $0\le x\le10$，$0\le y\le8$。

| Segment | $o_1$ | $o_2$ | AND | 结论 |
|---|---|---|---|---|
| $(12,1)$ 到 $(14,9)$ | `0010` | `1010` | `0010` | 都在 right 外侧，reject |
| $(-4,2)$ 到 $(6,12)$ | `0001` | `1000` | `0000` | 要切 |
| $(-3,5)$ 到 $(3,12)$ | `0001` | `1000` | `0000` | 要切 |

第二条：slope $=\frac{12-2}{6+4}=1$。$(-4,2)$ 的 left bit 是 1，和 $x=0$ 求 intersection：$y=2+1\times4=6$，得 $(0,6)$，outcode `0000`。$(6,12)$ 的 top bit 是 1，和 $y=8$ 求 intersection：$x=-4+(8-2)/1=2$，得 $(2,8)$，outcode `0000`。两端都是 `0000`，accept $(0,6)$ 到 $(2,8)$。

第三条：slope $=\frac{12-5}{3+3}=\frac76$。$(-3,5)$ 和 $x=0$ 的 intersection：$y=5+\frac76\times3=8.5$，得 $(0,8.5)$，它的 outcode 是 `1000`。现在两端都是 `1000`，AND 不为 0，reject。这条 segment 从 window 左上角外面擦过去，第一轮看不出来，切一刀之后才看出来。

::fig[cs3241-outcode] 9 个区域的 outcode 和上表的三条 segment。粗线段是第二条被裁剩的部分；第三条切了一刀后两端都落在 `1000` 区域。

3D 里是 6 bit（多了 near、far），算法不变。Polygon 的 clipping 不能只裁边：一个 triangle 被裁后可能变成 quadrilateral。Sutherland–Hodgman algorithm 一次只对一个 clipping plane 处理整个 vertex list，沿着 polygon 的边走：从里到里，输出终点；从里到外，输出 intersection；从外到里，输出 intersection 和终点；从外到外，什么也不输出。对六个 plane 依次做一遍，每一遍的输出是下一遍的输入，正好排成一条 pipeline。

### 一条 line 点亮哪些 pixel

Clipping 之后，primitive 到了 window coordinates，要决定点亮哪些 pixel。先看 line，从 $(x_0,y_0)$ 到 $(x_1,y_1)$，设 slope $0\le m\le1$（其他情况交换 $x,y$ 或翻转符号）。每一列 $x$ 恰好点亮一个 pixel。

**DDA。** 直接沿 line 走：$x$ 每次加 1，$y$ 加 $m$，四舍五入。用 Utah CS 5600 的例子 $(5,8)$ 到 $(9,11)$，$m=0.75$：

| $x$ | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|
| $y$ | 8 | 8.75 | 9.5 | 10.25 | 11 |
| 点亮 | 8 | 9 | 10 | 10 | 11 |

每一步一次 floating-point 加法和一次 rounding。

**Bresenham。** 每一步其实只有两个选择：同一行的 E $=(x+1,y)$，或上一行的 NE $=(x+1,y+1)$。看 line 从两个候选 pixel 中心的 midpoint $M=(x+1,\,y+\tfrac12)$ 的哪一边经过。把 line 写成 implicit form

$$F(x,y)=\Delta y\,x-\Delta x\,y+c=0$$

（$\Delta x=x_1-x_0>0$，$\Delta y=y_1-y_0$。由 $y=\frac{\Delta y}{\Delta x}x+B$ 乘 $\Delta x$ 移项得到，$c=B\Delta x$。）在 line 下方的点，$y$ 小，$F>0$。Decision variable $d=F(M)$：$d\ge0$ 说明 midpoint 在 line 下方，line 更靠近上面的 NE；$d<0$ 选 E。

不必每步重新算 $F$。选了 E，下一个 midpoint 是 $(x+2,y+\tfrac12)$，$x$ 多了 1，$d$ 增加 $\Delta y$；选了 NE，下一个 midpoint 是 $(x+2,y+\tfrac32)$，$x,y$ 各多 1，$d$ 增加 $\Delta y-\Delta x$。初值：起点在 line 上，$F(x_0,y_0)=0$，所以

$$d_0=F(x_0+1,\,y_0+\tfrac12)=F(x_0,y_0)+\Delta y-\tfrac12\Delta x=\Delta y-\tfrac12\Delta x$$

有个 $\tfrac12$。整个 $F$ 乘 2 不改变 line，也不改变 $d$ 的符号，于是全部变成 integer：

$$d_0=2\Delta y-\Delta x,\qquad d\mathrel{+}=2\Delta y\ \text{（选 E）},\qquad d\mathrel{+}=2(\Delta y-\Delta x)\ \text{（选 NE）}$$

同一个例子，$\Delta x=4$，$\Delta y=3$，$d_0=2$，E 加 6，NE 加 $-2$：

| 当前 pixel | $d$ | 选择 |
|---|---|---|
| $(5,8)$ | $2$ | NE |
| $(6,9)$ | $2-2=0$ | NE |
| $(7,10)$ | $0-2=-2$ | E |
| $(8,10)$ | $-2+6=4$ | NE |
| $(9,11)$ | | 终点 |

和 DDA 点亮的 pixel 完全一样，但只用 integer 加法和比较。

::fig[cs3241-bresenham] 动图：Bresenham 从 $(5,8)$ 走到 $(9,11)$。每一步标出两个候选 pixel 和它们中间的 midpoint，右边是当时的 $d$。第一帧是走完的结果。

### 一个 triangle 盖住哪些 pixel

Triangle 的三条边各是一条 line，triangle 的内部是三个 half-plane 的交集。每条边写一个 edge function $E_i(x,y)=a_ix+b_iy+c_i$，约定在 triangle 内侧为正。Pixel 中心 $(x,y)$ 在 triangle 内，当且仅当三个 $E_i$ 都 $\ge0$。

逐个 pixel 去试整个屏幕太浪费，MIT 6.837 第 21 讲的做法是只试 triangle 的 bounding box（三个 vertex 的 $x,y$ 的最小值和最大值围成的 rectangle）。而且 $E_i$ 是 linear 的：$x$ 加 1，$E_i$ 加 $a_i$；$y$ 加 1，$E_i$ 加 $b_i$。逐个 pixel 走时，每步只要三次加法。

**例子。** Triangle 的 vertex $A=(1,1)$、$B=(7,2)$、$C=(3,6)$，按 counterclockwise 排列。边 $AB$ 的 edge function 取 $E_{AB}(p)=(B-A)\times(p-A)$（2D cross product，$p$ 在 $AB$ 左边为正）：

$$E_{AB}(x,y)=6(y-1)-1\cdot(x-1)=-x+6y-5$$

同理 $E_{BC}(x,y)=(C-B)\times(p-B)=(-4)(y-2)-4(x-7)=-4x-4y+36$，$E_{CA}(x,y)=(A-C)\times(p-C)=(-2)(y-6)-(-5)(x-3)=5x-2y-3$。

Pixel 中心 $(4.5,3.5)$：

$$E_{AB}=-4.5+21-5=11.5,\qquad E_{BC}=-18-14+36=4,\qquad E_{CA}=22.5-7-3=12.5$$

都是正的，在内部。$(6.5,3.5)$：$E_{BC}=-26-14+36=-4$，在 $BC$ 外侧。

三个值还有一个用处。2D cross product $(C-B)\times(p-B)$ 等于以 $B,C,p$ 为 vertex 的 triangle 面积的两倍，所以 $E_{BC}(p)$ 量的是 $p$ 对着 vertex $A$ 的那个小 triangle 有多大。$E_{BC}(A)=-4-4+36=28$ 是整个 triangle 面积的两倍。比值

$$\alpha=\frac{E_{BC}(p)}{28},\quad\beta=\frac{E_{CA}(p)}{28},\quad\gamma=\frac{E_{AB}(p)}{28}$$

就是 $p$ 的 barycentric coordinates：$p=\alpha A+\beta B+\gamma C$，$\alpha+\beta+\gamma=1$。对 $(4.5,3.5)$：$\alpha=\frac{4}{28}$，$\beta=\frac{12.5}{28}$，$\gamma=\frac{11.5}{28}$，和为 $\frac{28}{28}=1$。核对：

$$\alpha A+\beta B+\gamma C=\frac{4(1,1)+12.5(7,2)+11.5(3,6)}{28}=\frac{(4+87.5+34.5,\;4+25+69)}{28}=\frac{(126,\,98)}{28}=(4.5,\,3.5)$$

Barycentric coordinates 是从三个 vertex 往内部插值任何量（颜色、depth、texture coordinate）的权重：$c(p)=\alpha c_A+\beta c_B+\gamma c_C$。第 6 站会说明，在 window coordinates 里这样插值对 depth 是对的，对 texture coordinate 要多一步修正。

::fig[cs3241-edge] Triangle $A,B,C$ 的 bounding box 和被点亮的 pixel。标出的 pixel 中心 $(4.5,3.5)$ 三个 edge function 都是正的，它的 barycentric coordinates 是三个小 triangle 的面积比。

### 谁在前面：z-buffer

开头第二张错图：几个 surface 盖住同一个 pixel，谁后画谁赢。

最直接的想法是按远近排序，从远到近画（painter's algorithm）。它对互相穿插的 surface 无能为力：两个 triangle 各有一部分在对方前面，没有一个先后顺序能画对。

Z-buffer 把问题拆到每个 pixel 上。除了 color buffer，再给每个 pixel 存一个 depth，初始化成最远（$z_w=1$）。

```
for each triangle:
    for each pixel (x, y) it covers:
        z = interpolated depth at (x, y)
        if z < depth[x][y]:
            depth[x][y] = z
            color[x][y] = fragment color
```

每个 pixel 自己比较，和画的顺序无关，穿插也没问题：在 depth 相等的那条线两边，各自是近的那个赢。

::fig[cs3241-zbuf] 动图：两个互相穿插的 triangle，先画 A（depth 处处 0.5），再画 B（depth 从左往右由 0.2 增加到 0.8）。每个格子显示当时 depth buffer 里的值；两者重叠的格子里，B 只在它的 depth 小于 0.5 的那一半赢。第一帧是画完 B 的结果。

为什么在 window coordinates 里对 $z_w$ 做线性插值是对的？第 3 站说过，projection 把 plane 映射成 plane。Triangle 在 camera coordinates 里是一个 plane 的一部分，projection 之后仍然是 $(x_n,y_n,z_n)$ 空间里的一个 plane，所以 $z_n$ 是 $x_n,y_n$ 的 linear function，用 barycentric 插值是 exact 的。这正是 depth 要存 $1/z_e$ 的 affine function 而不是 $z_e$ 本身的理由：$z_e$ 在 window 里不是线性变化的。

**Back-face culling。** 一个封闭物体（例如 cube），背向 camera 的面一定被前面的面挡住。在 z-buffer 之前就把它们扔掉，平均省一半的工作。OpenGL 约定从正面看 vertex 是 counterclockwise 排列；投影到 window 后如果三个 vertex 变成 clockwise，这个面就背对 camera。在 camera coordinates 里等价的判断是 normal $N$ 和从 surface 指向眼睛的 vector $V$ 满足 $N\cdot V\le0$。

### Z-fighting 由什么决定

两个 surface 离得很近（例如墙上贴着的海报），depth buffer 分不清谁在前面，每个 pixel 的胜负由 rounding 决定，画面上两者的颜色斑驳交错。分辨能力取决于 $z_w$ 随 $z_e$ 变化有多快。

由 $z_n=-A-B/z_e$，$\frac{dz_n}{dz_e}=\frac{B}{z_e^2}$，$z_w=(z_n+1)/2$ 又减半。24-bit depth buffer 能区分的最小 $z_w$ 差是 $2^{-24}=5.96\times10^{-8}$。取 $f=100$，在 $z_e=-50$ 处：

| near | $\lvert B\rvert$ | $\frac{dz_w}{dz_e}=\frac{\lvert B\rvert}{2z_e^2}$ | 能分辨的 $z_e$ 差 |
|---|---|---|---|
| 1 | 2.0202 | $4.04\times10^{-4}$ | $1.5\times10^{-4}$ |
| 0.01 | 0.020002 | $4.00\times10^{-6}$ | $0.015$ |

海报离墙 0.01 个单位：$n=1$ 时没有问题，$n=0.01$ 时 z-fighting。治法是把 near 推远（影响最大，$|B|$ 和 $n$ 成正比），其次是减小 far 或者用更多 bit 的 depth buffer。

:::wrong 打开 z-buffer 以后，画的顺序就完全无关了
对不透明的 surface 是这样。半透明的 surface 要和它背后已经画好的颜色 blend，背后的东西必须先画；z-buffer 只存一个 depth，记不住“这里有一层半透明的玻璃，后面还有东西”。所以半透明物体要在所有不透明物体之后，按从远到近的顺序画，painter's algorithm 在这里又回来了。
:::

:::from
“除以 $w$ 之前先 clip”、edge function、bounding box、incremental evaluation 和 z-buffer pseudocode，跟着 [MIT 6.837 第 21 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec21/)和[第 22 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec22/)。Outcode 的 bit 顺序、subdivision 的步骤、Sutherland–Hodgman 的四种情况，跟着 [CMU 15-462 第 14 讲](https://www.cs.cmu.edu/~fp/courses/02-graphics/pdf-2up/14-clip.pdf)；Bresenham 的 midpoint 推导和 $(5,8)$ 到 $(9,11)$ 的例子来自 [Utah CS 5600](https://my.eng.utah.edu/~cs5600/slides/Wk%202%20Lec02_Bresenham.pdf)。Cohen–Sutherland 的三条 segment、triangle 的 edge function 与 barycentric 数字、z-fighting 的表是这一页自己算的。“Depth 存 $1/z$ 才能在 window 里线性插值”的解释是自己补的推理，6.837 的 slides 只给出了结论。

## [light] Illumination 与 shading

:::skip
能对一个 surface point 算出 Phong model 的三项，算 $R$ 和 $H$，说出 flat、Gouraud、Phong shading 在哪里算 lighting，并解释 Gouraud 为什么漏掉 highlight，就可以去第 6 站。
:::

### 斜着照的面为什么暗

前四站决定了每个 pixel 看到哪个 surface 上的哪一点。这一点是什么颜色？

一个平面上的点，光从 normal 方向直射时最亮；光越斜，越暗。原因是同一束光摊在了更大的面积上。设一束截面宽度为 $w$ 的平行光，和 normal 成 angle $\theta$ 射到 surface 上，照亮的那段 surface 长 $w/\cos\theta$。同样多的能量分到更长的一段上，单位面积收到的能量乘了 $\cos\theta$。

::fig[cs3241-lambert] 同一束光，直射时照亮宽度 $w$；斜 $60^\circ$ 时照亮 $2w$，每单位面积只收到一半。

$N$、$L$（从 surface 指向 light）都是 unit vector 时 $\cos\theta=N\cdot L$。如果 surface 把收到的光向所有方向均匀散射（粉笔、纸、没有上光的木头），从哪个方向看都一样亮，亮度只取决于收到多少：

$$I_\text{diffuse}=I_p\,k_d\,\max(N\cdot L,\,0)$$

这叫 Lambert 的 cosine law。$k_d\in[0,1]$ 是 material 对 diffuse 的反射率，RGB 各一个。$\max(\cdot,0)$ 不能省：$N\cdot L<0$ 说明光从背面来，这一面根本照不到，不能给负的亮度。

### Highlight：Phong 的 specular term

光滑的 surface（塑料、上了漆的东西）上还有一块亮斑，而且随着眼睛移动。它是 light 在镜面方向的反射。理想镜面只把光反射到一个方向 $R$：$L$ 和 $R$ 关于 $N$ 对称。把 $L$ 分成沿 $N$ 的部分 $(N\cdot L)N$ 和垂直于 $N$ 的部分 $L-(N\cdot L)N$；reflection 保留前者、翻转后者：

$$R=(N\cdot L)N-\big(L-(N\cdot L)N\big)=2(N\cdot L)N-L$$

真实的光滑 surface 不是理想镜面，反射光集中在 $R$ 附近一个范围里。Phong 用 $R$ 和 $V$（从 surface 指向眼睛）的 angle 来描述它：

$$I_\text{specular}=I_p\,k_s\,\max(R\cdot V,0)^{\,n}$$

Exponent $n$ 叫 shininess。$R\cdot V=\cos\phi$ 小于 1，乘方越高，偏离 $R$ 一点就衰减得越快，highlight 越小越锐。

再加一个常数项代替“从周围其他物体反射过来的光”，即 ambient。MIT 6.837 第 15 讲直接称它为 “a total hack”：真正的 indirect illumination 不在这个 model 里算。Phong illumination model 是三项之和：

$$I=I_a\,k_a+f_\text{att}\,I_p\big[k_d\max(N\cdot L,0)+k_s\max(R\cdot V,0)^n\big]$$

$f_\text{att}$ 是距离衰减。物理上 point light 的强度按 $1/d^2$ 衰减（同样的能量穿过越来越大的球面），但离 light 很近时 $1/d^2$ 会爆掉，所以 OpenGL 用 $f_\text{att}=\frac{1}{a+bd+cd^2}$，三个常数自己调；很多时候直接取 $f_\text{att}=1$。多个 light 时方括号对每个 light 各算一份再加起来。

**例子。** $N=(0,1,0)$，$L=(-0.6,0.8,0)$，$V=(0,1,0)$，$k_a=0.1$，$k_d=0.6$，$k_s=0.4$，$n=20$，$I_a=I_p=1$，$f_\text{att}=1$。

$$N\cdot L=0.8,\qquad R=2\times0.8\times(0,1,0)-(-0.6,0.8,0)=(0.6,\,0.8,\,0),\qquad R\cdot V=0.8$$

$$I=0.1+0.6\times0.8+0.4\times0.8^{20}=0.1+0.48+0.4\times0.01153=0.5846$$

Specular 只贡献了 0.0046。$R$ 和 $V$ 差 $36.9^\circ$，对 $n=20$ 来说已经在 highlight 之外了。

::fig[cs3241-phong] 这个例子的几个 vector：$L$ 和 $R$ 关于 $N$ 对称，$V$ 和 $R$ 差 $36.9^\circ$，$H$ 是 $L$ 与 $V$ 的 halfway vector，和 $N$ 差 $18.4^\circ$。

### Blinn–Phong：用 halfway vector

每个点都要算一次 $R$。Blinn 换了一个量：$L$ 和 $V$ 的 halfway vector

$$H=\frac{L+V}{\|L+V\|},\qquad I_\text{specular}=I_p\,k_s\max(N\cdot H,0)^{\,n}$$

当 $V$ 正好等于 $R$ 时，$H$ 正好等于 $N$，两种 model 都在这里取最大值。Light 和 viewer 都很远时，$L$、$V$ 对整个物体几乎是常数，$H$ 也是常数，只算一次；$R$ 却随 $N$ 变，每个点要重算。

同一个例子：$L+V=(-0.6,1.8,0)$，长度 $1.8974$，$H=(-0.3162,0.9487,0)$，$N\cdot H=0.9487$，angle $18.4^\circ$，正好是 $R$ 与 $V$ 之间 $36.9^\circ$ 的一半（$N,L,V$ 在同一个 plane 里时总是这样）。同样 $n=20$：$0.9487^{20}=0.349$，比 Phong 的 $0.0115$ 大三十倍。要得到差不多大小的 highlight，Blinn–Phong 的 exponent 要取大约 4 倍：$0.9487^{80}=0.0148$，和 Phong 的 0.0115 接近。

:::wrong Phong 和 Blinn–Phong 只是算法不同，同样的 $n$ 画出来一样
$N$ 与 $H$ 的 angle 只有 $R$ 与 $V$ 的一半，$\cos$ 更接近 1，同样的 exponent 下 highlight 明显更大。上面的例子里同为 $n=20$，specular 差了三十倍。从 Phong 换成 Blinn–Phong 时 exponent 要放大约 4 倍。
:::

### 在哪里算：flat、Gouraud、Phong shading

上面的 model 回答“给定一点、它的 normal，颜色是什么”。一个 polygon mesh 上有成千上万个 pixel，在哪些点上真正去算？

- **Flat shading。** 每个 polygon 只算一次，整个 polygon 一个颜色。Mesh 的每个面都看得出来。`glShadeModel(GL_FLAT)`。
- **Gouraud shading。** 每个 vertex 算一次，vertex 的 normal 取共享这个 vertex 的几个 polygon 的 normal 的平均；然后在 rasterization 时把**颜色**插值到内部。`glShadeModel(GL_SMOOTH)`，legacy OpenGL 的 lighting 就是这样做的。
- **Phong shading。** 把 **normal** 插值到每个 pixel（插值后要重新 normalize），在每个 pixel 上算一次 lighting。（Phong illumination model 是公式，Phong shading 是在哪里用这个公式，两件事同名。）

Gouraud 便宜，问题在 specular。看一个例子：一条从 $x=-1$ 到 $x=1$ 的平面，两端是 vertex，normal 都是 $(0,1)$；light 和眼睛都在正中央上方 $(0,2)$，shininess $n=50$。

在 vertex $x=\pm1$：$L=V=(\mp1,2)/\sqrt5$，$N\cdot L=2/\sqrt5=0.894$，$R\cdot V=2(N\cdot L)^2-1=2\times0.8-1=0.6$（$L=V$ 时 $R\cdot V=R\cdot L$），$0.6^{50}=8\times10^{-12}$。两个 vertex 的 specular 都是 0。Gouraud 在中间插值两个 0，得到 0。

在正中央 $x=0$：$L=V=N$，$R\cdot V=1$，specular 是 $1$。Phong shading 在这个 pixel 上真的去算，得到了这块 highlight。

::fig[cs3241-gouraud] 同一个平面，上面是 light 和眼睛的位置，下面是 diffuse 加 specular 沿 $x$ 的亮度。Gouraud（虚线）只用两端 vertex 上算出的值连成直线；Phong shading（实线）在中间算出了 specular 的尖峰。

Highlight 恰好落在 polygon 内部、离 vertex 远时，Gouraud 会让它整块消失；物体一转，highlight 移到某个 vertex 上，又突然出现，并且被插值摊成一大片。这就是 Gouraud 下 highlight 一闪一闪的原因。

:::edge Vertex normal 从哪里来
光滑 surface 的解析 normal 最好：sphere 上一点的 normal 就是从 center 指向这一点的方向。只有 mesh 时，取共享这个 vertex 的 polygon 的 normal 的平均。Cube 的角不能这样平均，否则棱角被抹圆；要在那里把 vertex 复制成几个，每个带各自那个面的 normal。
:::

:::edge `glNormal3f` 给的 normal 必须是 unit vector
上面所有 dot product 都假设 $N$、$L$、$V$ 是 unit vector。`glScalef` 也会把 normal 缩放（按第 2 站的 $(M^{-1})^\top$）。要么自己保证长度，要么 `glEnable(GL_NORMALIZE)`，后者每个 vertex 多一次 normalize。
:::

:::from
Cosine law 来自“光摊在更大的面积上”、clamp、$1/r^2$ 与 $1/(a+bd+cd^2)$、ambient 是 hack、Phong 与 half vector 的讲法，跟着 [MIT 6.837 第 15 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec15/)。Gouraud 和 Phong shading 的区别、“specular highlights are poorly captured”跟着 [Cambridge 讲义](https://www.cl.cam.ac.uk/teaching/1617/Graphics/Introduction_to_Graphics_notes_1pp.pdf)第 3 部分；OpenGL 的 lighting 公式和 `light_pos[3]` 的约定来自[学生笔记](https://trxe.github.io/notes-blog/cg)第 7 章（那里 Phong 的 specular 写成了 $(R\cdot L)^n$，应为 $(R\cdot V)^n$）。两个数值例子、“$H$ 的 angle 是一半所以 exponent 约 4 倍”是这一页自己算的。
:::

## [tex] Texture mapping 与 aliasing

:::skip
能做 perspective-correct interpolation，手算一次 bilinear filtering，为一个 pixel 选 mipmap level，并说明 minification 为什么需要 mipmap，就可以去第 7 站。
:::

### 每个 vertex 带一个 $(s,t)$

想让一面墙看起来是砖墙。用几万个小 polygon 去建每块砖太贵。办法是把一张砖墙的照片当作“颜色表”贴到墙这个大 polygon 上。

照片叫 texture，它的 pixel 叫 texel，位置用 texture coordinates $(s,t)\in[0,1]^2$ 表示。给每个 vertex 指定一个 $(s,t)$，说明它对应 texture 上哪一点；polygon 内部每个 fragment 的 $(s,t)$ 由 rasterization 插值得到，然后去 texture 里查颜色。这是 inverse mapping：从 pixel 出发找它在 texture 里的 pre-image，每个 pixel 恰好查一次，不会有空洞。

```c
glBegin(GL_QUADS);
    glTexCoord2f(0, 0); glVertex3f(-2, -1, 0);
    glTexCoord2f(1, 0); glVertex3f( 2, -1, 0);
    glTexCoord2f(1, 1); glVertex3f( 2,  1, 0);
    glTexCoord2f(0, 1); glVertex3f(-2,  1, 0);
glEnd();
```

Sphere、cylinder 这类简单物体可以用 two-part mapping：先把 texture 贴到一个简单的中间 surface 上（S-mapping：plane、cylinder、sphere），再从中间 surface 投到真正的物体上（O-mapping，例如沿物体的 normal、或从物体 center 发出的 ray）。

### Screen space 里线性插值是错的

开头第三张错图。设一段 line segment 在 camera coordinates 里从 $P_0=(-1,0,-1)$ 到 $P_1=(1,0,-3)$，两端的 texture coordinate 是 $s_0=0$、$s_1=1$。用 $d=1$ 投影，$x_s=x/(-z)$：$P_0$ 投到 $-1$，$P_1$ 投到 $1/3$。

在 screen 上两个端点的正中间 $x_s=-\tfrac13$ 处，按 screen space 线性插值，$s=0.5$。

这一点在 3D 里到底是哪里？3D segment 上的点是 $P_0+\lambda(P_1-P_0)=(-1+2\lambda,\,0,\,-1-2\lambda)$，投到

$$x_s=\frac{-1+2\lambda}{1+2\lambda}=-\frac13\ \Rightarrow\ -3+6\lambda=-1-2\lambda\ \Rightarrow\ \lambda=\frac14$$

真正的 $s=\tfrac14$。远的那一半在 screen 上被压短了，screen 上的中点在 3D 里偏向近端。按 screen space 线性插值的 $s=0.5$ 把 texture 往近处拉，一个 quadrilateral 被拆成两个 triangle 各自插值时，两边拉得不一样，diagonal 处就折了。

修正：$s$ 本身在 screen 上不是 linear 的，但 $s/w$ 和 $1/w$ 是（$w=-z_e$，就是第 3 站的 $w_c$）。理由和第 4 站的 depth 一样：一个在 3D 里随位置 linear 变化的量 $s$，除以 $w$ 以后在 window 里是 linear 的。所以插值 $s/w$ 和 $1/w$，在每个 pixel 上相除：

$$s=\frac{\text{interp}(s/w)}{\text{interp}(1/w)}$$

检验：$P_0$ 处 $s/w=0$，$1/w=1$；$P_1$ 处 $s/w=\tfrac13$，$1/w=\tfrac13$。Screen 中点：$s/w=\tfrac16$，$1/w=\tfrac23$，$s=\tfrac16\big/\tfrac23=\tfrac14$。和 3D 里算的一致。

::fig[cs3241-persp] 一块倾斜的地板贴棋盘格，拆成两个 triangle。左边在 screen space 里对 $(s,t)$ 线性插值，格子沿 diagonal 折断；右边插值 $(s/w,t/w,1/w)$ 再相除，格子是透视正确的直线。

### 查到的位置落在 texel 之间

插值出来的 $(s,t)$ 乘上 texture 的大小，一般不是整数，落在四个 texel 之间。取最近的一个（`GL_NEAREST`）最快；放大时会看到一格一格的马赛克。

Bilinear filtering（`GL_LINEAR`）用四个最近 texel 加权：设落点相对左下 texel 的 fractional offset 是 $(a,b)$，先在两行里沿 $s$ 方向插值，再沿 $t$ 方向插值。

**例子。** 四个 texel 的值 $c_{00}=10$，$c_{10}=50$（右下），$c_{01}=30$（左上），$c_{11}=90$，落点 $(a,b)=(0.25,0.6)$：

$$\text{下行}=10\times0.75+50\times0.25=20,\qquad\text{上行}=30\times0.75+90\times0.25=45$$

$$c=20\times0.4+45\times0.6=35$$

::fig[cs3241-bilinear] 四个 texel 的中心和落点 $(0.25,0.6)$。先在下行、上行各插出一个值，再在两者之间插。

$(s,t)$ 超出 $[0,1]$ 时由 wrap mode 决定：`GL_CLAMP` 把它截到边界，边缘的 texel 被拉长；`GL_REPEAT` 取 fractional part，texture 平铺，砖墙、地板就是这样用一张小 texture 铺满的。

### 缩小时的 aliasing

远处的地板上，一个 pixel 覆盖了 texture 里好几十个 texel（minification）。如果仍然只在 pixel 中心查一个点（即使用 bilinear，也只看 4 个 texel），这个 pixel 的颜色就由“中心恰好落在哪个 texel 上”决定，几十个 texel 里的其他颜色全被忽略。

一维的例子：texture 是黑白相间的条纹，周期 0.9 个 pixel，每个 pixel 中心采样一次。相邻两个 pixel 采样点在条纹上的相位差 $1/0.9-1=0.111$ 个周期，9 个 pixel 才走完一个周期。屏幕上出现的是周期 9 个 pixel 的宽条纹，原来那个细密的 pattern 冒充成了一个粗得多的 pattern。这就是 aliasing。

::fig[cs3241-alias] 周期 0.9 个 pixel 的条纹（上），在每个 pixel 中心采样（圆点），得到周期 9 个 pixel 的宽条纹（下）。

画面一动，这种假 pattern 会游移闪烁（moiré）。正确的做法是让每个 pixel 取它覆盖的那片 texel 的平均。上面的例子里每个 pixel 覆盖约 1.1 个周期，平均下来接近灰色，宽条纹就不会出现。放大（magnification）时一个 texel 盖住好几个 pixel，没有被跳过的 texel，不产生 aliasing，只是模糊或有马赛克。

### Mipmap：预先算好所有大小的平均

每个 pixel 现场去平均几十个 texel 太慢。Mipmap 预先把 texture 每次长宽减半：level 0 是原图，level 1 的每个 texel 是 level 0 里 $2\times2$ 个 texel 的平均，依此类推，直到 $1\times1$。$256\times256$ 的 texture 一共 9 个 level（$256,128,\dots,1$）。

额外的 memory：每一级是上一级的 $\tfrac14$，总共

$$1+\frac14+\frac1{16}+\cdots<\frac{1}{1-\frac14}=\frac43$$

只多三分之一。

用的时候，看这个 pixel 在 texture 里的 footprint 有多大：如果一个 pixel 横跨 $k$ 个 texel，就去 level $\log_2k$，那里一个 texel 正好约等于一个 pixel，而且已经是 $k\times k$ 个原 texel 的平均。例如 $256\times256$ 的 texture 贴在屏幕上 $32\times32$ 个 pixel 的 square 里，每个 pixel 横跨 8 个 texel，用 level 3（$32\times32$），一一对应。

$k$ 通常不是 2 的 power。$k=5.7$ 时 $\log_2k=2.51$，在 level 2 和 level 3 之间。Trilinear filtering（`GL_LINEAR_MIPMAP_LINEAR`）在两个 level 上各做一次 bilinear，再按 0.51 的比例在两者之间插值。只用一个 level 时，物体由近到远移动，level 切换的地方会看到一条明显的分界线。

::fig[cs3241-mipmap] 一张 $8\times8$ 的 texture 的 mipmap，每级长宽减半；右边是 footprint 为 5.7 个 texel 时在 level 2 和 level 3 之间的插值比例。

:::wrong Bilinear filtering 已经平滑了，缩小时不需要 mipmap
Bilinear 只看落点周围 4 个 texel。一个 pixel 覆盖 $8\times8=64$ 个 texel 时，另外 60 个对结果没有任何贡献，上面那个条纹的例子照样产生宽条纹。Bilinear 解决的是放大时的马赛克；缩小时的 aliasing 要靠先平均（prefilter）。
:::

:::edge 倾斜的地板：footprint 不是正方形
地板斜着远去时，一个 pixel 的 footprint 在一个方向上跨 1 个 texel，另一个方向上跨 16 个。Mipmap 只能按一个数选 level：按 16 选，横向被过度模糊；按 1 选，纵向 aliasing。Anisotropic filtering 沿长的方向取几个样本，每个样本用较细的 level，再平均。
:::

### Texture 不只是颜色

Lighting 公式里任何一个常数都可以换成 texture lookup。

**Environment mapping。** 想画一个镜面的球，不做 ray tracing。先把周围环境拍成六张图，贴在一个包围场景的 cube 的六个面上（cube map）。对球上每一点，用第 5 站的 formula 求视线 $V$ 关于 $N$ 的 reflection $R$，用 $R$ 的方向去 cube map 里查颜色：$R$ 的三个 component 里 absolute value 最大的那个决定查哪个面，另外两个除以它，换算成那个面上的 $(s,t)$。代价是两个近似：环境被当作无穷远（物体离墙越近，误差越大），物体也照不到自己（cube map 里没有它）。

**Bump mapping。** 第 5 站说过，亮度主要由 $N\cdot L$ 决定。所以不改几何，只按一张 texture 在每个 pixel 上扰动 normal，平的 surface 就会显出凹凸。MIT 6.837 第 16 讲的例子是 500 个 triangle 加一张 normal map，看起来接近 400 万个 triangle 的原 mesh。轮廓线仍然是平的，因为几何没有变；要真正改轮廓，要用 displacement mapping 移动 vertex。

:::back
Perspective-correct interpolation 用的是[第 3 站](#view)的 $w_c=-z_e$ 和[第 4 站](#raster)的 barycentric coordinates；environment mapping 用的是[第 5 站](#light)的 reflection formula。
:::

:::from
UV 用 barycentric 插值、tiling、texture 可以替换 lighting 里的任何常数、normal map 的 500 与 400 万 triangle、tangent-space 的必要性，跟着 [MIT 6.837 第 16 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec16/)；pixel 是 sample、prefilter、mipmap 选 level、anisotropy，跟着[第 17 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec17/)；“screen space 线性插值 BAD、要 perspective-correct”出自[第 22 讲](https://ocw.mit.edu/courses/6-837-computer-graphics-fall-2012/resources/mit6_837f12_lec22/)，但那几讲没有给出 $s/w$、$1/w$ 的推导，这一部分和 $\lambda=\tfrac14$ 的例子是这一页自己写的。Two-part mapping、wrap mode、mipmap 的 OpenGL 调用跟着[学生笔记](https://trxe.github.io/notes-blog/cg)第 8 章。条纹、bilinear、$\log_2 5.7$ 的数字是自己算的。Cube map 查哪个面的规则凭自己的知识写，没有核对 OpenGL 规范的符号约定。

## [ray] Ray casting 与 recursive ray tracing

:::skip
能求 ray 与 plane、sphere、triangle 的 intersection，算 reflection 和 refraction direction，写出 Whitted ray tracing 的递归，并说清 epsilon 为什么必要，就可以去第 8 站。

### 一条 ray 和一个 surface

第 1 站说过，shadow、镜子、玻璃都是“从这一点往某个方向看见什么”的问题。Ray 写成

$$P(t)=O+tD,\qquad t>0$$

$O$ 是起点，$D$ 是方向（最好 normalize）。Ray casting 的核心问题：对场景里每个 object，求最小的正 $t$ 使 $P(t)$ 在它的 surface 上。

**Plane。** $N\cdot P+d=0$。代入：$N\cdot(O+tD)+d=0$，

$$t=-\frac{N\cdot O+d}{N\cdot D}$$

$N\cdot D=0$ 时 ray 和 plane 平行，没有 intersection（或者整条 ray 在 plane 上），要单独处理。

**Sphere。** Center $C$，radius $r$：$\|P-C\|^2=r^2$。代入 $P=O+tD$，记 $m=O-C$：

$$(D\cdot D)\,t^2+2(D\cdot m)\,t+(m\cdot m-r^2)=0$$

$D$ 是 unit vector 时第一个 coefficient 是 1。记 $b'=D\cdot m$，$c=m\cdot m-r^2$，$t=-b'\pm\sqrt{b'^2-c}$。Discriminant $b'^2-c<0$ 没有 intersection，$=0$ 恰好擦过，$>0$ 两个 intersection，取最小的正根。Intersection 点的 normal 是 $(P-C)/r$。

**例子。** $O=(0,0,0)$，sphere $C=(0,0,-5)$，$r=4$，$m=(0,0,5)$，$c=25-16=9$。

| $D$ | $b'=D\cdot m$ | $b'^2-c$ | 结果 |
|---|---|---|---|
| $(0,0.6,-0.8)$ | $-4$ | $7$ | $t=4-\sqrt7=1.354$ |
| $(0,0.8,-0.6)$ | $-3$ | $0$ | 擦过，$t=3$ |
| $(0,0.96,-0.28)$ | $-1.4$ | $-7.04$ | 没有 intersection |

第一条 ray：$P=1.354\times(0,0.6,-0.8)=(0,\,0.8125,\,-1.0834)$，normal $(P-C)/4=(0,\,0.2031,\,0.9792)$。第二条：$P=(0,2.4,-1.8)$，normal $(0,0.6,0.8)$，和 $D$ 的 dot product 是 $0.48-0.48=0$，正好 perpendicular，确实是擦过。

::fig[cs3241-sphere] 在 $x=0$ 的 plane 里看这三条 ray：一条穿过 sphere（两个 intersection，取近的），一条正好 tangent，一条错过。

### Ray 与 triangle：barycentric coordinates 加 Cramer's rule

Mesh 由 triangle 组成，这是最常用的 intersection。可以先和 triangle 所在的 plane 求 intersection，再判断点在不在 triangle 里；MIT 6.837 第 12 讲用的办法一步到位。Triangle $a,b,c$ 所在 plane 上的点都能写成

$$a+\beta(b-a)+\gamma(c-a)$$

$\beta\ge0$、$\gamma\ge0$、$\beta+\gamma\le1$ 时恰好在 triangle 里（这就是第 4 站的 barycentric coordinates，$\alpha=1-\beta-\gamma$）。让 ray 等于它：

$$O+tD=a+\beta(b-a)+\gamma(c-a)\ \Longleftrightarrow\ \beta(a-b)+\gamma(a-c)+tD=a-O$$

三个 component 三个 equation，三个 unknown $\beta,\gamma,t$：

$$\begin{pmatrix}a-b&a-c&D\end{pmatrix}\begin{pmatrix}\beta\\\gamma\\t\end{pmatrix}=a-O$$

左边的 matrix 以三个 vector 为 column。用 Cramer's rule：每个 unknown 等于把对应的 column 换成 $a-O$ 后的 determinant 除以原 matrix 的 determinant。

**例子。** $a=(0,0,-2)$，$b=(2,0,-4)$，$c=(0,2,-3)$，$O=(0,0,0)$，$D=(0.25,0.25,-1)$（这里 $D$ 没有 normalize，$t$ 不是距离，但不影响求交点）。

$$a-b=(-2,0,2),\quad a-c=(0,-2,1),\quad a-O=(0,0,-2)$$

$$\det\begin{pmatrix}-2&0&0.25\\0&-2&0.25\\2&1&-1\end{pmatrix}=-2\big((-2)(-1)-0.25\times1\big)-0+0.25\big(0\times1-(-2)\times2\big)=-2\times1.75+0.25\times4=-2.5$$

把第一个 column 换成 $a-O$：

$$\det\begin{pmatrix}0&0&0.25\\0&-2&0.25\\-2&1&-1\end{pmatrix}=0.25\big(0\times1-(-2)(-2)\big)=-1,\qquad\beta=\frac{-1}{-2.5}=0.4$$

同理换第二个 column 得 $-1$，$\gamma=0.4$；换第三个 column 得 $-8$，$t=3.2$。$\beta,\gamma\ge0$，$\beta+\gamma=0.8\le1$，$t>0$：hit。核对：$O+3.2D=(0.8,0.8,-3.2)$；$a+0.4(b-a)+0.4(c-a)=(0.8,\,0.8,\,-2-0.8-0.4)=(0.8,0.8,-3.2)$。

$\beta,\gamma$ 顺便给出了插值的权重：这一点的 normal、颜色、texture coordinate 都是 $0.2\times(\text{在 }a)+0.4\times(\text{在 }b)+0.4\times(\text{在 }c)$。

### Shadow ray、reflection、refraction

找到 eye ray 的 intersection $P$ 后，Whitted 的 ray tracing 从 $P$ 再射出几条 secondary ray。

**Shadow ray。** 从 $P$ 射向每个 light。如果在到达 light 之前碰到了别的 object，$P$ 在这个 light 的 shadow 里，这个 light 的 diffuse 和 specular 项不算。只需要知道“有没有挡住”，找到任何一个 intersection 就可以停，不必找最近的。

**Reflection。** 从 $P$ 沿镜面方向射出一条 ray，它看到的颜色乘一个 reflection coefficient 加进来。入射方向 $D$（从眼睛指向 $P$）关于 $N$ 的镜像，把 $D$ 沿 $N$ 的 component 翻转：

$$R=D-2(D\cdot N)N$$

这和第 5 站的 $R=2(N\cdot L)N-L$ 是同一个 formula，只是 $L$ 指离 surface，$D$ 指向 surface，$D=-L$。

**Refraction。** 光从 index $\mu_1$ 的介质进入 $\mu_2$ 的介质，满足 Snell's law $\mu_1\sin\theta=\mu_2\sin\phi$。记 $\mu=\mu_1/\mu_2$，$L$ 指向入射的一侧（unit），$\cos\theta=N\cdot L$。Transmitted direction 由两部分组成：垂直于 $N$ 的部分是入射的切向部分缩放 $\mu$（这样 $\sin\phi=\mu\sin\theta$），沿 $-N$ 的部分长 $\cos\phi$：

$$T=-\mu L+\Big(\mu\cos\theta-\sqrt{1-\mu^2(1-\cos^2\theta)}\Big)N$$

根号里是 $1-\mu^2\sin^2\theta=1-\sin^2\phi=\cos^2\phi$。

**例子。** 从空气（1）进入玻璃（1.5），入射 $45^\circ$：$\mu=\tfrac23$，$\sin\phi=\tfrac23\times0.7071=0.4714$，$\phi=28.1^\circ$。取 $N=(0,1)$，$L=(-0.7071,0.7071)$：

$$T=-\tfrac23(-0.7071,0.7071)+\big(\tfrac23\times0.7071-\sqrt{1-\tfrac49\times0.5}\big)(0,1)=(0.4714,\,-0.8819)$$

它是 unit vector，和 $-N$ 的 angle 是 $\arctan(0.4714/0.8819)=28.1^\circ$，和 Snell's law 一致。

反过来从玻璃射向空气，同样 $45^\circ$：$\mu=1.5$，根号里 $1-2.25\times0.5=-0.125<0$，没有 real solution。这就是 total internal reflection：$\sin\phi=1.5\times0.7071>1$，不存在这样的折射角，光全部反射。临界角 $\arcsin(1/1.5)=41.8^\circ$。程序里根号里为负时只算 reflection。

::fig[cs3241-refract] 空气到玻璃 $45^\circ$ 入射，折射成 $28.1^\circ$（左）；玻璃到空气 $45^\circ$ 入射，超过临界角 $41.8^\circ$，没有折射光（右）。

### 递归：ray tree

Reflection ray 和 transmitted ray 碰到下一个 surface，又在那里算 local lighting、射 shadow ray、再射 reflection 和 transmitted ray。一个 pixel 的颜色是

$$I=I_\text{local}+k_r\,I_\text{reflected}+k_t\,I_\text{transmitted}$$

后两项又由同一个 formula 递归给出。

```
trace(ray, depth):
    hit = closest intersection of ray with scene
    if no hit: return background
    color = ambient
    for each light:
        if shadow ray from hit.P to light is not blocked:
            color += diffuse + specular        // 第 5 站
    if depth < maxDepth:
        if hit is reflective:  color += k_r * trace(reflected ray, depth + 1)
        if hit is transparent: color += k_t * trace(refracted ray, depth + 1)
    return color
```

停止的条件：ray 没碰到东西；surface 只有 diffuse；到了最大 depth；或者累乘的 coefficient 已经小到对颜色没有影响。

每个 intersection 最多分出两条，ray 的数量随 depth 按 power of 2 增长。Depth 3（eye ray 下面再三层）时一个 pixel 最多 $1+2+4+8=15$ 个 intersection，每个 intersection 对 2 个 light 各射一条 shadow ray，共 30 条；加上 15 条 eye 与 secondary ray，45 条 ray。$800\times600$ 的 image 就是 2160 万条 ray，每条都要和场景求 intersection。

::fig[cs3241-raytree] 动图：一条 eye ray 打在玻璃球上，分出 reflection 和 refraction；refraction 穿出球后打在地面上，射出 shadow ray。右边是对应的 ray tree，一层层长出来。第一帧是完整的 tree。

### Shadow acne：epsilon

Shadow ray 从 $P$ 出发。$P$ 是算出来的，带 rounding error，可能落在 surface 下面一点点。从那里射向 light，第一个碰到的就是这个 surface 自己，$t$ 是一个极小的正数，于是 $P$ 被判定为在自己的 shadow 里。Rounding 的方向因 pixel 而异，surface 上出现一片黑点，叫 shadow acne。

Single precision 在 5 附近相邻两个数的间隔是 $4.8\times10^{-7}$，距离 5 个单位的 intersection，误差就在这个量级。治法二选一：只接受 $t>\varepsilon$ 的 intersection；或者把新 ray 的起点沿方向挪 $\varepsilon$（或沿 normal 挪出 surface）。$\varepsilon$ 要比 rounding error 大，又要比场景里最小的真实距离小。

:::wrong 求 intersection 时 $t>0$ 就够了，secondary ray 也一样
对 eye ray 够了，起点是眼睛，不在任何 surface 上。Secondary ray 的起点就在 surface 上，它和这个 surface 的“intersection”在 $t=0$ 附近，rounding 后有一半机会是正的。用 $t>0$ 判断，大约一半的点被自己挡住，就是 shadow acne。
:::

### 一次 ray 要试多少个 object

2160 万条 ray，每条和一个 10 万 triangle 的场景逐个求 intersection，是 $2\times10^{12}$ 次 ray–triangle test。几乎所有的 test 都是 miss。

Bounding volume：给一个复杂的 object 套一个简单的外壳（sphere 或 axis-aligned box），先和外壳求 intersection，miss 了就跳过里面所有 triangle。外壳要尽量紧（否则很多 ray 碰到外壳却不碰物体），又要算得快。把 bounding volume 一层层嵌套成 tree（bounding volume hierarchy），一条 ray 从根往下走，只进入它碰到的那些子树，test 的次数从 triangle 数目 $N$ 降到大约 $\log N$ 的量级。另一种思路是划分空间（uniform grid、octree、BSP tree），ray 按顺序穿过空间格子，只和格子里的 object 求 intersection，而且找到第一个 hit 就能停，后面的格子不用看。

:::edge Whitted ray tracing 画不出的东西
Shadow ray 只有挡住和没挡住两种结果，所以只有 hard shadow；area light 的 soft shadow 要对 light 上很多点各射一条。Diffuse surface 之间的光（红墙把旁边的白墙映红，color bleeding）、玻璃杯把光聚到桌面上（caustics）都不在这个递归里：它只沿镜面方向和折射方向追，不追 diffuse 反射出去的光。
:::

:::back
Shading 用的是[第 5 站](#light)的 Phong model，intersection 点的插值用的是[第 4 站](#raster)的 barycentric coordinates。Ray 在 volume 里一路积分的版本（NeRF）见 [CMU-16825 第 3 站](../courses/CMU-16825.html#volume)。
:::

### 用什么方程描述一条 curve

想画一条光滑的 curve（字体的轮廓、一条路、物体运动的轨迹），用很多短 line segment 去逼近要存很多点，放大以后还是折线。最好用一个方程，屏幕上要多细就算多细。

三种写法：

- **Explicit**：$y=f(x)$。一个 $x$ 只能对一个 $y$，circle 就写不出来；curve 有竖直的切线时也不行。
- **Implicit**：$f(x,y)=0$，例如 $x^2+y^2-1=0$。判断一个点在不在 curve 上很容易，但要依次生成 curve 上的点很难。
- **Parametric**：$p(u)=(x(u),y(u))$，$u\in[0,1]$。$u$ 从 0 走到 1，点沿着 curve 走过去，生成点很容易；而且 $x,y,z$ 各自独立，2D 和 3D 写法一样。

Parametric polynomial 用得最多。Degree 太高会振荡，所以通常每段用 cubic：

$$p(u)=c_0+c_1u+c_2u^2+c_3u^3=\begin{pmatrix}1&u&u^2&u^3\end{pmatrix}\begin{pmatrix}c_0\\c_1\\c_2\\c_3\end{pmatrix}$$

每个 $c_k$ 是一个 2D 或 3D 的点。四个 unknown，要四个条件。直接给 $c_k$ 没有几何意义，没人知道 $c_2=(3,-1)$ 会让 curve 长什么样。所以用 control point 来给条件。

### 第一种条件：过四个点

要求 curve 依次经过 $p_0,p_1,p_2,p_3$，分别在 $u=0,\tfrac13,\tfrac23,1$：

$$\begin{pmatrix}p_0\\p_1\\p_2\\p_3\end{pmatrix}=\underbrace{\begin{pmatrix}1&0&0&0\\1&\frac13&\frac19&\frac1{27}\\1&\frac23&\frac49&\frac8{27}\\1&1&1&1\end{pmatrix}}_{A}\begin{pmatrix}c_0\\c_1\\c_2\\c_3\end{pmatrix}$$

$A$ 的每个 row 是 $(1,u,u^2,u^3)$ 在对应的 $u$ 处的值。解出 $c=A^{-1}p$，

$$M_I=A^{-1}=\begin{pmatrix}1&0&0&0\\-5.5&9&-4.5&1\\9&-22.5&18&-4.5\\-4.5&13.5&-13.5&4.5\end{pmatrix}$$

$p(u)=(1,u,u^2,u^3)\,M_I\,(p_0,p_1,p_2,p_3)^\top$。把 $(1,u,u^2,u^3)M_I$ 展开，得到四个 polynomial $b_0(u),\dots,b_3(u)$，叫 blending function：$p(u)=\sum b_i(u)\,p_i$。

问题在于两段 curve 接起来时。第一段过 $p_0,\dots,p_3$，第二段从 $p_3$ 开始，在接点处位置相同，但切线方向一般不同，接点处有一个尖角。而且 $M_I$ 里有 $-22.5$ 这样大的数，blending function 会取负值、超过 1，curve 可以跑到 control point 围成的范围之外。

### 第二种条件：两端的位置和切线

Bezier curve 换一组条件：过两个端点，并且两端的切线由中间两个 control point 决定：

$$p(0)=P_0,\qquad p(1)=P_3,\qquad p'(0)=3(P_1-P_0),\qquad p'(1)=3(P_3-P_2)$$

$p(u)=c_0+c_1u+c_2u^2+c_3u^3$，$p'(u)=c_1+2c_2u+3c_3u^2$。四个条件：

$$c_0=P_0,\qquad c_1=3(P_1-P_0)$$

$$c_0+c_1+c_2+c_3=P_3,\qquad c_1+2c_2+3c_3=3(P_3-P_2)$$

后两式消元：第二式减去 2 倍的第一式，$-2c_0-c_1+c_3=3P_3-3P_2-2P_3$，代入 $c_0,c_1$：

$$c_3=P_3-3P_2+2P_0+3P_1-3P_0=-P_0+3P_1-3P_2+P_3$$

再由第一式：$c_2=P_3-c_0-c_1-c_3=P_3-P_0-3P_1+3P_0+P_0-3P_1+3P_2-P_3=3P_0-6P_1+3P_2$。

$$M_B=\begin{pmatrix}1&0&0&0\\-3&3&0&0\\3&-6&3&0\\-1&3&-3&1\end{pmatrix},\qquad p(u)=\begin{pmatrix}1&u&u^2&u^3\end{pmatrix}M_B\begin{pmatrix}P_0\\P_1\\P_2\\P_3\end{pmatrix}$$

把 $(1,u,u^2,u^3)M_B$ 展开（例如第一个 column：$1-3u+3u^2-u^3=(1-u)^3$）：

$$p(u)=(1-u)^3P_0+3u(1-u)^2P_1+3u^2(1-u)P_2+u^3P_3$$

四个 blending function 叫 degree 3 的 Bernstein polynomial。它们正是 $\big((1-u)+u\big)^3$ 的 binomial expansion 的四项，所以对每个 $u$ 加起来等于 1；在 $[0,1]$ 上每一项都 $\ge0$。

所以 $p(u)$ 是四个 control point 的加权平均，权重非负、和为 1，这样的点一定在四个点的 convex hull 里。这就是 convex hull property：curve 永远不会跑出 control polygon 围成的范围。Clipping 和求 intersection 时，先拿 convex hull（或它的 bounding box）测一下，碰不到就整条 curve 都碰不到。

**例子。** $P_0=(0,0)$，$P_1=(1,2)$，$P_2=(3,2)$，$P_3=(4,0)$，$u=0.25$：四个权重 $0.75^3=0.421875$，$3\times0.25\times0.75^2=0.421875$，$3\times0.0625\times0.75=0.140625$，$0.25^3=0.015625$，和为 1。

$$p(0.25)=0.421875(1,2)+0.140625(3,2)+0.015625(4,0)=(0.90625,\;1.125)$$

两端的切线：$p'(0)=3(P_1-P_0)=(3,6)$，$p'(1)=3(P_3-P_2)=(3,-6)$。

::fig[cs3241-bernstein] 左边是四个 Bernstein polynomial，竖线标出 $u=0.25$ 时的四个权重；右边是这条 curve 和它的 control polygon，$p(0.25)$ 落在灰色的 convex hull 里。

### De Casteljau：只用 line interpolation 求点

上面的权重要算 power。De Casteljau algorithm 只用“在两点之间按比例取点”：

1. 在 control polygon 的三条边上，各取 $(1-u):u$ 的分点，得到 3 个点。
2. 在这 3 个点连成的两条边上，再各取分点，得到 2 个点。
3. 两点之间再取分点，得到 1 个点，就是 $p(u)$。

同一个例子，$u=0.25$：

$$\text{第一层：}(0.25,0.5),\ (1.5,2),\ (3.25,1.5)$$

$$\text{第二层：}(0.5625,0.875),\ (1.9375,1.875)$$

$$\text{第三层：}0.75(0.5625,0.875)+0.25(1.9375,1.875)=(0.90625,\,1.125)$$

和 Bernstein form 的结果一致。为什么？每一层都是相邻两点的 $(1-u),u$ 加权平均，三层下来 $P_0$ 只能走“一直向左”这一条路，权重 $(1-u)^3$；$P_1$ 有三条路（在三层中哪一层向右），权重 $3u(1-u)^2$。恰好是 binomial coefficient。

最后一层那两个点的连线就是 $p(u)$ 处的切线方向：$(1.9375,1.875)-(0.5625,0.875)=(1.375,1)$，乘 3 得 $p'(0.25)=(4.125,3)$。直接对 Bernstein form 求导核对：$p'(u)=3\big[(1-u)^2(P_1-P_0)+2u(1-u)(P_2-P_1)+u^2(P_3-P_2)\big]$，$u=0.25$ 时 $=3[0.5625(1,2)+0.375(2,0)+0.0625(1,-2)]=3(1.375,1)=(4.125,3)$，一致。

::fig[cs3241-decast] 动图：$u$ 从 0 走到 1，de Casteljau 的三层分点跟着移动，最后一个点描出 curve。第一帧停在 $u=0.25$，数字和上面的计算相同。

还有一个副产品：$u=\tfrac12$ 时，$P_0$、第一层第一个点、第二层第一个点、$p(\tfrac12)$ 这四个点恰好是左半段 curve 的 control point，另外四个是右半段的。递归地对半分，control polygon 会迅速贴近 curve，分到足够平就当作 line segment 画出来。

### 往年题：沿着山谷摆花

（据公开 repo 的解答代码，AY2013/14 S2 的第 3 题。）一条 quadratic Bezier curve，control point 是 $(-200,100)$、$(0,-100)$、$(200,100)$，画出这个“山谷”，再在 $u=0.1,0.2,\dots,0.9$ 处各摆一朵花，花要垂直于山谷的表面。

Quadratic Bezier 是三个 control point、degree 2 的 Bernstein polynomial：

$$p(u)=(1-u)^2Q_0+2u(1-u)Q_1+u^2Q_2$$

代入：

$$x(u)=-200(1-u)^2+200u^2=400u-200$$

$$y(u)=100(1-u)^2-200u(1-u)+100u^2=100\big[(1-u)-u\big]^2=100(1-2u)^2$$

消去 $u$：$1-2u=-x/200$，$y=x^2/400$，是一条 parabola。

切线：$p'(u)=2(1-u)(Q_1-Q_0)+2u(Q_2-Q_1)=\big(400,\;-400(1-2u)\big)$。$u=0.1$ 处点在 $(-160,64)$，切线 $(400,-320)$，和 $x$ 轴的 angle $\arctan(-320/400)=-38.7^\circ$。

花的 model 是一个指向 $+x$ 的小 triangle。要它垂直于 surface，就要把它转到 normal 方向，也就是切线方向再转 $90^\circ$：

```c
glPushMatrix();
glTranslatef(p.x, p.y, 0);
glRotatef(90, 0, 0, 1);
glRotatef(angle, 0, 0, 1);    // angle = atan2(tangent.y, tangent.x)，单位 degree
drawFlower();
glPopMatrix();
```

从 draw 往上读：先转到切线方向，再转 $90^\circ$ 到 normal 方向，最后搬到 curve 上的点。$u=0.1$ 处花朝向 $-38.7^\circ+90^\circ=51.3^\circ$，即左上方，垂直于下坡的山谷。

::fig[cs3241-valley] 这条 quadratic Bezier 山谷、三个 control point，以及 $u=0.1,\dots,0.9$ 处沿 normal 方向的九朵花。

:::wrong 用 atan(tangent.y / tangent.x) 求 angle 就够了
$\arctan$ 的值域是 $(-90^\circ,90^\circ)$，分不清 $(400,-320)$ 和 $(-400,320)$。这道题 $x'(u)=400$ 恒为正，碰巧不出错；curve 一旦往回走（$x'<0$），花就会朝反方向。那份解答代码在 $x<0$ 时手动加 $180^\circ$；用 `atan2(y, x)` 直接得到 $(-180^\circ,180^\circ]$ 里正确的 angle。
:::

### 两段接起来：continuity

一个 cubic Bezier 只有四个 control point，复杂的形状要把很多段接起来。设第一段 $P_0,\dots,P_3$，第二段 $Q_0,\dots,Q_3$，看接点：

- **$C^0$**：位置相同，$Q_0=P_3$。可以有尖角。
- **$G^1$**：切线方向相同。第一段在终点的切线是 $3(P_3-P_2)$，第二段在起点的是 $3(Q_1-Q_0)$，要求 $Q_1-Q_0=k(P_3-P_2)$，$k>0$，即 $P_2,P_3=Q_0,Q_1$ 在一条直线上，且 $P_3$ 在中间。看起来光滑。
- **$C^1$**：切线 vector 完全相同，$k=1$：$Q_1-Q_0=P_3-P_2$，接点是 $P_2$ 和 $Q_1$ 的中点。沿 curve 匀速运动的物体，过接点时速度不跳变。
- **$C^2$**：second derivative 也相同。

$C^1$ 推出 $G^1$，反之不成立。

**例子。** 接上面那条 curve，$P_2=(3,2)$，$P_3=(4,0)$，$P_3-P_2=(1,-2)$。第二段取 $Q_0=(4,0)$：$Q_1=(5,-2)$ 是 $C^1$；$Q_1=(6,-4)$ 方向相同、长度两倍，是 $G^1$ 不是 $C^1$；$Q_1=(5,0)$ 方向不同，只有 $C^0$。

::fig[cs3241-cont] 第二段的 $Q_1$ 取三个位置：$(5,0)$ 在接点处有尖角；$(6,-4)$ 方向对上、长度是两倍，光滑但速度在接点跳变；$(5,-2)$ 和 $P_2$ 关于接点对称，$C^1$。

:::wrong Interpolating curve 过每个 control point，所以比 Bezier 更好用
过每个点的代价是没有切线可以控制：两段在接点处只能保证 $C^0$。而且 $M_I$ 的 entry 有正有负、绝对值很大，blending function 会小于 0、大于 1，没有 convex hull property，移动一个 control point 时 curve 可能在别处大幅摆动。Bezier 不过中间两个点，但用它们直接控制切线，接起来能做到 $G^1$、$C^1$，并且 curve 不出 convex hull。
:::

### Surface patch

把同样的想法用到两个 parameter 上。Bicubic Bezier patch 有 $4\times4=16$ 个 control point $P_{ij}$：

$$p(u,v)=\sum_{i=0}^{3}\sum_{j=0}^{3}b_i(u)\,b_j(v)\,P_{ij}$$

固定 $v$，它是 $u$ 方向的一条 cubic Bezier curve，四个 control point 由四条 $v$ 方向的 curve 在这个 $v$ 处的值给出。Patch 过四个角的 control point，其余 12 个只是拉着它。权重 $b_i(u)b_j(v)$ 非负、和为 1，所以 patch 也在 16 个点的 convex hull 里。

Lighting 要 normal。$\partial p/\partial u$ 和 $\partial p/\partial v$ 是 surface 在这一点的两个 tangent vector，normal 和它们都 perpendicular：

$$n=\frac{\partial p}{\partial u}\times\frac{\partial p}{\partial v}$$

一般不是 unit vector，要 normalize。

和固定的 polygon mesh 相比，patch 可以按屏幕上的大小决定切多细：离得远、在屏幕上很小，切成几个 triangle 就够；拉近了，切得更细，轮廓始终光滑。固定的 mesh 要么远处浪费，要么近处粗糙。

:::back
Patch 的 normal 拿去做[第 5 站](#light)的 lighting；Bezier curve 摆花用的是[第 2 站](#xform)的 transformation 和 matrix stack。
:::
