先看三件事。每一件里，写的人都相信自己是对的。

**第一件。** 一个 function 号称计算加法，跑了四个 unit test：`add 0 0 = 0`、`add 0 5 = 5`、`add 2 3 = 5`、`add 7 0 = 7`，全部通过。可它的定义是“第一个 argument 不超过 7 时做加法，否则返回 0”，`add 8 1` 给出 0。四个 test 检查了无穷多个 input 中的四个，剩下的它们什么也没说。

**第二件。** “Every student is younger than some instructor” 和 “Some instructor is older than every student” 读起来像同一句话。两个 student、两个 instructor、每个 student 只比自己的那个 instructor 小，第一句为真，第二句为假（第 3 站画出这个 model）。

**第三件。** 一个 Prolog 程序把“X 是 Y 的 descendant”写成两条在逻辑上完全正确的 rule，问 `descend(martha, rose)` 时程序不返回，最后报 out of stack。把同样两条 rule 的顺序换一下，立刻得到 yes（第 9 站）。

三件事背后是同一个问题：一个 statement 什么时候算被证明了，证明了之后机器能不能检查，能不能执行。这门课把 logic 当作三样东西来学：一种 language（写出 specification），一个 proof system（推出结论，并且推导本身可以被检查），一种 programming language（Coq 里的 proof 就是 program，Prolog 里的 program 就是一组 formula）。

## [nd] Natural deduction 与 classical propositional logic

:::skip
能用 box proof 证明一个含 ∨ 和 ¬ 的 sequent，能用一个 valuation 说明一个 sequent 不可证，并说清 soundness 和 completeness 各是哪个方向，就可以去第 2 站。
:::

### Truth：用 valuation 定义

Propositional logic 的 formula 由 atom（$p,q,r,\dots$）、$\top$、$\bot$ 和 connective 拼成：

$$\varphi::=p\mid\bot\mid\top\mid(\neg\varphi)\mid(\varphi\land\varphi)\mid(\varphi\lor\varphi)\mid(\varphi\to\varphi)$$

约定 $\neg$ 比 $\land$、$\lor$ 绑得紧，$\land$、$\lor$ 比 $\to$ 紧，$\to$ 向右结合：$p\to q\to r$ 是 $p\to(q\to r)$。

一个 valuation $v$ 给每个 atom 指定 T 或 F，然后按 truth table 一层层算出整个 formula 的值。$\varphi\to\psi$ 只在 $\varphi$ 为 T、$\psi$ 为 F 时为 F。

有了 valuation，就能说“由 premise 得出 conclusion”是什么意思：

$$\varphi_1,\dots,\varphi_n\models\psi\quad\text{当且仅当}\quad\text{每个使所有 }\varphi_i\text{ 为 T 的 valuation 都使 }\psi\text{ 为 T}$$

这叫 semantic entailment。$n=0$ 时写 $\models\psi$，意思是 $\psi$ 在所有 valuation 下为 T，叫 valid。

拿 $p\land q\to p\lor q$ 试一下，两个 atom，四个 valuation：

| $p$ | $q$ | $p\land q$ | $p\lor q$ | $p\land q\to p\lor q$ |
|---|---|---|---|---|
| T | T | T | T | T |
| T | F | F | T | T |
| F | T | F | T | T |
| F | F | F | F | T |

最后一个 column 全是 T，所以 valid。

### 为什么还要 proof

Truth table 是一个完整的判定方法，但行数是 $2^n$。30 个 atom 就有 $2^{30}=1073741824$ 行。到了第 3 站，atom 换成 $P(x)$ 这样的 predicate，$x$ 可以取无穷多个值，表根本列不完。

另一条路是从 premise 出发，每一步只用一条机械可查的 rule，推到 conclusion。这样的推导叫 proof，写作

$$\varphi_1,\dots,\varphi_n\vdash\psi$$

读作“由 $\varphi_1,\dots,\varphi_n$ 可以 prove $\psi$”，整个式子叫 sequent。检查一个 proof 只要逐行对照 rule，不需要看任何 valuation。

### Natural deduction 的 rule

每个 connective 有两类 rule：introduction（怎样得到它）和 elimination（得到它之后能用来干什么）。

| Connective | Introduction | Elimination |
|---|---|---|
| $\land$ | $\land$i：由 $\varphi$ 和 $\psi$ 得 $\varphi\land\psi$ | $\land$e₁、$\land$e₂：由 $\varphi\land\psi$ 得 $\varphi$，或得 $\psi$ |
| $\to$ | $\to$i：假设 $\varphi$，在 box 里推出 $\psi$，box 外得 $\varphi\to\psi$ | $\to$e（modus ponens）：由 $\varphi$ 和 $\varphi\to\psi$ 得 $\psi$ |
| $\lor$ | $\lor$i₁、$\lor$i₂：由 $\varphi$ 得 $\varphi\lor\psi$，或由 $\psi$ 得 $\varphi\lor\psi$ | $\lor$e：由 $\varphi\lor\psi$、假设 $\varphi$ 推出 $\chi$ 的 box、假设 $\psi$ 推出 $\chi$ 的 box，得 $\chi$ |
| $\neg$ | $\neg$i：假设 $\varphi$，在 box 里推出 $\bot$，得 $\neg\varphi$ | $\neg$e：由 $\varphi$ 和 $\neg\varphi$ 得 $\bot$ |
| $\bot$ | 无 | $\bot$e：由 $\bot$ 得任意 $\varphi$ |
| $\neg\neg$ | 无 | $\neg\neg$e：由 $\neg\neg\varphi$ 得 $\varphi$ |

最简单的例子，$p\land q,\ r\vdash q\land r$：

| 行 | Formula | 理由 |
|---|---|---|
| 1 | $p\land q$ | premise |
| 2 | $q$ | $\land$e₂ 1 |
| 3 | $r$ | premise |
| 4 | $q\land r$ | $\land$i 2, 3 |

### Box：一个假设管到哪里

要证 $\varphi\to\psi$，自然的做法是“假设 $\varphi$，推出 $\psi$”。但假设只是暂时的。如果假设在用完之后还留着，就能证出任何东西。所以每个假设开一个 box：box 外面的行在 box 里都能用；box 里的行，包括那个假设本身，在 box 关上之后都不能再用。Box 关上时只带出一行结论，比如 $\varphi\to\psi$，它不再依赖那个假设。

例子，$p\to q\vdash\neg\neg p\to q$：

| 行 | Formula | 理由 |
|---|---|---|
| 1 | $p\to q$ | premise |
| 2 | $\neg\neg p$ | assumption（开 box） |
| 3 | $p$ | $\neg\neg$e 2 |
| 4 | $q$ | $\to$e 1, 3（关 box） |
| 5 | $\neg\neg p\to q$ | $\to$i 2–4 |

第 4 行用到 box 外的第 1 行，这是允许的。第 5 行的理由写的是一段行号 2–4，表示整个 box。

$\lor$e 要开两个 box。要从 $p\land(q\lor r)$ 推出 $(p\land q)\lor(p\land r)$，手里有 $q\lor r$ 却不知道是哪一个，只能两种情况都推一遍，而且两边必须推到同一个 formula。

::fig[cs3234-boxor] $p\land(q\lor r)\vdash(p\land q)\lor(p\land r)$ 的 box proof。第 4 行的 $q$ 只活在左边的 box 里，第 7 行的 $r$ 只活在右边的 box 里。

:::wrong Box 关上之后，里面的假设还能接着用
如果允许，下面三行就是一个“proof”：第 1 行假设 $p$；第 2 行 $p\to p$，理由 $\to$i 1–1；第 3 行再引用第 1 行，得 $p$。这样就证出了 $\vdash p$，没有任何 premise。可是 valuation $v(p)=$ F 使 $p$ 为 F，$\models p$ 不成立。一个 proof system 证出了不 valid 的东西，它就没有用了。Box 的规则存在，正是为了排除这种推导。
:::

### Derived rule 和 LEM

有些推导反复出现，证一次以后当作 rule 用。比如 $\neg\neg$i，$\varphi\vdash\neg\neg\varphi$：

| 行 | Formula | 理由 |
|---|---|---|
| 1 | $\varphi$ | premise |
| 2 | $\neg\varphi$ | assumption |
| 3 | $\bot$ | $\neg$e 1, 2 |
| 4 | $\neg\neg\varphi$ | $\neg$i 2–3 |

这个 proof 对任意 $\varphi$ 都成立，所以可以当作一条 rule。Modus tollens（由 $\varphi\to\psi$ 和 $\neg\psi$ 得 $\neg\varphi$）也是这样来的。

Law of the excluded middle（LEM），$\vdash\varphi\lor\neg\varphi$，没有 premise。$\lor$i 需要先有 $\varphi$ 或者先有 $\neg\varphi$，两样都没有，所以只能绕路：先证它的 double negation。

| 行 | Formula | 理由 |
|---|---|---|
| 1 | $\neg(\varphi\lor\neg\varphi)$ | assumption |
| 2 | $\varphi$ | assumption |
| 3 | $\varphi\lor\neg\varphi$ | $\lor$i₁ 2 |
| 4 | $\bot$ | $\neg$e 3, 1 |
| 5 | $\neg\varphi$ | $\neg$i 2–4 |
| 6 | $\varphi\lor\neg\varphi$ | $\lor$i₂ 5 |
| 7 | $\bot$ | $\neg$e 6, 1 |
| 8 | $\neg\neg(\varphi\lor\neg\varphi)$ | $\neg$i 1–7 |
| 9 | $\varphi\lor\neg\varphi$ | $\neg\neg$e 8 |

前 8 行一条 $\neg\neg$e 都没用。最后一行是唯一用到它的地方。第 4 站会看到，去掉 $\neg\neg$e 之后第 8 行仍然可证，第 9 行就证不出来了。

### Soundness 与 completeness

现在有两种“得出”：$\models$ 看所有 valuation，$\vdash$ 看有没有 proof。它们由两个 theorem 连起来：

- **Soundness**：如果 $\varphi_1,\dots,\varphi_n\vdash\psi$，那么 $\varphi_1,\dots,\varphi_n\models\psi$。能证出来的都是真的。
- **Completeness**：如果 $\varphi_1,\dots,\varphi_n\models\psi$，那么 $\varphi_1,\dots,\varphi_n\vdash\psi$。真的都能证出来。

Soundness 的证明思路是对 proof 的行数做 induction：每条 rule 都保持“在所有使 premise 和当前有效假设为 T 的 valuation 下为 T”。以 $\to$e 为例：若某个 valuation 使 $\varphi$ 和 $\varphi\to\psi$ 都为 T，由 $\to$ 的 truth table，$\varphi\to\psi$ 为 T 而 $\varphi$ 为 T，只剩 $\psi$ 为 T 一种可能。

Soundness 最直接的用处是证明某个东西**证不出来**。要说明 $p\to q\nvdash q\to p$，不必试遍所有可能的 proof，只要找一个 valuation：$v(p)=$ F，$v(q)=$ T。这时 $p\to q$ 为 T，$q\to p$ 为 F，所以 $p\to q\not\models q\to p$。如果有 proof，soundness 就会给出 $\models$，矛盾。

:::edge Soundness 这个词在别处也用
Danvy 的讲义第一周把同一对概念用在 program 上：一个判断 prime 的 function，sound 指“它说 true，那个数就是 prime”，complete 指“那个数是 prime，它就说 true”。两个方向和这里的 $\vdash\Rightarrow\models$、$\models\Rightarrow\vdash$ 一一对应。第 5 站用这个说法来谈 unit test。
:::

## [sat] SAT：CNF、DPLL 与 resolution

:::skip
能把 formula 化成 clause set，手算 DPLL 和 resolution 直到得到 empty clause 或者删光所有 clause，并说清这和 validity 的关系，就可以去第 3 站。
:::

### Validity 变成 satisfiability

$\varphi$ valid，意思是没有 valuation 使它为 F，也就是没有 valuation 使 $\neg\varphi$ 为 T，也就是 $\neg\varphi$ unsatisfiable。所以只要有一个判断 satisfiable 的程序，validity 和 entailment 都能交给它：$\varphi_1,\dots,\varphi_n\models\psi$ 当且仅当 $\varphi_1\land\dots\land\varphi_n\land\neg\psi$ unsatisfiable。

判断一个 formula 是否 satisfiable，这个问题叫 SAT。它是第一个被证明 NP-complete 的问题（证明见 [CS3231 的最后一站](../courses/CS3231.html#np)），所以不指望有对所有 input 都快的 algorithm。但实际的 SAT solver 在上百万个 variable 的工业 instance 上常常几秒出结果，靠的是先把 formula 化成统一的形状，再用能大量剪枝的 search。

### Conjunctive normal form

SAT solver 只吃一种形状：若干 clause 的 conjunction，每个 clause 是若干 literal 的 disjunction，literal 是 atom 或 atom 的 negation。这叫 CNF。化成 CNF 分四步：

1. 消去 $\to$：$A\to B$ 换成 $\neg A\lor B$。
2. 把 $\neg$ 往里推到 atom 上：$\neg\neg A\equiv A$，$\neg(A\land B)\equiv\neg A\lor\neg B$，$\neg(A\lor B)\equiv\neg A\land\neg B$。
3. 把 $\lor$ 往里推过 $\land$：$A\lor(B\land C)\equiv(A\lor B)\land(A\lor C)$。
4. 化简：删掉同时含 $P$ 和 $\neg P$ 的 clause（它恒为 T）。

例子，$P\lor Q\to Q\lor R$：

$$\neg(P\lor Q)\lor(Q\lor R)\;\equiv\;(\neg P\land\neg Q)\lor Q\lor R\;\equiv\;(\neg P\lor Q\lor R)\land(\neg Q\lor Q\lor R)\;\equiv\;\neg P\lor Q\lor R$$

第三步之后第二个 clause 同时含 $Q$ 和 $\neg Q$，删掉。剩下一个 clause，它在 $P=1,Q=0,R=0$ 时为 0，所以原 formula 不 valid。

Clause 写成 literal 的 set：$\neg P\lor Q\lor R$ 写作 $\{\neg P,Q,R\}$。一个 clause set 是这些 set 的 conjunction。空的 clause $\{\}$ 是零个 literal 的 disjunction，没有 literal 能为 T，所以它恒为 F，表示 contradiction。

:::wrong 化成 CNF 只是机械改写，代价可以忽略
第 3 步会让 formula 成倍变长。$(x_1\land y_1)\lor(x_2\land y_2)\lor\dots\lor(x_n\land y_n)$ 只有 $2n$ 个 literal，按 distributivity 展开后，每个 clause 要从每个 $(x_i\land y_i)$ 里各挑一个 literal，共 $2^n$ 个 clause。$n=10$ 时是 1024 个 clause，每个 10 个 literal。实际的 solver 改用 Tseitin 编码：对每个 $(x_i\land y_i)$ 引入一个新 variable $z_i$，加三个 clause $\{\neg z_i,x_i\}$、$\{\neg z_i,y_i\}$、$\{\neg x_i,\neg y_i,z_i\}$ 表示 $z_i\leftrightarrow x_i\land y_i$，再加一个 $\{z_1,\dots,z_n\}$。$n=10$ 时一共 $3\times10+1=31$ 个 clause。新 formula 和原来的不 equivalent（多了 variable），但 satisfiable 当且仅当原来的 satisfiable，这对 SAT 就够了。
:::

### DPLL

最笨的 search 是试遍 $2^n$ 个 valuation。DPLL 在每一步先做不需要猜的事，实在没有了才猜一次：

1. **Unit propagation。** 只有一个 literal 的 clause $\{L\}$ 叫 unit clause，它逼着 $L$ 为 T。于是删掉所有含 $L$ 的 clause（已经满足），并从所有 clause 里删去 $\neg L$（它为 F，对 disjunction 没有贡献）。
2. **Pure literal。** 如果 $\neg L$ 不出现在任何 clause 里，就让 $L$ 为 T，删掉所有含 $L$ 的 clause。这不会伤害任何别的 clause。
3. 出现 empty clause：这一支 unsatisfiable。所有 clause 都删光了：satisfiable。
4. 否则 **case split**：挑一个 literal $L$，分别在 $L$ 为 T 和 $L$ 为 F 两种情况下递归。两支中有一支 satisfiable，原来的 clause set 就 satisfiable。

先看上面那个不 valid 的例子。要找 $P\lor Q\to Q\lor R$ 的 counterexample，就是要 satisfy 它的 negation，negation 的 clause 是 $\{P,Q\}$、$\{\neg Q\}$、$\{\neg R\}$。Unit $\neg Q$：删掉 $\{\neg Q\}$，从 $\{P,Q\}$ 里删去 $Q$，剩 $\{P\}$、$\{\neg R\}$。Unit $P$：剩 $\{\neg R\}$。Unit $\neg R$：全部删光，satisfiable，一路上逼出来的 $P=1$、$Q=0$、$R=0$ 就是 counterexample，和上一小节的结论一致。

再看一个必须 case split 的例子。下面 6 个 clause 里没有 unit clause，每个 literal 的 negation 都出现过，所以也没有 pure literal。

::fig[cs3234-dpll] DPLL 在 6 个 clause 上的执行。先 split $P$，两支各自做两次 unit propagation，都得到 empty clause。

$P=1$ 那一支的第一步写全：含 $P$ 的 clause $\{\neg R,P\}$、$\{P,Q\}$ 满足了，删掉；含 $\neg P$ 的 $\{\neg P,Q,R\}$、$\{\neg P,\neg Q\}$ 去掉 $\neg P$，变成 $\{Q,R\}$、$\{\neg Q\}$。剩下 $\{\neg Q,R\}$、$\{\neg R,Q\}$、$\{Q,R\}$、$\{\neg Q\}$。Unit $\neg Q$ 删掉 $\{\neg Q,R\}$ 和 $\{\neg Q\}$，把 $\{\neg R,Q\}$ 变成 $\{\neg R\}$、$\{Q,R\}$ 变成 $\{R\}$。Unit $R$ 把 $\{\neg R\}$ 变空。

两支都得到 empty clause，所以这 6 个 clause unsatisfiable。如果它们是某个 $\neg\varphi$ 的 clause，$\varphi$ 就是 valid 的。

:::edge Case split 的 literal 怎么挑
DPLL 本身不规定挑哪个。挑得好，一边很快出 empty clause；挑得差，search tree 指数级变大。现代 solver（CDCL）在每次冲突时从冲突里学出一个新 clause 加进去，下次不再走进同样的死路，并按最近参与冲突的频率挑 variable。这一部分 Paulson 的讲义没有讲，这里只说明它在 DPLL 的哪一步上改进。
:::

### Resolution

DPLL 是 search，找的是 valuation。另一条路是直接从 clause 推出新 clause，直到推出 empty clause。只需要一条 rule：

$$\frac{\{B,A_1,\dots,A_m\}\qquad\{\neg B,C_1,\dots,C_n\}}{\{A_1,\dots,A_m,C_1,\dots,C_n\}}$$

为什么它是对的：任取一个使两个 clause 都为 T 的 valuation。若 $B$ 为 T，第二个 clause 里的 $\neg B$ 为 F，必须有某个 $C_j$ 为 T；若 $B$ 为 F，第一个 clause 里必须有某个 $A_i$ 为 T。两种情况下结论都为 T。特例 $\{B\}$ 和 $\{\neg B\}$ 推出 $\{\}$。

由 resolution 得到的 clause 被原来的 clause set entail，所以一旦推出 $\{\}$，原 clause set 就 unsatisfiable。反过来，unsatisfiable 的 clause set 一定能推出 $\{\}$（resolution 的 refutation completeness，这里不证）。

例子。假设 $H\to(M\lor N)$、$M\to(K\land P)$、$N\to(L\land P)$，要证 $H\to P$。前三个化成 clause：$\{\neg H,M,N\}$、$\{\neg M,K\}$、$\{\neg M,P\}$、$\{\neg N,L\}$、$\{\neg N,P\}$。Goal 取 negation，$\neg(H\to P)\equiv H\land\neg P$，给两个 clause $\{H\}$、$\{\neg P\}$。

::fig[cs3234-resol] 四次 resolution 推出 empty clause。每一步消掉一个 atom 和它的 negation。

$\{\neg M,K\}$ 和 $\{\neg N,L\}$ 没有用上：$K$ 和 $L$ 的 negation 从不出现，它们是 pure literal，DPLL 会第一时间删掉这两个 clause。

:::wrong 一次可以同时消掉两对互补的 literal
$\{P,Q\}$ 和 $\{\neg P,\neg Q\}$ 似乎可以一步消掉 $P$ 和 $Q$，得到 $\{\}$，从而说明两者矛盾。可是 $P=1,Q=0$ 同时满足这两个 clause，它们并不矛盾。正确的做法是一次只消一个 atom：消 $P$ 得到 $\{Q,\neg Q\}$，那是一个恒为 T 的 clause，没有用。
:::

只有一个 positive literal 的 clause，比如 $\{\neg M,P\}$（即 $M\to P$），叫 Horn clause。第 9 站的 Prolog 程序就是一组 Horn clause，它的执行就是一种特定顺序的 resolution。

:::back
用的是[第 1 站](#nd)的 valuation 和 $\models$。
:::

## [pred] Predicate logic：quantifier 与它的 rules

:::skip
能把带 every、some 的英文句子翻成 formula 并分清 quantifier 的顺序，能写出含 $\forall$i、$\exists$e 的 box proof 并检查 fresh variable，就可以去第 4 站。
:::

### Propositional logic 说不出来的话

“Every student is younger than some instructor.” 在 propositional logic 里它只能是一个 atom $p$，里面的结构全丢了：谁是 student、谁是 instructor、谁比谁小，都没法单独说，也就没法从它推出“Alice is younger than some instructor”。

把结构拆出来：$S(x)$ 表示 $x$ 是 student，$I(y)$ 表示 $y$ 是 instructor，$Y(x,y)$ 表示 $x$ 比 $y$ 小。

$$\forall x\,\bigl(S(x)\to\exists y\,(I(y)\land Y(x,y))\bigr)$$

再加上 function symbol 就能说得更短。“Every girl is younger than her mother” 用 $m(x)$ 表示 $x$ 的 mother：$\forall x\,(G(x)\to Y(x,m(x)))$。

Term 是 variable、constant，或 function symbol 作用在 term 上；formula 由 predicate 作用在 term 上，加上第 1 站的 connective 和 $\forall x$、$\exists x$ 拼成。$=$ 是内置的 binary predicate。

### Model：truth 换了定义

现在一个 formula 的真假要看一个 model：一个非空的 universe，以及每个 predicate、function、constant 在这个 universe 上的意思。开头第二件事里的两句话，用一个四个 element 的 model 就能分开。

::fig[cs3234-model] 两个 student，两个 instructor，$Y$ 只连了两对。先 $\forall$ 再 $\exists$ 的句子为真，先 $\exists$ 再 $\forall$ 的句子为假。

逐个检查。第一句：$x=s_1$ 时取 $y=i_1$，$I(i_1)$ 和 $Y(s_1,i_1)$ 都为真；$x=s_2$ 时取 $y=i_2$；$x$ 是 instructor 时 $S(x)$ 为假，implication 自动为真。所以第一句为真，每个 $x$ 可以挑自己的 $y$。

第二句要求同一个 $y$ 对所有 student 都行。$y=i_1$：$Y(s_2,i_1)$ 不成立。$y=i_2$：$Y(s_1,i_2)$ 不成立。$y$ 是 student 时 $I(y)$ 就为假。所以第二句为假。

由 $\exists y\forall x$ 能推出 $\forall x\exists y$（同一个 $y$ 给每个 $x$ 用），反过来不行，这个 model 就是反例。

Model 可以有无穷个 element，也有无穷多个 model，所以 $\models$ 不能再靠列表来检查。这正是第 1 站说的“为什么还要 proof”。

### Substitution 和 capture

Quantifier rule 要把一个 term $t$ 代进 formula 里的 variable $x$，记作 $[x\Rightarrow t]\varphi$：把 $\varphi$ 里每个 free 的 $x$ 换成 $t$。Free 指没有被 $\forall x$ 或 $\exists x$ 管住；被管住的叫 bound。

危险在于 $t$ 里的 variable 被 $\varphi$ 里的 quantifier 抓住。设

$$\varphi=S(w)\land\forall v\,(P(w)\to Q(v)),\qquad t=f(v,v)$$

直接替换 $w$ 得到 $S(f(v,v))\land\forall v\,(P(f(v,v))\to Q(v))$。第二个 $f(v,v)$ 里的 $v$ 原本是外面的 free variable，现在被 $\forall v$ 抓了进去，意思变了。正确做法是先把 bound variable 改名，$\forall v$ 换成 $\forall z$，再替换：

$$S(f(v,v))\land\forall z\,(P(f(v,v))\to Q(z))$$

$t$ 里没有 variable 会被抓住时，说“$t$ is free for $x$ in $\varphi$”。下面每条 rule 都默认满足这个条件。

### $\forall$ 和 $\exists$ 的 rules

| | Introduction | Elimination |
|---|---|---|
| $\forall$ | $\forall$i：开一个 box，引入一个 fresh variable $x_0$，在 box 里证出 $[x\Rightarrow x_0]\varphi$，box 外得 $\forall x\,\varphi$ | $\forall$e：由 $\forall x\,\varphi$ 得 $[x\Rightarrow t]\varphi$，$t$ 是任意 term |
| $\exists$ | $\exists$i：由 $[x\Rightarrow t]\varphi$ 得 $\exists x\,\varphi$ | $\exists$e：由 $\exists x\,\varphi$，开一个 box，引入 fresh $x_0$ 并假设 $[x\Rightarrow x_0]\varphi$，在 box 里推出 $\chi$，且 $\chi$ 不含 $x_0$，box 外得 $\chi$ |
| $=$ | $=$i：$t=t$ | $=$e：由 $t_1=t_2$ 和 $[x\Rightarrow t_1]\varphi$ 得 $[x\Rightarrow t_2]\varphi$ |

$\forall$i 的 fresh variable 保证 $x_0$ 是“任意的一个”：关于它，除了 box 外已知对所有东西都成立的事，什么也不知道，所以对它证出的事对每个 element 都成立。$\exists$e 的 fresh variable 保证 witness 只是一个名字：只知道有这么一个东西满足 $\varphi$，不知道它是谁。

$\forall x\,(P(x)\to Q(x)),\ \exists x\,P(x)\vdash\exists x\,Q(x)$：

::fig[cs3234-boxex] 先用 $\exists$e 给 witness 起名 $x_0$，在 box 里用 $\forall$e 把 premise 1 用在 $x_0$ 上，推出 $Q(x_0)$，再用 $\exists$i 忘掉名字。

:::wrong $\exists$e 的 box 里得到了 $P(x_0)$，$x_0$ 是任意的，所以可以接着用 $\forall$i 得到 $\forall x\,P(x)$
这样就从 $\exists x\,P(x)$ 证出了 $\forall x\,P(x)$。Universe $\{1,2\}$、$P$ 只在 1 上成立：$\exists x\,P(x)$ 为真，$\forall x\,P(x)$ 为假，所以这个 sequent 不 valid。错在 $\forall$i 要求 $x_0$ fresh，不出现在任何还开着的 assumption 里，而这里 $x_0$ 正出现在 $\exists$e 的 assumption $P(x_0)$ 里。它不是“任意的一个”，它是那个已知满足 $P$ 的 witness。
:::

### 还剩什么性质

Propositional logic 的 soundness 和 completeness 在 predicate logic 里仍然成立（completeness 是 Gödel 1929 年证的）。但 truth table 那样的判定方法没有了：没有 program 能对任意 formula 判定它是否 valid。讲义的证明思路是把 Post Correspondence Problem 编码成一个 formula，PCP 有 solution 当且仅当 formula valid，而 PCP 是 undecidable 的（见 [CS3231 的 undecidability 一站](../courses/CS3231.html#undec)）。所以 proof 在这里不只是省时间的办法，而是唯一的办法；能证出来的都可以检查，但没有 algorithm 保证一定找得到 proof。

:::back
Box 的规则和 soundness、completeness 的意思见[第 1 站](#nd)。
:::

## [intu] Intuitionistic logic 与 Curry–Howard

:::skip
能用两个 world 的 Kripke model 说明 $p\lor\neg p$ 在 intuitionistic logic 里不成立，能把一个 natural deduction proof 写成 proof term 并做 reduction，就可以去第 5 站。
:::

### 一个不告诉你答案的 proof

Theorem：存在两个 irrational number $a,b$，使 $a^b$ 是 rational。

Proof：看 $\sqrt2^{\sqrt2}$。它要么 rational，要么 irrational。若 rational，取 $a=b=\sqrt2$。若 irrational，取 $a=\sqrt2^{\sqrt2}$、$b=\sqrt2$，则

$$a^b=\left(\sqrt2^{\sqrt2}\right)^{\sqrt2}=\sqrt2^{\sqrt2\cdot\sqrt2}=\sqrt2^{\,2}=2$$

是 rational。

这个 proof 在第 1 站的 rule 下完全正确，用的是 LEM。可读完之后仍然不知道 $a$ 到底是哪个数。如果把 proof 当作 program，希望它给出 witness，这个 proof 做不到。

### 只承认构造出来的东西

Intuitionistic logic 把“$A$ is true”读成“手里有一个 $A$ 的 proof”，并且 proof 要有具体内容：

- $A\land B$ 的 proof 是一对：一个 $A$ 的 proof 和一个 $B$ 的 proof。
- $A\lor B$ 的 proof 要说明是哪一边，并给出那一边的 proof。
- $A\to B$ 的 proof 是一个方法，把任何 $A$ 的 proof 变成 $B$ 的 proof。
- $\neg A$ 就是 $A\to\bot$；$\bot$ 没有 proof。

按这个读法，$A\lor\neg A$ 要求对每个 $A$ 都能说出是 $A$ 还是 $\neg A$ 并给出 proof，这等于说每个问题都已经解决。所以 intuitionistic logic 去掉 $\neg\neg$e（等价地，去掉 LEM、proof by contradiction 或 Peirce's law $((A\to B)\to A)\to A$，这几条互相推得出来），其余 rule 全部保留。

### Kripke model：为什么证不出 $p\lor\neg p$

Valuation 只有 T 和 F 两种状态，用它没法说明 $p\lor\neg p$ 证不出来，因为在任何 valuation 下它都为 T。需要一个能表达“还不知道”的 semantics。

Kripke model 是一组 world，带一个 partial order $w\le w'$，读作“从 $w$ 出发，以后可能到达 $w'$”。每个 world 上有一些 atom 成立，而且成立了就不会失效：$w\le w'$ 且 $p$ 在 $w$ 成立，则 $p$ 在 $w'$ 也成立。复合 formula 在 world $w$ 成立（记作 $w\Vdash$）的条件是：

- $w\Vdash A\land B$：$w\Vdash A$ 且 $w\Vdash B$。
- $w\Vdash A\lor B$：$w\Vdash A$ 或 $w\Vdash B$。
- $w\Vdash A\to B$：每个 $w'\ge w$，只要 $w'\Vdash A$，就 $w'\Vdash B$。
- $w\Vdash\neg A$：没有任何 $w'\ge w$ 使 $w'\Vdash A$。

Intuitionistic natural deduction 对这个 semantics 是 sound 的：可证的 formula 在每个 Kripke model 的每个 world 上都成立。所以只要找一个 world 让 $p\lor\neg p$ 不成立，它就证不出来。

::fig[cs3234-kripke] 两个 world。$w_0$ 上还不知道 $p$，以后会到达 $p$ 被证明的 $w_1$。

在 $w_0$ 上逐条检查。$p$：$p$ 只在 $w_1$ 成立，所以 $w_0\nVdash p$。$\neg p$：$w_1\ge w_0$ 且 $w_1\Vdash p$，所以 $w_0\nVdash\neg p$。$p\lor\neg p$：两边都不成立，所以 $w_0\nVdash p\lor\neg p$。

同一个 model 也说明 $\neg\neg p\to p$ 证不出来。$\neg\neg p$ 在 $w_0$ 成立，要求没有 $w'\ge w_0$ 使 $\neg p$ 成立：$w_0$ 上 $\neg p$ 不成立（刚才算过），$w_1$ 上 $p$ 成立所以 $\neg p$ 也不成立。于是 $w_0\Vdash\neg\neg p$，而 $w_0\nVdash p$，implication 在 $w_0$ 失败。

:::wrong 证不出 $p\lor\neg p$，就说明 intuitionistic logic 里 $\neg(p\lor\neg p)$ 成立
正好相反，$\neg\neg(p\lor\neg p)$ 可证。第 1 站 LEM 的九行 proof 里，前八行没有用 $\neg\neg$e，所以它们在 intuitionistic logic 里照样成立，第 8 行就是 $\neg\neg(p\lor\neg p)$。也可以在上面的 model 里检查：$\neg(p\lor\neg p)$ 要在 $w_0$ 成立，需要 $w_0$、$w_1$ 上都没有 $p\lor\neg p$，可 $w_1\Vdash p$，所以不成立。Intuitionistic logic 不否认 LEM，只是不肯把它当作一个能给出答案的 proof。
:::

### Proof 就是 program

把每个 rule 配上一个 term，记录这个 proof 是怎么造出来的。$M:A$ 读作“$M$ 是 $A$ 的 proof”，同时读作“$M$ 是 type 为 $A$ 的 program”。下面 $A\supset B$ 是 Pfenning 讲义里 implication 的写法，就是 $A\to B$。

| Rule | Proof term | 作为 program |
|---|---|---|
| $\land$I | $\langle M,N\rangle$ | pair |
| $\land$E₁、$\land$E₂ | $\mathsf{fst}\,M$、$\mathsf{snd}\,M$ | 取 pair 的第一、第二个分量 |
| $\supset$I（discharge 假设 $u$） | $\mathsf{fn}\,u\Rightarrow M$ | function，参数是 $u$ |
| $\supset$E | $M\,N$ | function application |
| $\lor$I₁、$\lor$I₂ | $\mathsf{inl}\,M$、$\mathsf{inr}\,M$ | 带标签的值 |
| $\lor$E | $\mathsf{case}\,M\,\mathsf{of}\,\mathsf{inl}\,u\Rightarrow N\mid\mathsf{inr}\,w\Rightarrow O$ | 按标签分情况 |

拿 $(A\land B)\supset(B\land A)$ 试一下。假设 $u:A\land B$；$\mathsf{snd}\,u:B$，$\mathsf{fst}\,u:A$；配成 pair $\langle\mathsf{snd}\,u,\mathsf{fst}\,u\rangle:B\land A$；最后 discharge $u$。

::fig[cs3234-curry] 同一棵 derivation tree，左边每个 node 写 proposition，右边写 proof term。最后得到的 term 是一个把 pair 两个分量交换的 function。

这个对应叫 Curry–Howard correspondence：proposition 对应 type，proof 对应 program，$\land$ 对应 product type，$\supset$ 对应 function type，$\lor$ 对应 sum type。第 5 站的 Coq 就是建在它上面的。

LEM 在这里没有 term：一个 type 为 $A\lor\neg A$ 的 program 必须对任意 $A$ 决定返回 $\mathsf{inl}$ 还是 $\mathsf{inr}$。而 $\neg\neg(A\lor\neg A)$，即 $((A\lor\neg A)\supset\bot)\supset\bot$，有 term：

$$\mathsf{fn}\,u\Rightarrow u\,\bigl(\mathsf{inr}\,(\mathsf{fn}\,v\Rightarrow u\,(\mathsf{inl}\,v))\bigr)$$

它拿到一个“$A\lor\neg A$ 会导致矛盾”的 $u$，先回答“是 $\neg A$”；这个 $\neg A$ 的 proof 是一个 function，一旦有人真的递来一个 $v:A$，它就改口回答“是 $A$”，把 $\mathsf{inl}\,v$ 交给 $u$。这就是第 1 站九行 proof 的前八行。

### Proof 的化简就是计算

Introduction 之后紧接着同一个 connective 的 elimination，是绕了一个弯：先造出一个 pair，马上又拆开。这样的一对可以直接消掉，叫 local reduction：

$$\mathsf{fst}\,\langle M,N\rangle\Longrightarrow M,\qquad\mathsf{snd}\,\langle M,N\rangle\Longrightarrow N,\qquad(\mathsf{fn}\,u\Rightarrow M)\,N\Longrightarrow[N/u]M$$

$[N/u]M$ 是把 $M$ 里的 $u$ 换成 $N$。在 proof 这一边，它的意思是“把假设 $u$ 的地方换成 $N$ 这个现成的 proof”；在 program 这一边，它就是调用 function。

Function composition 的 proof 是 $\mathsf{fn}\,u\Rightarrow\mathsf{fn}\,w\Rightarrow(\mathsf{snd}\,u)((\mathsf{fst}\,u)\,w)$，type 是 $((A\supset B)\land(B\supset C))\supset(A\supset C)$。把它用在两个 identity function 组成的 pair 上：

::fig[cs3234-reduce] 五步 reduction。每一步拆掉一对 introduction 和 elimination，最后得到 $\mathsf{fn}\,w\Rightarrow w$，它就是 identity，和“两个 identity 复合还是 identity”一致。

Reduction 不改变 type，所以算到最后得到的仍然是同一个 proposition 的 proof，只是不再绕弯。运行一个 program，就是把它的 proof 化简到 normal form。

:::edge 往 Coq 里加 LEM
Coq 的 logic 是 intuitionistic 的，`forall P : Prop, P \/ ~ P` 证不出来，但可以作为 `Axiom` 加进去而不导致矛盾。代价是用了它的 proof 不再能算出 witness：Axiom 没有 reduction rule，计算会卡在它上面。Software Foundations 的 Logic 一章讲到这一点。
:::

Natural deduction 的 rules 和 LEM 的 proof 见[第 1 站](#nd)。

## [coq] Coq：Gallina、specification 与 tactic

:::skip
能把一个 function 的 specification 写成 `Definition ... : Prop`，用 `unfold`、`intros`、`rewrite`、`exact` 证明某个 implementation 满足它，并能举例说明 unit test 证明不了什么，就可以去第 6 站。
:::

### Gallina：一个不会出错的 programming language

Coq 里写 program 的 language 叫 Gallina。它是 pure 的（没有 side effect：不打印、不改变量、不抛 exception）和 total 的（每个 function 都必须 terminate）。Total 是必需的：按第 4 站的对应，一个 program 就是一个 proof，一个永不返回的“proof”可以有任何 type，会证出任何东西。

Natural number 按 Peano 的方式定义，只有两个 constructor：

```coq
Inductive nat : Type :=
  O : nat
| S : nat -> nat.
```

3 写作 `S (S (S O))`。Danvy 的讲义第一周就问了这个 representation 的两个性质：用 `O` 和 `S` 造出来的每个值都表示一个 natural number（sound），每个 natural number 都能这样造出来（complete）。

Function 按 constructor 分情况写，递归调用只能作用在更小的 argument 上，这样 Coq 能自动确认它 terminate：

```coq
Fixpoint add (i j : nat) : nat :=
  match i with
    O => j
  | S i' => S (add i' j)
  end.
```

`Compute (add 2 3).` 得到 `5`。

### Unit test 能说明什么

Danvy 的讲义每写一个 function 先写 unit test，而且 test 本身是一个以“候选 function”为参数的 function：

```coq
Definition test_add (candidate : nat -> nat -> nat) : bool :=
  (Nat.eqb (candidate 0 0) 0) &&
  (Nat.eqb (candidate 0 5) 5) &&
  (Nat.eqb (candidate 2 3) 5) &&
  (Nat.eqb (candidate 7 0) 7).

Compute (test_add add).
```

这样同一组 test 可以跑在不同的 implementation 上。可是开头第一件事里那个“第一个 argument 超过 7 就返回 0”的 function 也通过这四个 test。用第 1 站的说法：test 失败一定说明 function 错了（失败是 sound 的），test 通过却不说明 function 对。要说“对所有 input 都对”，需要一个关于所有 input 的 statement，以及它的 proof。

### Specification：一个关于 function 的 Prop

“加法应该满足什么”写成一个 proposition，它的参数是一个 function：

```coq
Definition recursive_specification_of_addition (add : nat -> nat -> nat) :=
  (forall y : nat, add O y = y)
  /\
  (forall x' y : nat, add (S x') y = S (add x' y)).
```

`Prop` 是 Coq 里 proposition 的 type。按 Curry–Howard，证明 `recursive_specification_of_addition add` 就是造出一个这个 type 的 term。

写了 specification，就有三个要问的问题，每个都对应一个 theorem：

1. **有没有 function 满足它？** 证明某个 implementation 满足它。没有的话，这个 specification 是 vacuous 的。
2. **满足它的 function 是不是只有一个？** 证明任意两个满足它的 function 在所有 input 上相等。不是的话，它是 ambiguous 的。
3. **满足它的 function 对不对？** 这要拿别的已知事实去比。

### Tactic：一步一步造 proof term

直接写 proof term 很快就写不动了。Coq 里的 proof 是交互式的：屏幕上显示当前的 goal（横线下面）和可用的 hypothesis（横线上面），每个 tactic 把 goal 变成更简单的 goal，Coq 在背后拼出 proof term。

最常用的几个：

| Tactic | 对 goal 做什么 | 对应的 rule |
|---|---|---|
| `intro x` | goal 是 `forall x, P` 或 `A -> B` 时，把 `x` 或 `A` 移到 hypothesis | $\forall$i、$\to$i |
| `exact H` | hypothesis `H` 正好就是 goal，完成 | 直接引用 |
| `apply H` | `H : A -> B`、goal 是 `B` 时，goal 变成 `A` | $\to$e |
| `split` | goal 是 `A /\ B` 时，拆成两个 goal | $\land$i |
| `destruct H as [H1 H2]` | `H : A /\ B` 时，换成 `H1 : A`、`H2 : B` | $\land$e |
| `left`、`right` | goal 是 `A \/ B` 时，选一边证 | $\lor$i |
| `destruct H as [H1 \| H2]` | `H : A \/ B` 时，分两个 goal | $\lor$e |
| `exists t` | goal 是 `exists x, P` 时，给出 witness `t` | $\exists$i |
| `rewrite -> H` | `H : a = b` 时，把 goal 里的 `a` 换成 `b` | $=$e |
| `reflexivity` | goal 是 `a = a`（按定义算完后相同）时，完成 | $=$i |
| `unfold f` | 把 goal 里的 `f` 换成它的定义 | |

Resident 的 `Nat.add` 满足上面的 specification：

```coq
Theorem Nat_add_satisfies_the_recursive_specification_of_addition :
  recursive_specification_of_addition Nat.add.
Proof.
  unfold recursive_specification_of_addition.
  split.
  - intro y.
    exact (Nat.add_0_l y).
  - intros x' y.
    exact (Nat.add_succ_l x' y).
Qed.
```

`unfold` 把 goal 变成两个 `forall` 的 conjunction；`split` 拆成两个 goal；第一个 goal 是 `forall y, 0 + y = y`，`intro y` 之后正好是库里的 lemma `Nat.add_0_l y : 0 + y = y`。

:::wrong 每个 specification 都唯一地确定一个 function
Predecessor 的 specification 只写了 `forall n, pred (S n) = n`，没说 `pred 0` 是多少。定义 `make_predecessor_function zero n`：`n` 为 `O` 时返回 `zero`，为 `S n'` 时返回 `n'`。`make_predecessor_function 0` 和 `make_predecessor_function 1` 都满足 specification，在 input 0 上一个给 0、一个给 1。Danvy 的讲义用 `exists pred1 pred2, ... /\ exists n, pred1 n <> pred2 n` 把这件事证了出来。反过来，同时要求 `ps (S n) = n` 和 `ps n = S n` 的 specification 没有 function 能满足：取 $n=0$ 和 $n=1$ 得到 `ps 1 = 0` 与 `ps 1 = 2`，而 `0 <> 2`。
:::

### 在 Coq 里，logic 是 intuitionistic 的

第 4 站的对应在 Coq 里是字面意义上的。证明 `A /\ B -> B /\ A`：

```coq
Lemma and_swap : forall A B : Prop, A /\ B -> B /\ A.
Proof.
  intros A B H.
  destruct H as [HA HB].
  split.
  - exact HB.
  - exact HA.
Qed.

Print and_swap.
(* fun (A B : Prop) (H : A /\ B) =>
     match H with conj HA HB => conj HB HA end *)
```

`Print` 显示的 term 就是第 4 站的 $\mathsf{fn}\,u\Rightarrow\langle\mathsf{snd}\,u,\mathsf{fst}\,u\rangle$，只是 pair 叫 `conj`，拆 pair 用 `match`。

所以第 4 站的 $\neg\neg(A\lor\neg A)$ 在 Coq 里也能证（`~ A` 定义为 `A -> False`）：

```coq
Lemma not_not_excluded_middle : forall A : Prop, ~ ~ (A \/ ~ A).
Proof.
  intros A H.        (* H : ~ (A \/ ~ A)，goal : False *)
  apply H.           (* goal : A \/ ~ A *)
  right.             (* goal : ~ A *)
  intro a.           (* a : A，goal : False *)
  apply H.           (* goal : A \/ ~ A *)
  left.
  exact a.
Qed.
```

每一行对应那个 proof term 的一层：第一个 `apply H` 是 $u(\dots)$，`right` 是 $\mathsf{inr}$，`intro a` 是 $\mathsf{fn}\,v$，`left` 是 $\mathsf{inl}$。而 `forall A : Prop, A \/ ~ A` 用这些 tactic 证不出来。

:::back
Proof term 和 intuitionistic logic 见[第 4 站](#intu)；tactic 和 rule 的对应见[第 1 站](#nd)、[第 3 站](#pred)。
:::

Gallina 是 pure 和 total 的、Curry–Howard 是讲义的出发点，来自 [Danvy 讲义 week 01 的 Introduction and motivation](https://delimited-continuation.github.io/CS3234/2024-2025_Sem2/week-01_introduction-and-motivation.html)；Peano 数的 representation 是 sound 和 complete 的，来自 [week 04 的 Structural induction over Peano numbers](https://delimited-continuation.github.io/CS3234/2024-2025_Sem2/week-04_structural-induction-over-Peano-numbers.html)；`recursive_specification_of_addition`、`Nat.add` 满足它的 proof、ambiguous 的 predecessor specification 和 vacuous 的 predecessor-and-successor specification，来自 [week 04 的 Specifications](https://delimited-continuation.github.io/CS3234/2024-2025_Sem2/week-04_specifications.html)。以 candidate 为参数的 unit test 的写法是讲义的风格，`test_add` 的具体 test 和“超过 7 返回 0”的例子是我写的。Tactic 表按 [Software Foundations 的 Logic 一章](https://www.cs.cornell.edu/courses/cs4160/2020sp/sf/lf/terse/Logic.html)和自己的知识整理。`and_swap` 的 `Print` 输出和 `not_not_excluded_middle` 的 proof 是凭自己的知识写的，这个环境里没有 Coq，没有实际跑过。

## [ind] Peano 数上的 induction、accumulator 与 Eureka lemma

:::skip
能用 `induction n as [| n' IHn']` 证明 `add_0_r`，能看出 accumulator-based function 的直接 induction 卡在哪里并写出推广后的 Eureka lemma，就可以去第 7 站。
:::

### 按定义算不下去的地方

`add` 按第一个 argument 递归。`0 + n = n` 按定义一步就出来：`reflexivity`。可是 `n + 0 = n` 呢？`n` 是一个不知道是 `O` 还是 `S` 的 variable，`match n with` 选不了分支，`simpl` 算不动。

对 `n` 分情况（`destruct n`）：`n = O` 时 goal 是 `0 + 0 = 0`，算得出来；`n = S n'` 时 goal 是 `S n' + 0 = S n'`，算一步得 `S (n' + 0) = S n'`，又卡在 `n' + 0` 上，和原来是同一个问题。再分情况还是一样，永远分不完。

需要的是一条 rule：处理 `S n'` 的情况时，可以假定 `n'` 的情况已经成立。

### Peano 的 induction principle

定义 `nat` 时，Coq 自动生成一个 theorem：

```coq
nat_ind : forall P : nat -> Prop,
  P 0 ->
  (forall n : nat, P n -> P (S n)) ->
  forall n : nat, P n
```

这就是 Peano axioms 里的 induction axiom，在 Coq 里它是一个可以直接用的 term。`P 0` 是 base case，`forall n, P n -> P (S n)` 是 induction step，其中的 `P n` 是 induction hypothesis。它为什么对：每个 natural number 都是从 `O` 开始用 `S` 一次次造出来的，base case 给出 `P O`，step 用一次就把 `P` 沿着 `S` 往前推一格，推 $n$ 次就到达 $n$。

`induction n as [| n' IHn']` 就是 `apply nat_ind`，然后给 step 里的 variable 和 hypothesis 起名。

::fig[cs3234-goals] `add_0_r` 的 proof。左边高亮当前执行到的 tactic，右边是 Coq 显示的 proof state。

在 step 里，`simpl` 用 `add` 的第二条 equation 把 `S n' + 0` 算成 `S (n' + 0)`；这正好露出了 IHn' 的左边 `n' + 0`，`rewrite -> IHn'` 把它换成 `n'`，剩下 `S n' = S n'`。

Danvy 的讲义用同样的方法证明 specification 的唯一性。前面问的第 2 个问题，“满足 `recursive_specification_of_addition` 的 function 至多一个”：

```coq
Proposition there_is_at_most_one_recursive_addition :
  forall add1 add2 : nat -> nat -> nat,
    recursive_specification_of_addition add1 ->
    recursive_specification_of_addition add2 ->
    forall x y : nat, add1 x y = add2 x y.
Proof.
  intros add1 add2.
  unfold recursive_specification_of_addition.
  intros [H_add1_O H_add1_S] [H_add2_O H_add2_S].
  intro x.
  induction x as [ | x' IHx'].
  - intro y.
    rewrite -> (H_add2_O y).
    exact (H_add1_O y).
  - intro y.
    rewrite -> (H_add1_S x' y).
    rewrite -> (H_add2_S x' y).
    rewrite -> (IHx' y).
    reflexivity.
Qed.
```

Step 里 goal 是 `add1 (S x') y = add2 (S x') y`。两次 rewrite 把它变成 `S (add1 x' y) = S (add2 x' y)`，再用 `IHx' y` 把左边的 `add1 x' y` 换成 `add2 x' y`。

注意 `intro y` 写在 `induction` 之后。这样 `IHx'` 是 `forall y, add1 x' y = add2 x' y`，对任何 `y` 都能用。下一小节会看到这一点什么时候是关键。

### Accumulator：induction hypothesis 不够用了

另一种写加法的方式，把“还要加的 1”在调用时就加到第二个 argument 上：

```coq
Fixpoint add_acc (n a : nat) : nat :=
  match n with
    O => a
  | S n' => add_acc n' (S a)
  end.
```

第二个 argument `a` 叫 accumulator。每次递归调用都是 tail call，返回时什么也不用做。想证明 `forall n, add_acc n 0 = n`。

::fig[cs3234-tradd] 计算 `add_acc 3 0`。每一步 $n$ 减 1、accumulator 加 1，到 $n=0$ 时 accumulator 就是答案。

直接对 `n` 做 induction。Step 里 goal 是 `add_acc (S n') 0 = S n'`，按定义算一步得

```coq
add_acc n' 1 = S n'
```

而 induction hypothesis 是 `add_acc n' 0 = n'`。Goal 里 accumulator 是 1，hypothesis 里是 0，用不上。图里看得很清楚：从第二步起 accumulator 就不再是 0 了，一个只谈 accumulator 为 0 的 statement 跟不上计算。

办法是先证一个对所有 accumulator 都成立的 statement：

```coq
Lemma about_add_acc : forall n a : nat, add_acc n a = n + a.
```

对 `n` 做 induction，并且 `a` 在 induction 之后才 intro，这样 hypothesis 是 `forall a, add_acc n' a = n' + a`。Step 的 goal 是 `add_acc (S n') a = S n' + a`。左边算一步是 `add_acc n' (S a)`；用 hypothesis 时把 `a` 取成 `S a`，得 `n' + S a`。右边按 `add` 的定义是 `S (n' + a)`。剩下 `n' + S a = S (n' + a)`，是库里的 `Nat.add_succ_r`。原来的目标是 $a=0$ 的特例：`add_acc n 0 = n + 0 = n`。

Danvy 把这种为了让 induction 过得去而推广出来的 lemma 叫 Eureka lemma。讲义第八周把它写成“reset the accumulator”的统一形式：`add_acc n a = add_acc n 0 + a`，`power_acc x n a = power_acc x n 1 * a`。也就是：从任意 accumulator 开始算，等于从初始值开始算，再把 accumulator 合并进去。

:::wrong 先 `intros n a` 再 `induction n`，效果一样
`intros n a` 把 `a` 固定成一个具体的、不知道是什么的数，`induction n` 生成的 hypothesis 就是 `add_acc n' a = n' + a`，只对这一个 `a`。Step 里需要的是 `add_acc n' (S a)`，accumulator 是 `S a`，和 hypothesis 里的 `a` 不同，又卡住了。Danvy 讲义在 specification 唯一性的 proof 后面专门提醒：`intro x` 之后再在每个 case 里 `intro y`，得到的 induction hypothesis 比 `intros x y` 强。
:::

### Fold-unfold lemma

`simpl` 有时把一个递归 function 展开成一大团 `fix` 表达式，或者在不想展开的地方也展开。Danvy 的讲义改为对每个递归 function 证两条 lemma，正好是它定义里的两条 equation，以后只用 `rewrite` 来展开或收起一次调用：

```coq
Lemma fold_unfold_power_acc_O :
  forall x a : nat, power_acc x 0 a = a.

Lemma fold_unfold_power_acc_S :
  forall x n' a : nat, power_acc x (S n') a = power_acc x n' (x * a).
```

用它们证明 accumulator 版本的 power 和直接版本一致。直接版本的两条 equation 是 `power x 0 = 1`、`power x (S n') = x * power x n'`，同样各有一条 fold-unfold lemma，叫 `fold_unfold_power_O`、`fold_unfold_power_S`。`power_acc 10 3 1` 依次算成 `power_acc 10 2 10`、`power_acc 10 1 100`、`power_acc 10 0 1000`，得 1000。Eureka lemma：

```coq
Lemma power_and_power_acc_aux :
  forall x n a : nat, power x n * a = power_acc x n a.
Proof.
  intros x n.
  induction n as [ | n' IHn']; intro a.
  - rewrite -> (fold_unfold_power_O x).
    rewrite -> (fold_unfold_power_acc_O x a).
    exact (Nat.mul_1_l a).
  - rewrite -> (fold_unfold_power_S x n').
    rewrite -> (fold_unfold_power_acc_S x n' a).
    rewrite <- (IHn' (x * a)).
    rewrite -> (Nat.mul_comm x (power x n')).
    symmetry.
    exact (Nat.mul_assoc (power x n') x a).
Qed.
```

Step 里逐行看 goal：

$$\begin{aligned}
&\texttt{power x (S n') * a = power\_acc x (S n') a}\\
\to\ &\texttt{x * power x n' * a = power\_acc x n' (x * a)}&&\text{两条 fold-unfold}\\
\to\ &\texttt{x * power x n' * a = power x n' * (x * a)}&&\text{IHn' 取 }a:=x*a\text{，从右往左用}\\
\to\ &\texttt{power x n' * x * a = power x n' * (x * a)}&&\text{交换 }x\text{ 和 power x n'}
\end{aligned}$$

最后一行两边只差括号的位置，`Nat.mul_assoc` 说 $n(mp)=(nm)p$，`symmetry` 把等式两边对调，好让它和 `Nat.mul_assoc` 的方向一致。取 $a=1$，再用 `power x n * 1 = power x n`，就得到 `power x n = power_acc x n 1`。

### 一次退两步的 induction

有的 function 一次递归往回退两步，比如判断偶数：`evenp 0 = true`，`evenp 1 = false`，`evenp (S (S n'')) = evenp n''`。证明它的性质时，step 里要用的是 $n-2$ 的情况，而 `nat_ind` 只给 $n-1$ 的。需要这样一条 principle：

```coq
Lemma nat_ind2 :
  forall P : nat -> Prop,
    P 0 ->
    P 1 ->
    (forall n : nat, P n -> P (S n) -> P (S (S n))) ->
    forall n : nat, P n.
```

它不需要新的 axiom，可以由 `nat_ind` 推出来。办法和 accumulator 一样，把要证的东西推广：对 $Q(n)=P(n)\land P(n+1)$ 做普通的 induction。$Q(0)=P(0)\land P(1)$ 就是两个 base case。由 $Q(n)$ 推 $Q(n+1)=P(n+1)\land P(n+2)$：前一半已经在 $Q(n)$ 里，后一半由 step 用 $P(n)$ 和 $P(n+1)$ 推出。最后从 $Q(n)$ 取出前一半。

::fig[cs3234-ind2] 虚线框是 $Q(n)=P(n)\land P(n+1)$。框每次右移一格，新进框的那个数由框里左边的数往后跳两格得到。

:::edge Course-of-values induction
再推广一步，step 可以用所有比 $n$ 小的情况：由“对所有 $k<n$ 有 $P(k)$”推出 $P(n)$。Danvy 讲义第十一周把它叫 course-of-values induction，并要求由它推出 `nat_ind2`。证明它的办法同样是推广要证的 statement：对“$P(0)\land\dots\land P(n)$”做普通 induction。
:::

:::back
Tactic 见[第 5 站](#coq)。
:::

## [proc] Interpreter、compiler 与 commuting diagram

:::skip
能对一个 arithmetic expression 手算 interpreter 的结果和 compile 后 VM 上的 stack，写出 compiler correctness 的 statement，并说清为什么它的 lemma 要对任意 stack 成立，就可以去第 8 站。
:::

### 两条路要得到同一个答案

Danvy 那一期的 term project 是这样一个问题。一个 arithmetic expression 可以直接用 interpreter 求值；也可以先 compile 成 byte code，再在一台 stack machine（virtual machine，VM）上执行。Compiler 正确，意思是两条路得到同样的结果：

$$\texttt{interpret}\ e\ =\ \texttt{run}\ (\texttt{compile}\ e)$$

画成图，source 和 target 各在一边，两条路径在结果处汇合，这叫 commuting diagram。Unit test 只能检查有限个 $e$；要对所有 expression 都保证，就需要第 6 站的 induction，这次是对 expression 的结构做。

### Source language 和 interpreter

Expression 有三种：literal、加法、减法。

```coq
Inductive arithmetic_expression : Type :=
  Literal : nat -> arithmetic_expression
| Plus : arithmetic_expression -> arithmetic_expression
         -> arithmetic_expression
| Minus : arithmetic_expression -> arithmetic_expression
          -> arithmetic_expression.
```

Natural number 的减法可能不够减。Gallina 是 total 的，不能抛 exception，所以 interpreter 的结果要么是一个数，要么是一个 error message，error 里记下差了多少：

```coq
Inductive expressible_value : Type :=
  Expressible_nat : nat -> expressible_value
| Expressible_msg : msg -> expressible_value.
(* msg 里有 Numerical_underflow : nat -> msg *)

Fixpoint evaluate (ae : arithmetic_expression) : expressible_value :=
  match ae with
    Literal n => Expressible_nat n
  | Plus ae1 ae2 =>
      match evaluate ae1 with
        Expressible_msg s => Expressible_msg s
      | Expressible_nat n1 =>
          match evaluate ae2 with
            Expressible_msg s => Expressible_msg s
          | Expressible_nat n2 => Expressible_nat (n1 + n2)
          end
      end
  | Minus ae1 ae2 =>
      match evaluate ae1 with
        Expressible_msg s => Expressible_msg s
      | Expressible_nat n1 =>
          match evaluate ae2 with
            Expressible_msg s => Expressible_msg s
          | Expressible_nat n2 =>
              if n1 <? n2
              then Expressible_msg (Numerical_underflow (n2 - n1))
              else Expressible_nat (n1 - n2)
          end
      end
  end.
```

这个 interpreter 先算左边的 subexpression。左边出错就不再看右边。

:::wrong Evaluation order 只影响效率，不影响结果
没有 error 时确实不影响，加减法的结果和先算哪边无关。有 error 时就不同了。$e=\texttt{Minus}(\texttt{Minus}(0,1),\ \texttt{Minus}(0,2))$：左边 $0<1$，underflow 差 $1-0=1$；右边 $0<2$，underflow 差 $2-0=2$。先算左边得到 `Numerical_underflow 1`，先算右边得到 `Numerical_underflow 2`。Term project 的第一项任务就是判断给出的 specification 是 left-to-right 还是 right-to-left，并给出一个让两种 order 结果不同的 expression。
:::

### Byte code、VM 和 compiler

VM 只有三条 instruction，操作一个 natural number 的 stack：

```coq
Inductive byte_code_instruction : Type :=
  PUSH : nat -> byte_code_instruction
| ADD : byte_code_instruction
| SUB : byte_code_instruction.
```

`PUSH n` 把 `n` 压上 stack。`ADD` 弹出顶上的 $n_2$ 和下面的 $n_1$，压入 $n_1+n_2$。`SUB` 同样弹出 $n_2$、$n_1$，若 $n_1<n_2$ 就以 `Numerical_underflow (n2 - n1)` 停机，否则压入 $n_1-n_2$。Stack 上不够两个数时以 stack underflow 停机。

```coq
Fixpoint fetch_decode_execute_loop
  (bcis : list byte_code_instruction) (ds : list nat)
  : result_of_decoding_and_execution :=
  match bcis with
    nil => OK ds
  | bci :: bcis' =>
      match decode_execute bci ds with
        OK ds' => fetch_decode_execute_loop bcis' ds'
      | KO s => KO s
      end
  end.
```

`run` 从空 stack 开始执行；结束时 stack 上恰好一个数，那个数就是结果，零个或多于一个都算 error。

Compiler 按 expression 的结构翻译：literal 变成一条 `PUSH`；`Plus` 和 `Minus` 先翻译左边，再翻译右边，最后加一条 `ADD` 或 `SUB`。

```coq
Fixpoint compile_aux (ae : arithmetic_expression) : list byte_code_instruction :=
  match ae with
    Literal n => PUSH n :: nil
  | Plus ae1 ae2 => compile_aux ae1 ++ compile_aux ae2 ++ ADD :: nil
  | Minus ae1 ae2 => compile_aux ae1 ++ compile_aux ae2 ++ SUB :: nil
  end.
```

拿 $\texttt{Minus}(\texttt{Literal}\ 10,\ \texttt{Plus}(\texttt{Literal}\ 3,\ \texttt{Literal}\ 4))$ 走一遍。Interpreter：$3+4=7$，$10\ge7$，结果 $10-7=3$。Compiler 给出 `PUSH 10; PUSH 3; PUSH 4; ADD; SUB`。

::fig[cs3234-vm] 每一帧执行一条 instruction，左边高亮它来自哪个 node。`ADD` 时 stack 顶上的 3、4 正好是 `Plus` 两个 subtree 的值。

再看一个出错的例子，$\texttt{Minus}(\texttt{Literal}\ 3,\ \texttt{Literal}\ 10)$。Interpreter：$3<10$，`Numerical_underflow 7`。VM：`PUSH 3; PUSH 10; SUB`，`SUB` 时 $n_1=3<n_2=10$，以 `Numerical_underflow (10 - 3)` 即 7 停机。两边的 error 一致，这也是 commuting diagram 要求的。

### 证明：又是推广

图里有一件事是证明的关键：执行 `compile_aux e` 的那段 byte code 时，下面压着的 stack 原封不动，它只在顶上多放一个数。对 `Plus` 的右 subtree 来说，下面压着的是左 subtree 留下的值，并不是空 stack。所以要证的 lemma 必须对任意 stack `ds` 成立：

```coq
Lemma about_compile_aux :
  forall (ae : arithmetic_expression) (ds : list nat),
    (forall n, evaluate ae = Expressible_nat n ->
       fetch_decode_execute_loop (compile_aux ae) ds = OK (n :: ds))
    /\
    (forall s, evaluate ae = Expressible_msg s ->
       fetch_decode_execute_loop (compile_aux ae) ds = KO s).
```

只对空 stack 陈述，induction 到 `Plus ae1 ae2` 时，右 subtree 的 hypothesis 说的是空 stack，而它实际跑在 `n1 :: nil` 上，用不上。这和第 6 站 `add_acc` 的 accumulator 是同一件事：stack 就是 VM 的 accumulator。

对 `Plus ae1 ae2` 的情况，还需要知道“执行两段拼起来的 byte code”等于“先执行前一段，成功了再在得到的 stack 上执行后一段”：

```coq
Lemma about_fetch_decode_execute_loop_append :
  forall (bcis1 bcis2 : list byte_code_instruction) (ds : list nat),
    fetch_decode_execute_loop (bcis1 ++ bcis2) ds =
    match fetch_decode_execute_loop bcis1 ds with
      OK ds' => fetch_decode_execute_loop bcis2 ds'
    | KO s => KO s
    end.
```

它对 `bcis1` 做 induction，`ds` 同样要在 induction 之后才 intro，因为每执行一条 instruction stack 就变了。有了这两条，`Plus ae1 ae2` 且两边都成功的情况是：

$$\begin{aligned}
&\texttt{loop (c1 ++ c2 ++ [ADD]) ds}\\
=\ &\texttt{loop (c2 ++ [ADD]) (n1 :: ds)}&&\text{append lemma，再用 ae1 的 hypothesis（stack 是 ds）}\\
=\ &\texttt{loop [ADD] (n2 :: n1 :: ds)}&&\text{append lemma，再用 ae2 的 hypothesis（stack 是 n1 :: ds）}\\
=\ &\texttt{OK ((n1 + n2) :: ds)}&&\texttt{ADD}\text{ 的定义}
\end{aligned}$$

第二行用 `ae2` 的 hypothesis 时 stack 是 `n1 :: ds`，这正是 lemma 必须对任意 `ds` 成立的原因。Commuting diagram 是 `ds = nil` 的特例加上 `run` 的定义。

:::edge Accumulator 版本的 compiler
`compile_aux` 用了 `++`，每次 append 都要把左边的 list 走一遍，最坏是 quadratic 的。Term project 还要求写一个 accumulator 版本：`compile_acc ae a` 把 `ae` 的 byte code 放在 `a` 前面，只用 `::`。证明它和原来的一致，需要的 Eureka lemma 是 `compile_acc ae a = compile_aux ae ++ a`，又是第 6 站那个形状。
:::

:::back
对任意 stack 推广 lemma，和[第 6 站](#ind)对任意 accumulator 推广是同一个办法。
:::

:::from
Term project 的整体设计（arithmetic expression 有 literal、plus、minus；minus 的 numerical underflow 记下差值；VM 有 PUSH、ADD、SUB，有 stack underflow；compiler 先左后右再加 operator；commuting diagram；append 两段 byte code 的 Eureka lemma；accumulator 版本的 compiler；判断 evaluation order 并给出区分两种 order 的例子）来自 [Danvy 讲义的 Three program processors for arithmetic expressions](https://delimited-continuation.github.io/CS3234/2024-2025_Sem2/term-project_three-program-processors-for-arithmetic-expressions.html)。抓取工具只给了这一页的结构和任务清单，没有给出原文代码，所以这里的 Coq 代码是按那个设计自己写的，type 和 constructor 的名字不一定和讲义一致，也没有在 Coq 里跑过。两个数值例子、区分 evaluation order 的具体 expression、`about_compile_aux` 的 statement 和 `Plus` 情况的推导是我写的。

## [hoare] Hoare logic

:::skip
能用 assignment rule 从 postcondition 往上算，能为一个 while loop 找 invariant 并检查三条 verification condition，并分得清 partial 和 total correctness，就可以去第 9 站。
:::

### Imperative program 需要另一种 statement

第 5 到第 7 站的 program 都是 function，一个 function 的性质就是关于它的 input 和 output 的 equation。Imperative program 改的是 state：

```
X := X + Y;
Y := X - Y;
X := X - Y
```

它没有“返回值”，要说的是：运行前 state 满足什么，运行后 state 就满足什么。Hoare triple

$$\{P\}\ c\ \{Q\}$$

的意思是：从任何满足 precondition $P$ 的 state 开始运行 command $c$，如果 $c$ terminate，结束时的 state 满足 postcondition $Q$。“如果 terminate”这一条使它叫 partial correctness。上面这段程序要证的是 $\{X=m\land Y=n\}\ c\ \{X=n\land Y=m\}$：它交换 $X$ 和 $Y$。

### Assignment rule：从后往前

$$\{[X\mapsto e]Q\}\ X:=e\ \{Q\}$$

$[X\mapsto e]Q$ 是把 $Q$ 里的 $X$ 换成 $e$。想让赋值之后 $Q$ 对 $X$ 成立，赋值之前 $Q$ 就得对 $e$ 成立，因为赋值之后 $X$ 的值就是赋值之前 $e$ 的值。

例子：$\{X=5\}\ X:=X+1\ \{X=6\}$。Rule 给出的 precondition 是 $[X\mapsto X+1](X=6)$，即 $X+1=6$，它和 $X=5$ 等价。

这条 rule 只能从后往前用：知道 $Q$ 和 $e$，算出 precondition。从前往后（已知 $X=5$，赋值后 $X$ 是多少）反而要引入旧值的名字，麻烦得多。

其余的 rules：

- **Sequence**：由 $\{P\}\ c_1\ \{R\}$ 和 $\{R\}\ c_2\ \{Q\}$ 得 $\{P\}\ c_1;c_2\ \{Q\}$。
- **Consequence**：若 $P\to P'$、$\{P'\}\ c\ \{Q'\}$、$Q'\to Q$，则 $\{P\}\ c\ \{Q\}$。Precondition 可以加强，postcondition 可以减弱。
- **If**：由 $\{P\land b\}\ c_1\ \{Q\}$ 和 $\{P\land\neg b\}\ c_2\ \{Q\}$ 得 $\{P\}\ \texttt{if}\ b\ \texttt{then}\ c_1\ \texttt{else}\ c_2\ \{Q\}$。
- **Skip**：$\{P\}\ \texttt{skip}\ \{P\}$。

把 assignment 和 sequence 连起来用，从 postcondition 一条一条往上推，每一行写出当时成立的 assertion，这叫 decorated program。

::fig[cs3234-swap] 交换程序的 decorated program。从最下面的 postcondition 开始，每过一条 assignment 就把被赋值的 variable 换成右边的 expression。

推到最上面得到 $(X+Y)-((X+Y)-Y)=n\land(X+Y)-Y=m$。逐项化简：$(X+Y)-Y=X$，所以第二项是 $X=m$；$(X+Y)-X=Y$，所以第一项是 $Y=n$。它和 precondition $X=m\land Y=n$ 一样，consequence rule 把两者接上。

### While loop 和 invariant

Loop 执行多少次事先不知道，不能一条条往上推。要找一个 assertion $I$，每执行一次 body 都保持它：

$$\frac{\{I\land b\}\ c\ \{I\}}{\{I\}\ \texttt{while}\ b\ \texttt{do}\ c\ \texttt{end}\ \{I\land\neg b\}}$$

$I$ 叫 loop invariant。Rule 对不对很好看：进入 loop 时 $I$ 成立；每次进 body 时 guard $b$ 也成立，premise 保证 body 结束时 $I$ 仍成立；loop 退出时 $b$ 不成立而 $I$ 成立。

例子，slow subtraction：

```
{ X = m ∧ Y = n }
while X ≠ 0 do
  Y := Y - 1;
  X := X - 1
end
{ Y = n - m }
```

每轮 $X$ 和 $Y$ 各减 1，所以它们的差不变：invariant 取 $Y-X=n-m$。

::fig[cs3234-inv] $m=3$、$n=5$ 时的执行。$X$ 和 $Y$ 每轮各减 1，$Y-X$ 一直是 2；$X$ 到 0 时退出，$Y$ 就是 $n-m$。

一个 invariant 要满足三条 verification condition，逐条检查：

1. **进入时成立**：$X=m\land Y=n\to Y-X=n-m$。代进去就是 $n-m=n-m$。
2. **Body 保持它**：用 assignment rule 从 body 末尾的 $Y-X=n-m$ 往上推。过 $X:=X-1$ 得 $Y-(X-1)=n-m$；过 $Y:=Y-1$ 得 $(Y-1)-(X-1)=n-m$。要检查的是 $Y-X=n-m\land X\ne0\to(Y-1)-(X-1)=n-m$，而 $(Y-1)-(X-1)=Y-X$。
3. **退出时推出 postcondition**：$Y-X=n-m\land X=0\to Y=n-m$。把 $X=0$ 代进去，$Y-0=Y$。

:::wrong Invariant 只要在 loop 里一直成立就行
$X\ge0$ 在这个 loop 里一直成立，第 1、2 条都过得去。但第 3 条变成 $X\ge0\land X=0\to Y=n-m$，左边对 $Y$ 只字未提，推不出来。反过来，$Y=n-m$ 本身太强：$m=3$、$n=5$ 时进入 loop 前 $Y=5\ne2$，第 1 条就不成立。Invariant 要弱到进入时成立，又要强到退出时（配上 $\neg b$）能推出 postcondition，同时被 body 保持。找 invariant 的办法通常是看 loop 每轮在“哪个量不变”，这里是 $Y-X$。
:::

:::edge Natural number 的减法
Software Foundations 里 $X$、$Y$ 都是 natural number，减法不够减时得 0。第 2 条在 $Y=0$ 时也成立吗？$X\ge1$、$Y=0$ 时，$(0-1)-(X-1)=0-(X-1)=0$，而 $Y-X=0-X=0$，两边相等。所以 invariant 照样成立，最后得到的是截断后的 $n-m$：$n<m$ 时 $Y=0$。
:::

### Total correctness：loop 会不会停

Partial correctness 对不 terminate 的程序什么也不要求。

```
y := 1; z := 0;
while z ≠ x do
  z := z + 1;
  y := y * z
end
```

Invariant $y=z!$：开始时 $1=0!$；body 把 $z$ 加 1 再乘到 $y$ 上，$y=z!$ 变成 $y\cdot(z+1)=(z+1)!$。退出时 $z=x$，所以 $y=x!$。可是 $x=-1$ 时 $z$ 从 0 往上加，永远碰不到 $-1$，loop 不停。$\{\top\}\ c\ \{z=x\}$ 作为 partial correctness 仍然成立，因为不停的那些 run 不算数。

Total correctness 记作 $[P]\ c\ [Q]$，额外要求一定 terminate。While rule 里多一个 variant $t$：一个取 natural number 值的 expression，每轮严格变小。

$$\frac{[I\land b\land t=k]\ c\ [I\land t<k]}{[I]\ \texttt{while}\ b\ \texttt{do}\ c\ \texttt{end}\ [I\land\neg b]}$$

Natural number 不能无限变小，所以 loop 必停。Factorial 程序在 precondition $x\ge0$ 下取 $t=x-z$，invariant 里加上 $z\le x$：每轮 $z$ 加 1，$t$ 减 1，且 $z\le x$ 保证 $t\ge0$。Slow subtraction 取 $t=X$。

:::back
Assertion 是[第 3 站](#pred)的 predicate logic formula；verification condition 就是普通的 implication，可以交给第 5 站的 Coq 去证。
:::

:::from
Hoare triple 的 partial 与 total 的定义、所有 proof rules（含带 termination measure 的 total while rule）、$\{X=5\}X:=X+1\{X=6\}$ 的例子和 factorial 程序（invariant $y=z!$），来自 [Henz、Hobor 的 Hoare Logic 讲义](https://www.comp.nus.edu.sg/~cs3234/notes/Hoare.pdf)。交换程序的 decorated program 来自 [Software Foundations PLF 的 Hoare2 一章](https://softwarefoundations.cis.upenn.edu/plf-current/Hoare2.html)（读了前 100000 个字符）；slow subtraction 的 invariant、三条 verification condition 和 invariant 必须满足的三个条件来自同一章的 [Cornell CS4160 terse 版](https://www.cs.cornell.edu/courses/cs4160/2020sp/sf/plf/terse/Hoare2.html)。Natural number 减法的边界检查、$X\ge0$ 与 $Y=n-m$ 两个失败的 invariant、$x=-1$ 时 factorial 程序不停、factorial 和 slow subtraction 的 variant 是我补的。

## [prolog] Prolog：unification 与 search

:::skip
能读懂一个 Prolog 程序、手算 unification、画出 query 的 search tree 并标出 backtracking，能解释为什么换了 clause 顺序程序就不 terminate，就可以结束。
:::

### Program 就是一组 Horn clause

Prolog 程序由 fact 和 rule 组成：

```prolog
f(a).  f(b).
g(a).  g(b).
h(b).
k(X) :- f(X), g(X), h(X).
```

`k(X) :- f(X), g(X), h(X).` 读作 $\forall X\,(f(X)\land g(X)\land h(X)\to k(X))$，写成 clause 是 $\{\neg f(X),\neg g(X),\neg h(X),k(X)\}$，只有一个 positive literal，正是第 2 站的 Horn clause。Fact 是没有 body 的 rule。

Query `?- k(Y).` 问的是 $\exists Y\,k(Y)$ 能不能由程序推出，能的话 $Y$ 是什么。按第 2 站的办法，把 goal 取 negation 加进 clause set（$\{\neg k(Y)\}$），用 resolution 推出 empty clause；推的过程中对 $Y$ 做的替换就是答案。Prolog 的执行就是一种固定了顺序的 resolution。

### Unification

Resolution 要消掉 $k(Y)$ 和 $\neg k(X)$，它们不是同一个 literal，要先找一个替换让两边一样，这叫 unification。规则：

1. 两个 constant 相同才 unify。
2. 一个 variable 和任何 term unify，把 variable 换成那个 term。
3. 两个 compound term 要 functor 和 argument 个数都相同，然后逐个 argument unify，而且各处得到的替换要相容。

例子：`k(s(g), Y) = k(X, t(k))` 得 `X = s(g)`、`Y = t(k)`。`loves(X, X) = loves(marsellus, mia)` 失败：第一个 argument 给出 `X = marsellus`，第二个 argument 就要求 `marsellus = mia`。

一个要把替换带下去的例子：

::fig[cs3234-unify] 两个 term 画成 tree。Root 相同，两个 $X$ 分别对上两个 $g$ 的 subtree；第一个对上之后 $X$ 被替换，第二个对齐就变成两个 $g$ 之间的比较。

得到的替换 $X=g(a,a)$、$Y=a$ 是 most general unifier：任何能让两边相等的替换，都是先做它、再做别的替换得到的。

:::edge Occurs check
`father(X) = X` 没有有限的解：$X$ 要等于一个包含 $X$ 的 term。标准的 unification algorithm 在把 variable 换成 term 之前检查这个 variable 是否出现在 term 里，叫 occurs check。多数 Prolog 为了速度默认不做，SWI-Prolog 会回答 `X = father(father(father(...)))`；要做检查用 `unify_with_occurs_check(father(X), X)`，它回答 false。
:::

### Search：从上到下，从左到右，失败就回头

一个 goal 可能和好几个 clause 的 head unify。Prolog 的选择是固定的：clause 按程序里从上到下的顺序试；rule body 里的 goal 从左到右解；一条路失败了，回到最近一个还有别的 clause 可试的地方（choice point），撤销那之后做的替换，试下一个。这叫 backtracking。

::fig[cs3234-sld] `?- k(Y).` 的 search tree。先试 $V=a$，到 `h(a)` 没有 clause 可用，回到 `f` 的 choice point 改试 $V=b$。

第一步把 rule 里的 `X` 改名为一个新的 variable `V`，因为每次使用 rule 都要用一份全新的 variable，否则不同次调用之间的 `X` 会互相干扰。`h(a)` 失败时，最近的 choice point 是 `f(V)`（还有 `f(b)` 没试）；`g(a)` 那里只有一个 clause 可用，不是 choice point。

### 逻辑相同，执行不同

```prolog
child(martha, charlotte).
child(charlotte, caroline).
child(caroline, laura).
child(laura, rose).

descend(X, Y) :- child(X, Y).
descend(X, Y) :- child(X, Z), descend(Z, Y).
```

问 `?- descend(martha, rose).`：第一条 rule 要 `child(martha, rose)`，失败；第二条 rule 先找 `child(martha, Z)`，得 `Z = charlotte`，再问 `descend(charlotte, rose)`，一路往下，到 `child(laura, rose)` 成功。

把两条 rule 的顺序对调，并把第二条 rule 的 body 里两个 goal 对调：

```prolog
descend(X, Y) :- descend(Z, Y), child(X, Z).
descend(X, Y) :- child(X, Y).
```

作为 logic，这两个程序是同一组 formula（conjunction 和 clause 的顺序都不影响真假）。作为 program，第二个不 terminate。

::fig[cs3234-descend] 左边先查 `child` 再递归，每一步都离 rose 近一代；右边最左边的 goal 永远是一个新的 `descend(W, rose)`，第二条 rule 永远轮不到。

:::wrong 只要每条 rule 在逻辑上都对，Prolog 就能找到答案
右边那个程序的每条 rule 都是对“descendant”的正确描述，`descend(martha, rose)` 也确实是它的 logical consequence。可 Prolog 总是先试第一条 rule、先解最左边的 goal，而那个 goal 和 head 形状一样、argument 没有变小：`descend(martha, rose)` 变成 `descend(W1, rose), child(martha, W1)`，`descend(W1, rose)` 又变成 `descend(W2, rose), child(W1, W2)`，每一步都多一个 goal，最后 out of stack。Prolog 的 search 是 depth-first 的，它对 logical consequence 不 complete；写程序时要同时考虑 declarative meaning（它说了什么）和 procedural meaning（它按什么顺序找）。
:::
