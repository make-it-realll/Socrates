先看三次失败。每一次，前一步都做对了。

**第一次。** 在 grid 上用 A* 找到了最短 path，交给一辆 car 去开。Path 在 corner 处要求原地转 90°，而 car 的 turning radius 是 1.5 个 cell。它只能沿一条 arc 转过去，切进旁边的 cell，那里可能就是 wall。

**第二次。** Path 对了，car 也开得了。Robot 按 wheel 转过的圈数算出自己走了 20 m，该在 door 前面了，于是左转。Wheel 的 radius 实际比标称的小 3%，robot 其实只走了 19.4 m，差 0.6 m，比半个 door（0.9 m 宽）还多，左转直接撞到 wall。

**第三次。** 两个 robot 各自在同一张 map 上 plan，各自的 path 都是最短的。两条 path 在 $t=2$ 同时经过路口中心。

::fig[rb3302-intro] 三次失败各自的样子。① 粗线是 A* 的 path，虚线是 car 实际能走的 arc；② 空心圆是 robot 以为的位置，实心圆是真实位置；③ 两个 robot 下一步同时进入中心那个 cell。

## [search] Grid、graph search 与 heuristic search

:::skip
能在 8-connected grid 上写出 octile heuristic 并证明它 consistent，能说出 weighted A* 的 bound 怎么来的、它为什么不一定更快，就可以去第 2 站。

### 从 map 到 graph

Planner 不能直接在一张 map 上 search，先要把它变成 graph：node 是什么，edge 连哪两个 node，edge 的 cost 是多少。最直接的办法是 occupancy grid：把 plane 切成 cell，被 obstacle 碰到的 cell 标成 occupied，剩下的 cell 当 node。Robot 有大小时先把 obstacle 向外长一个 robot radius，robot 就缩成一个点（[NW-MODERNROBOTICS 第 7 站](../courses/NW-MODERNROBOTICS.html#plan)）。

Edge 怎么连，决定了 path 能长什么样。只连上下左右（4-connected），从 (0, 0) 到 (5, 3) 的最短 path 是 $5+3=8$；再加上四个 diagonal（8-connected，diagonal 的 cost 是 $\sqrt2$），先斜走 3 步再直走 2 步，cost 是 $3\sqrt2+2=6.243$；真正的直线距离是 $\sqrt{34}=5.831$。Edge 越多，graph 上的最短 path 越接近 plane 上的最短 path，但每个 node 要检查的 successor 也越多。这页都用 8-connected，并且规定 diagonal 两侧的两个 cell 都 free 才能斜着走，否则 robot 会从两个 obstacle 的 corner 之间挤过去。8-connected 的 path 方向只能是 45° 的倍数；16-782 的 slides 再加上“邻居的邻居”，得到 16-connected grid，多出 26.6° 和 63.4° 这些方向（$\arctan\tfrac12=26.6^\circ$），代价是每个 node 的 successor 从 8 个变成 16 个。

Graph 不一定要先建好。16-782 区分两种：explicit graph 在 search 之前整个存进 memory，2D 的 grid 用一个二维 array 就行；implicit graph 只提供两个 function，GetSuccessors$(s)$ 和 ComputeEdgeCost$(s,s')$，search 走到哪里才生成到哪里。第 3 站的 $(x,y,\theta)$ 和更高维的问题都只能用 implicit graph：16-782 的例子是非圆形的 robot，C-space 是 $(x,y,\theta)$，先把 robot 当成点，只对 search 真正 expand 到的 $(x,y,\theta)$ 才去算这个 pose 是否碰撞。

这一步就是大纲里的 motion representation：graph 的 edge 代表 robot 一步能做的动作。Grid 的 edge 假设 robot 能朝八个方向直接走，第 3 站会换成 car 真正能做的动作。

### Dijkstra 的力气花在哪里

Map M 上，Dijkstra（也就是 $h=0$ 的 A*）按 $g$ 从小到大 expand：先 expand 离 start 近的 cell，一圈一圈往外推，直到 pop 出 goal。它 expand 了 321 个 cell，几乎是全部 354 个 free cell，其中大半在 start 的左边，离 goal 越来越远。

A* 改按 $f=g+h$ 排序，$h(s)$ 是对 $s$ 到 goal 的 cost 的估计。CMU 16-782 的说法是：$f(s)$ 估计的是“从 start 出发、经过 $s$、到达 goal 的最好 path 的 cost”，所以 A* 先 expand 的是看起来在好 path 上的 cell。

::fig[rb3302-astar] 两边同时开始，每 0.03 s expand 一个 cell。Dijkstra 向四面八方推开；A* 一路朝右，钻进 U 形口里，撞到底再绕出去。两边最后的 path cost 一样。

A* 只 expand 了 117 个 cell，path cost 和 Dijkstra 一样是 22.14。它也在 U 形里浪费了不少：heuristic 不知道有 wall，口里的 cell 看起来离 goal 很近。

### Octile heuristic，以及它为什么是 consistent 的

8-connected grid 上没有 obstacle 时，从 $(x_1,y_1)$ 到 $(x_2,y_2)$ 的最短 path cost 是多少？设 $\Delta x=|x_1-x_2|$、$\Delta y=|y_1-y_2|$。每一步 diagonal 同时减少一个 $\Delta x$ 和一个 $\Delta y$，cost $\sqrt2$，比分开走两步省 $2-\sqrt2$。所以先走 $\min(\Delta x,\Delta y)$ 步 diagonal，再沿剩下的方向走 $\max-\min$ 步：

$$h_{\text{oct}}=\sqrt2\,\min(\Delta x,\Delta y)+\big(\max(\Delta x,\Delta y)-\min(\Delta x,\Delta y)\big)=\max(\Delta x,\Delta y)+(\sqrt2-1)\min(\Delta x,\Delta y)$$

这叫 octile distance。上面 (0, 0) 到 (5, 3) 的例子：$5+0.414\times3=6.243$，和数出来的一样。

A* 要 pop 出 goal 就停，需要 $h$ consistent：$h(\text{goal})=0$，并且对每条 edge $s\to s'$，

$$h(s)\le c(s,s')+h(s')$$

Octile 满足它，理由只有一句话：$h_{\text{oct}}(s)$ 是空 grid 上 $s$ 到 goal 的最短 path cost，而“先走 $s\to s'$ 再从 $s'$ 走最短 path”是空 grid 上从 $s$ 出发的一条 path，最短的那条不会比它长。有 obstacle 的 grid 只是删掉一些 edge，最短 path 只会更长，所以 $h_{\text{oct}}$ 也不会超过真实的 cost-to-goal，也就是 admissible。

检验一次。$s=(3,7)$，goal $(21,7)$，$h=18$。沿 diagonal 走到 $s'=(4,6)$：$h(s')=\max(17,1)+0.414\times1=17.414$，$c+h(s')=1.414+17.414=18.83\ge18$。沿 x 走到 $(4,7)$：$1+17=18\ge18$，取等号，这一步正好在空 grid 的最短 path 上。

:::wrong Euclidean distance 是真正的直线距离，所以它是最好的 heuristic
它 admissible，但在 8-connected grid 上，robot 根本走不出直线，真实 cost 至少是 octile distance。两个都 admissible 的 heuristic，处处更大的那个更好：A* 一定会 expand 所有 $f<C^*$ 的 node，$h$ 越大，满足 $g+h<C^*$ 的 node 越少。$\Delta x=4$、$\Delta y=2$ 时 Euclidean 是 $\sqrt{20}=4.47$，octile 是 $4+0.83=4.83$。在 Map M 上，Euclidean 让 A* expand 了 133 个 cell，octile 是 117 个，path cost 都是 22.14。
:::

### Weighted A*：用 optimality 换速度

把 heuristic 放大 $\varepsilon>1$ 倍，按 $f=g+\varepsilon h$ 排序，search 会更急着往 goal 走。代价是 path 不一定最短，但能说清最多差多少：

$$\text{cost(solution)}\le\varepsilon\cdot C^*$$

16-782 的 slides 只给了结论，并分成两个版本：允许 re-expansion（没有 CLOSED list，一个 state 的 $g$ 变小了就重新放回 OPEN）的版本来自 Pohl 1970；不 re-expand（有 CLOSED list，每个 state 最多 expand 一次）的版本来自 Likhachev 等人 2004，两者的 bound 一样。下面是允许 re-expansion 的版本的证明。设 goal 在被 pop 出来时 $g(\text{goal})=G$。那一刻，optimal path 上一定有一个 node $s'$ 还在 OPEN 里，而且它前面的 node 都已经用 optimal 的 $g$ expand 过，所以 $g(s')=g^*(s')$（这是 A* 证明里的同一个论证，见 [CS2109S 第 2 站](../courses/CS2109S.html#astar)）。Goal 先于 $s'$ 被 pop，说明

$$G=g(\text{goal})+\varepsilon\,h(\text{goal})\le g(s')+\varepsilon\,h(s')$$

右边用 $g(s')=g^*(s')$ 和 $h$ admissible（$h(s')\le C^*-g^*(s')$）：

$$g^*(s')+\varepsilon\,h(s')\le g^*(s')+\varepsilon\,(C^*-g^*(s'))=\varepsilon C^*-(\varepsilon-1)\,g^*(s')\le\varepsilon C^*$$

最后一步用了 $\varepsilon>1$、$g^*\ge0$。不 re-expand 的版本证明更难：$s'$ 前面的 node 可能在 $g$ 还不 optimal 时就进了 CLOSED，上面“$g(s')=g^*(s')$”那一步不再直接成立。那个证明没有读到。

Map M 上实际跑一遍：

| $\varepsilon$ | expand 的 cell | path cost | bound $\varepsilon\times22.14$ |
|---|---|---|---|
| 1 | 117 | 22.14 | 22.14 |
| 1.5 | 95 | 22.14 | 33.21 |
| 2 | 90 | 22.14 | 44.28 |
| 5 | 82 | 24.49 | 110.71 |

$\varepsilon=5$ 时 path 长了 10.6%，远在 bound 之内。Bound 是最坏情况，实际差得少得多；这是 weighted A* 在 robot 上常用的原因。

:::edge ε 越大不一定 expand 得越少
16-782 的 slides 把“weighted A* 是否保证比 A* expand 得少”留成问题，没有回答。在 Map M 上把 start 换到 (2, 0)（左上角），A* expand 54 个 cell，cost 21.90；$\varepsilon=2$ expand 74 个，cost 23.56；$\varepsilon=5$ expand 76 个，cost 也是 23.56。放大的 heuristic 把 search 更深地推进 U 形口里，在那里绕的冤枉路比省下的多。Slides 的说法是：要让 weighted A* 快，function $h(s)-h^*(s)$ 的 local minimum 要浅。$h\le h^*$，所以 $h-h^*\le0$；U 形口里的 cell 离 goal 的直线距离很近（$h$ 小），真实 cost 却要绕出去（$h^*$ 大），$h-h^*$ 在那里是一个很深的坑。至于 weighted A* 具体会 expand 哪些 state，slides 写的是“No one knows”，还是研究问题。
:::

### 什么时候 grid 不够用

Grid 的 cell 数随 dimension 指数增长。2D 的 Map M 只有 375 个 cell；7-dof arm 每个 joint 取 2° 一格，是 $180^7=6.1\times10^{15}$ 个 cell。Heuristic 只能少 expand 一些，改变不了 graph 本身太大这件事，所以高维的 C-space 要换成第 2 站的 sampling。

A* 的基本做法、admissible 的证明来自 [CS2109S 第 2 站](../courses/CS2109S.html#astar)；obstacle 向外长 robot radius、grid 的 resolution completeness 来自 [NW-MODERNROBOTICS 第 7 站](../courses/NW-MODERNROBOTICS.html#plan)。
:::

## [sample] Sampling-based planning：RRT*、asymptotic optimality 与高维

:::skip
能说清 RRT 为什么停在第一条 path、RRT* 的 choose parent 和 rewire 各改了什么，能估算 narrow passage 在高维需要多少 sample，就可以去第 3 站。
:::

### RRT 找到的 path 不再变好

RRT 的步骤在 [NW-MODERNROBOTICS 第 7 站](../courses/NW-MODERNROBOTICS.html#plan)手算过：sample、找最近的 node、朝它走一步、不碰就加进 tree。这里看它在一个简单的问题上跑久了会怎样。

$[0,10]^2$ 里有一个 rectangle obstacle $[3,7]\times[2,8]$，start (1, 5)，goal (9, 5)，step size 0.8，离 goal 0.5 以内算到达。最短 path 从 obstacle 的上角或下角擦过去：

$$2\sqrt{2^2+3^2}+4=2\times3.606+4=11.21$$

RRT 在第 123 个 sample 时第一次到达 goal，path cost 13.48。之后一直跑到第 1000 个 sample，cost 还是 13.48。

原因在 tree 的结构里。一个 node 加进 tree 时就定下了 parent，以后再也不改；从 start 到它的 path 因此永远是加入那一刻的那条。后来的 sample 只能在 tree 的边上接新枝，改不了已经在 tree 里的 path。只有当一根全新的枝从别处长到 goal、而且恰好更短时，cost 才会下降。16-782 的 slides 把这一点列为 RRT 的缺点：solution 可能很差，要靠 post-processing 改善，而 post-processing 之后 path 仍然在原来那个 homotopy class 里（绕上面还是绕下面，一开始就定了）。

### RRT*：choose parent 与 rewire

RRT* 在每加一个 node $x$ 时多做两件事，范围是 $x$ 周围 radius $r$ 内的 node（neighborhood）：

1. **Choose parent。** 不直接用最近的 node 当 parent，而是在 neighborhood 里挑让 $x$ 的 cost 最小、而且连过去不碰的那个：$\text{parent}(x)=\arg\min_{y}\big(c(y)+\|y-x\|\big)$。
2. **Rewire。** 对 neighborhood 里的每个 node $y$，如果改经 $x$ 走更短，即 $c(x)+\|x-y\|<c(y)$，而且这段不碰，就把 $y$ 的 parent 改成 $x$。$y$ 下面整棵 subtree 的 cost 跟着减少同样的量。

手算一次。Tree 里有四个 node：S (0, 0) 是 start；A (2, 0)，parent S，$c=2$；B (2, 2)，parent A，$c=4$；C (4, 2)，parent B，$c=6$。新 node $x=(2.6,1.6)$，$r=2$。先算 $x$ 到各点的距离：

$$\|x-B\|=\sqrt{0.6^2+0.4^2}=0.721,\quad\|x-A\|=\sqrt{0.6^2+1.6^2}=1.709,\quad\|x-C\|=\sqrt{1.4^2+0.4^2}=1.456,\quad\|x-S\|=3.053$$

S 在 neighborhood 外。最近的是 B，RRT 会让 B 当 parent，$c(x)=4+0.721=4.721$。RRT* 比较三个候选：经 A 是 $2+1.709=3.709$，经 B 是 4.721，经 C 是 $6+1.456=7.456$，选 A，$c(x)=3.709$。

然后 rewire。C：$3.709+1.456=5.165<6$，改以 $x$ 为 parent。B：$3.709+0.721=4.430>4$，不动。

::fig[rb3302-rewire] 左边选 parent：最近的 B 不是最好的 parent。右边 rewire：C 从“S→A→B→C”改成“S→A→x→C”，cost 从 6 降到 5.17。

Rewire 正是 RRT 缺的那一步：已经在 tree 里的 node 的 path 可以被后来的 node 改短。

::fig[rb3302-rrtstar] 同一串 random sample 下两棵 tree 的生长（第一帧是 $n=1000$ 的结果）。左边 RRT 的 tree 是一根根往外伸的枝，path 找到后不再变（虚线是下面 short-cutting 的结果）；右边 RRT* 的 edge 越来越像从 start 放射出去的直线，path 慢慢贴向 obstacle 的角。

| sample 数 $n$ | 150 | 300 | 600 | 1000 |
|---|---|---|---|---|
| RRT 的 path cost | 13.48 | 13.48 | 13.48 | 13.48 |
| RRT* 的 path cost | 13.03 | 12.75 | 11.96 | 11.67 |

RRT* 是 asymptotically optimal 的：$n\to\infty$ 时 path cost 以 probability 1 converge 到 optimal 的 11.21。代价是每加一个 node 都要对整个 neighborhood 做 collision check，16-782 的 slides 指出它通常比 RRT 慢。

### Neighborhood 为什么要随 $n$ 缩小

Radius $r$ 取固定值会怎样？$r$ 太小，neighborhood 里经常只有一两个 node，rewire 起不了作用；$r$ 太大，比如盖住整个 space，每加一个 node 都要检查所有 node，加 $n$ 个 node 就是 $n^2$ 次 collision check。想要的是 neighborhood 里的 node 数大约按 $\log n$ 增长：$d$ 维 space 里 node 的密度和 $n$ 成正比，radius $r$ 的球里平均有 $n\,r^d$ 量级个 node，令它等于 $\log n$，得到 $r\propto(\log n/n)^{1/d}$。Karaman 与 Frazzoli 给 RRG 的 Near 取的 radius 是（RRT* 用同样形式的 radius）

$$r_n=\min\left\{\gamma\left(\frac{\log n}{n}\right)^{1/d},\ \eta\right\},\qquad \gamma>2\left(1+\frac1d\right)^{1/d}\left(\frac{\mu(\mathcal X_{\text{free}})}{\zeta_d}\right)^{1/d}$$

$n$ 是 tree 里的 node 数，$\eta$ 是 step size，$\mu(\mathcal X_{\text{free}})$ 是 free space 的体积（Lebesgue measure），$\zeta_d$ 是 $d$ 维 unit ball 的体积。$\gamma$ 大于右边这个常数时，path cost 以 probability 1 converge 到 optimal。

代进上面的例子：$d=2$，$\zeta_2=\pi$，free space 是 $100-4\times6=76$，

$$2\left(1+\tfrac12\right)^{1/2}\left(\frac{76}{\pi}\right)^{1/2}=2\times1.225\times4.918=12.05$$

所以这一页取 $\gamma=13$。$n=1000$ 时 $13\sqrt{\ln1000/1000}=13\times0.0831=1.08$，仍比 step size 0.8 大；$n$ 更小时 radius 更大。所以这一整次 run 实际用的都是 $r=\eta=0.8$，$\log n$ 那一项要到 $n$ 大约 2000 以上才开始起作用。

:::wrong RRT 跑得越久，path 越好
上面的表就是反例：从第 123 个 sample 到第 1000 个，RRT 的 cost 一点没变。跑得久只让 tree 覆盖得更满（probabilistically complete 说的是这个），path 的质量不会因此变好。这不只是这一次 run 的运气：Karaman 与 Frazzoli 证明，在温和的条件下，RRT 返回的 cost 以 probability 1 converge 到一个不 optimal 的值。要更好的 path，要么用 RRT* 这类 asymptotically optimal 的 planner，要么事后做 post-processing（下一小节和第 4 站）。
:::

### Short-cutting：最简单的 post-processing

16-782 要求会写的 post-processing 是 short-cutting。Path 是一串点 $P_0,P_1,\dots,P_m$。从 $P_0$ 出发，往后找最远的一个点 $P_j$，使 $P_0$ 到 $P_j$ 的线段不碰 obstacle，把 $P_0P_j$ 放进新的 path；再从 $P_j$ 出发做同样的事，直到 goal。每一步只做 segment 的 collision check，不需要 search。

把它用在上面 RRT 的 path 上。这条 path 有 20 个点（start、18 个 tree node、goal），cost 13.48。从 start (1, 5) 往后，最远能直接连到的是 (2.80, 1.27)；从那里能一直连到 (7.41, 1.53)；再连到 goal。新的 path 只剩 4 个点：

$$\|(1,5)-(2.80,1.27)\|+\|(2.80,1.27)-(7.41,1.53)\|+\|(7.41,1.53)-(9,5)\|=12.58$$

比 13.48 短了 0.90，但离 optimal 的 11.21 还差 1.37。差在两处：新 path 的点只能从原 path 的点里挑，挑不到 obstacle 的角 (3, 2) 和 (7, 2)；path 仍然从 obstacle 下面绕，homotopy class 没有变。在这个对称的例子里下面和上面一样短，换一个 obstacle 位置，RRT 一开始选错了一侧，short-cutting 也救不回来。

### 高维：narrow passage

Sampling 不铺满整个 space，所以不怕 dimension 高。但它怕窄的通道。设 C-space 是 $[0,1]^d$，有一条贯穿的 passage，在其余 $d-1$ 个方向上宽度都是 $w=0.05$。一个 uniform sample 落进 passage 的 probability 是它的体积：

$$w^{d-1}=0.05^{d-1}$$

$d=2$ 时是 0.05，平均 20 个 sample 就有一个落进去；$d=6$ 时是 $0.05^5=3.1\times10^{-7}$，平均要 320 万个 sample 才落进去一个，而且要连通一条 path 往往要在 passage 里有好几个 node。Robot arm 伸进一个窄柜子就是这种情形。

RRT 的每一步只走 step size 那么远，从两边各长一棵 tree 能少走一半。16-782 讲的 RRT-Connect 就是这样：从 start 和 goal 各长一棵 tree，一棵 tree 加了新 node $q_{\text{new}}$ 后，另一棵 tree 不只走一步，而是朝 $q_{\text{new}}$ 一直走（CONNECT），直到连上或碰到 obstacle，然后两棵 tree 交换角色。它在 $\mathcal C_{\text{free}}$ connected、bounded、open 的假设下 probabilistically complete，但和 RRT 一样不是 asymptotically optimal。

:::edge PRM 和 RRT 选哪个
PRM 先建一张 roadmap 再查询（[NW-MODERNROBOTICS 第 7 站](../courses/NW-MODERNROBOTICS.html#plan)），roadmap 建一次能回答很多次查询，适合 map 不变、要反复 plan 的情形，比如同一个 workcell 里的 arm。RRT 从 start 长、长到 goal 就停，适合每次 start 不同、只查一次的情形，比如 mobile robot 每走一段就要重新 plan。PRM 也有对应的 PRM*，Karaman 与 Frazzoli 给它的连接 radius 是 $\gamma_{\text{PRM}}(\log n/n)^{1/d}$，$\gamma_{\text{PRM}}$ 的门槛和上面 RRG 的完全一样。
:::

:::back
RRT、PRM 的步骤，segment 与 obstacle 的 collision check 来自 [NW-MODERNROBOTICS 第 7 站](../courses/NW-MODERNROBOTICS.html#plan)；高维 grid 的 cell 数来自[第 1 站](#search)。
:::

:::from
EXTEND、goal bias、RRT 的 solution 可能很差、RRT-Connect 的 CONNECT 与 probabilistic completeness 的条件、RRT* 是 RRT 加 rewire、asymptotically optimal 但更慢，short-cutting 的算法、post-processing 后仍在原来的 homotopy class，来自 [CMU 16-782 的 RRT 一讲](https://www.cs.cmu.edu/~maxim/classes/robotplanning_grad/lectures/RRT_16782_fall26.pdf)（逐页转述）。Slides 没有写 radius 的 formula；radius 的 formula、$\gamma$ 的条件、PRM* 的 radius 和“RRT 的 cost 几乎必然 converge 到非 optimal 的值”来自 [Karaman 与 Frazzoli](https://ar5iv.labs.arxiv.org/html/1105.1186)，读的是 RRG 与 PRM* 的那一段；RRT* 的 Algorithm 6 只读到末尾，它和 RRG 用同一个 radius 这一点没有在读到的段落里看到原句。“$\log n$ 个邻居”的直观推法、narrow passage 的体积估算凭自己的知识写。Rectangle 的例子、手算的 rewire、RRT 与 RRT* 的对比、$\gamma$ 的门槛 12.05 和 short-cutting 的 12.58 是为这一页实际算的。

## [nonholo] Nonholonomic robot：Dubins path 与 lattice search

:::skip
能写出 Dubins car 的 model，对一组 start、goal 算出 RSR 和 LSL 的长度并说明为什么只要比较六个 word，能说出 lattice search 的 edge 从哪里来，就可以去第 4 站。
:::

### Car 不能侧着走

开头第一次失败里，car 跟不上 grid 的 corner。原因是 car 的 velocity 只能沿着车身方向。设 car 后轴中点在 $(x,y)$，heading 是 $\theta$，速度是 $v$：

$$\dot x=v\cos\theta,\qquad\dot y=v\sin\theta,\qquad\dot\theta=\omega$$

消掉 $v$ 就是一条和 velocity 有关的 constraint：

$$\dot x\sin\theta-\dot y\cos\theta=0$$

它说 velocity 在垂直车身方向上的分量为零。Configuration 有三个数 $(x,y,\theta)$，能直接控制的只有两个，而且这条 constraint 积不成只含 $(x,y,\theta)$ 的 equation，car 仍然能到达任意 $(x,y,\theta)$，只是不能沿任意方向走过去。这叫 nonholonomic constraint（[NW-MODERNROBOTICS 第 1 站](../courses/NW-MODERNROBOTICS.html#cspace)）。Differential-drive 的 robot 满足同一条 constraint（[RB2203 第 8 站](../courses/RB2203.html#mobile)），但它能原地转（$v=0$、$\omega\ne0$），grid 的 corner 只是慢；car 有最小 turning radius $\rho$，$|\omega|\le v/\rho$，corner 是做不到。

### Dubins car：最短 path 只有六种

LaValle 书里的 Dubins car 只能以单位速度前进，$|\omega|\le1/\rho$，问从 $(x_0,y_0,\theta_0)$ 到 $(x_1,y_1,\theta_1)$ 的最短 path。Dubins 证明了：最短 path 一定由不超过三段组成，每段是 L（以 $\rho$ 左转到底）、R（右转到底）或 S（直走），而且只有六种组合可能是最短的：

$$\{LRL,\ RLR,\ LSL,\ LSR,\ RSL,\ RSR\}$$

所以求最短 path 不需要 search，把六个 word 都算一遍取最短。每个 word 的几何都一样：在 start 和 goal 各画一个左转圆和右转圆，找圆之间的 tangent line。左转圆的圆心在车身左边 $\rho$ 处，右转圆在右边：

$$c_L=(x-\rho\sin\theta,\ y+\rho\cos\theta),\qquad c_R=(x+\rho\sin\theta,\ y-\rho\cos\theta)$$

例子：$\rho=1$，start $(0,0,90^\circ)$（朝上），goal $(5,0,-90^\circ)$（朝下），也就是在 5 m 外掉头。

**RSR。** Start 的右转圆圆心 $(0+1,\ 0-0)=(1,0)$；goal 的右转圆圆心 $(5+\sin(-90^\circ),\ 0-\cos(-90^\circ))=(4,0)$。两个圆一样大，所以 S 段和两圆心的连线平行，在连线的左侧（行进方向的左边）$\rho$ 处，也就是 $y=1$。Car 从 (0, 0) 绕 (1, 0) 顺时针转 90° 到 (1, 1)，heading 变成 0°；直走 3 到 (4, 1)；绕 (4, 0) 顺时针转 90° 到 (5, 0)，heading $-90^\circ$。长度 $\tfrac\pi2+3+\tfrac\pi2=6.14$。

**LSL。** 左转圆圆心是 $(0-1,0)=(-1,0)$ 和 $(5+1,0)=(6,0)$。Car 从 (0, 0) 朝上开始左转，先往左绕开，要转 270° 才朝向右，到达圆的最低点 $(-1,-1)$；沿 $y=-1$ 直走 7 到 $(6,-1)$；再左转 270° 到 (5, 0)。长度 $\tfrac{3\pi}2+7+\tfrac{3\pi}2=16.42$。

剩下几个 word 的 tangent 是斜的，用代码按同样的几何算：

| word | LSL | RSR | LSR | RSL | RLR | LRL |
|---|---|---|---|---|---|---|
| 长度（m） | 16.42 | **6.14** | 11.69 | 11.69 | 12.32 | 不可行 |

LRL 不可行：两个左转圆圆心相距 7，中间那段 R 的圆要同时和两个圆相切，圆心相距最多只能是 $4\rho=4$。

::fig[rb3302-dubins] 五个可行的 word（虚线标了长度）和最短的 RSR（粗线）。Car 沿 RSR 匀速开过去。

:::wrong 离 goal 越近，path 越短
Start $(0,0,0^\circ)$，goal $(0,1,0^\circ)$：goal 就在左边 1 m，heading 相同。Car 不能侧移，最短的 Dubins path 是 LSL：左转 90°，直走 1，再左转 270°，长 $\tfrac\pi2+1+\tfrac{3\pi}2=7.28$。Goal 换成正后方 1 m 的 $(-1,0,0^\circ)$，也是 7.28。而 3 m 外正前方的 $(3,0,0^\circ)$ 只要 3。Dubins distance 和 Euclidean distance 不是一回事；LaValle 指出它甚至不是真正的 metric：不对称，而且不连续。不连续的原因是 Dubins car 不是 small-time locally controllable（STLC）：要到达附近、但需要比 $\rho$ 更小的转弯才能到的点，只能换一串长得多的 primitive，cost 在那里跳一下。用 Euclidean distance 当 RRT 的 nearest neighbor，选出的“最近” node 可能是最难到达的那个。
:::

:::edge CCC 只在两端很近时出现
LaValle 给出的条件是 CCC word 中间那段转过的 angle $\beta>\pi$。中间转大半圈比走一段 S 还划算，只在两个圆挨得很近时发生。Start $(0,0,90^\circ)$，goal $(1,0,-90^\circ)$（1 m 外掉头）：RSR 是 10.42，LRL 是 6.03，最短的是 LRL，它中间那段 R 转了 $262.8^\circ$，确实大于 $180^\circ$。
:::

### 有 obstacle 时：lattice 上的 search

Dubins path 不管 obstacle。有 obstacle 时，回到第 1 站的做法，但把 graph 的 edge 换成 car 真正开得出来的动作，这样 graph 上的任何 path 都开得出来。最直接的办法是从每个 pose 出发取几个 motion primitive：左转到底 45°、直走同样长度、右转到底 45°。

::fig[rb3302-lattice] 左边：固定转角的 arc 展开两层，终点散落在 cell 里；右边：state lattice 的 primitive 专门设计成从 cell 中心连到 cell 中心。

问题在终点。$\rho=1.8$ m 时，左转 45° 的终点是 $(\rho\sin45^\circ,\ \rho(1-\cos45^\circ))=(1.27,0.53)$，不在任何 cell 的中心；再展开一层，9 个终点也没有一个在中心。同一个 $(x,y,\theta)$ 几乎不会被到达两次，graph 没有重复的 node，一直长下去。有两种处理办法。

**State lattice。** 16-782 引用 Pivtoraiko 与 Kelly 2005 的定义：vertex 是 cell 的中心（连同离散的 heading），edge 是连接两个 cell 中心的短的、可行的 motion。Primitive 离线设计好，每一条都保证终点正好落在某个 cell 中心、heading 正好是离散的值，search 时把同一套 primitive 复制到每个 state 上。

右边那套 primitive 是这样凑出来的。Heading 取 45° 的倍数，cell 边长 1 m。从 $(0,0,0^\circ)$ 出发要转到 45°，先沿 radius $R$ 的 arc 左转 45°，再沿 45° 方向直走 $L$：

$$x=R\sin45^\circ+L\cos45^\circ,\qquad y=R(1-\cos45^\circ)+L\sin45^\circ$$

要终点是 $(2,1)$，两式相减消掉 $L$：$x-y=R(\sin45^\circ+\cos45^\circ-1)=0.414R=1$，所以 $R=2.414$；代回 $y$：$0.293\times2.414+0.707L=1$，$L=0.414$。$R=2.414\ge\rho$，car 开得出来。把它关于 $x$ 轴镜像就是到 $(2,-1,-45^\circ)$ 的右转，再加上直走一格到 $(1,0,0^\circ)$，轴向 heading 的三个 primitive 齐了。斜向 heading（45°）的三个是：直走到 $(1,1)$，以及先直走 0.414 再转 45° 到 $(2,1,0^\circ)$ 或 $(1,2,90^\circ)$，由上面那条倒过来走、再镜像得到。其他 heading 都是这两套转 90° 的倍数。展开两层，9 个终点全部落在 cell 中心，同一个 state 会从不同的路被到达，graph 是有限的，第 1 站的 A* 原样可用。

16-782 的 autonomous driving case study 是 CMU Tartan Racing 在 Urban Challenge 里用的 lattice：高分辨率的有 32 个 heading、36 个 action，低分辨率的有 16 个 heading、24 个 action，$x,y$ 都是 0.25 m。低分辨率的 action 是高分辨率的子集，所以两种可以拼在一起用：起点和终点附近约束多，用高分辨率，中间空旷的地方用低分辨率。Slides 给的例子里，只用高分辨率 expand 2933 个 state、0.19 s，multi-resolution expand 1228 个、0.06 s。代价是 lattice 只能到达离散的 pose，primitive 也要为每种 car 重新设计。

**Hybrid A*。** Dolgov 等人（Stanford 参加 Urban Challenge 的车）走另一条路：仍然用固定的 steering action 往前模拟一小段，node 记下真实的、连续的 $(x,y,\theta)$；同时把 $(x,y,\theta)$ 按 cell 离散化（search 用 0.5 m 和 5°），每个 cell 只关联一个 continuous state，落进同一个 cell 的 state 被合并。Cell 只用来去重，下一层从 continuous state 展开。论文明说，因为这一步合并，hybrid A* 不保证找到 cost 最小的 solution，但 path 是 car 开得出来的，通常离 optimal 不远，之后再用 gradient 类的 smoothing 改进。离散的 action 也不会正好落在 goal 上，所以每隔若干个 node 就试一次从当前 state 到 goal 的 Reeds–Shepp path（Dubins path 允许倒车的版本），不碰就直接接上；离 goal 越近试得越频繁。

两种做法用同样的 heuristic 思路。一个是不管 obstacle、只管 nonholonomic constraint 的 cost（Dubins 或 Reeds–Shepp 的长度，或在 lattice 上离线查表），它知道 car 掉头有多难；一个是不管 turning radius、只管 obstacle 的 2D 最短 path（第 1 站的 Dijkstra 从 goal 往回算一遍），它知道 wall 和死胡同在哪里。两个都 admissible，取 max 也 admissible。数字说明了为什么两个都要：

| 例子 | heuristic | expand 的 node | 时间 |
|---|---|---|---|
| Dolgov 等人，简单场景 | 2D Euclidean distance | 21,515 | |
| | 不管 obstacle 的 nonholonomic cost | 1,465 | |
| Dolgov 等人，有死胡同的场景 | 不管 obstacle 的 nonholonomic cost | 68,730 | |
| | 两者取 max | 10,588 | |
| 16-782 的 Tartan Racing | 只用 obstacle 的 2D cost | 26,108 | 1.30 s |
| | 只用不管 obstacle 的 cost | 124,794 | 3.49 s |
| | 两者取 max | 2,019 | 0.06 s |

只管 nonholonomic 的那个在开阔处很好，碰到死胡同就在里面白白展开；只管 obstacle 的那个会让 car 以错误的 heading 冲到 goal 跟前再慢慢调。

Nonholonomic constraint 来自 [NW-MODERNROBOTICS 第 1 站](../courses/NW-MODERNROBOTICS.html#cspace)；differential drive 的 model 和 control 见 [RB2203 第 8 站](../courses/RB2203.html#mobile)。Lattice 上的 search 就是[第 1 站](#search)的 A*。

## [trajopt] Trajectory optimization

:::skip
能写出 waypoint 上的 smoothness cost 和 obstacle cost，推出 CHOMP 的 update 并说明 $A^{-1}$ 的作用，能举出一个 local minimum，就可以去第 5 站。
:::

### Search 给出的 path 能走，但不好走

第 2 站 RRT 的 path 由一段段折线组成，每个折点都要求 robot 停下来转向；第 1 站的 grid path 贴着 obstacle 的 corner 走，没有任何余量。这两件事都不是 search 能解决的：search 只回答“有没有一条不碰的 path”，不回答“这条 path 好不好”。要把“好”写成一个数，然后让 path 去 minimize 它。

把 trajectory 写成 $n$ 个 waypoint $\xi=(q_1,\dots,q_n)$，两端 $q_0$、$q_{n+1}$ 固定。CHOMP 的 objective 是两项之和：

$$U(\xi)=f_{\text{smooth}}(\xi)+f_{\text{obs}}(\xi)$$

**Smoothness。** 相邻 waypoint 之差近似 velocity，取 squared velocity 的和：

$$f_{\text{smooth}}=\frac12\sum_{i=0}^{n}\|q_{i+1}-q_i\|^2$$

对一个 interior 的 $q_i$ 求 gradient，只有 $\|q_i-q_{i-1}\|^2$ 和 $\|q_{i+1}-q_i\|^2$ 两项含它：

$$\frac{\partial f_{\text{smooth}}}{\partial q_i}=(q_i-q_{i-1})-(q_{i+1}-q_i)=2q_i-q_{i-1}-q_{i+1}$$

所有 $i$ 拼起来（每个坐标分开看）就是 $A\xi+b$，其中 $A$ 是 diagonal 上为 2、两旁为 $-1$ 的 tridiagonal matrix，$b$ 装着两个固定端点的贡献。$n=4$ 时

$$A=\begin{pmatrix}2&-1&0&0\\-1&2&-1&0\\0&-1&2&-1\\0&0&-1&2\end{pmatrix}$$

CHOMP 原文把同一件事写成 $f_{\text{prior}}=\tfrac12\|K\xi+e\|^2$：$K$ 是 finite differencing matrix，$n+1$ 行、$n$ 列，第 $i$ 行在第 $i$ 列放 1、在第 $i-1$ 列放 $-1$，于是 $(K\xi)_i=q_i-q_{i-1}$；$e$ 把两个固定端点补上，第一个 entry 是 $-q_0$，最后一个是 $q_{n+1}$，其余为 0。展开 $\tfrac12(K\xi+e)^\top(K\xi+e)=\tfrac12\xi^\top K^\top K\xi+\xi^\top K^\top e+\tfrac12e^\top e$，所以 $A=K^\top K$、$b=K^\top e$。$n=2$ 时可以直接乘出来：

$$K=\begin{pmatrix}1&0\\-1&1\\0&-1\end{pmatrix},\qquad K^\top K=\begin{pmatrix}2&-1\\-1&2\end{pmatrix}$$

令 gradient 为零，$2q_i=q_{i-1}+q_{i+1}$：每个 waypoint 是两个邻居的中点，所以 smoothness 最小的是两端之间等距的直线。

**Obstacle。** 设 $e(x)$ 是点 $x$ 到 obstacle 表面的 signed distance（在里面为负），$\epsilon$ 是想要的 clearance。CHOMP 用的 cost 是

$$c(x)=\begin{cases}-e(x)+\tfrac12\epsilon,&e(x)<0\\[2pt]\dfrac{1}{2\epsilon}\big(e(x)-\epsilon\big)^2,&0\le e(x)\le\epsilon\\[2pt]0,&e(x)>\epsilon\end{cases}$$

在 obstacle 里面线性增长，在 clearance 带里平滑地降到 0，两段在 $e=0$ 处的值都是 $\tfrac12\epsilon$、slope 都是 $-1$。这里为了简单，robot 是一个点，$f_{\text{obs}}=w\sum_i c(q_i)$；CHOMP 原文的 obstacle 项是对 robot 身上每个点 $u$、沿 trajectory 积分：

$$f_{\text{obs}}=\int_0^1\!\!\int_u c\big(x(q(t),u)\big)\,\Big\|\frac{d}{dt}x(q(t),u)\Big\|\,du\,dt$$

乘上 workspace 里的速度 $\|x'\|$，等于按 workspace 的 arc length 积分：同一段路走快走慢，obstacle cost 一样，optimizer 不能靠“在 obstacle 里加速冲过去”来降低 cost。它的 gradient 里有 projection $I-\hat x'\hat x'^\top$，只留下垂直于运动方向的分量，另加一项和 curvature 有关的修正。原文也提到更简单的 $c(x)=\max(\epsilon-e(x),0)$。

### 只推撞上的点，会留下折角

最直接的 update 是 gradient descent：$\xi\leftarrow\xi-\eta\,\nabla U$。看 obstacle 那一项的 gradient：它只在撞上或靠近 obstacle 的 waypoint 上不为零。于是第一步只把这几个点推开，path 上出现一个尖角；smoothness 再慢慢把尖角两边的点拉过来。

慢到什么程度，看 $A$ 的 eigenvalue。$n\times n$ 的这个 $A$ 的 eigenvalue 是 $2-2\cos\frac{k\pi}{n+1}$，$k=1,\dots,n$。$n=24$ 时最大的是 3.984，最小的是 $2-2\cos\frac{\pi}{25}=0.0158$，相差 253 倍。Step size 要按最大的 eigenvalue 取（$\eta=\tfrac14$，否则来回振荡），最小的 eigenvalue 对应的那个 mode，也就是整条 path 一起向一边弯，每步只衰减到 $1-0.0158/4=0.996$ 倍，40 步之后还剩 $0.996^{40}=0.85$。

### CHOMP 的 update：用 $A$ 量步长

CHOMP 每一步解一个小问题：把 $U$ 在当前 $\xi_k$ 处 linearize，再加一个惩罚步长的项，

$$\xi_{k+1}=\arg\min_\xi\Big\{U(\xi_k)+g_k^\top(\xi-\xi_k)+\frac\lambda2\,(\xi-\xi_k)^\top A\,(\xi-\xi_k)\Big\}$$

$g_k=\nabla U(\xi_k)$。对 $\xi$ 求导令其为零：$g_k+\lambda A(\xi-\xi_k)=0$，

$$\xi_{k+1}=\xi_k-\frac1\lambda A^{-1}g_k$$

和普通 gradient descent 的唯一区别是步长用 $A$ 来量：$(\xi-\xi_k)^\top A(\xi-\xi_k)$ 是“这一步本身有多不 smooth”，一个尖锐的 displacement 在这个 norm 下很大，所以允许的一步只能是 smooth 的。

$A^{-1}$ 对 gradient 做了什么？$n=4$ 时

$$A^{-1}=\frac15\begin{pmatrix}4&3&2&1\\3&6&4&2\\2&4&6&3\\1&2&3&4\end{pmatrix}$$

假如 obstacle 只推第 2 个 waypoint，gradient 是 $(0,1,0,0)^\top$。普通 gradient descent 只动第 2 个点；乘上 $A^{-1}$ 后是 $(0.6,1.2,0.8,0.4)^\top$，四个点一起动，形状是一个以第 2 个点为顶的帐篷，两端平滑地降下去。对 smoothness 那一项，$A^{-1}(A\xi+b)$ 让所有 mode 以同样的比例衰减，那个 0.0158 的慢 mode 不再拖后腿。

::fig[rb3302-chomp] 同一条穿过 obstacle（圆心 (5, 0.4)、radius 1.5）的直线，24 个 waypoint，$w=4$，$\epsilon=0.6$。上面是 CHOMP 的 update（$\lambda=300$），下面是普通 gradient descent（$\eta=\tfrac14$）。看折角：上面整条 path 一起弯开，下面先被顶出一个尖。

|---|---|---|---|---|---|---|---|
| CHOMP 的 $U$ | 30.43 | 22.97 | 14.42 | 3.01 | 2.27 | 2.26 | 2.26 |

:::wrong Trajectory optimization 从任何初始 path 都能找到不碰的 path
把 obstacle 的圆心挪到 (5, 0)，正好在初始直线上。每个 waypoint 上 obstacle cost 的 gradient 都沿着 $x$ 方向（从圆心指向这个点），$y$ 方向的分量恰好为 0；smoothness 的 gradient 在一条直线上也没有 $y$ 分量。于是 $y$ 永远是 0，400 步之后 path 仍然是直线，只是 waypoint 沿着线往两头挤，$U$ 停在 7.81，仍然穿过 obstacle。这是一个 saddle point，往上往下都更好，gradient 却看不见。不对称的情形也一样：path 从哪一侧绕，完全由初始 path 决定，optimization 只会在那一侧找最好的。CHOMP 的论文在 WAM arm 上取 15 个 configuration，两两配对得到 105 个问题，从直线初始化解出 99 个；拿 bidirectional RRT 的 path 当初始值反而通常更差，论文报告的 log objective 平均高约 0.5。一条已经不碰的初始 path 并不保证 optimization 之后更好：从哪里开始，决定落进哪个 local minimum。
:::

## [loc] Localization：Bayes filter、particle filter 与 Kalman filter

:::skip
能在 corridor 上手算 histogram filter 的 predict 和 update，做一次 particle filter 的 resample，手算一维 Kalman filter，并说清 Gaussian belief 为什么做不了 global localization，就可以去第 6 站。
:::

### 位置要估计，不是读出来的

开头第二次失败里，robot 用 odometry 算位置：wheel 转了多少圈乘以周长。每一步的 error 都很小，但只加不减，20 m 后差 0.6 m。要纠正它，robot 必须拿 sensor 看到的东西和 map 对照。可 sensor 本身也不可靠：一个 door detector 在 door 前面也可能没看到 door，在 wall 前面也可能误报。

所以 robot 能有的不是一个位置，而是在所有可能位置上的一个 probability distribution，叫 belief。Localization 就是每走一步、每看一次，把 belief 更新一次。

### Bayes filter：predict 与 update

记 $x_t$ 是时刻 $t$ 的位置，$u_t$ 是这一步的 control（让 wheel 转了多少），$z_t$ 是这一步的 measurement。Belief $\text{bel}(x_t)$ 是给定到目前为止所有 $u$ 和 $z$ 时 $x_t$ 的 distribution。假设 Markov：知道 $x_{t-1}$ 和 $u_t$ 后，更早的事不再影响 $x_t$；知道 $x_t$ 后，$z_t$ 和其他一切无关。在这个假设下，更新分两步。

**Predict（motion update）。** Robot 动了，不再看任何东西。$x_t$ 落在某处的 probability，是从每个可能的 $x_{t-1}$ 走过来的 probability 之和：

$$\overline{\text{bel}}(x_t)=\sum_{x_{t-1}}p(x_t\mid u_t,x_{t-1})\,\text{bel}(x_{t-1})$$

**Update（measurement update）。** 看到 $z_t$。按 Bayes rule，posterior 正比于 likelihood 乘 prior：

$$\text{bel}(x_t)=\eta\,p(z_t\mid x_t)\,\overline{\text{bel}}(x_t)$$

$\eta$ 让总和为 1。这两条合起来叫 Bayes filter，对 map 已知的情形叫 Markov localization。$p(x_t\mid u_t,x_{t-1})$ 是 motion model，$p(z_t\mid x_t)$ 是 sensor model；robot 的物理特性全部装在这两个 model 里。

### Histogram filter：在 corridor 上算一遍

把位置离散成 cell，belief 就是一个 histogram。用 Corridor 设定：10 个 cell 首尾相连，door 在 cell 0、3、7。

- Sensor model：在 door 前，看到 door 的 probability 是 0.8；在 wall 前，误报 door 的 probability 是 0.1。
- Motion model：命令走 $k$ 格，实际走 $k$ 格的 probability 是 0.8，走 $k-1$ 格和 $k+1$ 格各 0.1。

Robot 实际从 cell 3 出发，但它不知道，prior 是每格 0.1。

**第 1 次 update：看到 door。** 每格乘 likelihood：door 格 $0.1\times0.8=0.08$，wall 格 $0.1\times0.1=0.01$。总和 $3\times0.08+7\times0.01=0.31$，normalize：door 格 $0.08/0.31=0.258$，wall 格 $0.01/0.31=0.032$。三个 door 一样可能，robot 只知道自己在某个 door 前。

**Predict：命令走 4 格。** 新的 cell $c$ 的 probability 来自三个地方：从 $c-4$ 正好走 4 格、从 $c-3$ 少走一格（只走了 3 格）、从 $c-5$ 多走一格（走了 5 格）。

$$\overline{\text{bel}}(c)=0.8\,\text{bel}(c-4)+0.1\,\text{bel}(c-3)+0.1\,\text{bel}(c-5)$$

Cell 4 的三个来源是 cell 0（door）、cell 1 和 cell 9（都是 wall）：$0.8\,\text{bel}(0)+0.1\,\text{bel}(1)+0.1\,\text{bel}(9)=0.8\times0.258+0.1\times0.032+0.1\times0.032=0.213$。Cell 7（来自 cell 3）和 cell 1（来自 cell 7，绕过 cell 9 接回 cell 0 再到 1）同样是 0.213。三个峰整体右移了 4 格，并且各自漏了一点给两旁。

**第 2 次 update：又看到 door。** 三个峰里只有 cell 7 是 door。乘 likelihood 后，cell 7 是 $0.213\times0.8=0.170$，cell 1 和 4 是 $0.213\times0.1=0.021$；峰旁边漏出去的那些格也要算：cell 0 和 3 是 door，各 $0.055\times0.8=0.044$，cell 2、5、6、8 各 $0.055\times0.1=0.0055$，cell 9 是 $0.032\times0.1=0.0032$。总和 $0.170+2\times0.021+2\times0.044+4\times0.0055+0.0032=0.326$，normalize 后 cell 7 是 $0.170/0.326=0.523$。Robot 第一次有了一个明显的猜测。

**再走 3 格、再看到 door**，cell 0 的 probability 是 0.645，cell 3 是 0.176，cell 7 是 0.103。

::fig[rb3302-histo] 上面是 belief，下面是 robot 的真实位置（第一帧是最后一步）。每次 update 让 door 格变高，每次 predict 让整个 histogram 平移并变宽一点。

单看一次 measurement，robot 永远分不清是哪个 door；是 door 之间的间隔（3、4、3）和走过的距离对上了，才把它定下来。Measurement 让 belief 变尖，motion 让 belief 变平，localization 就在两者之间来回。

### Particle filter：用 sample 代替 histogram

Histogram 的 cell 数随 dimension 指数增长：一个 $20\,\text{m}\times20\,\text{m}$ 的 floor，10 cm 一格、heading 5° 一格，是 $200\times200\times72=2.9\times10^6$ 个 cell，每一步都要全部更新。Particle filter 改用 $M$ 个 sample（particle）表示 belief：particle 多的地方 probability 高。一步更新三件事：

1. **Predict**：每个 particle 按 motion model 随机走一步（各自 sample 自己的 noise）。
2. **Weight**：每个 particle 的 weight 是 $p(z_t\mid x^{[m]})$。
3. **Resample**：按 weight 有放回地抽 $M$ 个 particle，构成新的一组。

在 Corridor 上做第一次 update。20 个 particle，每格 2 个。看到 door：6 个 door 格里的 particle weight 0.8，14 个 wall 格里的 0.1，总和 $6\times0.8+14\times0.1=6.2$。Normalize 后 door particle 是 $0.8/6.2=0.129$，wall particle 是 0.016。按 weight 抽 20 次，每个 door particle 平均抽中 $20\times0.129=2.58$ 次，每个 wall particle 0.32 次。

Resample 用 low-variance 的做法：只抽一个 random number $r\in[0,1/M)$，然后取 $r,\ r+\tfrac1M,\ r+\tfrac2M,\dots$ 这 $M$ 个等距的点，看每个点落在哪个 particle 的累积 weight 区间里。取 $r=0.025$，结果是 cell 0、3、7 分别有 5、6、5 个 particle，cell 1、5、6、9 各 1 个，cell 2、4、8 没有了。

::fig[rb3302-particles] 一次 weight 与 resample。Resample 不改变 particle 的位置，只复制 weight 大的、丢掉 weight 小的。

Low-variance resampling 的好处是：所有 weight 都相等时，它原样返回原来那组 particle，不会凭运气丢掉谁；每个 particle 被抽中的次数是 $\lfloor M w\rfloor$ 或 $\lceil Mw\rceil$。

:::edge Particle 被抽光
上面 cell 2、4、8 已经一个 particle 都没有。如果 robot 其实在那里（比如 door detector 误报），之后无论看到什么，belief 都回不去，因为 weight 只能给存在的 particle。这叫 particle deprivation。Stanford AA274A 讲义里的 kidnapped robot problem（robot 运行中随时可能被搬到别处）是它的极端情形，讲义给的办法是每一步注入一些新的 random particle，不让 sample 过分集中。
:::

### Kalman filter：belief 是一个 Gaussian

如果 belief、motion noise 和 sensor noise 都是 Gaussian，而 model 是 linear 的，Bayes filter 的两步都能写成 closed form，只要记 mean $\mu$ 和 variance $\sigma^2$。

一维的例子。Robot 在一条直的 corridor 里，belief 是 $\mathcal N(2.0,\ 0.04)$（$\sigma=0.2$ m）。命令向前 1.0 m，motion noise 的 variance 是 0.01。

**Predict。** 位置加上 1.0，两个独立的 noise 的 variance 相加：

$$\bar\mu=2.0+1.0=3.0,\qquad\bar\sigma^2=0.04+0.01=0.05$$

**Update。** 一个 range sensor 量到前方已知位置的 wall，换算成 robot 在 $z=3.2$，sensor noise 的 variance 是 0.02。两个 Gaussian 相乘，结果还是 Gaussian：

$$K=\frac{\bar\sigma^2}{\bar\sigma^2+\sigma_z^2}=\frac{0.05}{0.07}=0.714$$

$$\mu=\bar\mu+K(z-\bar\mu)=3.0+0.714\times0.2=3.143,\qquad\sigma^2=(1-K)\,\bar\sigma^2=0.286\times0.05=0.0143$$

$K$ 是 Kalman gain：predict 越不确定（$\bar\sigma^2$ 大）、sensor 越准（$\sigma_z^2$ 小），越相信 measurement。Update 之后 $\sigma=0.12$ m，比 predict 的 0.224 和 sensor 的 0.141 都小。真实 robot 的 motion model 和 sensor model（比如量 landmark 的 range 和 bearing）不是 linear 的，在当前 mean 处 linearize 再套同样的 formula，就是 EKF localization。

:::wrong Kalman filter 和 histogram filter 只是同一件事的两种写法，哪个都能用
Kalman filter 的 belief 只能是一个 Gaussian，只有一个峰。Corridor 上第一次看到 door 后，真实的 belief 有三个一样高的峰（cell 0、3、7 各 0.258）。用一个 Gaussian 去拟合它，mean 是 $\sum_c c\cdot\text{bel}(c)=3.71$，standard deviation 2.92：mean 落在 cell 3 和 4 之间，而 cell 4 的 probability 只有 0.032；整个 Gaussian 宽得几乎盖住整条 corridor，三个 door 的信息全丢了。Stanford AA274A 讲义的分法是：初始位置大致已知、只需要跟踪（pose tracking）时，error 小，belief 当作 unimodal 是合理的，可以用 Kalman filter 或 EKF；初始位置未知（global localization）或会被 kidnap 时，要用 particle filter 这类能表示多个 hypothesis 的 filter。讲义开 non-parametric filter 一章时举的就是这个例子：robot 不知道自己在哪个房间，belief 在几个房间里各有一个峰。
:::

### Occupancy grid：每个 cell 一个 Bayes filter

上一站假设 map 已知。如果 robot 知道自己在哪，反过来可以画 map：把 plane 分成 cell，每个 cell 估计一个 probability $p(m_i)$，表示它被占据。Laser 的一条 beam 在距离 $r$ 处返回，说明 beam 停下的那个 cell 很可能被占，beam 穿过的 cell 很可能空着，beam 之后的 cell 看不到，什么也没说明。

UW CSE 571 的 slides 把这一步的假设列成三条：各个 cell 是否被占互相 independent；robot 的 pose 已知；map 是 static 的。于是每个 cell 可以各自当作一个不会动的 binary state，用 Bayes filter 更新。一个只有两个值的 probability 用 log-odds 记最方便：

$$\ell=\log\frac{p}{1-p}$$

$p=0.5$ 时 $\ell=0$。Bayes rule 在 log-odds 下变成加法（假设每次 measurement 独立）：

$$\ell_t=\ell_{t-1}+\log\frac{p(m_i\mid z_t)}{1-p(m_i\mid z_t)}-\log\frac{p(m_i)}{1-p(m_i)}$$

最后一项是 prior 的 log-odds，记作 $\ell_0$。

$p(m_i\mid z_t)$ 叫 inverse sensor model：只看这一次 measurement 时，cell 被占的 probability。取 beam 停下的 cell 为 0.7、穿过的 cell 为 0.4，prior $\ell_0=0$：

$$\ell_{\text{occ}}=\log\frac{0.7}{0.3}=+0.847,\qquad\ell_{\text{free}}=\log\frac{0.4}{0.6}=-0.405$$

同一个方向上扫四次。Wall 在 cell 6；第 1 次 scan 时，cell 3 恰好站着一个人。

::fig[rb3302-occ] 每一行是一次 scan 对每个 cell 的贡献，最后两行是累加的 log-odds 和换回来的 probability。

- Cell 6（wall）：scan 1 被人挡住没看到，后三次都是 hit，$3\times0.847=2.54$，$p=1-\dfrac{1}{1+e^{2.54}}=0.93$。
- Cell 3（人站过）：一次 hit 三次穿过，$0.847-3\times0.405=-0.369$，$p=0.41$。人走了，map 自己改了回来。
- Cell 0 到 2：四次穿过，$-1.62$，$p=0.16$；cell 7 从来看不到，$p=0.5$。

UW 的 slides 还给了一个更简单的 counting model：$\text{hits}$ 是 beam 停在这个 cell 的次数，$\text{misses}$ 是穿过它的次数，估计 $p=\text{hits}/(\text{hits}+\text{misses})$。同样四次 scan，cell 6 是 $3/(3+0)=1$，cell 3 是 $1/(1+3)=0.25$，cell 0 到 2 是 0，cell 7 是 $0/0$，没有定义。它只数次数，看一次 hit 就给出 probability 1，没有 inverse sensor model 里“这次读数本身有多可靠”的信息；log-odds 的版本里，三次 hit 才到 0.93。

:::wrong 把每次 scan 给出的 probability 取平均就行
Cell 6 三次 hit，每次的 inverse sensor model 都是 0.7，平均还是 0.7，看一百次也是 0.7。可三次独立的证据应该让 robot 更确定：Bayes rule 给出 0.93，看十次是 $1-1/(1+e^{8.47})=0.9998$。平均把“看了很多次”这件事扔掉了。实际实现会把 $\ell$ 限制在一个范围里（clamping；UW 的 slides 引 Yguel 2007，说它保证 map 还能被更新。$\pm3.5$ 是这里举的数），否则一个 cell 被看了上千次之后，环境真的变了（有人搬来一个箱子）也要看上千次才翻得过来。
:::

### SLAM：两件事互相要对方

Occupancy grid 要 pose 已知，localization 要 map 已知。在一个没来过的地方，两者都没有，只能一起估计，叫 SLAM（simultaneous localization and mapping）。

难点在 drift。Robot 用 odometry 和 scan matching 一步步估计相对运动，每一步的 error 都很小，但 pose 是一路累加的，map 跟着 pose 一起歪。等 robot 绕一圈回到起点，认出这里来过（loop closure），才第一次拿到一个能纠正累积 error 的 measurement。问题是：这个 error 该算到哪一步头上？

### Pose graph：把 SLAM 写成 least squares

Graph-based SLAM 的回答是：哪一步都算一点，按每条 measurement 有多可靠来分。把每个 pose 当 node $x_i$，每个 measurement 当 edge：edge $\langle i,j\rangle$ 带一个 measurement $z_{ij}$（$x_j$ 相对 $x_i$ 的位移）和一个 information $\Omega_{ij}$（variance 的倒数）。Edge 的 error 是 measurement 减去当前估计给出的预测：

$$e_{ij}=z_{ij}-(x_j-x_i)$$

找让所有 error 加权平方和最小的 pose：

$$F(x)=\sum_{\langle i,j\rangle}e_{ij}^\top\,\Omega_{ij}\,e_{ij}$$

一维的例子。Robot 沿一条 corridor 走三步，odometry 给出 1.1、1.0、1.1，每条的 standard deviation 0.1，$\Omega=100$。到 $x_3$ 时，robot 用 laser 和在 $x_0$ 时存下的 scan 做 scan matching，得到 $x_3-x_0=3.0$，这个更准，standard deviation 0.05，$\Omega=400$。只用 odometry 拼起来，$x=(0,1.1,2.1,3.2)$，和 loop closure 差 0.2。

$e_{ij}$ 对 $x_i$ 的 derivative 是 $+1$，对 $x_j$ 是 $-1$。Grisetti 等人的 tutorial 给出的拼法：每条 edge 往 $H$ 的 $(i,i)$、$(j,j)$ 加 $\Omega$，往 $(i,j)$、$(j,i)$ 加 $-\Omega$，往 $b_i$ 加 $\Omega e_{ij}$，往 $b_j$ 加 $-\Omega e_{ij}$。在初始估计处，三条 odometry edge 的 error 都是 0，只有 loop closure 的 $e_{03}=3.0-3.2=-0.2$：

$$H=\begin{pmatrix}500&-100&0&-400\\-100&200&-100&0\\0&-100&200&-100\\-400&0&-100&500\end{pmatrix},\qquad b=\begin{pmatrix}-80\\0\\0\\80\end{pmatrix}$$

然后解 $H\,\Delta x=-b$。这个 $H$ 是 singular 的：把四个 pose 一起平移，所有 error 都不变，$F$ 也不变，所以 $\Delta x$ 不唯一。必须固定一个 pose。Grisetti 等人的 Algorithm 1 的做法是往 $H_{[11]}$ 上加一个 identity，相当于额外加一条“$x_0$ 别动”的 measurement；tutorial 也提到另一种做法，直接删掉对应的 block row 和 block column。这里用后者，固定 $x_0=0$，删掉第一个 row 和 column：

$$\begin{pmatrix}200&-100&0\\-100&200&-100\\0&-100&500\end{pmatrix}\begin{pmatrix}\Delta x_1\\\Delta x_2\\\Delta x_3\end{pmatrix}=\begin{pmatrix}0\\0\\-80\end{pmatrix}$$

第一行 $\Delta x_2=2\Delta x_1$；第二行 $-\Delta x_1+2\Delta x_2=\Delta x_3$，所以 $\Delta x_3=3\Delta x_1$；第三行 $-100\times2\Delta x_1+500\times3\Delta x_1=-80$，即 $1300\,\Delta x_1=-80$，$\Delta x_1=-0.0615$。于是

$$x=(0,\ 1.038,\ 1.977,\ 3.015)$$

::fig[rb3302-posegraph] 上面是只用 odometry 拼起来的 pose 和那条对不上的 loop closure（虚线），下面是 least squares 之后。

代回去看每条 edge 的 error：三条 odometry edge 都是 $+0.0615$，loop closure 是 $-0.0154$。0.2 的矛盾被分成了 $3\times0.0615+0.0154=0.2$。分法看 information：三条 odometry 串起来的 variance 是 $3\times0.01=0.03$，loop closure 是 0.0025，前者大 12 倍，所以 odometry 那一侧让出 $0.2\times\dfrac{0.03}{0.0325}=0.185$，loop closure 只让出 0.015。$F$ 从 16.0 降到 1.23。

这个例子是 linear 的，一步就解完。二维、三维里 pose 带 angle，$x_j-x_i$ 要换成“在 $x_i$ 的 frame 里看 $x_j$”，error 对 pose 是 nonlinear 的，就在当前估计处 linearize，解 $H\Delta x=-b$，更新，重复，这就是 Gauss–Newton。$H$ 是 sparse 的：只有被 edge 连着的两个 pose 之间有非零的 block，非零 block 的个数是 edge 数的两倍加 node 数（这里是 $2\times4+4=12$ 个非零 entry），所以几千个 pose 也能用 sparse Cholesky 很快解出。Tutorial 里 Intel 实验室的数据有 1802 个 node、3546 条 edge，在 laptop 上大约 100 ms 解完。

:::edge Front-end 定错一条 edge
上面的计算（back-end）相信给它的每条 edge。哪两个 pose 之间有 loop closure、measurement 是多少，是 front-end 用 scan matching 判断的。Front-end 把两个长得很像的走廊认成同一个，就会加进一条错的 edge，least squares 会忠实地把 map 拧弯去迁就它。Tutorial 自己假设 front-end 给的 edge 是一致的，不讨论 data association；它在 related work 里提到，front-end 常用 $\chi^2$ test 或 joint compatibility test（JCBB）检查一条候选 edge 和当前估计是否 compatible。它自己找 loop closure 候选的办法是：只考虑那些 marginal covariance 的 $3\sigma$ 范围里包含当前 pose 的旧 node。
:::

## [nav] Navigation：local planner 与 replanning

:::skip

### 两层 planner

把第 1 站的 A* 直接放到 robot 上，会遇到两个问题。Path 是一串 cell，robot 需要的是每 0.25 s 一个 $(v,\omega)$ 指令；而且 robot 有 acceleration limit，不能瞬间从 0.5 m/s 变成 0。另外，sensor 每一刻都在看到 map 上没有的东西（一个人、一把椅子），每次都在整张 map 上重新 A* 太慢。

常见的结构是分两层。Global planner 在整张 map 上 plan，周期是秒级，给出一条大致的 path；local planner 只看 robot 周围几米、接下来一两秒，周期和 control loop 一样快，选出下一步的 velocity，目标是沿着 global path 走、躲开眼前的 obstacle。

### Dynamic window approach

Fox、Burgard、Thrun 的 DWA 直接在 velocity space 里 search。假设接下来一小段时间 $(v,\omega)$ 保持不变，robot 就走一段 circular arc，于是每个 $(v,\omega)$ 对应一条 arc。三层筛选：

1. **Dynamic window。** 下一个 control cycle（$\Delta t$）里，acceleration limit 允许到达的 velocity：$v\in[v_a-\dot v\,\Delta t,\ v_a+\dot v\,\Delta t]$，$\omega$ 同理。
2. **Admissible。** 沿这条 arc 走，在碰到 obstacle 之前刹得住。Arc 上离 obstacle 的距离是 $\text{dist}(v,\omega)$，以最大 deceleration $\dot v_b$ 刹车需要的距离是 $v^2/(2\dot v_b)$，所以要求 $v\le\sqrt{2\,\text{dist}(v,\omega)\,\dot v_b}$。论文对 $\omega$ 也要求同样的事：以最大角减速度 $\dot\omega_b$ 能在撞上之前停止转动。

$$V_a=\Big\{(v,\omega)\ \Big|\ v\le\sqrt{2\,\text{dist}(v,\omega)\,\dot v_b}\ \wedge\ \omega\le\sqrt{2\,\text{dist}(v,\omega)\,\dot\omega_b}\Big\}$$

真正搜索的是三个集合的交 $V_r=V_s\cap V_a\cap V_d$，$V_s$ 是 robot 硬件允许的所有 velocity，$V_d$ 是上面的 dynamic window。

3. **打分。** 在剩下的 velocity 里 maximize

$$G(v,\omega)=\alpha\cdot\text{heading}+\beta\cdot\text{dist}+\gamma\cdot\text{velocity}$$

heading 是朝向 goal 的程度（robot 正对 goal 时最大），dist 是这条 arc 上离最近 obstacle 的距离（arc 上没有 obstacle 就取一个大常数），velocity 就是 $v$ 本身。论文用 $\alpha=0.2$、$\beta=0.2$、$\gamma=2.0$，三项都 normalize 到 $[0,1]$，再在 velocity space 上做一点 smoothing（$\sigma$），说这样 robot 离 obstacle 侧面更远。论文的实现每 0.25 s 算一次，velocity space 取 10×10 个格点；robot 是 RWI B21 平台的 RHINO，最快约 95 cm/s。

例子。Robot 在原点朝 $+x$，当前 $v=0.5$ m/s、$\omega=0$；$\dot v=0.5$ m/s²，$\dot\omega=2$ rad/s²，$\Delta t=0.25$ s，所以 window 是 $v\in[0.375,0.625]$，$\omega\in[-0.5,0.5]$，各取 3 个和 5 个值，共 15 个候选。Robot 前方偏右有一个 obstacle，圆心 $(0.92,-0.3)$，加上 robot radius 后是 radius 0.5 的圆；刹车 deceleration $\dot v_b=0.25$ m/s²、$\dot\omega_b=2$ rad/s²；goal 在 $(4,1.2)$。15 个候选里最近的碰撞距离是 0.475 m，$\sqrt{2\times0.475\times2}=1.38>0.5$，所以 $\omega$ 的条件对每个候选都满足，下面只看 $v$ 的条件。这里 dist 沿 arc 最多算 3 m；heading 用“沿 arc 走 1 s 后，heading 和指向 goal 的方向之差”换算成 $1-|\Delta\theta|/\pi$；三项都除以 admissible 候选里的最大值来 normalize。论文的 heading 用的是走一个 cycle 再全力刹车后的位置，这两处是这一页的简化。

先看 $v=0.625$ 的五条 arc。直走（$\omega=0$）在 0.52 m 处碰：$\sqrt{2\times0.52\times0.25}=0.51<0.625$，刹不住，不 admissible。$\omega=-0.5,-0.25,0.25$ 同样在 0.48 到 0.59 m 处碰，都不 admissible。只有 $\omega=0.5$ 的 arc 向左绕开，3 m 内不碰。它的分数：

$$G=0.2\times\frac{0.936}{0.982}+0.2\times\frac{3}{3}+2.0\times\frac{0.625}{0.625}=0.191+0.2+2.0=2.391$$

（0.982 是所有 admissible 候选里最大的 heading，属于 $v=0.375$、$\omega=0.25$。）$v=0.5$、$\omega=0.5$ 是 $0.191+0.2+1.6=1.991$。Velocity 的 weight 最大，所以最快的那个 admissible 候选胜出。

::fig[rb3302-dwa] 左边是 $v=0.625$ 的五条 arc，四条刹不住；右边是全部 15 个候选的分数。

Robot 执行 $(0.625,0.5)$ 一个 cycle，0.25 s 后重新算一遍。每次只承诺 0.25 s，所以 obstacle 动了也来得及改。

:::wrong 有了 DWA 这样的 local planner，global planner 可有可无
DWA 每次只看一个 cycle 加一段 arc，它只知道“往 goal 的方向转”。把 robot 放在第 1 站 Map M 的 start，goal 在 U 形 obstacle 的另一边：heading 项一直把它往右拉，进了 U 形口之后，每一条掉头往外走的 arc 的 heading 分数都比继续朝里的低，而 $G$ 只比较眼前这一个 cycle。论文在 related work 里说 local method 容易被 U 形 obstacle 这类 local minimum 困住；对 DWA 本身，它承认少数情况下会卡住：没有任何 admissible 的 $(v,\omega)$ 能往前走时，就进入 rotate-away 模式，原地转到能走为止。原地转能解开眼前的死角，解不开“整个 U 形口都是死路”这种要先往回走很远的情形（这一页没有在 Map M 上模拟 DWA）。真正能绕出去的是知道整张 map 的 global planner：让 DWA 的 heading 指向 global path 上前方的一个点，而不是 goal 本身。
:::

### 不知道 map 时：freespace assumption 与 replanning

再难一步：map 本身不完整。CMU 16-782 列了 replanning 的四个原因：environment 只部分已知、environment 在变、执行不准、localization 不准。D* Lite 论文里的 robot 是这样做的：总是在“状态未知的 cell 都可以通过”的假设下算最短 path，沿着走，看到八个邻居里有走不通的，就重新 plan。这个假设通常叫 freespace assumption（这个名字没有在读到的材料里找到原句）。

在 Map M 上模拟。Robot 一开始什么 obstacle 都不知道，sensor 能看到 2.5 个 cell 以内的东西，每步走一格。

::fig[rb3302-replan] 第一帧是走完的样子。Robot 先直奔 goal，进了 U 形口才看到底部的 wall；之后每看到一段新的 wall 就 replan 一次，在口里上下探，最后从上面绕出去。

Robot 一共走了 44 步，replan 12 次，path 长 47.31，是 map 已知时 22.14 的两倍多。多出来的部分不是 planner 的错：在 robot 看到 wall 之前，直奔 goal 就是当前信息下最好的 plan。

### Replanning 为什么要从 goal 往回搜

每次 replan 都从头跑一遍 A*，大部分计算是重复的。能不能让上一次 search 的结果留下来？

看 forward search（从 robot 当前位置出发）存的是 $g(s)$，从 robot 到 $s$ 的 cost。Robot 每走一步，search 的 root 就变了，所有 $g$ 都要重算：空的 25×15 map 上，robot 从 (13, 7) 走到 (14, 7)，375 个 cell 的 $g$ 全部改变。

Backward search（从 goal 出发）存的是每个 cell 的 cost-to-goal。Robot 走动不改变它；只有 map 改变才会，而且只影响 path 要经过新 obstacle 的那些 cell。在上面的模拟里，robot 在 (13, 7) 第一次看到 U 形底部的 wall，在更新前后的 map 上各从 goal 往回算一遍 cost-to-goal，375 个 cell 里只有 48 个变了。

::fig[rb3302-ctg] Robot 在 (13, 7) 看到底部的 wall 之后，cost-to-goal 变了的 48 个 cell 都在 wall 左边、原来要穿过那段 wall 的地方。

16-782 的结论是：D* Lite 从 $s_{\text{goal}}$ 往 $s_{\text{start}}$ 搜，search tree 的 root 不随 robot 移动，robot 走动后 $g$ 更可能保持不变。

### D* Lite：只修不再 consistent 的 state

要只修这 48 个，算法得知道哪些 value 过时了。16-782 换了一种看 A* 的方式。每个 state 记两个数：$v(s)$ 是它上一次被 expand 时的 $g$（没被 expand 过就是 $\infty$），$g(s)$ 由邻居的 $v$ 算出来，$g(s)=\min_{s'}\big(c(s,s')+v(s')\big)$（backward search 里 $s'$ 是 $s$ 的 successor）。

- $v(s)=g(s)$：consistent，这个 state 的 value 可信。
- $v(s)>g(s)$：over-consistent，邻居那边出现了更好的路，还没传出去。A* 的 OPEN 里放的就是这种 state，expand 一次令 $v=g$，再更新邻居的 $g$。
- $v(s)<g(s)$：under-consistent，它记的 value 太乐观了。Edge cost 变大（看到新的 wall）时才会出现。办法是令 $v(s)=\infty$，它就变成 over-consistent 或 consistent，再把变化传给依赖它的邻居。

16-782 的结论是：把 A* 改成“初始 OPEN 是所有 over-consistent 的 state”，就能复用上一次的 value，这就是全部改动。D* Lite（Koenig 与 Likhachev 2002）用的是同一个想法，记号不同：$g$ 是这里的 $v$，rhs 是这里的 $g$，rhs 是“看一步”的值，goal 的 rhs 为 0；$g=\text{rhs}$ 叫 locally consistent，$g>\text{rhs}$ 叫 locally overconsistent，$g<\text{rhs}$ 叫 locally underconsistent。ComputeShortestPath 每次 pop key 最小的 state $u$：overconsistent 就令 $g(u)=\text{rhs}(u)$，再对它的 predecessor 做 UpdateVertex；underconsistent 就令 $g(u)=\infty$，对 $u$ 自己和 predecessor 做 UpdateVertex。UpdateVertex 重算 rhs，不 consistent 就放进（或留在）queue，consistent 就移出。Key 是两个数，按 lexicographic order 比较：

$$k(s)=\Big[\min\big(g(s),\text{rhs}(s)\big)+h(s_{\text{start}},s)+k_m;\ \ \min\big(g(s),\text{rhs}(s)\big)\Big]$$

$h$ 指向 robot 的当前位置 $s_{\text{start}}$，所以 robot 一动，queue 里所有 key 的第一项都该变。论文的观察是：robot 从 $s$ 走到 $s'$，所有 key 的第一项最多减少 $h(s,s')$；与其把整个 queue 重排，不如把这个量累加进 $k_m$，以后新算的 key 都加上 $k_m$，旧的 key 等 pop 出来时发现过时了再重算放回。当 $s_{\text{start}}$ 已经 consistent、而且 queue 顶的 key 不比 $s_{\text{start}}$ 的小时，search 停止，robot 沿 $\arg\min_{s'}\big(c(s_{\text{start}},s')+g(s')\big)$ 走一步。

在 Map M 上用同样的设定跑一遍 D* Lite（unknown 当作 free，sensor radius 2.5，每看到新的 obstacle 就更新相关 edge 再 ComputeShortestPath），和每次都从头跑一遍 backward A* 比 expansion 数。Tie 的处理和上面的 replanning 模拟不同，robot 走的路线也不完全一样：36 步，path 长 38.49。

| 时刻 | 开始 | (13, 7) | (13, 8) | (13, 9) | (13, 6) | (13, 5) | (12, 5) | (11, 5) | (10, 5) | (13, 2) |
|---|---|---|---|---|---|---|---|---|---|---|
| D* Lite | 19 | 36 | 15 | 26 | 10 | 81 | 15 | 20 | 28 | 1 |
| 从头 backward A* | 19 | 35 | 37 | 58 | 37 | 119 | 123 | 132 | 137 | 9 |

第一次 plan 两者一样。第一次看到 wall 时 D* Lite 还多 expand 了 1 个：under-consistent 的 state 要先抬到 $\infty$、之后再作为 over-consistent 被 expand 一次，同一个 state 可能 expand 两次。之后差距越来越大，因为 robot 越往前走，从头 search 要重算的范围越大，D* Lite 只修新 wall 附近。十次加起来 251 对 706。

Anytime 是另一个方向的复用。16-782 的例子：先用 $\varepsilon=2.5$ 的 weighted A* 快速给出一条 path，再降到 1.5、1.0；每次从头算分别要 13、15、20 次 expansion，而 ARA* 复用前一次的结果，降到 1.5 时只要 1 次，降到 1.0 时 9 次，最后得到 optimal 的 10 步 path。

## [multi] Multi-robot path finding

### 把所有 robot 当成一个 robot

开头第三次失败里，两个 robot 各自的 path 都最短，合起来撞车。最直接的修法是把所有 robot 当成一个大 robot：state 是所有 robot 位置的组合，一步是所有 robot 同时各走一步，在这个 joint state space 里跑 A*，得到的就是 optimal 而且不撞的 plan。

代价是大小。Map M 有 354 个 free cell，2 个 robot 的 joint state 有 $354^2=125{,}316$ 个，5 个 robot 有 $354^5=5.6\times10^{12}$ 个；每个 robot 一步有 9 种选择（8 个方向加原地等），5 个 robot 的 branching factor 是 $9^5=59{,}049$。16-782 给的经验界是：robot 很少（比如少于 3 个）时用 joint state space；少于 10 个左右、而且 robot 之间能通信时，用 distributed planning（每个 robot 一个 planner，共享结果、必要时 replan）；robot 很多或通信受限时用 decentralized。

先把问题写清楚（multi-agent path finding，MAPF，按 CBS 论文的定义）：graph 上有 $k$ 个 agent，各有 start 和 goal；时间离散，每一步每个 agent 走到一个邻居或原地等，cost 都是 1；cost 是所有 agent 到达 goal 所用时间之和（sum of costs）。不允许的是 conflict：

- **Vertex conflict** $(a_i,a_j,v,t)$：两个 agent 在时刻 $t$ 同在 vertex $v$。
- **Edge conflict**：两个 agent 在 $t-1$ 到 $t$ 之间沿同一条 edge 对换位置。只查 vertex conflict 会漏掉它，两个 robot 在 corridor 里迎面穿过对方。

### Prioritized planning：一个一个来

另一个极端是给 robot 排个顺序，一个一个 plan，后面的 robot 把前面所有 robot 的 path 当作会动的 obstacle 来躲。前面的 robot 某一刻在某处，后面的 robot 就不能那一刻在那里，所以后面的 robot 要在 $(x,y,t)$ 的 space-time 里 search（16-782 指出 time 必须成为 search 的一个 dimension）。每个 robot 只做一次单 robot 的 search，很快。

::fig[rb3302-prio] 同一个问题，两种顺序。

一条四格的 corridor，cell 0 到 3，cell 1 旁边有一个只能容一个 robot 的凹处 n。A 从 cell 1 去 cell 2，B 从 cell 0 去 cell 3。

**A 先 plan。** A 的最短 path 是 $t=1$ 走到 cell 2，然后停在那里。B 要到 cell 3 必须经过 cell 2，而 cell 2 从 $t=1$ 起永远被占，B 找不到 path，整个 planner 失败。

**B 先 plan。** B 的 path 是 0→1→2→3，$t=1$ 到 cell 1。A 在 $t=0$ 位于 cell 1，必须在 $t=1$ 之前让开；不能退到 cell 0（会和 B 对换位置，edge conflict），只能进凹处 n；$t=2$ B 在 cell 2，A 回到 cell 1；$t=3$ B 到了 cell 3，A 走到 cell 2。Sum of costs 是 $3+3=6$。

:::wrong 每个 robot 都避开前面的 robot 走最短 path，问题就解决了
上面 A 先的顺序就是反例：先 plan 的 robot 不知道后面还有谁，停在了别人的必经之路上。Prioritized planning 不 complete（有解时可能报告无解），也不 optimal。换个顺序能救这个例子，但 $k$ 个 robot 有 $k!$ 种顺序，而且有的问题任何顺序都不行，因为解需要先 plan 的 robot 也为后面的让路。
:::

### Conflict-based search

CBS 在两个极端之间：每次只为一个 agent search（像 prioritized planning 那样便宜），但出了 conflict 就分两种情况各试一遍（所以不漏掉解）。

它有两层。**Low level**：为一个 agent 在 space-time 里 search 最短 path，必须满足给这个 agent 的一组 constraint，每条 constraint 形如 $(a_i,v,t)$，“$a_i$ 在时刻 $t$ 不能在 $v$”；其他 agent 一概不管。**High level**：在一棵 constraint tree（CT）上做 best-first search。每个 CT node 存一组 constraint、每个 agent 一条满足这些 constraint 的 path，以及这些 path 的 sum of costs。

1. Root 没有 constraint，每个 agent 各自走最短 path。
2. Pop 出 cost 最小的 CT node，检查它的 path 之间有没有 conflict。没有，返回。
3. 有 conflict $(a_i,a_j,v,t)$：任何合法的 solution 里，$a_i$ 和 $a_j$ 至少有一个不在 $(v,t)$。所以生成两个 child，一个加 constraint $(a_i,v,t)$，一个加 $(a_j,v,t)$；每个 child 只为被加了 constraint 的那个 agent 重跑 low level，其他 path 照抄。

在一个十字路口上手算。a1 从 W2 去 E2，a2 从 N2 去 S2，都要经过中心 C。

- Root：a1 走 W2→W1→C→E1→E2，a2 走 N2→N1→C→S1→S2，cost $4+4=8$。两者都在 $t=2$ 到 C，conflict $(a_1,a_2,C,2)$。
- 左 child 加 $(a_1,C,2)$：a1 不能在 $t=2$ 到 C，最短的办法是在 W1 等一步：W2→W1→W1→C→E1→E2，cost 5。a2 不变。总 cost 9。
- 右 child 加 $(a_2,C,2)$：对称地 a2 在 N1 等一步，总 cost 9。
- 两个 child 一样，先 pop 左边那个，检查：a1 在 $t=3$ 到 C，a2 在 $t=3$ 已经在 S1，没有 conflict，返回，cost 9。

::fig[rb3302-cbs] 第一遍按 root 的 path 走，$t=2$ 两个 robot 都到了 C；第二遍按左 child 的 path 走，a1 在 W1 多等一步，一路无碰撞。

为什么返回的一定是 optimal？CBS 论文靠两条 lemma。**Lemma 1**：一个 CT node 的 cost 不超过它允许的任何 solution 的 cost，因为它的每条 path 都是在它的 constraint 下最短的。**Lemma 2**：任何合法的 solution，在任何时刻都被 OPEN 里某个 CT node 允许，因为每次分裂时，合法的 solution 至少满足两条新 constraint 中的一条。于是第一个被 pop 出来的无 conflict 的 node，cost 不超过 OPEN 里的任何 node，也就不超过任何合法的 solution。

回到 corridor 的例子，CBS 不需要猜顺序。加上 edge conflict（分裂时禁止其中一个 agent 在那一刻走那条 edge）后跑一遍：root cost 是 $1+3=4$，CBS 一共生成 15 个 CT node、expand 其中 8 个，cost 从 4 涨到 5 再到 6，最后找到 cost 6 的 solution，和上面 B 先 plan 的结果一样。

:::edge CBS 什么时候比 joint A* 慢
CBS 的 high level 每次分裂都只解决一个 conflict。两个 agent 在开阔的地方、有很多条同样短的 path 时，几乎每种组合都在某处撞上，CT 要一个个试。CBS 论文的例子：两个 agent 各有 4 条最短 path，16 种组合全都有 conflict，joint A* 只 expand 8 个 node，CBS 要 expand 16 个 CT node、71 个 low-level state。反过来，在只有一个 bottleneck 的地图上，joint A* 要 expand $m^2+3$ 个 node（$m$ 是每个 agent 的最短 path 数），CBS 只要 $2m+14$ 个，$m\ge5$ 时 CBS 胜出。论文在 4-connected 的 8×8 grid 上做了实验（每个 $k$ 取 100 个 instance 平均）：6 个 agent 时，CBS 用 16 ms，plain joint A* 用 47,783 ms，加了 operator decomposition 的 A*+OD 用 90 ms；7 个 agent 起 plain A* 在 5 分钟内解不出。和更强的 ICTS 比，CBS 要到 8 个以上 agent 才更快。在游戏地图上，CBS 在 bottleneck 和窄走廊多的 brc202d 上表现最好，在大片开阔区域的 den520d 上排第三。
:::

### 目的变了：不是到达，而是看到

前八站的 robot 都有一个 goal，cost 是走过的路。另一类任务里没有 goal：扫地 robot 要把整个房间扫一遍；救援 robot 进一栋没有 map 的楼，要尽快把 map 建出来；巡检的 drone 要把十几个点各看一眼再回来；电量有限的 drone 只能看其中一部分，要挑看到信息最多的那些。16-782 把前三种分别叫 coverage（已知 map，用 sensor 把它完整检查一遍）、mapping（未知 map，把它完整建出来）、surveyal（访问一组指定的 waypoint，顺序任意）；NUS 2025 版大纲里这一项写的是 coverage、search、orienteering，最后一种就是带 budget 的版本。

### Coverage 与 exploration：frontier

没有 obstacle 的已知区域，最简单的是 lawn-mowing pattern：来回平行地扫，像割草。16-782 指出它碰到 obstacle 就不好用了：每一行被 obstacle 截断，robot 要在缺口两边来回绕。通用的办法是 frontier：总是沿最短 path 去最近的、还没看过的地方。

在 grid 上，“还没看过的 cell”本身可能是 wall，path 不能 plan 进去。所以把 frontier cell 定义成：已经看过、是 free 的、而且四个邻居里至少有一个还没看过。Robot 每一步用第 1 站的 search 找最近的 frontier cell，走一步，sense，再找。“最近的 frontier cell”有很多个候选 goal，16-782 的做法是第 1 站提过的 multi-goal A*：加一个 imaginary goal，从每个 frontier cell 连一条 cost 0 的 edge 到它，问题就变回单个 goal；用 Dijkstra 时，等价于从 robot 出发、pop 出第一个 frontier cell 就停。

Map 未知时（mapping），做法完全一样，只是 obstacle 也是边走边看到的。在 Map M 上跑一遍：robot 从 start (3, 7) 出发，什么都不知道，sensor 看到 2.5 个 cell 以内的所有 cell（这里为了简单，sensor 能看穿 wall）。

::fig[rb3302-explore] 第一帧是走完的样子。Robot 先钻进 U 形口，再沿下边、右边、上边绕一圈，最后回头补左边、U 形口里和右边边缘漏下的 cell。

Robot 走了 139 步，path 长 143.14，375 个 cell 全部看过。走到第 70 步时已经看到 288 个 cell，后面 69 步只多看到 87 个；第 100 步到第 139 步，只多看到 9 个。越到后来，frontier 越零散，要走很远才看到几个新 cell。16-782 对这个 greedy 的评价是：每一步都一定有 information gain，所以一定能把 map 建完（只要所有动作可逆），它可以利用已有的部分 map，也能扩展到多个 robot（16-782 的 multi-robot 一讲里，robot 依次 plan，后面的 robot 把前面 robot 会看到的 cell 当作已经看过）；但它不保证总路程最短。

### Surveyal：要访问的点之间的顺序

在 Map M 上有三个要看的 waypoint：P1 (12, 7) 在 U 形口里，P2 (10, 1) 和 P3 (10, 13) 在 U 形的上下两侧，robot 从 start (3, 7) 出发，看完就停。先用第 1 站的 A* 算出每两点之间的最短 path cost：

| | start | P1 | P2 | P3 |
|---|---|---|---|---|
| start | 0 | 9.00 | 9.49 | 9.49 |
| P1 | 9.00 | 0 | 9.66 | 9.66 |
| P2 | 9.49 | 9.66 | 0 | 14.83 |
| P3 | 9.49 | 9.66 | 14.83 | 0 |

问题变成选一个顺序。16-782 把它写成一个 graph search：state 是 $\{\alpha,\Omega\}$，$\alpha$ 是长度 $M$ 的 bit vector，第 $i$ 位为 1 表示 waypoint $i$ 已经访问过，$\Omega$ 是 robot 现在在哪个 waypoint（robot 不是 omnidirectional 时还要记 heading）；从 $\{\alpha,i\}$ 到 $\{\alpha\cup\{j\},j\}$ 有一条 edge，cost 是 $i$ 到 $j$ 的 path cost，由底层的 motion planner 算；$\alpha$ 全为 1 的 state 都是 goal。

$M=3$ 时，start 是 $\{000,\text{start}\}$；robot 在 waypoint $i$ 时，$\alpha$ 的第 $i$ 位一定是 1，其余两位任意，有 $2^2=4$ 种，三个 waypoint 共 12 个 state，加上 start 是 13 个。在这个 graph 上跑 Dijkstra，就是在比较所有顺序：

$$\text{start}\to\text{P2}\to\text{P1}\to\text{P3}:\ 9.49+9.66+9.66=28.80$$

另一个 optimal 是倒过来的 start → P3 → P1 → P2，也是 28.80。State 的个数是 $M\cdot2^{M-1}+1$，$M=20$ 时已经有 $20\times2^{19}+1=10{,}485{,}761$ 个，而且每条 edge 都要跑一次 motion planner。

::fig[rb3302-survey] 粗线是 optimal 的顺序，虚线是每次去最近那个点的顺序。

:::wrong 每次去最近的 waypoint，总路程就最短
从 start 看，最近的是 P1（9.00），先去 P1；从 P1 看，P2 和 P3 一样近（9.66），去 P2；最后只剩 P3，从 P2 过去要绕过整个 U 形，14.83。总共 $9.00+9.66+14.83=33.49$，比 optimal 的 28.80 多 16%。Optimal 的顺序第一步反而走了更远的 P2（9.49），换来最后不用从 P2 直接去 P3。Greedy 每一步只看下一段的 cost，看不到这一步把后面的路逼成什么样。
:::

### 有 budget 时：orienteering

电量或时间有限时，问题不再是“全部看完、路最短”，而是“路程不超过 budget $L$，看到的信息最多”。Best 与 Fitch 的写法：graph 的 vertex 是 viewpoint，edge 有 travel cost $c_{ij}\ge0$，从 $v_0$ 出发；path $X$ 的 cost 是 $C(X)=\sum_{e_{ij}\in X}c_{ij}$，它看到的信息记作 $W(X)$，求

$$X^*=\arg\max_X W(X)\quad\text{subject to}\quad C(X)\le L$$

最简单的情形，每个 viewpoint 有一个 weight，$W(X)$ 就是 path 经过的 viewpoint 的 weight 之和，这就是 orienteering problem：在 travel budget 内访问 weight 总和最大的一组 vertex。论文证明它的一般版本是 NP-hard。

很自然的 greedy 是每次去“每单位 cost 带来最多 weight”的点：在还够得着的点里选

$$\arg\max_j\ \frac{W(X\cup\{j\})-W(X)}{c(\text{当前位置},\,j)}$$

论文指出这个 greedy 没有 approximation guarantee。没有 path 约束的 maximum coverage 里，greedy 至少能拿到 optimal 的 $1-1/e$；这里不行，因为一个点的 cost 取决于前面先去了哪里。

::fig[rb3302-budget] 直线上的三个点：$v_0$ 在 0，A 在 $-1$、weight 1，B 在 $+10$、weight 9，budget $L=10$。

按 gain/cost，A 是 $1/1=1$，B 是 $9/10=0.9$，greedy 先去 A。到了 A，剩下的 budget 是 9，去 B 要走 11，去不了，greedy 最后只拿到 1。直接去 B 正好用完 budget，拿到 9。把 A 挪得更近、weight 同比变小（距离 $\delta$、weight $\delta$），它的 ratio 仍是 1，greedy 仍然先去 A，只拿到 $\delta$，而 optimal 还是 9，比值 $\delta/9$ 可以任意小。论文的反例是同一个道理，optimal 是 $N$，greedy 只拿到 1。

论文用 branch and bound 求 optimal。Search tree 的每个 node 是一条从 $v_0$ 出发的 partial path，每个 node 有两个 bound：lower bound 是从这个 node 继续跑 greedy 得到的值，这是一个真实可行的 solution；upper bound 是这条 partial path 已经拿到的 weight，加上剩余 budget 内够得着的所有 vertex 的 weight，好像不用付它们之间的路费。一个 node 的 upper bound 比目前最好的 lower bound $LB^*$ 还小，就整枝剪掉；root 的 upper bound 等于 $LB^*$ 时停止。在上面的例子里手算：

1. Root $[v_0]$：A 和 B 都在 10 以内，upper bound $1+9=10$；greedy 给 lower bound 1。$LB^*=1$。
2. 展开成 $[v_0,A]$ 和 $[v_0,B]$。$[v_0,A]$ 剩 9，B 在 11 外，upper bound 1，lower bound 1。$[v_0,B]$ 剩 0，upper bound 9，lower bound 9。$LB^*=9$。
3. $[v_0,A]$ 的 upper bound $1<9$，剪掉。Root 的 upper bound 更新为两个 child 的最大值 $\max(1,9)=9=LB^*$，停止，答案是 $[v_0,B]$。

Upper bound 越紧，剪得越多。论文报告平均只需展开 search tree 的约 15% 就找到 optimal solution。

:::back
每一步找最近的 frontier、算两点之间的 path cost，用的是[第 1 站](#search)的 search 和 multi-goal A*；看到的 cell 怎样变成 map 见[第 6 站](#map)。
:::

## ME5413 的公开 project

RB3302 preclude 研究生课 ME5413 Autonomous Mobile Robotics，系里的开课表上两门课有同一位授课老师（Prof Marcelo Ang）。RB3302 自己的 project 在 Canvas 上，读不到；ME5413 的两个 project 放在 GitHub 上，README 写明了要做什么，可以拿来看这一类课的 project 长什么样。都在 ROS Noetic 和 Gazebo 里，robot 是 Jackal。

### Planning Project：path tracking

让 robot 跟踪一条给定的 figure 8 track，算法不限，实现在 `path_tracker_node` 里，替换模板代码。模板给了一个没有调好的 PID（管 throttle）和一个没有调好的 Stanley controller（管 steering），还有调参数的 dynamic reconfigure 界面，以及六个 topic 实时报告 position、heading、speed 的绝对 error 和 RMS error。要报告 tracking accuracy。这对应大纲最后的 navigation and control integration：第 7 站的 global planner 给出 path，之后要有一个 controller 把 robot 稳稳地放在 path 上。Pure pursuit 的推导见 [CS4278 第 7 站](../courses/CS4278.html#system)。

### Final Project（AY25/26）：mapping 与 navigation

两部分。第一部分是 map：可以手动开 robot，SLAM 算法和 sensor（2D / 3D LiDAR、camera、IMU 及其组合）都不限，但不能用 Gazebo 的 ground truth；建议用 EVO 之类的工具把自己的 odometry 和 `/gazebo/ground_truth/state` 比较，定量评价 SLAM。第二部分在自己建的 map 上全自主完成一串任务：在下层数出每种编号 box 各有几个，发一个 message 移开出口的 barrel（只能开一次，持续 10 s），上 ramp 到上层，穿过两条 corridor，在两个门洞里避开随机放了 traffic cone 的那个，躲开一个移动的“人”，最后停在编号 box 出现次数最少的那个房间。交 code、一次跑完的 demo video、map 文件、10 分钟 presentation 加 5 分钟 live demo，以及不超过 10 页的 report，要讲清 perception、mapping 与 localization、navigation 的方案和遇到的困难。模板里的 mapping 用 GMapping，navigation 的 launch 载入 map 并启动 AMCL localizer，README 把这两步分别标成“naive”和“incomplete”的版本。对应到这一页：map 是第 6 站，AMCL（adaptive Monte Carlo localization）是第 5 站的 particle filter，global planner 和 local planner 是第 1、7 站，被 cone 挡住的门洞要靠第 7 站的 replanning。
